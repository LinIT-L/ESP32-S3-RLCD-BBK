# 内置应用开发（C）

> 一个应用 = `components/apps/pages/page_xxx.c`，私有 static 状态，不跨页共享。

## 1 注册三步

```c
// ① CMakeLists 的 SRCS 加一行
// ② apps_registry.c 加 os_page_xxx_register()
// ③ 应用表 s_builtin_apps[] 加一条 { .name, .icon_idx, .page_id }
```

```c
static os_module_t s_mod = {
    .name = "xxx", .page_id = OS_PAGE_XXX,
    .on_enter = , .on_exit = , .render = , .action = , .touch = , .poll = ,
    .fullscreen = true,      // 隐藏状态栏
    .exit_confirm = true,    // 返回键先弹"退出程序?"
    .keep_on_idle = false,   // true = 空闲不自动回主菜单(工具页用)
};
```

## 2 图标

- 64×64 1bpp，512 字节，`tools/gen_main_icons_64.py` 从 PNG 生成 `icons_main.inc`。
- ⛔ **`main_icons[]` 顺序 = ABI**：新图标只能**追加末尾**，插队会让所有已注册应用的图标错位。
- 绘制统一走 `ui_common` 的 `draw_main_icon_stretched()` / `ui_main_icon_bitmap()`。

## 3 界面

- 屏 400×300，1bpp，无背光。左右留白相等，按键贴两侧，⛔ 不居中竖排。
- 弹窗几何只有一套：屏宽高 −25×2 = **350×250**，底栏 40，分隔线内缩 6px。
- 字体：中文 16px `ui_text16()`（依赖 `font_zh16` 已加载）、12px `ui_text12()`；ASCII 8×12 `FONT8X12`。⛔ 中英混排分两次调用。
- ⛔ 全局不要标题；⛔ 不加操作说明文字；主题只有"默认"。

## 4 渲染性能（核心）

> 滚动怎么做 → **只看《列表滚动规范》**（唯一实现 `ui_scroll`）。本节只讲"怎么少画像素"。

- 帧耗时 = **画了多少像素**。每帧不要 `fill_rect(0,0,399,299)`。
- 长列表用「离屏整列 + 只抄可视窗」：`ui_col_*`（`page_term.c` 是范式）。
- 静态部分只画一次；不透明图集 `img.load(path,true)` 可免 `app.clear()`。
- 滚动期间**跳过底层重绘**：`ui_scroll_busy()` 为真就尽早 return。

## 5 弹窗

- 统一 `os_dialog_*`，⛔ 不自绘。
- ⛔ 回调里不要 `os_dialog_pop()`（连上层页面一起关）→ 用 `os_dialog_mark_handled()`。
- 列表 0 基；confirm 左确定=0 / 右取消=1；-1 只在超时/BACK 时出现。

## 6 按键 / 触摸

- `action(ctx, a)`；BACK 语义归页面自己。返回键走 `os_request_exit_confirm()`（确认后下一帧才 pop）。
- 有旋转的页面，触摸必须走内核 `ctx->map_touch`，⛔ 只在页内换算。
- ⛔ `poll` 里 `input_get_touch_pos()` 是另一条坐标来源，仍需自己映射。

## 7 PIN 门禁

```c
if (!applock_gate(ctx, "xxx", "标题")) return;   // 没设密码也要弹，空着确认即可进
```

## 8 踩坑

- `render` 里做 IO / NVS / 扫描 ⇒ 卡死丢输入；慢操作放后台 + 脏标记。
- 退出后串口没了 = USB HID 没关。
- `malloc` 后所有 return 路径都要 `free`，包括错误分支。
- **`ui_scroll_init()` 只能在"没在动"时调**（会清 `pressed`/`fling` ⇒ 拖不动、松手弹回原位）。用 `ui_scroll_busy()` 守。
- **`render` 里别每帧 `ui_scroll_ensure_visible()`** ⇒ 选中项被拖出视野会被拉回来，表现为"拖不动"。只在按键上下时调。

## 9 返回键 = 退出确认（2026-10-25 起为硬规范）

**所有应用页按硬件返回键都必须先弹"退出程序?"，确认才退。** 两种接法：

| 情况 | 做法 |
|---|---|
| 页内 BACK 没有别的语义 | 模块声明 `.exit_confirm = true`（内核统一拦，最省事） |
| 页内 BACK 还要关详情/回上一步 | **不设** `exit_confirm`，在最外层那一处把 `os_pop(ctx)` 换成 `os_request_exit_confirm(ctx)` |
| 自绘帧的游戏（仙剑/模拟器） | 调 `os_confirm_exit_blocking(ctx->lcd)`（冻结帧直绘，确认=true 才退） |

⛔ 不要给"弹窗型"页面（usb_bt/usb_net/modtool）设 `exit_confirm` —— 它们的 BACK 只关弹窗。

## 10 资源包型应用（安装包伪装成应用）

仙剑这类"只有游戏数据、没有程序"的东西，**不要写成完整应用**，按资源包走。
2026-10-31 起有**两条路**，新包一律走第一条：

| 路径 | 触发条件 | 卡上写多少 | 装 41.7 MB 耗时 |
|---|---|---|---|
| **清单 + 多文件直接下载**（§10.1） | 索引里有 `manifest` 字段且清单可取 | **41.7 MB**（只写一遍） | ≈ 260 s（≈下载时间） |
| ZIP 下载 + 解包（§10.2 备用） | 没有 `manifest` / 清单 404 | 83 MB（zip + 解出来的） | ≈ 385 s |

1. 商店 `index.json` 里加一条（`manifest` 可省略，省略就走 zip）：
   ```json
   { "name":"仙剑奇侠传", "cat":"游戏", "type":"asset",
     "target":"/sdcard/apps/app/pal", "path":"pkgs/pal.zip",
     "manifest":"pkgs/pal/manifest.json",
     "size":43729607, "crc32":"deec847b" }
   ```
2. 打包用 `python3 tools/pack_asset.py make pal --src <目录> --target <目录> --label 名称 --write-index`
3. 应用条目加 `.requires="<target>"`：**目录不存在时整条不显示**，装完立刻出现在分类里。
4. 卸载 = 按 `.pkg.<zip主干>.lst` 清单删文件（共享目录如 `/sdcard/fonts` 必须这样，不能整目录删）。

### 10.1 ⭐ 首选：清单 + 多文件直接下载（2026-10-31 起）

**背景（真机实测，不是估算）**：仙剑 41.7 MB 走 zip 那条路

```
108.2s 点下载 → 360.4s 下载完成(41.7 MB) → 493.9s 解包完成   = 385 s
卡上总共写了 83 MB（41.7 zip + 41.7 解出来的文件）
```

而系统 `cp` 拷同一个文件 **200 s 都拷不完**（< 208 KB/s）——说明 313 KB/s 已经是
那张卡"边读边写"的上限，**再优化缓冲区也没用，唯一能省的是"别写两遍"**。

**做法**：服务器给一份文件清单，设备**逐个下载真实文件**，直接落最终位置。

1. 生成清单（从目录或现有 zip 都行，**必须用脚本，不要手写**）：

   ```bash
   python3 tools/mk_asset_manifest.py --name pal --zip pal_stored.zip \
           --out dist/asset/pal --title 仙剑奇侠传 --ver 3
   ```
   输出 `<out>/manifest.json` + 全部真实文件；脚本自己算 size/crc32 并做自洽校验。

2. 部署：整个目录传成 `bbk/pkgs/<name>/`，然后给 index.json 该条目加一行：

   ```json
   { "name":"仙剑奇侠传", "type":"asset", "target":"/sdcard/apps/app/pal",
     "path":"pkgs/pal.zip", "manifest":"pkgs/pal/manifest.json", ... }
   ```

3. 设备行为（`am_asset_multi.c`）：
   - 拉 `<mirror>/pkgs/pal/manifest.json` → 校验 fmt/count/total 自洽、逐条路径合法；
   - 逐文件 GET `<mirror>/pkgs/pal/<path>`，`net_client` 写 `.part`，
     **size+crc32 都对才替换目标文件**（校验在替换之前，坏数据顶不掉好文件）；
   - 文件已存在且 size+crc 都对 ⇒ **跳过**（这就是断点续传）；
   - 全部成功才写 `.installed.<zip主干>`（内容 `"<条数> <总字节>"`）；
   - 单文件失败重试 3 次；仍失败则保留已完成的部分，再点一次下载即续传。
   - 卸载：仍然读 `.pkg.<zip主干>.lst`，**与 zip 路径同一套**，上层零改动。

4. 连接复用：109 个文件走**同一条 TCP/TLS 连接**（`netc_req_t.keep_alive`）。
   实测到 bbk.linit.cn：单次请求 TLS 握手 **51~113 ms**，5 个请求复用后总共只用 20 ms。
   不复用的话 109 个文件光握手就白扔 5~35 秒（真机 CPU 慢，只会更多）。

5. **回退是自动的**：`manifest` 字段缺失、或清单 404/被改坏 ⇒ 自动落回
   §10.2 的 zip 下载 + 解包。所以「服务器还没出清单」和「要回滚」都不会让设备不可用。

**目录布局（唯一正确形状）**：

```
bbk/pkgs/pal/manifest.json      ← 清单，里面的 path 相对「本目录」
bbk/pkgs/pal/ABC.MKF
bbk/pkgs/pal/music/39.mp3
```

即：文件 URL = `<mirror>/<清单所在目录>/<path>`。清单里的 path **不能**带 `pkgs/pal/` 前缀。

### 10.2 ⛔ 备用路径：ZIP 包必须 **ZIP_STORED（method=0，不压缩）**

这不是"建议"，是**唯一可用的格式**。违反它会**把设备搞重启**。

**2026-10-31 真机事故（两次复现，栈 20 KB / 32 KB 都一样）**：

```
I AM_ASSET: 资源包 /sdcard/pal.zip: 109 个条目
Guru Meditation Error: Core 1 panic'ed (LoadProhibited)
EXCVADDR: 0x00000028          ← 访问 NULL+0x28
A4 = NULL, A2 = A3 = 0x10000(64KB)
PC = mz_zip_reader_extract_to_callback  miniz_zip.c:1909
→ RTC_SW_CPU_RST 重启，SD 上只留一个 ABC.MKF.tmp
```

**根因**：deflate 条目要走 miniz 的 tinfl，它内部要 `m_pAlloc(1, MZ_ZIP_MAX_IO_BUF_SIZE)`
= **64 KB 连续内存**。而 S3 内部 RAM 最大连续块只有 **31744 B**（31 KB）
（即便配了 `SPIRAM_USE_MALLOC`，这条路径仍然失败），拿到 NULL 后 1909 行直接解引用 ⇒ panic。
**与压缩算法无关、与栈大小无关**——就是那 64 KB 分配拿不到。

**顺带一个反例**：`pal.zip` 原本 31 MB(deflate) → 重打成 stored 是 41.7 MB，
即 deflate 只省 37%，却换来"必崩"。**这笔账不划算。**

### 10.3 固件怎么解包（仅 ZIP 路径）

| 条目类型 | 处理方式 |
|---|---|
| `stored (0)` | **完全不经过 miniz**：算出 local header 后的数据偏移，用 **1 MB PSRAM 缓冲**直接搬字节 |
| `deflate (8)` / 其它 | **直接判失败**并打 `E AM_ASSET: 该条目是压缩格式(method=8)…`，不再尝试解压、不会崩 |

- 拷贝缓冲 1 MB（PSRAM，按 1M→512K→256K→64K→16K→4K 逐级回退，用完即还）
  —— 源和目标在同一张 SD 卡上，缓冲越大读写交替越少，这是解包速度的决定因素。
- 首次安装（目标不存在）**直接写目标文件**，省掉 `.tmp + remove + rename`；
  目标已存在才走临时文件，保证掉电不会毁掉旧文件。
- 进度按**已写字节 / 总解压字节**回报（不是按文件数），大文件写入期间进度条也在动。
- 拒绝绝对路径与含 `..` 的条目（防 zip slip）。自测命令：`asset <zip> <dir>`（remcon）。

### 10.4 发版前必查：这个包是不是 stored

```bash
# 看第一条目的 compression method：0=stored(合格)  8=deflate(会被拒)
python3 - <<'PY'
import struct, sys, urllib.request
u = sys.argv[1] if len(sys.argv) > 1 else "https://bbk.linit.cn/bbk/pkgs/pal.zip"
d = urllib.request.urlopen(u, timeout=20).read(64)
m = struct.unpack_from("<H", d, 8)[0]
print("method =", m, "=>", "✅ stored" if m == 0 else "❌ deflate，必须重打")
PY
```

**2026-10-31 全量审计结果**：14 个资源包里 12 个字体包本来就是 stored；
`pal.zip` 与 `wuxia.zip` 是 deflate（都会崩）。
现已处理：`pal.zip` 重打成 stored 并更新索引；`wuxia.zip`（英雄坛说）连同商店条目下架，
包文件隔离在服务器 `bbk/pkgs_removed/`。

### 10.5 常见踩坑

| 做法 | 结果 |
|---|---|
| `tools/pack_asset.py` | ✅ 内部 `zipfile.ZIP_STORED`，永远合格 |
| Windows 右键"压缩为 ZIP" | ❌ 默认 deflate |
| 命令行 `zip -r out.zip dir/` | ❌ 默认 deflate（要加 `-0`） |
| `shutil.make_archive(...)` | ❌ 默认 deflate（要 `zipfile.ZIP_STORED`） |
| 手工改了包但没更新 `size`/`crc32` | ❌ 下载完校验失败，提示"校验失败" |
