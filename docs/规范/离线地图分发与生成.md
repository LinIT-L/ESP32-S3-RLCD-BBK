# 离线地图：生成与分发

> 适用：LinTOS 离线地图（`.ltm` v3 / 省级 `.bin`+`.json`）。
> 生成工具：`tools/map_prov.py`（已存在，勿重写）；分发端：WordPress 站点 `bbk.linit.cn`。
> 本文只写**规则与边界**，格式本身见 `docs/规范/地图数据格式.md`。

## 1 现状（2026-10-31 实测，只读探测）

| 项 | 实测结果 |
|---|---|
| 资源存放 | `/www/wwwroot/bbk.linit.cn/bbk/maps/`（webroot 内，与站点同域）|
| 目录列表 | `/bbk/maps/` → **403**（未开 autoindex）✅ |
| 直链可下 | `/bbk/maps/fj.bin` → **200**，文件名可猜、可枚举 ❌ |
| 公开清单 | `/bbk/maps.json` → **200**，含 `packs[].files[]` + 每个文件 `size`/`f16` ❌ |
| 备份泄露 | `/bbk/index.json.bak.20261031_*` → **200**（nginx 的 `.bak$` 规则没覆盖 `.bak.时间戳`）❌ |
| 分发方式 | **纯静态**，无 PHP/API 中间层 |
| 404 响应 | nginx 原生，**不泄露**服务器路径 ✅ |
| 设备端 | `apps/lua/src/map.lua`：硬编码 `MAPS_URL=/bbk/maps.json`，按 `mirrors[i] + "/" + path` 下载，crc 校验后落 `/sdcard/Map/` |

结论：**清单与文件都是公开静态资源**，隐藏只能靠"改分发方式"，改页面文案没用。

## 2 目标与不可破坏项

要的：
1. 地图由服务器按规则批量生成，不靠人工往网页上贴清单；
2. 前台只出现"区域 / 体积 / 更新时间 / 怎么下载"，不出现文件名、路径、内部 ID；
3. 设备仍能正常下载（这是硬约束）。

不能破坏：`.ltm` 格式、`/bbk/maps.json` 这个入口地址（老设备硬编码）、已发布的福建/莆田包、商店 `index.json`。

## 3 三档方案

| 方案 | 做法 | 隐藏效果 | 老设备 | 工作量 |
|---|---|---|---|---|
| **A 只藏清单** | 前台不列文件；`maps.json` 保持原样 | 弱：`maps.json` 仍可读，文件仍可直链 | ✅ 不变 | 小 |
| **B 清单+令牌分发**（推荐） | `maps.json` 仍在该地址，但 `files[].path` 改为**带签名的下载路径**；nginx 禁止直连 `/bbk/maps/`；PHP 端点校验签名+限速后 `X-Accel-Redirect` 出流 | 强：无签名拿不到文件，无法枚举 | ⚠ 需发一版 `map.lua`（仍用同一 `maps.json` 地址）| 中 |
| **C 迁出 webroot** | 文件移到 `/www/mapdata/`（不在 webroot），全走 PHP 出流 | 最强 | 同上 | 中+ |

推荐 **B**：`maps.json` 地址不变（老设备的 MIRRORS 逻辑不用改），变的是里面的 `path`——新 `map.lua` 直接当 URL 用即可；旧版本 `map.lua` 会在过渡期被 302 到签名地址（可设期限），到期后旧版本提示升级。

## 4 生成架构

```
OSM PBF（Geofabrik / openstreetmap.fr，ODbL）
      ↓  ① 按区域规则抓取（tools/dl_chunks.sh，按 Content-Length 分块）
cache_map/<region>.pbf
      ↓  ② tools/map_prov.py --pbf … --prefix <id> --outdir staging/<id>/
staging/<id>/{<id>.json, <id>.bin} 或 {<id>_road.ltm, <id>_poi.ltm}
      ↓  ③ 完整性校验（文件存在、大小>0、crc、索引 JSON 可解析、tile 数与 bin 对得上）
      ↓  ④ 增量判定（源 PBF 的 mtime+size+sha1 与 state 比对，未变则跳过）
      ↓  ⑤ 发布（rename 进 bbk/maps/，生成新的 maps.json，保留上一版 .prev 以便回滚）
      ↓  ⑥ 设备下载（maps.json → 签名 URL → PHP 出流）
```

规则写在 `tools/map_rules.json`（不写死在代码里）：

| 键 | 含义 |
|---|---|
| `regions[].id` | 区域短 ID（同时是产物前缀）|
| `regions[].label` | 前台展示名（**唯一**允许出现在页面上的地图字段）|
| `regions[].pbf` | 源文件路径 / 下载 URL |
| `regions[].tile` | 分块度数（0.15 / 0.2），影响单块体积与请求数 |
| `regions[].ovcls` | 概览层收哪些等级（0/1）|
| `limits.max_disk_mb` | 暂存区上限，超了拒绝启动（保护磁盘）|
| `limits.max_concurrent` | 同时生成区域数（默认 1）|
| `limits.timeout_s` | 单区域超时 |

## 5 资源预算（粗估，需实测校正）

已知实测：福建源 PBF 46.5 MB → 产出 **18.0 MB**（概览 605 KB + 610 路块 + 564 地标块），索引 46.7 KB；解析 13 s。

| 假设 | 结论 |
|---|---|
| 单省平均产出 8–20 MB（沿海大省偏高）| 34 个省级区划 ≈ **0.3–0.7 GB** |
| 现有磁盘 | 40 GB，已用 13 GB，剩 25 GB → **可以放**，但必须设 `max_disk_mb` 与暂存上限 |
| 生成耗时 | 单省 1–5 min（含下载 PBF）→ 全量跑一轮 1–3 h，**必须分批 + 断点续跑** |

⛔ 未授权前**不启动**全量生成；先用 1 个省（非福建，如浙江）在 staging 跑通再谈批量。

## 6 暴露面检查清单（每项都要有测试结果，不接受"已经加了权限"）

1. 目录列表：`/bbk/maps/` → 403
2. 直链：`/bbk/maps/<任意>.bin` → 403（nginx `deny all`）
3. 清单：`/bbk/maps.json` → 200，但 `path` 是签名 URL，且**不含**绝对路径/内部 ID
4. 备份/临时：`*.bak`、`*.bak.*`、`*.prev`、`*.tmp` → 403/404
5. 错误响应：404/500 只回 JSON `{"err":"not_found"}`，绝不带路径
6. 管理页：仅 `manage_options` 可见，未登录 → 302 到登录页
7. 生成状态/任务记录：只在后台，前台无接口
8. 签名 URL：HMAC(区域+文件+过期)，过期后 403；不能靠改数字枚举
9. 频率限制：同 IP 每 10 分钟 ≤ N 次下载（PHP 侧计数，不用插件）
10. 日志：nginx access log 不记录完整签名 URL（避免日志泄漏）
