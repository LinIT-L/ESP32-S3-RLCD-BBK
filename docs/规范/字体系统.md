# 字体系统规范

> 阅读器字体（LBF）与系统 UI 字体（ZH1FNT01）是**两条独立路线**，互不影响。
> 本文是两者的唯一权威说明：格式、工具、目录、字号规则、缓存、授权、生成方法。

---

## 1 总体架构

| 层 | 格式 | 位置 | 加载方式 | 谁在用 |
|---|---|---|---|---|
| 系统 UI 字库 | `ZH1FNT01`（既有格式，**未改**） | `appdata` 分区 `+0x400000`(24px) / `+0x480000`(16px) | `esp_partition_mmap` XIP | 全部 UI（370 处调用）|
| 阅读器字体 | **LBF v1**（唯一正式运行格式） | TF 卡 `/sdcard/fonts/*.lbf` | **整块读入 PSRAM，零 IO** | 电子书正文 / 菜单 |
| 阅读器兜底 | 复用上表 UI 字库 | 同上 | 同上 | TF 卡无 LBF 时 |

**硬规则**

- 设备端**没有任何 OTF/TTF/BDF/PCF/HZK 解析器**，全部在主机端 `tools/fontkit.py` 完成。
- 旧 `.fnt`（`BK16FNT1`）运行时代码已整体删除，设备不再读它。
- 阅读器只有一个取字入口 `font_book_glyph_unicode()`，一个渲染路径。
- OTF/TTF 只作为**转换输入**，不参与设备端渲染。

## 2 LBF 格式规范（v1.0）

全部小端。头固定 96 字节。

### 2.1 文件头

| 偏移 | 类型 | 字段 | 说明 |
|---:|---|---|---|
| 0 | u32 | magic | `0x3146424C` = `"LBF1"` |
| 4 | u16 | ver_major | 当前 `1`；设备端**主版本不符直接拒绝**，不静默读 |
| 6 | u16 | ver_minor | 当前 `0` |
| 8 | u32 | header_size | 固定 96 |
| 12 | u32 | flags | bit0 比例字体 / bit1 含 ASCII / bit2 含 CJK |
| 16 | u8 | native_w | 原生字宽（px）|
| 17 | u8 | native_h | 原生字高（px）|
| 18 | i8 | baseline | 基线（自字形顶向下行号）|
| 19 | u8 | line_height | 建议行高（px）|
| 20 | u32 | glyph_count | 字形数 |
| 24 | u32 | cmap_off | 码点表偏移（=96）|
| 28 | u32 | idx_off | 索引表偏移 |
| 32 | u32 | data_off | 字形数据偏移 |
| 36 | u32 | data_len | 字形数据长度 |
| 40 | u32 | file_size | 声称的文件总长 |
| 44 | u32 | crc32 | **本字段取 0 时**对全文件算的 CRC32 |
| 48 | char[32] | name | UTF-8 字体名，null 补齐 |
| 80 | u8 | src_format | 0=bdf 1=ttf 2=otf 3=pcf 4=hzk 5=fnt |
| 81 | u8 | reserved | — |
| 82 | u8[14] | pad | 对齐到 96 |

### 2.2 码点表 / 索引 / 数据

```
cmap  : u32[glyph_count]          严格升序（二分查找前提）
idx   : {u32 off; u8 w; u8 h; i8 xoff; i8 yoff}   × glyph_count，与 cmap 同序
data  : 字形位图，1bpp，行优先，每行 (w+7)/8 字节，MSB 在左，1=墨点
```

- `off` 相对 `data_off`；字形按 `w × ((w+7)/8)` 计算长度，**支持比例字体**（每字宽度可不同）。
- 只存**原生尺寸**字形；2 倍显示由渲染层做严格最近邻扩展，不占文件体积。

### 2.3 设备端校验（`lbf_open`）

拒绝条件（全部返回明确错误，不降级）：magic 不符、主版本不符、头长不符、
段偏移不自洽或越界、文件被截断、码点表非升序、任一索引项越界。
CRC 由 `fontkit.py verify` 在主机端全量校验。

## 3 主机端转换工具 `tools/fontkit.py`

依赖：Python 3.9+，轮廓字体需要 `fonttools` 与 `Pillow`。

```bash
# 查看字体真实格式/尺寸/覆盖/许可
python3 tools/fontkit.py info <src> [--size 16]

# 任意源 → LBF
python3 tools/fontkit.py lbf <src> --out x.lbf --name "显示名" \
        [--size 16] [--hzk-cell 24] [--charset gb2312]

# 批量（manifest 见 tools/fonts_manifest.json）
python3 tools/fontkit.py batch tools/fonts_manifest.json --outdir dist/fonts

# 校验 LBF
python3 tools/fontkit.py verify x.lbf

# 旧 .fnt 迁移（只读源文件，不覆盖）
python3 tools/fontkit.py fnt2lbf /sdcard/fonts/old.fnt --out old.lbf

# 生成 UI 16px 字库（严格按旧 bin 的字符表与顺序）
python3 tools/fontkit.py ui16 <src> --size 16 \
        --index-from components/ui/fonts/font_zh16.bin --out new.bin --report r.json
```

**识别方式**：按文件头判定，不看扩展名（`OTTO`→OTF、`\x00\x01\x00\x00`→TTF、
`STARTFONT`→BDF、`ZH1FNT01`/`BK16FNT1`→固件字库）。

**轮廓字体说明**：`--size` 必须给原生字号。像素字体（如方舟像素、缝合像素）的
轮廓本身就是「每像素一个方格」，在 em=原生字号上渲染后二值化即可还原。

二值化阈值固定 **96**（不是 128/200）：
- 200 会把 7px 字体的 1px 竖笔画整个滤掉（`口` 变成 `匚`、`日` 丢失竖线），实测已复现；
- 96 下细笔画保真，且方舟像素 OTF(CFF) 与 BDF 源的字形一致率仍是 **95%**
  （6749/7052，差异集中在 `¤ ¨ ° ×` 这类符号的边缘 1 像素，中文正文无差异）。

**能用 BDF 就优先 BDF**：轮廓渲染永远有 1 像素级的边界误差。

## 4 TF 卡目录

```
/sdcard/fonts/           # 设备端只认这一层目录里的 .lbf
    ark12.lbf
    fusion12.lbf
    ...
```

- `/sdcard/fonts` **不在** `sd_scan.c` 的自动创建清单里，需用户或安装包自行 `mkdir`。
- 文件名 ≤64 字节（工程约定），全路径 ≤128（阅读器菜单缓冲）。
- FATFS `max_files=24`，字库常驻 1 个句柄。
- **原始字体文件不要放进设备目录**：设备不解析它们，白占卡。

### 添加新字体

1. 主机上把源字体转成 `.lbf`（或用现成的）。
2. 拷到 `/sdcard/fonts/`。
3. 书内菜单 →「字体」→ 选中即可；书架设置页的字体会重新扫描。

## 5 旧 `.fnt` 迁移

设备**不再支持** `.fnt`，但也不能删用户卡上的文件。

1. 把旧 `.fnt` 拷到电脑。
2. `python3 tools/fontkit.py fnt2lbf old.fnt --out old.lbf`
3. 把 `old.lbf` 放回 `/sdcard/fonts/`，旧的 `.fnt` 自行决定去留。

> 当前 `fnt2lbf` 对「偏移表布局随版本变化」的旧文件会**明确报错**而不是猜；
> 遇到报错请先把该文件与生成它的固件版本一起提供。

## 6 字号规则

**只允许：原生尺寸，或原生的严格 2 倍。**

| 原生 | 允许显示 |
|---:|---|
| 8px | 8 / 16 |
| 10px | 10 / 20 |
| 12px | 12 / 24 |
| 14px | 14 / 28 |
| 16px | 16 / 32 |
| 24px | 24 / 48 |

- 2 倍是**严格最近邻**：源像素 → 2×2 像素，无插值、无平滑、无灰阶。
- 非整数倍已全部移除：旧 `20px` / `28px` 档收敛到相邻原生档
  （`book_reader_size_px()` 表为 `{16,16,24,24,32}`，档位编号不变以兼容存档）。
- 请求值不在合法档时按就近原则收敛（`font_book_select` 内的 `snap_px`）。

## 7 缓存与内存

| 项 | 策略 |
|---|---|
| 码点表 + 索引 | 打开 LBF 时一次性读入 **PSRAM**（2.6 万字约 310KB）|
| 字形数据 | **按需** `fseek+fread` 单字，绝不整库入内部 RAM |
| 字形缓存 | 固定 **64 槽 LRU**，每槽 160B，共约 11KB PSRAM，**不随字体增长** |
| 2 倍放大 | 静态 512B 缓冲，用完即弃 |
| 内部 RAM 新增 | 约 **2.6KB**（三个取字/放大静态缓冲）|

`BF_MAX_WIN` 从 256 提到 **1536**。最坏单页容量按源码度量逐项穷举得出
（边距 4/8/14 × 行距 0/+4/+8 × 横竖 × 8~48px）：

| 场景 | 行 | 列 | 页容量 |
|---|---:|---:|---:|
| 8px 横屏 边距4 行距+4 | 23 | 49 | **1127（最大）** |
| 8px 竖屏 边距4 行距+4 | 31 | 36 | 1116 |
| 12px 横屏 边距4 行距+4 | 17 | 32 | 544 |
| 16px 横屏 边距4 行距+4 | 17 | 24 | 408 |

1536 相对最坏 1127 有 **1.36 倍余量**。
注意 `book_rows()` 里有 `if (lh < 12) lh = 16;` 的下限保护，所以 8px 字体选"紧凑行距"时
行高被抬到 16，行数反而变少。

这 1536 组缓冲**全部是 `heap_caps_malloc(... MALLOC_CAP_SPIRAM)` 的运行时堆分配**，
不占静态 BSS —— 所以 `.ext_ram.bss` 数字不变（828,556B），PSRAM 增量出现在运行时堆里：
扫描侧 + 渲染侧合计 **约 58KB**（原 256 时为 9.5KB，净增约 48KB）。

## 8 系统 UI 字库（16px / 24px 双档）

### 8.1 不可动的东西

格式、字节布局、字符表顺序、槽位偏移、`mmap` XIP、`ui_text` / `ui_text16` 等 API
—— **全部保持原样**。替换只动字形内容，不动任何接口。

### 8.2 布局

```
[8B "ZH1FNT01"][u32 count][count×3B UTF-8 字符表][count×char_bytes 字形]
```

| 档位 | 槽位（appdata 内偏移） | 每字字节 | 行宽 | 当前字库 |
|---|---|---:|---:|---|
| 24px 默认 | `+0x400000`（512KB） | 72 | 3 B/行 | **HZK24S 宋体** |
| 16px 默认 | `+0x480000`（256KB） | 32 | 2 B/行 | **文泉驿点阵宋 16** |
| 16px 候选 | `+0x5C0000`（256KB） | 32 | 2 B/行 | 长坂点宋 16（OFL） |
| 24px 候选 | `+0x600000`（512KB） | 72 | 3 B/行 | 方正像素 24（内部测试） |
| 文曲星 | `+0x4C0000`（512KB） | — | — | lav_font，不参与切换 |

`os_db` 在 `+0x540000`，与字体槽互不重叠；四个字形槽后仍有 128KB 空余（`0x680000–0x6A0000`）。

### 8.3 生成方法（必须按旧索引）

```bash
# 16px（轮廓字体 → 16 格，带基线自适应）
python3 tools/fontkit.py ui16 <源.ttf> --size 16 --cell 16 \
    --index-from components/ui/fonts/font_zh16.bin \
    --out components/ui/fonts/font_zh16.bin --report /tmp/ui16.json

# 24px（HZK 原始字模 → 24 格，满格直通）
python3 tools/fontkit.py ui16 <HZK24x> --hzk-cell 24 --cell 24 \
    --index-from components/ui/fonts/font_zh.bin \
    --out components/ui/fonts/font_zh.bin --report /tmp/ui24.json
```

生成器保证：

1. **字符表逐字节沿用旧库**（数量 6818、Unicode、顺序、编码全部一致）。
2. 缺字时**沿用旧字形并列入报告**，绝不静默减字、绝不用空白掩盖。
3. **满格字模直通**：源字形若已经是 `cell×cell` 且 `xoff=yoff=0`（HZK / 点阵 ROM 的
   典型形态，墨迹直接顶到第 0 行和第 `cell-1` 行），**原样搬运，不做基线重排**。
   重排会把顶部或底部整行裁掉 —— 2026-10-30 实测：HZK24S 有 5690 个字顶到第 0 行、
   5269 个字顶到第 23 行，任何整体平移都会破坏字形。
4. **紧致字形才做基线自适应**：轮廓渲染出来的字形宽高可变、带 `xoff/yoff`，
   先按公式摆放，再统计**墨迹底部行众数**平移到旧库基线行（16px → 第 14 行）。
   不同字体声明 ascent 不可靠，这一步对轮廓字体是必需的。
5. 输出前写 `.tmp` 再原子替换。

### 8.4 当前选型

| 档位 | 字体 | 来源 | 许可 | 缺字 |
|---|---|---|---|---:|
| 16px | **文泉驿点阵宋 16px v1.0.0-RC1** | 官方 TTF（用户提供） | GPL-2.0 + 字体嵌入例外 | **0** |
| 24px | **HZK24S 宋体** | HZK24 原始字模 | ⚠ 字模权利不明（GPL 仅覆盖工具） | 19（沿用旧字形） |

16px 换掉正格点黑的原因：用户指定文泉驿为默认。文泉驿字形更接近传统宋体、
简体覆盖 30083 字、零缺字，且与 24px 的 HZK24S 宋体风格统一。

24px 缺的 19 字均为 GB2312 外生僻字（郃儁乂惇祎珪纮畯綝濬禛颙旻詝湉鬱郤黃 及 `—`），
沿用旧字库字形。

> ⚠ 注意：HZK24S 是满格 24×24 设计，字形比原来 PingFang 22px 渲染的更大更靠下。
> 真机上 24px 档的文字会比之前显得略大一号，这是字体本身的字面率差异，不是错位。

### 8.5 兼容校验

```bash
python3 tools/font_selftest.py dist/fonts \
    --ui-old <旧备份>.bin --ui-new components/ui/fonts/font_zh16.bin
```

检查：字符数/字符表/文件大小/magic 一致、无空白字、基线与旧库同众数、无触底。

### 8.6 字体切换（设置 → 显示与声音）

16px 与 24px **两档完全独立**，切一个不影响另一个。

```c
font16_apply(int i);   // 0 = 默认槽, 1 = 候选槽
font24_apply(int i);
```

实现要点：

- 切换 = 把 `font_zh16` / `font_zh` 的内部 mmap **重绑到另一个槽**，UI 绘制代码零改动。
- `rebind()` 校验 magic / count / 长度，失败**自动绑回该档默认槽**并返回 false。
- 持久化在应用层（`os_settings/uif16`、`uif24`），字体组件不碰 NVS ——
  否则 `fonts[ui] → svc_nvs[services]` 会触发分层倒置守卫。
- 开机时 `main.c` 读两个 key 分别恢复；槽不可用则**清掉该 key**，避免每次开机都失败。
- 切换后重建「显示与声音」菜单，标签与新字形同时刷新，不残留旧字形。

⚠ 这是**系统 UI 字库**的切换。阅读器字体走 LBF（TF 卡 `/sdcard/fonts`），
在书内菜单里选，两者互不影响。

## 9.1 Firefly 新宋为什么没做

`fireflysung.ttf` 用的是 Apple 旧式位表 `bloc`/`bdat`（11–16px，2/4bit 灰度）。
按 Apple 规范实现解析后实测：解出的字形度量明显不合理
（`h=32 w=33 adv=128`、`h=0 w=0`），说明该文件的 `bloc` 子表布局不是标准格式。
**宁可不出，也不出错误字形**，因此撤回实现，不用轮廓渲染充数（12px 宋体轮廓二值化后笔画会糊）。
要做需要逐子表比对原始字节反推私有布局，收益不抵成本。

## 10 已知限制

- OTF/TTF 轮廓渲染与 BDF 原生位图在符号边缘有 1 像素差异（95% 一致），中文无差异。
- `fnt2lbf` 对未知版本布局的 `.fnt` 直接报错，不猜。
- LBF 缺字不回落内置字库（避免"看着都有其实混排"），按严格模式画缺字框。
- 字形缓存 64 槽：翻一页最坏 1127 字，会触发约 1063 次单字 `fseek+fread`（FATFS 有
  per-file cache，但真机翻页耗时未实测）。
- **8/10px 字体在阅读器里固定按 2 倍显示**：书架字号档位只有 16/24/32，`snap_px()`
  会把 8px 字体的请求收敛到 16px；原生 8px 未暴露给 UI。
  这是**刻意的**：400×300 反射屏上 8px 汉字笔画只有 1px、无背光时基本糊成一片，
  2 倍显示才是可用状态。若要开放原生档，改动点在 `page_book.c` 的
  `bs_size_wheel_open()`/`bs_size_reader_idx()` 与 NVS 存档索引三处，属于独立小特性。
- **比例字体只是格式支持**：LBF 每字宽度独立，但阅读器排版按等宽 cell 算，实际等宽显示。
- 三个生僻字 `綝 / 詝 / 湉` 在正格点黑里缺字，沿用旧字库（文泉驿宋体）字形，
  笔画偏细、与新黑体略不协调；无可合法获取的黑体来源。
- 换字体后 `.idx` 页索引因布局指纹变化会重建，首次打开会重扫。

## 9 运行时加载策略（2026-10-31 起）

**整块预加载，不是按需读取。**

`lbf_open()` 把整个 LBF 文件一次读进一块 PSRAM（`f->img`），`cmap` / `idx` / 字形数据
全部指向这块映像内部，随后 `fclose` 放掉文件句柄。取字形变成一次指针加法，零 `fseek`、
零 `fread`、零拷贝。

为什么必须这样：早先只把 `cmap + idx` 常驻（约 300KB），**字形走 64 槽 LRU**。
而一页 24px 正文约 192 个不同字形 —— 64 槽根本装不下，等于**每个字打一次 TF 卡**。
翻页慢、切换字体后更慢（缓存被清空），根子都在这里。

| 项 | 规则 |
|---|---|
| 预加载上限 | `LBF_PRELOAD_MAX` = 2MB；实测最大字体 1.23MB（fusion12 37852 字）|
| 触发条件 | `file_size ≤ 上限` 且 PSRAM 余量 ≥ 文件大小 + 1MB |
| 失败处理 | **自动降级**回按需读取 + 64 槽 LRU（`f->preloaded = false`），不报错不崩 |
| 多字体缓存 | `font_book.c` 保留**两槽**：当前 + 上一个。A→B→A 切回时直接交换指针，零 IO |
| 释放时机 | `book_reader_close()` → `font_book_release_all()`，关书即放，避免长期占 PSRAM |
| 内存上限 | 峰值 2 × 1.23MB ≈ 2.5MB；PSRAM 余量 < 3MB 时主动放弃第二槽 |

⚠ 改这条路径前先量：`xtensa-esp32s3-elf-objdump -d` 看 `entry a1, N`，
或直接在真机看 `LBF 已加载: ... 整块 PSRAM·零IO` 这行日志是否出现。
