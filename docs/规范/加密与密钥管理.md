# 加密与密钥管理（keyvault）

> 适用：任何需要存"密码 / 账号 / 私密笔记"的模块。**不是可选建议，是硬规则。**

## 1 规则（强制）

1. **只要用加密模块，敏感数据就必须加密存储。**
   不准把密码/账号/令牌明文写 NVS、SPIFFS、TF 卡，也不准"先明文存、以后再加密"。
2. **PIN 只用来解锁，不当作加密本身。** PIN 通过后由 `keyvault` 派生密钥，数据用密钥加密。
3. **一个模块一套数据，全部走同一把密钥**（同一 PIN），不允许各存一份。
4. **失败要"解不开"，不要"解出乱码"**：读不出来就把这条当损坏，不得把垃圾当明文显示/回写。
5. **改格式必须带迁移**：升级加密实现时，旧数据要么能读，要么明确告知"旧数据不可用"，不许静默丢。

## 2 现在的实现

| 项 | 值 |
|---|---|
| KDF | `PBKDF2-HMAC-SHA256`，60000 次迭代，salt 16 字节（存 NVS） |
| 加密 | `AES-256-GCM`，每条独立 12 字节随机 nonce，16 字节认证标签 |
| 单条格式 | `[nonce 12][cipher][tag 16]` |
| PIN 校验 | `SHA-256(pin)` 存 NVS（仅用于判断对错） |
| 失败策略 | 前 3 次不锁；第 4 次起 30/60/120/300 秒 |
| 格式版本 | NVS 键 `fmt`，`2` = 新格式；`!=2` 时首次解锁自动迁移 |

## 3 接口

```c
os_keyvault_init();                        // 进入应用时一次
os_keyvault_has_pin();                     // 是否已设 PIN
os_keyvault_verify_pin(pin);               // 0=对 1=错 2=锁定
os_keyvault_pin_msg(r, buf, n);            // 统一失败文案
os_keyvault_unlock_secret(pin, key);       // 派生 32 字节密钥（含一次性迁移）
keyvault_add(key, cat, site, account, pwd);// 存一条（内部加密）
keyvault_get_secret(key, idx, out, cap);   // 取回明文
```

页面门禁统一走 `applock_gate()`（见 `components/apps/include/applock.h`）。


## 3.1 应用锁模块（所有 PIN 相关逻辑都在这里）

`components/apps/include/applock.h`：

```c
// ① 进入页面
s_authed = applock_gate(ctx, "fav", "收藏夹");
//   · 已设 PIN → 弹窗验证（输错提示剩余次数/锁定秒数）
//   · 未设 PIN → 在同一弹窗里走「设置Pin / 再次输入」流程（设置完直接进）
//   · BACK = 取消并退出

// ② 渲染 / 按键 / 触摸
if (applock_active()) { applock_render(ctx->lcd); return; }
if (applock_active()) { applock_action(ctx, a); return; }
if (applock_active()) { applock_touch(ctx, x, y); return; }

// ③ 数据加解密（解锁后有效，同一把密钥）
size_t n = applock_encrypt(plain, len, buf);   // buf ≥ len + 28
size_t m = applock_decrypt(buf, n, plain);     // 返回明文长度，0 = 失败/被改
```

> 规则：**任何要存密码的页面，只允许用 `applock_encrypt/decrypt`，不准自己派生密钥、不准明文落盘。**

## 4 安全边界（明确"不防"什么）

- **不防拆机读 flash 的"在线"爆破**：本机没有 Secure Element，HMAC/eFuse 方案未启用。
- **不防被抢整机**：pepper 不存在，芯片在就在。
- **不保护**：apps 分区（Lua 应用/存档）、appdata、TF 卡 —— 这些不是本模块管辖范围。
- 威胁模型 = **防"顺手翻到 NVS 备份/固件 dump 就看到明文密码"**，不是防国家级取证。

## 附：PSA Crypto 迁移与未验证项（2026-10）

IDF 6.0 迁移时，`keyvault` 从旧的 mbedtls 直接调用改为走 **PSA Crypto**。

### 关键风险（**未验证**）

| 项 | 状态 |
|---|---|
| 编译通过 | ✅ |
| **用同一 PIN 派生同一密钥、能解开历史 NVS 旧密文** | ❌ **未真机验证** |

编译通过只证明 API 用对，**不能证明算法参数、盐、迭代次数没变**。
若真机发现旧记录解不开：可**单独回退 `keyvault` 的实现文件**（算法参数未变，回退后旧数据仍可读）。

### 失败路径（已加固）

| 路径 | 处理 |
|---|---|
| PBKDF2 失败 | 不返回半成品密钥，调用方收到失败并提示 |
| SHA-256 失败 | 同上 |

> 这两条来自 P2 风险处理；原则是**失败必须显式失败**，不能"部分成功当成功"。

### 备份口令强度

< 6 位纯数字的口令在 GPU 上可秒破（PBKDF2 迭代次数不高）。界面对弱口令有提示但不强制。
真正的防线是**物理持有设备**，不要把备份文件放公开位置。
