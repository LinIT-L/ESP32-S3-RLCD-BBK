### 1.2 数据格式（生产契约，**冻结**）

```
/sdcard/wiki/<库名>/
  metadata.json        {"version":2,"articleCount":N,"chunks":{"pattern":"articles_%04d.dat"}}
  index.bin            80B/条，按标题 UTF-8 字节序升序：
                         title[64] | chunk:u32 | off:u32 | clen:u32 | ulen:u32   (小端)
  articles_%04d.dat    每篇：'WK1\0' | ulen:u32 | clen:u32 | crc:u32 | lz4_block
  py.bin               64B/条：key[60] 小写 ASCII 全拼 | id:u32   (按 key 升序)
  pyi.bin              64B/条：key[60] 首字母     | id:u32   (按 key 升序)
```

`version` 必须为 2；`index.bin` 大小必须**严格等于** `articleCount×80`，否则 `wiki_open` 直接拒读。

## 2 待办（按优先级，这就是你要解决的）

### P0 生产级数据库生成器（当前最大缺口）

现状：**只有测试用的小库**，真实数据（约 553MB）不存在，也**没有生产版生成脚本**
（`wiki_db.h` 注释指向 `nomad-wiki/tools/build_wiki_db.py`，该文件在本机不存在）。

需要你给出：
1. **输入源怎么选**：中文维基离线 dump（`zhwiki-latest-pages-articles.xml.bz2`）的解析方式；
   或是否改用一个更小的专业库（如中文维基"精选/地理/历史"子集）来控制体积。
2. **分块策略**：`articles_%04d.dat` 每块多大合适（当前代码按 `chunk` 字段索引，无块内偏移上限）。
3. **真 LZ4 压缩**：用什么库、块大小、`clen/ulen/crc` 怎么写。
4. **拼音索引生成**：`pypinyin` 的调用方式；多音字怎么处理（如「重庆」= chongqing）；
   首字母与全拼两套如何保证**与 id 一致且各自有序**。
5. **标题清洗**：MediaWiki 标题里的 `(消歧义)`、斜杠、全角符号怎么处理，保证 index.bin 里 64 字节够用且排序稳定。
6. 一个**可断点续跑**的流水线（553MB 级，不能在内存里一次性展开）。

验收标准：生成后用 `tests/wiki/wiki_db_test.c` 全过，并随机抽 100 篇，正文文本与原 dump 逐字比对无差异（除 HTML 标签）。

### P1 C 层两处加固（有明确证据的缺陷）

1. **`wiki_search` 栈越界读**：`wiki_db.c:230` 的 `memcmp(t, q, qlen)`，`t` 只有 64 字节，
   而 `qlen` 来自 Lua 字符串**无上限**。查询超过 64 字节会读到栈外。
   给出最小改法（`qlen` 截到 `WIKI_TITLE_MAX`），注意不要破坏 `lower_bound` 的前缀语义。
2. **拼音索引重复打开文件**：`wiki_search_py` 每次 `fopen/fclose`（`wiki_db.c:290`）。
   标题搜索有常驻句柄 `S.idx`，拼音没有。给出与 `S.idx` 同构的常驻方案（含 `wiki_close` 释放、换库重置）。

### P2 大库性能与 PSRAM 碎片

- 5 万篇时 `index.bin` ≈ 4MB，二分一次 18 次 IO（每次 80B）——是否需要**索引前 4KB 缓存**来减少 FATFS 目录遍历？
- `wiki_load` 每次 `malloc(clen)` + `malloc(ulen+1)`（单篇实测最大 1.76MB），用完 `ps_free`。
  连续切换文章会在 8MB PSRAM 上反复做 1.7MB 级分配。
  给出**缓冲复用**方案（何时复用、何时缩容、如何避免只增不减），并说明碎片风险如何量化验证。
- 单篇上限当前 `WIKI_MAX_ARTICLE = 4MB` × 2 缓冲 = 最坏 8MB > PSRAM 可用 7.3MB，必然失败。
  给出合理上限建议（依据真实数据的最长条目分布）。

## 3 硬约束（违反即不可接受）

1. **不改数据格式**：`index.bin` 80B、帧头 16B、`py/pyi` 64B、`version=2` —— 一旦改动，设备上已有的库全部作废。
2. **不改 Lua API 名字与语义**（`app.wiki.*` 10 个）—— `wiki.lua` 与将来第三方应用都依赖它。
3. **不动已通过的 C 逻辑**：`lz4_dec.c` 边界检查、`html_to_text` 原地压缩、`layout_lines` 的标点悬挂/英文不拆词，
   这些是踩过坑写出来的，重写只会引入回归。
4. **不加常驻 RAM**：索引不常驻（这是设计前提，8MB PSRAM 要留给游戏引擎）。
5. **数据库在 `/sdcard/wiki/`，与应用安装目录完全分离** —— 卸载应用绝不允许删数据。
6. 不能为了跑通测试去改生产代码里的路径宏（`DIR_ROOT`）。
