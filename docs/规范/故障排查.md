# 故障排查手册

> 按「现象 → 先查什么 → 怎么修 → 怎么确认好了」组织。
> **没在真机验证过的方案会明确标注**，不要把推测当结论用。
> 工具：串口 `remcon`（115200 8N1，`hello` 回 `REMOCON_READY v1`），命令表见[开发指南](../手册/构建测试与发布手册.md) §9。

## 0 三条通用纪律

1. **只认日志，不认眼睛和耳朵**。屏幕黑不等于没送帧，没声音不等于没合成 —— 都要看计数。
2. **每次只改一个变量**，改完立刻验，别叠加。
3. 数字要**同一外设状态下**比（蓝牙开/关、WiFi 开/关的内存数字没有可比性）。

## 1 编译失败

| 现象 | 原因 | 处理 |
|---|---|---|
| `PermissionError ... sitecustomize` / 构建中奇怪的删除失败 | 环境里有 Python 注入（如 Agent/WorkBuddy 的 shim）| 命令前加 `PYTHONPATH= `（见 `build.sh` 说明）|
| `check_deps.py` 报分层违例 | 反向依赖或跨层 include | 按提示改 `REQUIRES`/`PRIV_REQUIRES`，或走注入式回调；**不要**把它加进 `ALLOW_INVERSIONS` 了事 |
| `lua_api_doc.py` 相关构建失败 | 新增了 Lua API 但没重生成文档 | `python3 tools/lua_api_doc.py` 后重编 |
| 找不到 `miniz.h` 相关符号 | 用了 IDF 自带的 `miniz.h`（只声明 ROM tinfl）| 本项目用 `lmz.h`（改名避开遮挡），include 用 `lmz.h` |
| 构建报固件超 `factory` 分区 | 5 MB 装不下 | 看 `idf.py size-components` 找增长点，大块静态数据迁 PSRAM |

## 2 烧录失败

| 现象 | 原因 | 处理 |
|---|---|---|
| `No serial data received` | 设备在 app 运行态，USB 被 HID 占用或没进下载模式 | 进下载模式（BOOT+复位），或趁 USB 重新枚举的窗口 |
| 长写掉线 | 波特率过高 | **必须 460800**（921600 长写必掉）|
| 只改 C 却整片重烧 | 不必要 | 只改 C 写 `0x60000`；只改 Lua 写 `0xC00000` |
| 烧完还是老界面 | 见 §8「固件过期」| 核对 SHA |

## 3 启动异常

**先看串口最后一条 `boot_ts` 打点**，停在哪就知道卡在哪（顺序表见[系统架构](../手册/系统整体设计手册.md) §2）。

| 现象 | 检查 | 处理 |
|---|---|---|
| 卡在 `hw_cfg` 之后、屏上一直翻提示 | 板型没识别出来 | 确认屏/触摸排线；改过线就在「设置 → 硬件管理 → 重新自检」 |
| 卡在 `app_board_init` | LCD/触摸/SD 初始化失败 | 串口看具体 `esp_err_to_name`；黑屏优先怀疑 LCD 引脚与板型不匹配 |
| 反复重启 | 崩溃循环 | 抓 panic 地址 → `xtensa-esp32s3-elf-addr2line -pfiaC -e build/LinTOS.elf <地址>` |
| 开机直接关机 | 手动关机唤醒门控：PWR 没按住 ≥0.5s | 正常行为，按住再松开 |

## 4 屏幕异常

| 现象 | 检查 | 处理 |
|---|---|---|
| 全黑 | `remcon` 发 `fbdump` 抓一帧；看串口有无 `Loaded app`、`ST7305: ★送屏 #n` 是否在涨 | 送帧在涨 ⇒ 屏/排线/背光（反射屏无背光，看反光）；不涨 ⇒ 绘制路径没触发 |
| 画面卡住不动 | 送屏计数停了 | 检查是不是进了屏保（`remcon wpss`）；屏保期间 flush 被门禁丢弃属正常 |
| 花屏 / 局部残影 | 脏区计算错 | 看是否帧内容未变被跳过（这是优化，不是 bug）；强制 `st7305_invalidate_frame()` |
| 开机 Logo 后黑屏 | 桌面渲染异常 | `remcon page` 列页面，`remcon page <id>` 逐个打开定位 |

## 5 触摸异常

| 现象 | 原因 | 处理 |
|---|---|---|
| 完全没反应 | ① 微雪原版**本来就没有触摸**；② RST 时序没给 | 确认板型；探测前必须给 RST 低→高脉冲并等就绪 |
| 偶发 NACK / 失灵 | I2C 没有外部上拉 | 补 4.7k 到 3V3（见[硬件与IO](../手册/硬件与接口手册.md) §7）|
| 坐标偏移 | 旋转页没走 `ctx->map_touch` | 页面自己换算属错误用法 |
| 首次开机判"无触摸"且再也不探 | 结论被落盘 | 「设置 → 硬件管理 → 重新自检」|

## 6 没有声音

**按链路顺序查，别猜**：

1. `remcon audio` → 看 `underruns` 与 `play`/`want` 采样率。
   - `underruns` 持续涨 + `play` 远低于 `want` ⇒ 生产端供不上（合成太重）。
2. 播放器探针（直接问播放器有没有数据）→ 完整回调探针（走链路）→ 两者不一致就是链路里有人动了 buffer。
3. 功放使能 GPIO46 低有效：③ 有 100k 上拉，上电默认导通，固件要尽早拉低。
4. 音量：`app.volume()` / 系统音量是同一个值，别两处各调。

> ⛔ 血案教训：SDLPal 的 `AVI_FillAudioBuffer` 曾写成 `memset(stream,0,len)`，
> 而它在调用链**末端**，结果音乐音效全被清掉 —— 表现为"合成正常、音量正常、播放器满幅，但一帧声音都没有"。
> 空实现的桩只允许 `(void)参数;`。

## 7 Wi-Fi / 网络

| 现象 | 原因 | 处理 |
|---|---|---|
| 取数一直失败，错误码 **28674**（`ESP_ERR_HTTP_CONNECT`），200µs 内就返回 | 内部 RAM 连续块不足，TLS 上下文（需一整块）分配失败 | 见[架构与工程约定](../手册/系统整体设计手册.md) §6.1 四：mbedtls 动态缓冲 + 缩小 content len |
| 联网偶发失败，只在蓝牙+WiFi 同开时 | 内部堆最紧场景 | `remcon audit` 看 `largest`，不得低于 8 KB |
| `app.net.http_get` 返回空 | 只支持 http、≤4KB、静默截断 | 大包/HTTPS 用 `app.net.fetch_*` |
| 商店列表拉不到 | 镜像全失败 | 有内置索引会自动降级离线；检查 `remcon` 是否能 `ping` 网关 |

## 8 蓝牙

> 本项目**只支持 BLE**，没有经典蓝牙（BR/EDR）。经典蓝牙手柄（老 PS4 模式、部分 Xbox、早期国产柄）连不上是预期行为，**不要为兼容它们改代码**。

| 现象 | 检查 | 处理 |
|---|---|---|
| 手柄搜不到 | 对端是不是 BLE HID | 换成 BLE 手柄验证 |
| 连上但按键无反应 | 该手柄没做过映射 | 连上后会自动引导进按键映射（任意页面都会弹）|
| 回连很慢 / 不自动回连 | 一轮回连预算 14s，用尽即关射频 | 属设计；唤醒后重新发起 |
| 想彻底移除某只手柄 | — | 手柄页「忘记此手柄」：清连接记录 + 清 BLE 绑定 + 删档案 + 断开 + 停回连 |

## 9 Lua 应用崩溃 / 白屏

| 现象 | 原因 | 处理 |
|---|---|---|
| 界面全白且无报错 | 五个契约函数写成了 `local function` | 必须是**全局函数**；`tools/lua_check.py` 会拦 |
| 一进就退出 | 脚本语法错或运行时报错 | 串口看 `[APP]` 日志；`tools/lua_check.py` 静态检 |
| 卡顿 / 掉帧 | `render` 里做 IO / 每帧全屏 `fill` | 只画变化区，慢操作放后台置脏 |
| 中文不显示 | 用 `app.texts` 画汉字 / 用 `app.zh` 画 ASCII | 混排一律 `app.mix` |
| 数字算错 | `LUA_32BITS` ⇒ 数字是 **float**（~7 位）| 大地坐标用整数微度，先减后乘 |
| 触摸没反应 | 触摸不走框架回调，`lua_touch` 在 RUN 态恒 false | 应用自己在 `poll()` 里轮询 `app.touch()` |

## 10 应用下载 / 安装失败

| 现象 | 原因 | 处理 |
|---|---|---|
| 「下载失败」 | 网络失败 / 校验失败 / 写盘失败**三者提示相同** | 看串口错误码：`1`=HTTP 非 200，`2`=连接/超时，`4`=校验失败（`3` 未使用）|
| 装完显示「已安装」但打不开 | 自动安装失败被误报成成功（已知缺陷）| 看串口有没有 `ESP_LOGW`；重新下载一次 |
| 空间不足 | 下载前**不预检空间**，失败被归为「连接失败」| 先确认 TF 卡已挂载且有余量 |
| 资源包装完不可见 | 判据是 `target/.installed` 标记 | 检查标记文件；确认应用条目 `.requires` 指向同一目录 |
| 改了服务器索引但设备拉到空 | nginx `open_file_cache` 持有旧句柄 | 改完必须 `nginx -s reload` |

## 11 文件系统异常

| 现象 | 原因 | 处理 |
|---|---|---|
| 应用中心看不到任何内置 Lua 应用 | `/store` 没挂上 | 开机日志找 `SPIFFS /store 挂载`；没有就是挂载失败 |
| 认不到 TF 卡（只能断电恢复）| 深睡 hold 了 SD 三脚，开机没 `gpio_hold_dis` | 见[文件系统与分区](../手册/系统整体设计手册.md) §7 |
| 存储信息全空 / 引擎读不到卡 | 挂载未完成就扫目录，且"没卡"结论被记住 | 消费者要等 `sd_wait_ready()` |
| NVS 写入卡顿 | 在渲染/轮询里写 NVS（关 flash cache）| 交互触发才写，连续调节要防抖 |

## 12 GPS

| 现象 | 检查 | 处理 |
|---|---|---|
| 一直无定位 | `remcon` 看有无 NMEA/UBX 输出 | 确认 UART1 引脚（小智 41/14，微雪与标准 43/44）|
| 有数据但解析不出 | 波特率不匹配 | 固件按 38400→9600→115200→57600→230400→921600 依次试，谁先出数据用谁 |
| 待机耗电偏高 | PMREQ 发送时机 | 已修（v1.0.0）；仍高则查是否被别的模块反复唤醒 |
| 睡醒后失锁 | backup 不保留配置 | 属已知行为，靠重认，不做 UBX-CFG-PRT 重配 |

## 13 休眠 / 唤醒

| 现象 | 原因 | 处理 |
|---|---|---|
| 长按关机看不到确认框 | 屏保态 LCD 被壁纸独占 | 已修（2026-10-28）：先退屏保（解除独占 + 开刷屏门禁 + 恢复触屏）再弹框 |
| 自动关机与长按关机观感不一致 | 历史上自动关机走"快速开机"不画 Logo | 已统一：两种都画 Logo、都要按 PWR ≥0.5s |
| 解锁后停在最后一张壁纸 | 屏保期间主循环 continue，`os_render` 没跑 | 已修：退出屏保时作废送屏指纹 + 置脏 + 1 秒强制重绘 |
| 待机电流超标 | 射频/外设没关 | `remcon heap`/`audit` 看开关状态；高耗能模块必须有明确开关时机 |

| # | 问题 | 风险 |
