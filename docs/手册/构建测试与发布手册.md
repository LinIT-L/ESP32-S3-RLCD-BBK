## 协作
- 先给选项再动手（除明确"全自动"）。一律复用已有字体/资源/UI/模块；没有才新建。
- 内存优先 PSRAM。改动验证完再烧，不逐小改反复烧；排障先看串口日志。
- ⛔ 对外操作（push / 发布 / 远程）前先问。

## 1 开工前问清
1. 类型：全屏应用 / 引擎游戏 / 设置项 / 菜单工具 / 后台服务
2. 入口：主菜单图标 / 应用管家 / 设置子页 / 独立按键
3. 分类：引擎 / 游戏 / 应用 / 运维 / 学习 / 软件
4. 上主菜单还是只进应用管家（默认后者）
5. 弹窗：提示 / 确认 / 列表 / 无
6. 状态栏：保留 / 隐藏（fullscreen）
7. 联网 / 蓝牙 / USB / 触摸手柄双轨 / 存哪（NVS / TF）
8. 是否后台运行（默认不启动）

## 2 归位

| 类型 | 载体 | 备注 |
|---|---|---|
| 全屏应用 | `components/apps/pages/page_xxx.c` | 主菜单一图标 → 全屏 |
| 引擎游戏 | `engine_manager` 的 `s_engines[]` | 只加一行 |
| 设置项 | 设置页子项 | 不占主菜单 |
| 菜单工具 | 应用管家列项 | 复用 `os_app` |
| 后台服务 | `os_register_service` | 不占页面栈 |
| 商店应用 | Lua 单文件（`.lua`） | 复制安装，永不自动启动 |

默认 `hidden=true` 只进应用管家。新增引擎要同时改 `os_pages.c`（hidden+reveal）和 `page_app_manager.c` 的 `s_engine_order[]`。

## 3 常见任务改哪里

| 任务 | 改动点 |
|---|---|
| 加设置项 | `page_settings.c` 的菜单表加一条 + 选择回调加一个 case |
| 加引擎 | `s_engines[]` + `os_pages.c` + `s_engine_order[]` |
| 加后台服务 | 实现 `os_service_t` → `os_register_service()`；不占页面栈、无图标 |
| 加商店应用 | `apps/lua/xxx.lua` → `sync_apps.py` → 刷 `0xC00000` |
| 加弹窗 | `os_dialog_list/confirm/toast`，⛔ 不自绘 |
| 加提示音/震动 | `tone_player` / `vibrator_tap_ui()` |
| 加状态栏项 | `svc_statusbar.c` |
| 改桌面画面/交互 · 加主题引擎 | `apps/theme/r_*.c`（引擎）+ `page_main.c` 里 `os_theme_bind()` 换指针；`page_main` 只是壳（应用清单+启动+事件转发），画面五层与拖动/按键全归引擎 |

## 5 新建页面

```bash
python3 tools/new_app.py myapp --label "我的应用" --cat "程序"
```

手工等价：建 `page_xxx.c` 实现 `os_module_t`（on_enter/on_exit/render/action/touch/poll）→ `apps_registry.c` 注册 → `apps_pages.h` 声明 → `s_builtin_apps[]` 加一条。

- 应用只 `#include "os_app_api.h"`，不直连驱动。
- `tools/check_deps.py`（构建已内置守卫）会拦分层违例。

## 6 主循环与事件
- 主循环每帧：`os_tick()` → 当前页 `render()`（脏标记触发）→ `poll()` → 分发按键/触摸。
- 输入：按键走 `action(ctx, a)`；触摸走 `touch(ctx,x,y)`，命中返回 true。旋转页要用 `ctx->map_touch`。
- 阻塞任务（引擎/网络）自己起任务，`render` 里不许做 IO；用脏标记让主循环重绘。
- 息屏/屏保由独立监督任务驱动，不依赖主循环；要阻止息屏用 `wp_idle_hold(true)`。

## 7 自检清单
- [ ] 一页一 .c，已注册
- [ ] 先搜过同类模板再动手
- [ ] 弹窗走 `os_dialog`，不自绘
- [ ] 触摸/手柄双方案（触屏按压反馈、手柄方向键）
- [ ] 大缓冲进 PSRAM
- [ ] 退出释放全部资源（任务/堆/外设）

## 8 内存与生命周期
- 大数组/表/帧缓冲 → `EXT_RAM_BSS_ATTR` 或动态 PSRAM；内部 RAM 只留热路径与 DMA。
- `on_enter` 加载、`on_exit` 全释放；非必须模块走 `os_hw_request/release`。
- ⛔ 禁止自启动；非必须软件只在应用管家选"后台运行"时启动。

## 9 remcon（串口排障）
115200 8N1；`hello` 回 `REMOCON_READY v1`；一行一条，可 `;` 串联。

| 命令 | 作用 |
|---|---|
| `page` / `page <id>` | 列页面 / 打开页面 |
| `key <动作>` / `tap <x> <y>` | 注入按键 / 触摸 |
| `heap` `blk` `stack` `audit` | 内存 / 堆块 / 栈 / 总览 |
| `fbdump` | 抓屏（配 `tools/fb_png.py`） |
| `bat` `now` `wpss` `rst` | 电池 / ESP-NOW / 息屏分钟 / 复位历史 |
| `loglevel <0..5>` `reboot` | 日志级别 / 软复位 |

## 10 构建 · 烧录
```bash
PYTHONPATH= ./build.sh          # 全量；小改 ./build_fast.sh
bash merge_flash.sh             # 出 dist/merged_16mb.bin
esptool --port /dev/cu.usbmodem* --baud 460800 --after hard_reset \
        write_flash 0x0 dist/merged_16mb.bin
```
- 波特率必须 460800（921600 长写必掉线）；中途掉线重烧即可。
- 分段：只改 C → `0x60000`；只改 Lua → `sync_apps.py` 后刷 `0xC00000`。
- 设备在 app 运行态直连会 `No serial data received` ⇒ 进下载模式或趁新枚举窗口。

## 11 排障三件套
1. **黑屏/无刷新**：先看串口有无 `Loaded app`；有则看 `ST7305: ★送屏 #n` 是否在涨。
2. **崩溃**：`xtensa-esp32s3-elf-addr2line -pfiaC -e build/LinTOS.elf <地址>`。
3. **内存/泄漏**：`heap`→`blk`（看大块）→`audit`（栈水位）；数字要同一外设状态下比。

## 12 版本
唯一来源 `components/system/os/include/lintos_version.h`，接口 `os_version_str/date/name`、`os_build_stamp`、`os_git_desc`。⛔ 别处不许写死版本串。

```bash
vim lintos_version.h && vim CHANGELOG.md
python3 tools/version_check.py
touch components/system/os/CMakeLists.txt   # git 描述是配置期取的，增量不刷新
git tag -a vX.Y.Z -m "LinTOS vX.Y.Z — 主题"
```
⚠ macOS 上 git 要 `/opt/homebrew/bin/git`（`/usr/bin/git` 是 Xcode shim）。

## 13 编码规则（C）
业界通行做法里，只保留本项目**能判定**的这几条：

- **检查返回值**：`esp_err_t` 必须判；初始化失败要降级 + 打日志。⛔ 用 `ESP_ERROR_CHECK` 兜业务错误（会 abort 重启）。
- **ISR 只做最少的事**：置标志 / 发队列。⛔ 在 ISR 里 malloc、打日志、读写 I2C。
- **热路径干净**：`render` / `poll` 里 ⛔ 日志、⛔ 文件 IO、⛔ 每次分配内存。
- **超时必须有限**：除启动阶段，不用 `portMAX_DELAY`；每层等待都有上限。
- **跨任务共享要保护**：mutex 或消息传递；单写多读用快照（拷贝出结构再读）。
- **申请/释放成对**：`os_hw_request` ↔ `os_hw_release`、`malloc` ↔ 所有 return 路径的 `free`；句柄用完置 NULL。
- **可见性**：内部函数一律 `static`；跨文件只暴露头文件里的声明。
- **命名**：`模块_动作()`；常量全大写；文件内状态 `s_` 前缀；类型 `_t` 结尾。
- **魔法数**：进 `#define` 或 `enum`，不散落在表达式里。
- **函数长度**：一屏（~60 行）以内；超了就是该拆的信号。
- **提交**：一个改动一个 commit，前缀 `feat|fix|refactor|docs|chore`；⛔ 提交构建产物（`build/`、`dist/`、`*.log`）。

## 15 第三方组件与许可证交付

发布固件二进制（含 `dist/merged_16mb.bin`、在线刷机页）时，GPL/AGPL 要求**随附完整对应源码**
并保留版权声明与许可证全文；Apache-2.0 要求保留 NOTICE。

本项目含 **AGPL-3.0（gwenesis）** 与 **GPL-3.0（sdlpal）** 组件，**不能假定"全是 GPLv2"**。
完整的组件清单、许可证依据、构建与分发事实、兼容性分析、待法律确认事项，
见 → **[专题 · 第三方组件与许可证](../专题/第三方组件与许可证.md)**。

发布前至少确认：

1. 组件清单与实际编译产物一致（有多少 `.obj` 来自该组件）；
2. 分发镜像附带的许可证文件、源码获取方式已准备；
3. AGPL 组件的处理方式已有人确认（不是"默认没事"）。

## 16 从 ESP-IDF 5.5 迁到 6.0 的坑（2026-10 迁移记录）

本项目 v1.0.0 从 IDF 5.5.5 迁到 **6.0.3**，工具链换成 `esp-15.2.0_20251204`
（与 5.5 的 `esp-14.2.0` **不通用**），Python 环境换成 `idf6.0_py3.11_env`。

### 16.1 环境

| 项 | 值 |
|---|---|
| `IDF_PATH` | `~/esp/esp-idf-v60` |
| Python 环境 | `~/.espressif/python_env/idf6.0_py3.11_env` |
| 工具链 | `~/.espressif/tools/xtensa-esp-elf/esp-15.2.0_20251204/` |
| ROM ELF | `~/.espressif/tools/esp-rom-elfs/20260528` |

由 `build.sh` 设默认值，可用同名环境变量覆盖。

### 16.2 踩过的坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `idf.py` 启动即失败 | tarball 装的 IDF 没有 `.git`，`git describe` 失败 | `export ESP_IDF_VERSION=6.0.3` |
| 一堆莫名其妙的配置冲突 | 5.5 的 `sdkconfig` 与 6.0 混用 | 用 `sdkconfig.defaults` 重新生成，别复用旧 sdkconfig |
| 编译报 FreeRTOS 类型未定义 | 6.0 的公共驱动头**不再隐式包含** FreeRTOS 头 | 显式 `#include "freertos/FreeRTOS.h"` |
| `xTaskGetAffinity` 找不到 | 6.0 移除该兼容函数 | 改用 `xTaskGetCoreID` 或去掉 |
| `CONFIG_FREERTOS_PLACE_FUNCTIONS_INTO_FLASH` 报未知 | 6.0 删除该选项 | 从 sdkconfig 去掉 |
| `CONFIG_SPI_MASTER_IN_IRAM` 行为变化 | 改为依赖 `CONFIG_FREERTOS_IN_IRAM` | 未启用，无影响 |
| SPI Flash 头文件路径变了 | 6.0 重组成 `spi_flash/` 子目录 | 按新路径 include |

### 16.3 迁移后仍未解决（**升级或回退前必读**）

| # | 项 | 影响 |
|---|---|---|
| 1 | **keyvault 的 PSA Crypto 迁移无法静态验证** | 编译通过只证明 API 用对，**不能证明"同一 PIN 派生同一密钥、能解开历史 NVS 旧密文"**。必须真机验证；若解不开，可单独回退该文件（算法参数未变，旧数据仍可读）|
| 2 | 5 条 `esp_sleep_get_wakeup_cause` 弃用警告 | 未改（要把单值判断改成 bitmap，有行为风险、收益低）|
| 3 | 内存基线 | 迁移前后可用 `remcon audit` 对比，但需同外设状态 |

> ⚠ 迁移完成时**未获得烧录授权**，所以上述"编译通过"**不等于真机可用**。
> 首次上机请按 §11 排障三件套 + [故障排查](../规范/故障排查.md) 走一遍，重点验证密码解密。
