# 应用开发与审查规范

> **这份文档回答"怎么查、怎么判、怎么报"，不回答"怎么写"。**
> 写法在别处：《Lua应用开发手册》讲 Lua 怎么写，《系统整体设计手册》讲 C 与架构约束，
> 《内置应用开发》讲 C 应用怎么注册。本文只维护**检查项、判定标准、问题分级和报告格式**。
>
> 状态：**骨架版**（2026-10-30 立）。检查项来自已发生的真实问题，未发生的场景不预先编造。

## 1 适用范围

| 对象 | 典型入口 | 审查重点 |
|---|---|---|
| Lua 应用（商店包 / 内置）| `apps/lua/**/*.lua` | 契约函数、资源释放、每帧开销 |
| C 内置应用 | `components/apps/pages/page_*.c` | 模块契约、退出释放、阻塞点 |
| 系统模块 / 服务 | `components/{system,services,drivers,ui}/` | 生命周期配对、并发、内存归属 |
| 第三方组件 | `components/engines/`、`managed_components/` | 是否改动上游、许可证、资源占用 |

不适用的：纯文档改动、构建脚本单行修正。

## 2 检查清单

每项给「查什么 / 怎么查 / 通过标准 / 权威说明在哪」。
**判定标准只在这里维护一次**，别处引用本文即可。

### 2.1 契约与生命周期

| 检查项 | 怎么查 | 通过标准 |
|---|---|---|
| 五个契约函数是全局函数 | `grep -n "^local function render"` | 无命中（`local` 会导致静默白屏）|
| `on_enter` 申请的资源在 `on_exit` 全释放 | 对照两个函数逐个资源清点 | 任务、堆、外设、图片、定时器全部有对应释放 |
| `init/start` 与 `deinit/stop` 配对 | 看模块是否成对导出 | 无配对不得合入 |
| 退出确认符合约定 | 看是否设 `.exit_confirm` 或调 `os_request_exit_confirm` | 全屏应用/游戏必须有；弹窗型页面不得有 |
| 共享资源用引用计数 | 查 `os_hw_request/release` 是否成对 | 最后一个用户释放；无重复 request 泄漏 |

> 写法与例外清单见《Lua应用开发手册》§3、《内置应用开发》§9。

### 2.2 内存与资源

| 检查项 | 怎么查 | 通过标准 |
|---|---|---|
| 大块静态缓冲进 PSRAM | `grep` 静态数组是否 > 1KB 且无 `EXT_RAM_BSS_ATTR` | 超 1KB 长驻必须迁 PSRAM |
| 内部堆余量 | `remcon audit` 看 `internal free / largest` | **`largest` ≥ 8KB**；新功能后 `free` 下降 ≤ 8KB |
| 任务栈不被误放 PSRAM | 查任务创建是否用外部内存栈 | 会碰 flash 写 / NVS / 深睡的任务必须内部栈 |
| 无内存泄漏 | 进出页面各测一次 `remcon heap` | 退出后回到基线（同外设状态对比）|
| 资源上限有兜底 | 查图片池/定时器池/缓冲是否判满 | 满时返回失败而非越界 |

> 为什么是 8KB、哪些路径不能碰 PSRAM：见《系统整体设计手册》内存章 §6.1。
> 验收命令与对比方法：见《构建测试与发布手册》。

### 2.3 UI 与交互

| 检查项 | 怎么查 | 通过标准 |
|---|---|---|
| `render` 内无 IO / NVS / 网络 | 通读 render 与 poll | 无阻塞调用、无文件访问 |
| 不每帧全屏重绘 | 查是否每帧 `fill(0,0,399,299)` | 只画变化区；有 dirty 闸门 |
| 弹窗走系统弹窗 | 查是否自绘 | 一律 `os_dialog_*` / `app.dlg.*` |
| 中英混排用混排接口 | 查是否用汉字接口画 ASCII | 无空白格；不拆两次调用 |
| 触摸坐标经过映射 | 查旋转页是否用 `ctx->map_touch` / `app.touch()` | 无页内私自换算 |
| 列表/滚动用 `ui_scroll` | 查是否另写滚动 | 唯一实现，见《列表滚动规范》 |

### 2.4 文件与数据安全

| 检查项 | 怎么查 | 通过标准 |
|---|---|---|
| 密码/密钥走 keyvault | 查是否明文写 NVS 或文件 | 必须经 `keyvault`，见《加密与密钥管理》|
| 路径不越界 | 查是否拼接外部输入路径 | 拒绝 `..` 与绝对路径（参考资源包解包器）|
| 写盘走「写临时名 → rename」 | 查覆盖写是否直写目标 | 断电不产生半截文件（服务端同理）|
| 大文件分块 | 查是否一次 `fs.read` 超 512KB | 超限用 `read_at`（≤1MB/次）|
| 敏感数据不落日志 | 查日志是否打印凭据/坐标 | 无明文凭据 |

### 2.5 网络

| 检查项 | 怎么查 | 通过标准 |
|---|---|---|
| 按需启停射频 | 查 `os_hw_request/release` 配对 | 退出即关，不留常开 |
| TLS 内存余量 | `remcon audit` 在「蓝牙+WiFi 同开」下看 `largest` | ≥ 8KB（否则 TLS 上下文分配失败）|
| 超时有限 | 查是否有 `portMAX_DELAY` | 除启动阶段外必须有上限 |
| 失败有降级 | 查索引/下载失败路径 | 有内置兜底或明确提示，不静默卡死 |
| 下载有校验 | 查是否校验长度 + CRC | 双校验，失败删残文件 |

### 2.6 性能

| 检查项 | 怎么查 | 通过标准 |
|---|---|---|
| 帧预算 | `remcon` 查帧耗时 / 目测滑动 | 有脏帧 8ms、静止 16ms 周期 |
| 热路径无日志 | 查 `poll/tick/render` 是否 `ESP_LOGI` | 一律 `ESP_LOGD` |
| 热路径无分配 | 查是否每次 malloc | 预分配或池化 |
| 音频合成在模拟任务内 | 查是否另起音频任务 | 见《系统整体设计手册》§9 的 R1–R4 |

### 2.7 兼容与可维护

| 检查项 | 怎么查 | 通过标准 |
|---|---|---|
| 不写死板型相关引脚 | 查是否直接写 GPIO 号 | 一律走 `board_pins_get()` |
| 分层未越界 | `python3 tools/check_deps.py` | 无新增违例 |
| 新 Lua API 已重生成文档 | `python3 tools/lua_api_doc.py --check` | 通过 |
| 注释与实现一致 | 抽查关键函数头注释 | 注释过时按缺陷记（P2）|

## 3 问题分级

| 级别 | 定义 | 判据 | 处理 |
|---|---|---|---|
| **P0 阻断** | 崩溃、数据丢失、安全漏洞、必现功能失效 | 有复现路径或日志 | 修完才能合入 |
| **P1 严重** | 特定条件崩溃、资源泄漏、明显破坏体验 | 有证据但非必现 | 本批次内修 |
| **P2 一般** | 性能不达标、边界缺失、可维护性问题 | 有源码依据 | 排期修，可先记录 |
| **P3 建议** | 风格、注释、可选优化 | — | 记录即可 |

判定注意：

- **"关掉功能"不算修复**。降级只是止损，必须同时记一条 P1 待办。
- **注释过时也算缺陷**（P2）：它会让后来者按错的说明改代码。
- 同一原因连续失败两次，停止改动，只做根因分析。

## 4 审查报告格式

**项目不保留过程报告**：审查结论当场写进被审对象的权威文档（缺陷进应用资料"已知问题"，
通用教训进本规范 §5 或对应手册）。若客户/发布流程要一份记录，临时出，不入仓库。

| 段 | 内容 |
|---|---|
| 背景与基线 | 任务来源、分支/HEAD、工作区状态 |
| 范围与权限 | 审了哪些文件、有没有改、改了什么 |
| 发现的问题 | 按 P0→P3 排列，每条给**文件:行号 + 证据** |
| 证据分级 | 用【源码】【主机测试】【真机】【推断】【待核实】标注 |
| 验证方法 | 怎么复现、怎么确认修好了 |
| 遗留 | 未验证项、需他人确认项 |

⛔ 不把静态分析写成"已验证"；⛔ 不把推断写成源码事实。

## 5 已发生的典型问题（用于对照，来自历史报告）

> 这些是真实踩过的坑，审查同类代码时优先看有没有重犯。

| 现象 | 根因 | 来源 |
|---|---|---|
| 应用界面全白且无报错 | 契约函数写成 `local function` | 《Lua应用开发手册》§1.3 |
| 取消连接后射频常开 | 三个页面重复 `os_hw_request` 未配对 release | v1.3.1 全仓复查 |
| 合成正常、播放器满幅，但一帧声音都没有 | 桩函数在调用链**末端** `memset(stream,0)` | 《系统整体设计手册》§9.4 |
| 联网一直失败，200µs 内返回 28674 | 内部 RAM 连续块不足，TLS 上下文分配失败 | 《系统整体设计手册》§6.1 |
| 中文显示错乱 | UTF-8 十六进制转义越界 | v1.3.1 全仓复查 |
| 商店装完显示「已安装」但打不开 | 自动安装失败仍置 OK | 《系统整体设计手册》第四部分 |
| 拖不动 / 松手弹回 | `ui_scroll_init()` 在滚动中调用 | 《技术规范·列表滚动规范》 |

## 6 待补充

以下尚未发生过足够多的真实案例，**先留位置，不预先编造判据**：

- 多语言 / 字体裁剪的审查项
- 第三方组件引入的合规审查清单（当前只有许可证，见专题）
- 真机自动化测试的判定标准（目前靠 `remcon` + 人工）
- 功耗回归的门槛值（有零散实测数据，但没有统一判据）

补的时候必须带真实证据，不要写"应该"。
