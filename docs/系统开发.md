# 系统开发

> 只指导写 LinTOS 底层 C 代码：分层、模块契约、内存、音频、启动、页面、存储、NVS、C 应用、密钥。
> 引脚/电气 → [硬件配置](硬件配置.md)；UI/滚动/字体/灰阶 → [UI模块](UI模块.md)；Lua → [Lua应用](Lua应用.md)；构建/发布/排障/专题 → [综合手册](综合手册.md)。

## 1 分层与依赖

`apps(L4) → engines(L3) → system(L2) → services/ui(L1) → drivers/libs(L0)`；`tools/` 不受约束。

- **只允许高层→低层**；同层互调可以，跨层反向禁止（system 不得依赖 engines/apps）。
- **唯一 API 面**：引擎只经 `engine_api.h`，应用只经 `os_app_api.h`；⛔ 直接 include 驱动/服务头。
- **禁止循环依赖**；需要回调时用注入式（如 `gam4980_set_exit_confirm_cb()` 由 os 注入）。
- 依赖显式声明：`REQUIRES`（对外）/ `PRIV_REQUIRES`（内部）。新增 = 注册表加一行 + 实现模块。
- 守卫 `tools/check_deps.py` 已接入构建，违例即失败；IDF 的 `REQUIRES` 不管 include 可见性，分层必须靠它兜底。

## 2 模块契约

- **外设单一所有权**：一个 I2C/UART/I2S/SPI 设备只有一个组件初始化并持句柄，别人走它的 API。
- **API 只增不改**（改签名=ABI 事故）。未完成功能走 `LINTOS_ENABLE_*`，默认 0。
- `init/start` 必须配对 `deinit/stop`；deinit 顺序：**注销回调 → 停任务/定时器 → 关外设/射频 → 释放堆 → 归还总线/引脚** → 指针置 NULL。
- 共享资源（I2C、USB、PSRAM 池）用引用计数，最后一个用户释放。
- ⛔ 启动时全量初始化；高耗能模块（WiFi/BT/USB/音频/GPS）必须有明确开关时机。`esp_pm_lock` 配对、最小持有、⛔ 进 ISR。
- 新模块必须能独立验证（一条 `remcon` 命令或最小示例），不能只靠"进某页点几下"。
- 改内存/任务/生命周期的交付必须附：改动前后 heap、栈高水位、组件 size。

## 3 内存

**PSRAM（8MB）是默认去处；内部 RAM 只给物理上不能放 PSRAM 的。**

禁区（必须内部）：① 禁 cache 窗口内的代码/数据（写 flash、NVS commit、`esp_*_sleep_start`、`esp_bt_controller_init`）② 中断与 `IRAM_ATTR` 代码 ③ DMA 缓冲（LCD flush）④ PSRAM 初始化前的启动早期 ⑤ 逐帧热路径的大块数据（PSRAM 走 cache 且与 flash 争带宽）。

写法：≥1KB 长驻静态用 `EXT_RAM_BSS_ATTR`；大块动态用 `heap_caps_malloc(..., MALLOC_CAP_SPIRAM)`（失败再退内部）；小对象/热路径用普通 `malloc`；**任务栈默认内部**（确认不碰禁 cache 路径才可 PSRAM 栈，且写注释）；整组件 `.bss` 迁移必须同时在 CMake 写 `LDFRAGMENTS "linker.lf"`，否则静默失效。

验收：`remcon audit` 的 `largest ≥ 8KB`（低于就没法建 TLS），新功能后 `free` 下降 ≤ 8KB；必须同开关状态对比，联网项在"蓝牙+WiFi 同开"下测。

预载：>8KB 且会用 ≥2 次的资源一次加载进 PSRAM、用时零 IO、容器退出即释放；四条：谁加载谁释放、缓存归实现方持有、内容变更靠版本号、释放前先停使用者。

## 4 日志

高频上下文（ISR、HID 报告回调、PCM 回调、每帧 `poll/tick/render`、收包循环、心跳）**一律 `ESP_LOGD`**：一条日志经 115200 约 5ms，放 100Hz 路径等于一半时间在打日志。

## 5 音频

| 规则 | 内容 |
|---|---|
| R1 | 引擎合成**必须在模拟任务内**完成，只喂 `audio_player_feed_pcm()`；⛔ 另起"音频任务" |
| R2 | 必须独立音频任务时（SDL 回调）：钉 **CPU1**、优先级 **≤8**、**带超时自保**（单次 >120ms 连续 2 次 → 关该模块）|
| R3 | 高优先级只给"被信号量驱动"的任务；自由跑任务 >8 会饿死 `audio_out` |
| R4 | 贵合成先降级/预渲染（MP3/ADPCM），⛔ 靠调参救 |

`audio_out` 固定 CPU1 prio 8，勿改。

- **出声唯一入口 `audio_output_begin()`**（开 I2S → codec 自检 → **下发音量** → 最后开功放）。⛔ 别处手拼 `es8311_start()+pa_enable()`；漏写音量寄存器（REG32）= "全部成功但没声音"。
- 音量/静音持久化只在 `audio_player`（`set_volume` 防抖 / `set_muted` 立即），页面与 Lua 只调它。
- **桩函数红线**：空实现只允许 `(void)参数;`，⛔ 不许 memset/写缓冲（末端桩会清掉整条链的音效）。

### 5.1 触觉（haptic）

| 层 | 位置 | 职责 | ⛔ |
|---|---|---|---|
| 效果层 | `services/haptic/haptic.c` | 24 个具名效果 + 段式播放（esp_timer one-shot）+ 优先级/冷却/25ms 限频；只认 `strength 0..100 + ms` | 不 include 驱动头、不写 LEDC |
| 后端 | `haptic_backend_pwm.c` | 把强度翻成 vibrator 输出；`claim()` 独占马达 | 唯一碰 vibrator 的文件 |
| 系统接入 | `vibrator_sem()` / `vibrator_tap_ui/tap_game/click` | 语义 → 效果：`TICK→slider_tick` `STEP→step` `CONFIRM→confirm` `BACK→back` `DELETE→delete` `FAV→fav` `BOUNDARY→boundary` `ALERT→alert` `GAME→game_hit`；**调用点不改** | 钩子返回 false 才落回基础 tap |

- 开关：设置 → 触摸与反馈 →「丰富震动」（NVS `haptic/rich`，缺省 1）。关 ⇒ 停掉在播序列 + `play` 返回 `disabled` + 三类反馈回退基础震动。
- 开机 `main` 里 `haptic_init()` 必须紧跟 `vibrator_init()`（注册钩子 + 读开关）；否则首次 `app.haptic` 之前开关"看起来没生效"。
- 独占闸门 `vibrator_set_owner_haptic(true/false)`：播放期间 `tap/click/buzz/play_pattern` **连定时器都不起**（否则到点 `out_off()` 会把效果半路清零）；`vibrator_set/stop` 不受闸门影响（那是效果库的输出通道）。MP3 音乐随动绕闸门，与效果库互斥。

## 6 启动

`app_main()` → `os_boot_shell()` → `os_shell_loop()`（死循环，不返回）。

`app_main` 顺序即契约：唤醒门控（误触回深睡）→ 电源统计 → 日志 → 版本横幅 → 时间 → 挂 `/store` → 释放经典蓝牙内存池 → NVS → **识别板型** → 板级初始化（LCD/触摸/SD）→ 面板反色（**必须在画 Logo 前**）→ 画 Logo 送屏 → 等 SD 收尾 → `os_boot_shell()`。
`os_boot_shell`：`os_init` → `apps_register_all()`（只调一次）→ 串口控制台 → 绑屏到 `board_shim` → 注入平台能力 → 音频+电池初始化。

主循环顺序固定：屏保/关机判定 → `os_tick`（服务 tick + 模块 poll）→ 按键 → 触摸 → `os_render`（脏才画）→ 面板空闲降档 → 周期预算。
**帧节拍是周期不是延时**：脏帧 8ms / 静止 16ms / 屏保 32ms；圈尾只补足到目标周期并至少让出 2ms。

## 7 页面与任务

- 页面 = `os_module_t`：`on_enter/on_exit`（加载与**全释放**）、`render`（只画，⛔ IO/NVS/网络）、`poll`、`action`、`touch`、`.fullscreen`、`.exit_confirm`、`.keep_on_idle`。
- **页面栈**：`os_push/os_pop`，栈顶独占输入与渲染；**弹窗是旁路层**（`os_dialog_depth()` 单独计数）⇒ 回调里 pop 会连上层页面一起关，改用 `os_dialog_mark_handled()`。
- 常驻逻辑用 `os_register_service`（tick/render/touch 热区，不占页面栈）。
- 任务：模拟器 CPU1 prio 3~4（音频同任务）、`audio_out` CPU1 prio 8、网络/下载独立高栈任务（可退出回收）、TF 挂载异步 + `sd_wait_ready` 收口。⛔ `render/poll` 里阻塞。
- **触摸单所有者**：弹窗层 > 覆盖层（快捷栏）> 当前页/引擎，靠 `input_set_overlay_lock()` 闸门；锁置位时 `input_get_touch_pos/multi/get_action` 全部返回无触摸（含虚拟手柄）。覆盖层只读 `input_get_touch_pos_raw()`，不跑手势状态机；**归还只认抬手**，解锁同时 `input_touch_release_all()`；离开页面前必须收回（否则整机触摸失灵）。
- 引擎阻塞主循环时，覆盖层靠 `input_touch_age_ms()>50` 触发 `input_touch_resample()` 补采；`qb_tick/qb_render` 用 trylock 单写者。

## 8 存储边界

- `/store` = SPIFFS（apps 分区，开机挂载；挂失败 ⇒ Lua 应用全不可见）· `/sdcard` = FAT（异步挂载，消费前等 `sd_wait_ready()`）。
- 固件在 `factory`（5MB，实测占用 ~3.8MB，超了构建失败）；应用在 `apps`（4MB，可用 ~3.65MB）；**`appdata`（6.6MB）永不擦写**（字库在里面，擦了要重新 merge 才有）。
- ⛔ 不要在循环里写 NVS（会关 flash cache 停十几~几十 ms）；⛔ 不要 erase `appdata`；⛔ 下载前没有空间预检，装大包前自己确认。
- 陷阱：深睡 hold 了 SD 三脚 ⇒ 开机必须 `gpio_hold_dis`；挂载前扫目录会"记住没卡"；`opendir("/store")` 会吐出多层路径，扫列表需自己过滤。

## 9 应用中心（只需知道机制）

- 安装 = **复制文件，永不自动启动**；更新判定按 `build`（12 位构建时间）比较。
- 下载先写 `.part`，校验（size+CRC）通过才替换；失败只删 `.part`，旧文件只改名不删 ⇒ **可恢复的非原子替换**。
- `asset` 类解压到 `target`，以 `<target>/.installed` 为已装判据；卸载按清单删，共享目录不能整目录删。
- **改商店前必读**：① 下载任务与页面解耦 ② **弹窗回调里禁止导航调用**（会连商店页一起关）③ 同步兜底不得 `vTaskDelete(NULL)`（会删 UI 主任务）④ 操作完成只刷状态、不做导航。

## 10 NVS 归属

1. **一个命名空间一个主人**：只有主人能加 key，别人读走主人 API，⛔ 自己 `nvs_open`。
2. 跨模块共用必须登记（如 `os_settings` 的音量归音频服务、`eco` 由 wallpapers 缓存）。
3. 写 NVS 关 cache ⇒ 交互触发才写，连续调节要防抖。

关键归属：`os_settings`=全局设置（`page_settings`）· `os_wp`=屏保/关机（wallpapers）· `os_book`=阅读（引擎管进度、页面管样式）· `os_hw`=板型 · `wifi_cfg`/`btiman`/`usb_*`/`os_fav`/`keyvault`=各服务 · `luaapp`/`core_db`=Lua KV。Lua 侧有 1 秒节流，风险窗口是写后 1 秒内断电。

## 11 内置 C 应用

- **注册三步**：CMake SRCS 加一行 → `apps_registry.c` 加 `os_page_xxx_register()` → `s_builtin_apps[]` 加 `{name, icon_idx, page_id}`。**图标顺序 = ABI，只能追加末尾**。
- 界面：400×300 1bpp 无背光；⛔ 不要标题、不加操作说明文字；弹窗几何只有一套（350×250，底栏 40）；中英混排不分两次调用。
- **返回键 = 退出确认（硬规范）**：普通页 `.exit_confirm=true`；BACK 另有语义的页不设，在最外层把 `os_pop()` 换 `os_request_exit_confirm()`；自绘帧游戏用 `os_confirm_exit_blocking()`；⛔ 弹窗型页面不设。
- 性能：帧耗时=画了多少像素，⛔ 每帧全屏 fill；长列表离屏整列；滚动期间 `ui_scroll_busy()` 就早退；C 页长动画在帧循环里调 `input_pm_boost_now()`。
- 弹窗统一 `os_dialog_*`，⛔ 不自绘、⛔ 回调里 pop；列表 0 基，confirm 0=确定/1=取消/-1=超时或 BACK。
- PIN 门禁：`if (!applock_gate(ctx, "xxx", "标题")) return;`

## 12 KeyVault

红线：① 敏感数据必须加密存储，⛔ 明文落 NVS/SPIFFS/TF ② **PIN 只用于解锁**，密钥由 keyvault 派生 ③ 一个模块一套数据、同一把密钥 ④ 解不开按损坏处理，⛔ 把乱码当明文 ⑤ 改格式必须带迁移，⛔ 静默丢数据。

调用：`os_keyvault_*` + `keyvault_add/get_secret`；页面门禁 `applock_gate()`；加解密只许 `applock_encrypt/decrypt`，⛔ 自己派生密钥。
边界：无 Secure Element，**不防拆机读 flash 的离线爆破、不防整机被抢**；保护范围仅 keyvault 自身。

## 13 提交纪律

- 交付前静态自查（判据见 §1–§12，不在此重复）：契约齐全 · `on_enter` 申请的 `on_exit` 全释放 · `init/stop` 配对 · 退出确认合规 · `check_deps.py` 无新增违例 · 新增 Lua API 已跑 `lua_api_doc.py`。
- 内存类改动附改动前后 heap / 栈高水位 / size；引脚不写死（走 `board_pins_get()`）。
- 分级：P0 崩溃/丢数据/安全（修完才能合入）· P1 特定条件崩溃/泄漏（本批次修）· P2 性能/边界/**注释过时**（排期）· P3 建议。
  "关掉功能"不算修复（同时记 P1）；同一原因连续失败两次 → 停手只做根因分析；审查结论写进权威文档，不留过程报告。
