# 应用管理（App Manager）实现计划

**目标：** 把原「应用商店」落地为**纯本地应用管理**功能 —— 统一管理固件内置的所有功能模块的启用 / 停用 / 卸载，权限模型 + 注册表已就绪，为未来扩展（壁纸程序、电子白板、新引擎）预留接口。主菜单精简为 5 项固定项 + 应用管理入口。

**架构：** 复用已完成的 Phase A 模块注册表 `s_modules[]`（见 `components/menu/menu_system.c:3395-3500`）。新增：
1. 注册表增加 `default_installed`（出厂默认是否在主菜单显示）字段；
2. 新增 `MENU_PAGE_APP_MANAGER` 页面，以弹窗/列表形式列出所有模块及其状态（已启用/已停用）；
3. 主菜单渲染只显示「强制项 + 已安装项」，非强制/引擎项经应用管理点亮后才出现；
4. 状态持久化流：沿用现有 `feature_switch` + 新增 `app_installed` 位图，TF/NVS 存读共存。

**技术栈：** ESP-IDF v5.5.5 C 固件，`menu_system.c/.h`，注册表驱动。

> 关键边界：ESP32-S3 无法运行时编译新代码，引擎依赖编译进固件；「应用管理」只做**开关/管理**，不做代码下载（联网下载留待未来资源包阶段）。

- [ ] **Step 4：实现弹窗回调（新建函数，放在 feature_switch 弹窗附近 6031 行后）**

```c
/* 应用管理: 构建条目列表 (仅 kind != MANDATORY 的可管理项) */
static int app_mgr_build(menu_state_t *state, char buf[][64], int max) {
    int n = 0;
    for (int i = 0; i < (int)BBK_MODULE_COUNT && n < max; i++) {
        const bbk_module_t *m = bbk_module(i);
        if (!m || m->kind == BBK_MOD_MANDATORY) continue;
        bool installed = (state->settings.app_installed & (1u << i)) != 0;
        const char *label = m->dialog_label ? m->dialog_label : m->short_label;
        snprintf(buf[n], 64, "%s [%s]", label, installed ? "\xe5\xb7\xb2\xe5\xae\x89\xe8\xa3\x85" : "\xe6\x9c\xaa\xe5\xae\x89\xe8\xa3\x85"); /* 已安装/未安装 */
        n++;
    }
    return n;
}

static void app_mgr_on_select(menu_state_t *state, int idx) { /* 已装->停用, 未装->启用 */
    int phys = 0, n = 0;
    for (int i = 0; i < (int)BBK_MODULE_COUNT; i++) {
        const bbk_module_t *m = bbk_module(i);
        if (!m || m->kind == BBK_MOD_MANDATORY) continue;
        if (n++ == idx) { phys = i; break; }
    }
    state->settings.app_installed ^= (1u << phys);
    config_save_feature_switch(state); /* 持久化 */
    int cnt = app_mgr_build(state, state->list_dialog_items, 100);
    list_dialog_set_count(state, cnt);
    state->needs_redraw = true;
}

static void open_app_manager_dialog(menu_state_t *state) {
    int cnt = app_mgr_build(state, state->list_dialog_items, 100);
    list_dialog_open(state, state->list_dialog_items, cnt, 0, app_mgr_on_select);
    state->list_dialog_title = "应用管理";
}
```

> 编辑器镜像说明：`config_save_feature_switch` / `list_dialog_*` / `state->list_dialog_title` 以现有 `feature_switch_*`（5962-6031 行）为镜像实现，保持命名一致。

- [ ] **Step 1：新建 `app_meta.h`，声明权限能力常量**

```c
#ifndef APP_META_H
#define APP_META_H
#include <stdint.h>

/* 模块申请的系统能力 (权限位), 应用管理/商店据此授权 */
typedef enum {
    APP_CAP_SCREEN   = (1u << 0),  /* 屏幕渲染 */
    APP_CAP_AUDIO    = (1u << 1),  /* 音频输出 */
    APP_CAP_TOUCH    = (1u << 2),  /* 触摸 */
    APP_CAP_STORAGE  = (1u << 3),  /* TF 卡/存储 */
    APP_CAP_INPUT    = (1u << 4),  /* 按键/手柄 */
    APP_CAP_BT       = (1u << 5),  /* 蓝牙 */
    APP_CAP_NETWORK  = (1u << 6),  /* 联网 (未来资源包) */
    APP_CAP_USB      = (1u << 7),  /* USB HID/MSC */
} app_cap_t;

#endif
```

- [ ] **Step 2：`bbk_module_t` 增加 `caps` 字段并给各模块赋值**

```c
    uint32_t        caps;          /* 需要的系统能力 (app_cap_t 组合) */
```

为管理项补充（示例）：
```c

```

> 新引擎（文曲星/暴龙机）将来只需在 `s_modules[]` 加一条带 `caps` 的条目即可接入，无需改主逻辑 —— 这就是「预留接口 + 高权限」落点。
