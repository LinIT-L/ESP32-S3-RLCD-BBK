# 设置页改造方案：硬件自检 + 硬件配置（三版通用）

## 目标（linit 2026-10-16）
1. 小智版有时**不焊 GPS** ⇒ 需要**自检**：检测不到的硬件**不启动**。
2. **"网络与系统"里新增"硬件配置"**：可**运行时开关**各项硬件（触摸/SD/音频/电池/GPS/震动）。
3. 重排设置页；**"请作者喝杯饮料"必须保持在最下方**。
4. ★ **对所有版本通用**（小智/微雪/自制 共用一份代码）。

## 现状
- 设置主菜单：`components/apps/pages/page_settings.c:44`（5 项，饮料在末位）。
- 本轮临时方案：`components/drivers/board_pins/include/board_pins.h` 的**编译期** `LINTOS_USE_*`
  —— 换一项要重编，**不通用** ✗。

## 正式设计
- **引脚** ← `board_pins.c` 板型表（每版不同）。
- **启用/禁用** ← **NVS 运行时开关**（新命名空间 `os_hw`，键 `en_mask`）：位 0=触摸 1=SD 2=音频 3=电池 4=GPS 5=震动。
- **硬件自检** ← 开机探测（可手动重跑）：
  * I2C 扫描：`0x18`=ES8311(音频) · `0x15`=CST816(触摸) · `0x6B`=QMI8658(六轴)
  * GPS：9600 下读 200ms 有无字节（无 ⇒ 未焊）
  * SD：尝试挂载
  * 结果 → `det_mask`；**`en_mask 默认 = det_mask`**（检测到的才开）。
- **"硬件配置"页**：列出探测到的硬件 + 开关；改动立即生效 + 存 NVS。

## 页面结构（主菜单顺序不动）
```
显示与时间 / 声音与反馈 / 休眠与电源 / 网络与系统 / 请作者喝杯饮料(底)
                                    └─ 硬件自检 / 硬件配置  ← 新增
```

## 实现落点（下轮直接改这些）
1. 新增 `components/services/hw_cfg/`（NVS 读写 `en_mask`/`det_mask` + 探测函数）。
2. `app_board_init*` 各步加 `if (hw_cfg_enabled(HW_XXX))` 判断（取代现在的 `LINTOS_USE_*`）。
3. `page_settings.c`：在"网络与系统"子菜单加两项 + 新开 `open_hw_selfcheck_dlg()` / `open_hw_cfg_dlg()`。
4. 探测结果打印到串口（`HW: det=...`），便于日后排查。

# ★★★ 终极目标：一个固件通吃三块硬件（自适应检测）

## 判据（三块板各有什么"指纹"）
| 板 | 音频芯片 | 触摸芯片 | 指纹 |
|---|---|---|---|
| ① 小智 | ES8311 @0x18，I2C **38/47** | CST816 @0x15，I2C **5/13** | 38/47 上有 0x18 |
| ② 微雪原版 | ES8311 @0x18，I2C **13/14** | 无 | 13/14 上有 0x18，**无 0x15** |
| ③ 自制(仿微雪) | **NS4168（无 I2C）** | CST816 @0x15，I2C **15/7** | 13/14 上**无 0x18**，15/7 上有 0x15 |

## 检测流程（开机 200ms 内完成）
1. 依次在候选 I2C（38/47 → 5/13 → 13/14 → 15/7）尝试探测：
   - 找到 **0x18 (ES8311)** 且总线是 **38/47** ⇒ **① 小智**
   - 找到 **0x18** 且总线是 **13/14** ⇒ **② 微雪**
   - 找到 **0x15 (CST816)** 且总线是 **15/7** ⇒ **③ 自制**
2. 兜底：若都没探到 ⇒ **按上次存 NVS 的板型**（键 `board_id`）；再没有 ⇒ 默认小智。
3. 检测结果 → `board_id` 写 NVS（下次开机可先直用，探测失败也有退路）。

## 与"硬件配置/自检"的关系
- **板型**决定**引脚**（`board_pins.c` 表）
- **探测**决定**哪些模块真存在**（`det_mask`）
- **NVS `en_mask`** 决定**实际启动哪些**（默认 = det_mask，用户可在设置里改）

## 落地顺序
1. `components/services/hw_cfg/`：
   - `hw_detect_board_id()`：按上面流程探测（用 `i2c_master_probe` 风格的非阻塞探测）
   - `hw_scan_all()`：填 `det_mask`（音频/触摸/SD/GPS/电池）
   - NVS 读写：`board_id` / `en_mask` / `det_mask`
2. `main.c` 开机：**先 `hw_cfg_init()`（探测 + 设板型）→ 再 `app_board_init`**（引脚即来自探测出的板型）
3. `app_board_init*` 各步改成 `if (hw_cfg_enabled(HW_XXX))`
4. 移除 `board_pins.h` 里的选板宏与 `LINTOS_USE_*`（编译期 → 运行时），**只剩一张引脚表**
5. 串口打印一行指纹：`HW: board=微雪 det=0x3F en=0x3F`（便于日后排查）

## 风险与对策
- 探测用的 I2C 引脚可能与 LCD/SPI 冲突 ⇒ **探测前先配好引脚、探测后立即 deinit 总线**；探测只在开机做一次。
- 探测失败（断线/虚焊）⇒ 有 NVS 里的 board_id 兜底，不会变砖。
- 自制板音频无 I2C ⇒ **音频不能用 I2C 判据**，只能靠"其它两项指纹 + 兜底"区分。
