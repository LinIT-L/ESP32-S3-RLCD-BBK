# 固件占用审计与空间规划（2026-09-22）

> 目的：为引入裁剪版 LVGL 腾出空间。先回答"**空间在哪**"，because 结论与直觉相反 ——
> 镜像里几乎没有可删的死代码，**空间卡在分区划分上**。

---

## 一、权威占用（`idf.py size`，实测）

| 类别 | 大小 | 说明 |
|---|---|---|
| **Flash Code**（.text） | 2,470,636 B = **2.36 MB** | 所有代码 |
| **Flash Data**（.rodata + .appdesc） | 1,298,320 B = **1.24 MB** | 只读数据/字模/查表 |
| **合计进 Flash** | **3.59 MB** | `LinTOS.bin` 3,940,944 B（含头/对齐） |
| DIRAM（内部 RAM） | 176,935 / 341,760 B = **51.8%** | 余 164,825 B |
| IRAM | 16,384 / 16,384 = **100%** | 其实是"IRAM 用满 16KB，其余归堆" |
| RTC FAST / SLOW | 80 / 36 B | 几乎空 |

分区余量：`factory` 4.00 MB − 3.758 MB = **247.6 KB（6%）**。

## 三、死资源审计：**镜像里没有可删的辣鸡**

### 3.1 已确认"进了源码树但**没进镜像**"（0 flash）

| 项 | 大小 | 证据 |
|---|---|---|
| `oui_db.bin`（wifi_manager = macoui） | 287.5 KB | ① `macoui_lookup()` **零调用者**；② 在 `LinTOS.elf` 里**按字节搜不到** |
| `icons_main_extra.inc` | 41.4 KB | 全仓零 `#include` |
| `font_zh_light.bin` | 499.4 KB | 全仓零引用（appdata 已无此槽）|
| Lua 官方测试套件 `testes/` + `ltests.c` + `onelua.c` | 535.5 KB | 未列进 `SRCS` |
| simavr 未用外设 8 个 `.c`（usb/uart/twi/usi/lin/acomp/adc/bitbang）| 88.5 KB | 已由 `*_stub.c` + `SIMAVR_STUB_*` 替代 |
| 死头文件 3 个（`coleco_bios.h` 49.4 KB 最大）| 52.9 KB | 零 `#include` |
| **合计** | **1.2 MB** | **已移入 `.trash_20260922/`（可恢复）** |

> ⚠️ **对 flash 的收益：0**。实测移走这 1.2 MB 后 `LinTOS.bin` 尺寸不变。
> 收益是**仓库体积**，不是固件空间。

### 3.2 图标类：**总共只有 30.6 KB，且全在用**

| 类别 | Flash |
|---|---|
| 主菜单图标（33 个 64×64）| 16.7 KB |
| 赞助页二维码 | 11.1 KB |
| 分类图标 | 2.1 KB |
| 挂载/状态栏/杂项 | 0.6 KB |

33 个 `ICON_*` 枚举**全部被引用**，零未使用。→ **不是重点，没必要动**。

### 3.3 结论

`--gc-sections` 已经把未引用代码清干净了。**固件里剩下的每 1 KB 都是真实功能。**
想腾空间，只有三条路 —— 见下。

## 四、三条腾空间的路

### 方案 A：重划分区　**★ 推荐（零功能损失，收益最大）**

事实：**`apps` 应用安装区 5.625 MB 只用了 7.9%**（6 个应用净占 92.5 KB），
而 `factory` 只剩 247.6 KB。这是纯粹的分配失衡。

```
现在                                    改后（apps 5.625MB → 2MB）
  0x010000 nvs      256 KB                0x010000 nvs      256 KB
  0x050000 phy_init   4 KB                0x050000 phy_init   4 KB
  0x060000 factory    4 MB   ← 94%满       0x060000 factory  7.625 MB  ← 空 3.87 MB
  0x460000 appdata    6 MB                0x800000 appdata    6 MB
  0xA60000 apps     5.625 MB ← 7.9%用      0xE00000 apps       2 MB   ← 仍够装 ~1.9 MB
```

| | 现在 | 改后 |
|---|---|---|
| factory 空闲 | 247.6 KB | **3.87 MB** |
| apps 可用 | 5.18 MB | ~1.9 MB（≈20× 现有内容）|

- 代价：**分区表变化 → 必须整机重烧**（你本来就要烧），NVS/appdata/apps 内容位置会变。
- 影响面：`partitions.csv` + `merge_flash.sh` 里两个硬编码偏移。
  `font_part.h` 用的是 appdata **相对**偏移、`lua_launch.c` 用 **label** → 都不用改。
- 1 MB 的 apps 也够（还能装 ~60 个应用）→ 还能再多给 factory 1 MB。

### 方案 B：大只读表迁 appdata（mmap，不砍功能）

把 `const` 大表搬到 appdata，运行时 `esp_partition_mmap` 读（字库/`bp_lut` 已是这套）：

| 表 | 可迁 |
|---|---|
| m68k 跳转表 + cycles | 299.7 KB |
| GB2312 双向表 | 170.2 KB |
| lut + lb_prop_bmp | 128.0 KB |
| **合计** | **~598 KB** |

- 但 appdata 只剩 **384 KB** 空档 → 得先重排槽位，或把 8.BIN/E.BIN（4 MB）移到 TF 卡。
- 只动数据不动代码，**功能零损失**。

### 方案 C：砍功能（产品取舍，最后才考虑）

| 功能 | Flash |
|---|---|
| MD 模拟器 | 641 KB |
| SMS 模拟器 | 248 KB |
| 电子书 | 145 KB |
| NES 模拟器 | 71 KB |
| Arduboy | 56 KB |
| 文曲星 LavaX | 62 KB |

## 五、LVGL 预算（按方案 A）

| 项 | 需求 | 方案 A 后可用 |
|---|---|---|
| LVGL 核心（无控件）| ~120–180 KB | |
| + 控件（btn/label/bar/arc/list/switch）| +40–80 KB | |
| + 中文字体（复用现有字库 mmap，不新增）| 0 | |
| **Flash 合计** | **~200–300 KB** | **3.87 MB** ✅ 轻松 |
| LVGL 堆 | 走 PSRAM（`LV_STDLIB_CUSTOM`→ PSRAM 分配器）| PSRAM 充裕 ✅ |
| 绘制缓冲 | 走 PSRAM | ✅ |
| 内部 RAM 增量 | 尽量 0（对象/缓冲全放 PSRAM）| 余 164.8 KB ✅ |

**结论：走方案 A 后，LVGL 不需要激进裁剪也能放下；但仍按单色屏做瘦身配置**
（`LV_COLOR_DEPTH 1` + 只开必要控件 + 不引入 LVGL 自带字体 + 对象/缓冲走 PSRAM）。
