# 飞机信号（ADS-B / 1090MHz）接收 · 硬件与实施方案

> 2026-10-02 立项评估。**本文只做方案，未写任何代码。**
> 起因：linit 看到开源项目 `ironicbadger/ESP32-Plane-Radar`，问"想接收这些信号要加什么硬件"。

---

## 0. 先纠正一个前提（很重要）

**那个开源项目并不接收无线电信号。** 已核实其 README：

| 它实际用了什么 | 说明 |
|---|---|
| ESP32-C3 Super Mini | 只做联网 + 画界面 |
| 1.28″ 圆屏 GC9A01 (240×240) | SPI 显示 |
| **WiFi** | 拉 `https://opendata.adsb.fi/api/v3/` 的 **HTTP JSON** |
| — | 航线 `api.adsbdb.com`、天气 `Open-Meteo` |
| — | **没有 1090MHz 接收器、没有 SDR、没有天线** |

也就是说它是**"云数据的客户端 + 好看的表盘"**，不是"收音机"。

ESP32 的 WiFi/BT 射频是 **2.4GHz**，物理上**不可能**收到 **1090MHz** 的 ADS-B —— 想要"自己收信号"，**必须外挂 1090MHz 接收前端**。

所以先要明确你要哪一种：

- **要"看到我头顶有哪些飞机"** → 走网络数据，**不用加任何硬件**（LinTOS 已有 WiFi）。
- **要"掌机自己收 1090MHz 信号"** → 加接收前端（下面 B 方案）。

---

## 1. 四条路线对比

| 方案 | 要加的硬件 | 成本 | 难度 | 真收信号 | 掌机适配 | 说明 |
|---|---|---|---|---|---|---|
| **A. 纯网络数据** | 无（用现有 WiFi） | **0** | **低** | ✗ | ★★★★★ | 复刻那个开源项目的思路；1-2 天能出效果 |
| **B1. 专用接收模块** ⭐ | **GNS 5892 模块** + 1090MHz 天线 | ~¥100-250 | 中 | ✓ | ★★★★ | 低功耗(40mA)、便携；串口直出已解码数据 |
| B2. ADSBee 1090 | 开源硬件（RP2040+ESP32-S3+CC1312+自研 RF 前端），买成品或自己做 | 较高 | 高 | ✓ | ★★★ | UART/WiFi/Ethernet 输出目标串；GPL-3.0 |
| B3. RTL-SDR 棒 | RTL2832U+R820T2 USB 棒 + USB Host 改造 | ~¥80 | **很高** | ✓ | ★ | 要在 S3 上移植 RTL-SDR 驱动（批量传输、2.4MSPS）；功耗大、天线大 |
| B4. 外挂主机 | 树莓派 / 旧盒子跑 `dump1090`/`readsb` | ¥200+ | 低-中 | ✓ | ★★★★ | 最稳，但"信号不是掌机收的"，掌机只当显示端 |

**建议顺序：先 A（零硬件、当天可验证 UI）→ 再 B1（真正的"收信号"）。**
两条路共用同一个"目标表 + 雷达 UI"，所以 A 的投入不会浪费。

---

## 2. B1 方案（推荐）· 要加的硬件

| # | 物料 | 关键参数 | 备注 |
|---|---|---|---|
| 1 | **1090MHz 接收模块** | **GNS 5892**（1090ES Mode-S/ADS-B 专用接收+解调，**UART 921600 输出**，3.3V / ~40mA） | 模块已做射频与解调，MCU 只解析串口 → 这是"不用 SDR 也能收"的关键 |
| 2 | **1090MHz 天线** | 1/4 波长 ≈ **6.9 cm**；SMA 小鞭 或 板载 **PCB IFA/F 天线** | 天线位置/高度决定能看多远；室内通常只能收高处或近距离 |
| 3 | 连线 | 短杜邦线（模块到主板），**尽量短**（921600 波特） | 3.3V 供电直接取板载 3V3（SY8088 1A 余量够） |
| 4 | （可选）SMA 转接 + 外壳开孔 | — | 金属外壳会屏蔽，要注意开孔/塑壳 |

**引脚预算**：需要一个**空闲 UART**（TX+RX 两脚，921600 可用），可选一个 EN/RESET 脚。
⚠ 必须先确认当前板子还剩哪些可用 GPIO（GPS 占了 43/44/47、SD、LCD-SPI、按键…）。

**硬约定**：按项目规矩「**按需启停、管家统管**」——这个模块**必须**走 `os_hw_request(OS_HW_xxx)/os_hw_release()`，
用时开、不用关（40mA 不该常开），不要在各页面里自己 enable/disable。

## 3. B1 方案 · 要处理的东西（工作量都在这儿）

| # | 环节 | 要点 | 风险 |
|---|---|---|---|
| 1 | **UART 收数据** | 921600 + DMA/环形缓冲；本项目已有 921600 经验（GPS MAX-M10S） | 解码任务**不能**在 PSRAM 栈上做禁 cache 操作（项目踩过坑） |
| 2 | **协议解析** | 解析 GNS5892 的帧 → DF17/DF18(ADS-B)、DF4/DF20(高度)、DF11(ICAO)；**24 位 CRC + 单/双比特纠错** | 中 |
| 3 | **CPR 位置解码** | 偶/奇帧配对全局解码；**有参考坐标时单帧局部解码**即可 | 中（有成熟算法可照搬） |
| 4 | **参考位置从哪来** | 用你已经接的 **MAX-M10S GPS**（GPIO43/44/47），或 WiFi/手输坐标 | 低 |
| 5 | **目标表** | 最多 32-64 目标：ICAO/呼号/经纬度/高度/地速/航向/最后更新；超时淘汰 | 内存放 **PSRAM**（内部 RAM 要留给 WiFi/BT） |
| 6 | **距离/方位** | Haversine + 大圆方位，整数近似即可 | 低 |
| 7 | **UI（400×300 1bpp）** | 圆形 PPI 雷达：距离环、本机在中心、目标点 + 呼号/高度/距离；可复用 BIOS 模拟器那套混排排版工具（`textsb` 8×16 + `zhsb` 16×16） | 低 |
| 8 | **数据源抽象** | **一个目标表 + 两种数据源**（网络 JSON / 本地 1090MHz）→ 先做 A 后插 B1，UI 不用重写 | — |
| 9 | **合规** | 只收不发没问题；标注"仅供学习/爱好，**不得用于飞行决策**" | — |

**可参考的开源实现**：
- `moshe-braner/dump5892` —— **ESP32 + GNS5892 的完整实现**：CRC 校验、CPR **相对**解码、距离/方位、Gray 高度、
  甚至专门为"MCU 不闲着"做了优化（查表、整数运算、尽早过滤远/高目标）。**这是 B1 最该读的一份。**
- `pantsforbirds/ADSBee`（GPL-3.0）—— 开源硬件，1090 族就是 **RP2040 + ESP32-S3 + CC1312 + 自研 RF 前端**，
  已做板载 1090MHz 解码；可买/可照做，也可以只学它的前端设计。
- `Pilot Kit Box` —— ESP32-P4 + RTL-SDR + **板载 1090MHz IFA 天线**，整机 BOM ≈ ¥336，开源硬件参考。

## 4. A 方案（零硬件，建议先做）

就是那个开源项目的做法，但界面换成 LinTOS 的 400×300 1bpp 雷达：

1. WiFi 联网（现成）→ 拉 `opendata.adsb.fi/api/v3/`（给中心坐标 + 半径）→ 拿到附近飞机 JSON。
2. 解析：呼号、经纬度、高度、地速、航向。
3. 用 GPS 或手输坐标做中心 → 算距离/方位 → 画圆形雷达。
4. 可加：选中某架 → 显示呼号/机型/高度/距离；状态栏显示更新时间与目标数。

**产出形式**：一个 Lua 单文件应用（和 BIOS 模拟器同一条流水线：源码 → 闸门 → LAPP 打包 → 应用商店）。

## 5. 需要你拍板的三件事

1. **走 A 还是 B1？**（还是先 A 后 B1）
2. **B1 的话，GNS5892 模块你去买还是我先做"串口喂假数据"的解码+UI 部分？**
   —— 后者不需要硬件就能把解析/CPR/雷达 UI 全部做完并用模拟器验证，等模块到了直接接上。
3. **天线形式**：外壳内做 PCB 天线（美观、灵敏度一般），还是留 SMA 外接小鞭（灵敏度好、要开孔）？
