# 项目约定 · 详细版（LinTOS 0.6 → 0.8）

> `.workbuddy/memory/MEMORY.md` 是"必记规则"速查；本文件是它的**详细展开**，含踩坑证据与代码坐标。
> 什么时候看哪份：日常照着 MEMORY.md 做；要改某块代码、复现某个坑时翻这里。

---

## 1. 工作规范

- **按需启停、管家统管**：耗资源模块（蓝牙/WiFi/引擎/大缓冲）**用的时候才开，不用就关**，
  开关动作由**资源管家**统一执行（`components/os/kernel/os_housekeeper.c` + `os_hw.c`），
  不要散落在各页面/壁纸模块里各自 enable/disable。现成的引用计数懒加载调度器是
  `os_hw_request()/os_hw_release()`，新代码优先复用它，而不是直接调 `bt_manager_enable/disable`。
  ⛔ **共用入口负责开关的资源（如 `settings_wifi_connect_open()`）调用方不要再自己 request**
  ——会破坏所有权记账，表现为"取消后射频常开"。
- 中文；emoji + ✅/⏳；**结论先行**；长任务用"继续"推进。
- **删除/裁剪类动作先给体积拆解 + 决策表**，等拍板再动手；
- 需求不明要**反问确认**，但不要堆选项（"辣条选项"）；
- **验证优先于猜测**：结论必须有证据（readelf / map / idf.py size / 串口实测），不许凭印象断言。

## 2. 硬性技术约束（踩过的坑）

- **ESP32-S3 的 IRAM 与 DRAM 共享同一块物理 SRAM**：IRAM 常驻代码少 1KB = 内部堆多 1KB。
  评估"省内部 RAM"必须把 IRAM 代码算进去。
- ★★ **内存铁律（2026-10-02 立）**：**内部 RAM 只留给"物理上不能放 PSRAM 的东西"**，其余一律放 8MB PSRAM。
  不能放 PSRAM 的只有 4 类：① 禁 cache 窗口内会碰到的数据与**任务栈**（写 flash/NVS commit、
  `esp_bt_controller_init`、进深睡）② 中断处理与 `IRAM_ATTR` 代码 ③ 要求内部 RAM 的外设 DMA 缓冲
  ④ 启动早期（PSRAM 未初始化）。
  写法：大块静态缓冲 → `EXT_RAM_BSS_ATTR`；大块动态 → `heap_caps_malloc(..., MALLOC_CAP_SPIRAM)`；
  任务栈**默认内部 RAM**。验收：`remcon audit` 看 `internal free/largest`，**largest 不得低于 8KB**。
  完整规范见 `docs/内存使用强制规范.md`。
- **禁 cache 期间禁止 PSRAM 栈**（`esp_bt_controller_init` / `esp_*_sleep_start` / flash 写）→
  必须跑在内部 RAM 栈的任务里（`bt_init` 范式）。
- **IDF 组件普遍只有 init 没有 deinit**：拆栈重建时每层静态守卫变量必须显式复位，否则会滚出
  `E <TAG>: Already initialized`。已知两层：`esp_hidh_init`、`esp_hid_gap_init`。
- **S3 无经典蓝牙（BR/EDR）**，只有 BLE 5.0；`esp_hid_gap.c` 里的 Classic 调用是源码残留。
- **分区表**（单一真相源 = `partitions.csv`）：`nvs`@0x10000 / `phy`@0x50000 /
  **`factory` 5MB@0x60000（=固件烧录地址）** / `appdata`@0x560000 / **`apps`(SPIFFS) 4MB@0xC00000**。
- **深睡唤醒只有 EXT1**（电平触发）。⛔ **GPIO0(BOOT) 不可做唤醒源**（strapping 脚无外部上拉，
  深睡时数字域掉电 → 浮空判低 → 立刻自唤醒）；掩码只用 GPIO1(PWR)+GPIO18(KEY)。
  要 `rtc_gpio_pullup_en()`（**别调 `rtc_gpio_init()`**）+ 显式
  `esp_sleep_pd_config(ESP_PD_DOMAIN_RTC_PERIPH, ESP_PD_OPTION_ON)`。
- ⛔ **改引脚宏前先问"这是哪块板"**：当前板**没有触摸芯片**（报"未检测到"正常）。
- ⛔ "每列累加"的直方图必须 ≥uint16（uint8 回绕 → 瀑布全黑）；频谱仪 aperture 必须 64KB。
- **NULL 必须先判再进 VFS**：`opendir(NULL)/fopen(NULL)` 在 VFS 内部 `strlen` 崩 LoadProhibited。

## 3. 电源 / 关机（全部用官方 deep sleep）

- 唯一入口 `wp_power_off(origin)`（`components/wallpapers/sleep.c`）：
  停射频 → 清屏（polling 同步刷出）→ 按来源设 EXT1 掩码 → `esp_deep_sleep_start()`。
  - `WP_OFF_MANUAL`（长按 PWR 2s → 确认框）：只认 PWR 且须按住 ≥0.5s；开机显示 Logo。
  - `WP_OFF_AUTO`（休眠时间到）：任意键短按即开；开机不显示任何东西。
  掩码不同（`0x2` vs `0x40002`）正是"关机键正常、休眠关机异常"的唯一差别。
- 来源存 `RTC_NOINIT_ATTR`（magic 校验，不写 flash）。
- **不要再引入**：浅睡待机 / `wp_shut` 档位 / 诊断黑匣子（RTC 环形 + NVS diag）。
- **USB 连接中不休眠**：`usb_hid_host_mounted()` 为真时屏保与自动关机都跳过。
- 关机前必须 `wp_screensaver_halt()`，否则深睡禁缓存断言 → 关机变重启。

## 4. 排查纪律

- ⛔ **不要用 bash 的 `grep "a\|b\|c"`**：macOS BSD grep 对 BRE 交替不可靠，**已多次给出假阴性并导致错误结论**
  （误判 `page_keymanager` 未接线、误判 `bt_core.c` 无 `s_conn_dev`、误判 C 页面没有退出确认）。
  **一律用检索工具（Grep 工具 / ripgrep）或直接 Read 源码。**
- **同一文件的多个 Edit 必须串行发**（一条消息一个）；并行发会互相覆盖 → 文件半新半旧。
  多处改动写**带断言的 Python 脚本一次改完**（先全量校验再落盘）；插入式补丁锚点必须整段复制原文。
- **不要采信代码里的历史注释**（常常与实现相反）→ 回 IDF 源码 + `build/LinTOS.map` + 串口实测。
- **内存指标必须在同一外设开关状态下对比**（如蓝牙开/关）。
- **崩溃取证**：`xtensa-esp32s3-elf-addr2line -pfiaC -e build/LinTOS.elf <地址…>`（最内层在最前）
  + `page_lua.c` 的 `lua_probe_stage()`。阶段号：1-2 应用管家拉起、3-4 lua_enter、5-11 load_run、
  12-13 on_enter、14 lua_stop→pane reset。
- **真机抓帧必须连抓两次再下结论**：一次 fbdump 很可能是"渲染画到一半"的帧。
  判据：两次帧缓冲不一致（墨点数差很多）= 抓在了渲染中途，不是 bug。
  （2026-10-03 就因为这个把"QQ堂右栏没画出来"误判了半天，其实是渲染慢 + 抓帧时机。）

## 6. App 架构

- ⛔ 新增应用条目的 `icon_idx` **照抄 0.6 版对应值**（`main_icon_index()` 有 `tbl[32]` 兼容重映射表，
  按数组下标反推会整体错位）。参照 `LinTOS0.6/components/os/kernel/os_pages.c`。
- **内置应用一律 C 版**（`hidden=true` + `cat="程序"/"系统"` → 只进应用管家）；Lua 单文件保留作新应用载体
  （`docs/Lua单文件程序规则.md`，全流程见技能 `lintos-lua-app-pipeline`）。
- **Lua C 桥陷阱**：
  ① `lua_pcall` 要求"**函数在参数下面**"；
  ② UTF-8 逐字绘制**禁止写死 `str += 3`**（用首字节求长度）；
  ③ **动作/颜色常量一律用数值字面量**；
  ④ `LUA_32BITS=1` 必须是 **PUBLIC**（否则 Lua 库 32 位 / 消费方 64 位 → C→Lua 数字全是垃圾）。
- **按键通道（定案）**：**单通道 = `action(a)` 的形参**，应用自己拥有 BACK 语义。
  ⛔ 不要用 `app.key()` 做主通道，更不要双通道 + 时间去重。
- **中文 16px 一律 `app.mix`**（`ui_text16`，与系统 UI 同款）；12px 小标签用 **`app.zhsm`**；
  ⛔ `app.zhbs` 是 24×24 降采样，糊。ASCII 小字用 `app.texts`(8×12) / `app.textsb`(8×16)。
- **弹窗一律走 `os_dialog`**（几何一处来源、严格居屏、toast 0.5s）；Lua 侧 `app.dlg.*`。
- **退出确认（2026-10-03 定案）**：**所有游戏/独立程序按返回键都要弹「退出程序?」。**
  桥层统一入口 `lua_request_exit(ctx)`（`app.exit()` 与"框架 BACK 未消费"都走它）；
  **脚本顶层 BACK 必须 `return false` 或调 `app.exit()`**——`return true` 会把它吞掉，
  这正是"按返回直接退出、没有确认框"的根因。
  ⛔ 弹窗延迟到下一帧 poll 才 push（在被 Lua action 间接调用的路径里 push = 重入）；
  回调里只置标志、不直接 `os_pop`。C 侧已确认的只有模拟器页（`page_engine.c` 的 `eng_exit_confirm`）。
- **`app.img.*`**：`load(path[,opaque]) / blit(id,sx,sy,dx,dy,w,h[,mode]) / size / free / freeall`，
  `mode=1` = "位1画白"（图像素 = 墨；黑底上贴白精灵用它）。
  `IMG_MAX` 现在是 **10**（QQ堂要同时驻留 bg+tile+face+item+wicon+equip 六张，旧的 6 会开始顶槽）。
  ⛔ **绝不要逐行 `fseek` 读文件**（SPIFFS 每次 seek 扫对象索引 → task_wdt）；整文件一次读进 PSRAM 再解包。
- **Lua 作用域坑**：`local` 只对**声明之后**可见。写在表构造里会变全局；
  被**更早定义的函数**引用的局部变量必须提到文件顶部**前置声明**（`local msg`），
  否则那些函数会把名字解析成**全局** → 运行时 nil 调用。
  ⛔ **`local a = 1, b = 2` 是语法错误**（`local a, b = 1, 2` 才对）。

## 7. ★★ 1bpp UI 的性能法则（2026-10-03 真机定量得出，所有 Lua/C 全屏应用通用）

**结论：这块 ST7305 上，帧缓冲在 PSRAM，"画了多少像素"就是帧耗时。**
`st7305_draw_pixel` / `st7305_blit_1bit` 每次落笔都是**随机读改写**：
索引 `((x>>1) * 75 + (y>>2))`，相邻像素跨 75 字节 → **每次都是缓存未命中（≈100 周期）**。

真机实测（QQ堂冒险，400×300 满屏）：
```
整帧 54ms = 绘制 49.6 + flush 4.2
  场地 29ms = 背景满屏贴片 12 + 瓦片 17      ← 静态层, 却每帧重画
  顶部状态条 3ms
```
优化后只剩**换关那一帧**超 50ms，其余帧全部低于 50ms 阈值（原来每帧都在刷屏）。

### 五条铁律

1. **不要在 render 里刷"白底填充"**。`render` 开头一次 `app.clear(WH)`（memset，极快）就够了；
   之后的 `app.fill(..., WH)` 是逐像素随机写 —— 一个 235×239 的白框就是 5.6 万次随机写。
   只有"浮在场景之上的面板"才需要刷白。
2. **静态层 / 动态层分离**。场地 = 背景 + 瓦片 + 地板刻度（几乎不变）→ 只在**换关/砖被炸开**时整屏重建；
   动态层 = 道具/火焰/怪/玩家/泡泡 → 每帧只"**擦掉上一帧占用过的格子**（从背景取 20×20 贴片）+ 重画新的"。
   用 `y*100+x` 把一个格压成一个数记进数组，前后帧换表复用，不建表（省 GC）。
3. **脏标记的正确语义是两道独立的闸门**：
   ```lua
   if not GAME.dirty then return end                       -- 不脏就跳过
   if (now - GAME.last_draw) < GAP then return end         -- 脏但太近也跳过
   ```
   ⛔ 写成 `if not dirty and (now - last) < GAP then return end`（**旧版的写法**）等于
   "只要过了 GAP 就无条件重绘" —— 桥层每帧都会 `needs_redraw`，于是 render 每帧全量重画。
4. **静态页不要周期置 dirty**。大厅/选关/背包/锻造只在按键时变化（`action` 里置 dirty 即可）；
   在 `poll()` 里"每 16 帧置 dirty"会让静态页也满速重画。
5. **可缓存的小件就缓存**。顶部状态条只在数值变化时重画（算一个 key 字符串比较）。

### 抓帧验证的判据
改完性能后**连抓两次 fbdump**：两次墨点数差很多 ⇒ 抓在了渲染中途，说明还是慢；
两次几乎一致 ⇒ 该状态已经"静止"（静态页本来就该静止）。

## 8. ★★ 彩色原图 → 1bpp 的高质量转换（`tools/qqt_bw.py`）

**⛔ 不要再退回"全局分位数硬阈值 + 最近邻缩放"**——那正是被判定"太粗糙"的写法：
硬阈值把中间调压成纯黑/纯白（画面糊成黑疙瘩）；最近邻**缩小时**丢线并产生锯齿噪点。

正确流程（三步）：
1. **重采样**：放大缩小都用 **PIL LANCZOS**；等比铺满再居中裁切（不要拉伸，会把圆的压扁）。
2. **色调拉伸**：把 `[5%, 95%]` 分位拉到满量程，再按需要加 γ。**对比度交给这一步**。
3. **二值化**——按素材类型二选一：
   - **照片/背景** → **8×8 有序抖动（Bayer）**：灰阶表达成规则网点。用一个增益系数把**平均墨量**
     压到目标值（`k = target / mean`），保留相对层次。背景 ink 取 **0.10~0.15**（高了地板变麻点）。
   - **图标/表情（≤48px）** → **硬阈值**：小图上抖动只剩噪声。取"最暗的 ink 比例"当阈值。
     图标 ink **0.20~0.28**。
4. **可选描边 `outline=1`**：给墨团外圈补 1px 墨线，缩小后边缘发虚时能把形状"框住"——比单纯提高 ink 有效得多。

**黑底亮主体的图标**（QQ堂的 icon/faces/bigIcon 都是）必须 `invert=True`：先把灰度反相，
让主体变成"暗"的再当墨处理；**不做反相会整张变黑块**。

`qqt_pack.py` 里的参数是可调旋钮：`ink`（墨量）、`gamma`（明暗）、`use_dither`（抖动 or 硬阈值）、
`outline`（描边）。改完先看 `/tmp/qqt_pack_preview.png` 再上机。
