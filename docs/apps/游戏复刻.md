##### 0.0 v4（2026-10-03 第二轮）—— 地形 / 重影 / 提亮

| 问题 | 根因 | 处理 |
|---|---|---|
| **移动满屏重影** | 两个 bug 叠加：① `draw_field(P.x+P.mx, …)` 传到里面又 `* TILE`，等于把格内偏移乘了 20 倍（精灵瞬移最多 320px）；② `dcell()` 收的是**像素坐标**，`restore_cell` 越界直接 return，旧格从没擦过 | 参数改成 `(格坐标, 格内像素偏移)` 分开传；`dcell` 用格坐标，并把**移动中精灵会跨越的相邻格**也标记 |
| **忽然探险失败** | 怪物贴着出生点刷（只判 `距(1,1) > 4`），且一路追击 | 改成"距**真实出生点**曼哈顿 ≥7"；速度 900→1700ms、攻击间隔 2600→4200ms；受击无敌 1200→1600ms |
| **不像探险地图** | 旧版是炸弹人均匀方格阵 | 见 §0.6 凿巷式洞穴地形 |
| **太黑 / 太糊** | 硬墙是实心深块；底图墨量 0.13；图标走硬阈值成黑疙瘩 | 硬墙改"浅底 + 2px 粗框 + 中心十字"（~43% 墨）；底图 0.13→**0.07**；图标 0.42→0.36 |
| **左侧世界图标特别黑** | 原版 `map/bigIcon` 是 3D 渲染图，缩到 40×36 二值化必然是一坨黑 | 改成**程序化线描符号**（齿轮/皇冠/树/雪花…），墨量 ~15% |
| **右侧小地图糊** | 直接贴了一张背景图的窗口（抖动网点，根本不是地图） | 改成**真正的地形缩略图**：`LEVEL.build` 生成到临时表，黑=岩体、白=可走、方框=出口 |

##### 0.6 地形生成（`LEVEL.build`）：凿巷式，不是元胞自动机

试过元胞自动机 —— 在 20×15 这种小网格上只会出"一大坨岩"或"一大片空"（实测 4 轮后岩体 13%~83% 剧烈跳变），
既没有通道感也没有路线感。最终方案：

```
① 整张图先全是岩体
② 凿主通道 + 若干分叉（每条分叉都从**已有通道格**出发 → 全图天然连通）
   ⛔ 只有随机游走会把通道挤在一角 → 再加 3 条"偏置游走"的贯穿通道横穿地图
③ 在通道上掏洞厅（3~5 × 2~3）→ 有开阔区也有窄道
④ 空腔占比不足 58% 就继续补凿 → 每关都保证有得走，又不会是一片白纸
⑤ 岩体边缘风化 → 可炸碎石（沿路走 / 炸开捷径找宝，这就是探险手感）
⑥ 灌木（可炸，轻）+ 水塘（不可通行，放完验连通，断了就撤回）
⑦ **出生点 / 出口 = 空腔的"直径两端"**（两次 BFS 取对径点）→ 自然形成一条要走的路线
⑧ 通关条件改成 **走到出口**（不是"清光怪"）；HUD 常驻"出口 N 步"
```

栅格索引（= `tile.bmp` 的格子号）：
`0 地板 · 1 碎石(可炸) · 2 岩壁(不可) · 3 宝箱碎石 · 4 灌木(可炸) · 5 深坑(不可通行) · 6 出口`

##### 0.2 版面：为什么是 20px 格

`400/20 = 20`、`300/20 = 15` → **20px 是 400 与 300 的公约数，20×15 格正好铺满整屏**，
比原来的 16px 大一档（砖缝能画两层错缝），也不用再把场地缩成 240×208 的小框。

##### 0.3 素材打包 v3（`tools/qqt_pack.py` + `tools/qqt_bw.py`）

| 文件 | 内容 | 尺寸 |
|---|---|---|
| `bg1..12.bmp` | 原版 `map/pveN.img` 等比放大铺满 + 8×8 有序抖动（**墨量 0.07，很淡**） | **400×300** |
| `tile.bmp` | 7 格：地板/碎石/岩壁/宝箱碎石/灌木/深坑/出口（**程序化重绘**） | 7 格 @**20px** |
| `face.bmp` | 吉祥物表情（`res/uiRes/face/faces/*.img`）→ 人物展示 | 16 个 @48px |
| `item.bmp` | 道具图标（`res/uiRes/icon/item/*.img`）→ 背包 | 16 个 @24px |
| `wicon.bmp` | 世界图标 = **程序化线描符号**（不用原版 3D bigIcon） | 12 个 @40×36 |
| `equip.bmp` | 装备四槽图标（头/身/翅膀/泡泡，取自 item 图标） | 4 个 @32px |

**转换算法（`tools/qqt_bw.py`，⛔ 不要再退回旧写法）**：
`LANCZOS 重采样（等比铺满+居中裁）→ 色调拉伸 → 二值化`
—— 照片/背景走 **8×8 有序抖动**（墨量 0.07~0.12），图标走 **硬阈值**（墨量 0.36 左右），
黑底亮主体的图标必须 **`invert=True`**，再加 `outline=1` 描边。
旧写法"全局分位数硬阈值 + 最近邻缩放"正是被判定"太粗糙"的原因。

##### 0.4 性能（真机定量，见 MEMORY.md §7 与技能 `lintos-1bpp-ui-perf`）

一帧 54ms = 绘制 49.6 + flush 4.2，其中**场地 29ms（背景 12 + 瓦片 17）**。
帧缓冲在 PSRAM，每次落笔都是随机读改写 → **只能靠"少画"**：
静态层（背景+瓦片）只在换关/开砖时重建（**并带"地形变了 → play_full 重建"的开关**），
动态层每帧只"擦旧格 + 画新格"；并修掉"脏标记两道闸门写反"。
优化后只剩换关那一帧超过 50ms 阈值。

#### 1. 原版"探险模式"到底是什么（查证结果）

来源：百度百科 / 中文百科（QQ堂探险）、9game / 91单机 的关卡介绍。

| 项 | 事实 |
|---|---|
| 性质 | **PVE 闯关**（不是横版动作、**不是地牢 Roguelike**）。玩家数 2–4 人，也可单人（单人或卡） |
| 战斗方式 | **仍然是泡泡炸** —— 但对手是 **NPC 怪物**；怪物**不用普通糖泡**，各有**特殊技能**（魔法系 / 元素傀儡 / 范围毒雾与火焰 / 引爆糖泡） |
| 关卡 | 10 个世界：魔法王国 / 机械世界 / 黑龙王国 / 迷之森林 / 迷之沙漠 / 风暴海湾 / 极昼平原 / 怒风峡谷 / 守望山麓 / 永冬之巅（另有"迷之底"，需道具） |
| 失败/胜利 | 打完关卡内的怪（含 **BOSS**）→ 通关；通关给 **道具/材料/经验** |
| 成长 | **等级系统**：升级 → **加血量、提高泡泡威力**；另有 **勇气值**，可在商城换道具 |

| 掉落 | 打怪与炸砖掉**合成材料**；**血瓶**等补给 |
| 关卡示例 | 起程（旧 BOSS 当教练教操作）→ 野外 → 魔影若现 → 荆棘路 → 护城河 → 城区（魔法王国 6 关，怪越来越硬） |

**一句话**：`泡泡炸砖的地图 + 会放技能的怪 + 关卡制 + 等级/装备/锻造`。

#### 3. `.map` 布局格式：没破，但有办法绕过

- 文件 = 一堆 little-endian int32，含**负数**（如 `pve1` 里 `-17066`）与 5 位数（`17074`/`17103`），
  疑为"带引用/增删语义"的自定义序列化。**不是简单瓦片数组**，继续啃性价比低。
- **绕法（本次采用）**：关卡布局**程序生成**成经典炸弹人阵型
  （外圈硬墙 + 偶数坐标硬块 + 其余软砖），这是泡泡堂系地图的通用形态，观感与原版一致；
  **背景用原版 `pveN.img`**，所以每一关的"味道"仍是原版的。

##### 4.6 界面（沿用英雄坛说那套已验收版式）

#### 2. `.img`（`DIMG`）格式 —— ✅ **已完全破解，全量导出**

magic = `QQF\x1aDIMG`，随后 **15 个 little-endian uint32**，再是像素数据。

##### 定案口径

```
每帧 = [dw × dh 个 RGB565 小端]  ++  [dw × dh 个附加字节]   ← 两块**分开存**
dw, dh = f[12], f[13]          ← ★ 帧尺寸（不是 f[6]/f[7] 的画布尺寸！）
帧数    = f[2]
之后可有一小段尾部 (实测 28/56/112/140 B)，跳过即可
```

| 下标 | 含义 |
|---|---|
| f[0] | 65536 (0x00010000) 版本标记 |
| f[1] | 位深（24 = 16 位色 + 8 位附加） |
| f[2] | 帧数 |
| f[6] / f[7] | **画布**宽 / 高（常带留白） |
| f[11] | 帧数（重复） |
| f[12] / f[13] | **帧**宽 / 帧高 ← 数据按这个切 |
| f[14] | 彩色部分行字节数 = 帧宽 × 2 |

每像素字节数：实测 **875 个 3B/px**、24 个 4B/px（BGRA8888）、7 个 2B/px（纯 RGB565，无附加字节）。

##### 破它的判据链（三次踩坑，每次都留了证据）

| # | 错误假设 | 症状 | 推翻它的证据 |
|---|---|---|---|
| ① | RGB888 逐行 | 雪花噪声 | 平坦色块是 `84 00 84 00…` = **RGB565 常量 0x0084**，不是乱码 |
| ② | 3 字节交错 | **严格 1 像素棋盘** | 那是"2 字节像素被跨 3 字节读"的干涉纹；且 f[14] = 帧宽×**2** |
| ③ | 用画布尺寸 f[6]/f[7] | 470 个文件"长度对不上" | 改用**帧尺寸 f[12]/f[13]** 后，`payload = 帧数 × dw × dh × 3` 严丝合缝 |

外加一个只有肉眼能发现的坑：**第 3 个字节不是显示 alpha** —— 拿它合成到白底会把整图洗成
"水印级"浅灰（形状都在、看不清）。只在拼总览图时才会暴露；长度/CRC 自洽完全查不出来。

#### 2. 现在"丑"的三个具体原因（对照参考）

| 现状 | 参考里怎么做的 | 怎么改 |
|---|---|---|
| **地面是一整片完全相同的点阵**（72×54 格全一样） | Bombman / BnB 都给**同一格 3~6 个变体**（草、碎石、裂纹交替），靠变体打破重复感 | tile.bmp 加 **floor 变体 ×4 / rock 变体 ×2**，Lua 用 `(x*7+y*13) % 4` 选变体 → 同一区域立刻有质感 |
| **地形种类太少**（只有地板/碎石/岩/灌木/水） | SugarBubble 探险模式有 **糖果箱、硬糖箱（炸两次）、传送带、传送门、减速泥地** | 加 3 种：**硬糖箱**（要炸 2 次）、**传送带**（踩上去自动滑一格）、**减速泥地**（移动 sms×2） |
| **角色/怪只有 2 帧、太小** | BnB 是 **4 向 × 多帧行走图集**；Bevy Bomber 有 front/back/side 三视图 | 人物扩到 **4 向 × 4 帧**（+受击/胜利表情）；怪物每个 **2 帧**（呼吸/移动） |

#### 3. 玩法对齐（SugarBubble 的探险模式最接近 linit 想要的）

原版 / 糖泡堂的探险模式要点，掌机版应补：
1. **一波波来**：每关分 2~3 波怪，清完一波再刷下一波（而不是一次全刷）。
2. **3 条命**（现在的 3 血即是），**越往后 AI 越凶**（追击概率/速度随世界提升）。
3. **被困机制**：被炸中不是直接掉血，而是**被困糖泡里**，几秒内自救或被队友/敌人碰到 —— 这是 QQ堂最上瘾的几秒。掌机单机版可做成"被困 3 秒内连按确认键自救，否则掉血"。
4. **地形互动**：传送带 / 传送门 / 泥地，让"走位"有内容。
5. **小地图常驻**（Bevy Bomber 的做法）：把选关页的缩略图缩到 60×45 常驻左上角，比"出口 N 步"直观得多。

#### 4. 建议的落地顺序（按"性价比"排）

1. **瓦片变体 + 地形 3 种**（半天）—— 直接治"丑"，且不动架构。
2. **人物 4 向 × 4 帧 + 怪物 2 帧**（半天）—— `qqt_spr.py` 已经是 4 倍超采样绘制，加帧只是多几组参数。
3. **小地图常驻**（1 小时）—— 复用现有 `draw_minimap`，改成画在屏幕右上角的小尺寸版 + 只画"已探索区域"。
4. **解 `pveNN_8.map`**（1~2 天）—— 拿 qqt_map_editor_fin 的 `main.cpp` 对照，解开后**直接用原版 50 关布局**，地图就"原汁原味"了。
5. **探险模式玩法**（1 天）—— 分波刷怪 + 被困自救。

#### 5. 注意

- ②③⑤ 里的**美术素材版权属腾讯/盛大**，自用研究可以，**分发固件/应用不行**（`docs/QQ堂UI素材-来源与解析.md` §3 已记）。
- ⑥ Bombman 是 **CC0**，唯一可安全分发的素材来源；真要发布就用它。
- ① 的地图**数据**（`.map` 里的瓦片编号/坐标）是"事实数据"，通常不受著作权保护，可用；但**贴图**仍属腾讯。

```
CFG  RNG  TILE            底层 (不依赖任何模块)
MAP  ENT  BATTLE  ITEM    中层 (地图/实体/回合战斗/数据表)
INV  SKILL  NPC/DLG  UI   上层
SAVE  NET                 存档 / 网络门面
GAME                      总装 (状态机: TITLE/MAP/TALK/BATTLE/BAG/MENU)
```
- **`BATTLE` 是本作新增的核心模块**（qqtang 是实时泡泡，这里是回合制）
- 其余模块**照搬 qqtang 的写法**（脏标记节流、固定 tick + 追帧护栏、内存上限、确定性 RNG）
- 屏幕/文字：160×80 逻辑画布 → 2 倍缩放绘制（一个 `put(x,y)` 辅助函数统一换算）

### v2 修正（v1 漏掉的 6 个关键设计 —— 每一个漏了都会返工）

#### 2.6 ★ 160×80 画布的实际映射与相机（v1 只说"2 倍放大"）
- **逻辑单位 = 原版像素**。绘制辅助：`P.put(x, y, c)` → 实际写屏 `app.px(OX + x*2, OY + y*2, c)`（2×2 块），
  `P.rect/fill/text` 同理。汉字 8×12 逻辑 → 实屏 16×24，**一屏约 40 逻辑列 × 6.6 行**。
- 画布区 320×160（=160×80 逻辑×2），原点 `(OX,OY) = (40, 24)`（左右各留 40px 给指令条）。
- **地图比一屏大 → 必须相机**：地图 = 场景瓦片表（每瓦片 8×8 逻辑），视口 20×10 逻辑瓦片，
  相机跟随主角格子；绘制只跑可见瓦片（与 qqtang 的视野循环同构）。

#### 2.7 ★ 回合制时序（v1 说"回合制"但没说怎么驱动、会不会卡 UI）
- **事件驱动，不用 tick 累积**：按确认 → 进"结算窗口"，用 `T`（毫秒计时）推进：
  `选出指令 → 300ms 播招式文字 → 结算伤害 → 敌人行动(如有先手权则战前) → 300ms 显示结果 → 回输入`。
- **先手权**：`先手 = 身法 + 随机(0..悟性/4)`；谁高谁先。两边都算完才算一回合。
- **绝不阻塞**：结算窗口期间 `poll()` 仍每帧跑，只是**不接受输入**（`BATTLE.lock`），
  这样按键不丢、UI 还能画数字飘字。回合数/连击用 `BATTLE.round` 记，便于以后联机校验。

#### 2.8 ★ 滚动日志（MUD 的灵魂，v1 完全没写）
- 环形缓冲 `LOG.buf[6]`（6 行）+ `LOG.push(s)`；新行进顶部、旧行下移（或底部追加，二选一：
  **定"新行在底部"**，像聊天窗）。
- 行宽上限 `40 逻辑列`（≈320 实屏像素）：超长按 **UTF-8 安全**截断（`--` 补"…"不能用，用 ASCII "..")。
- 战斗/对话/拾取/系统提示**全部只通过 `LOG.push`**（不要各处直接画字），这样联机时能把服务器消息原样塞进同一管道。

#### 2.9 ★ 战斗公式（不定死就没法调平衡）
```
命中   = 0.75 + (攻方身法 - 守方身法) * 0.02      钳制 [0.25, 0.97]
伤害   = max(1, 招式基础 + 臂力/3 - 守方防御/2)   × (1 + 内力加成)
内力   = 用招式扣 招式消耗；不足则只能"普通攻击"(伤害 ×0.6, 不耗内力)
升级   = 每级 +1 属性点、+体力上限；打坐回内力(按时间)、睡觉回体力(城镇)
```

#### 2.10 ★ 对话/NPC 数据格式（MUD 的内容全在这里）
```lua
NPC.def[id] = { name=, tile=, x=, y=, scene=,
  talk = { { text="少侠何来?", opts={ { "拜师", goto="join" }, { "打听", goto="info" }, { "告辞" } } } },
           join = { text="...", require={ level=3 }, act="join_sect:shaolin" , opts={ {"多谢"} } },
           info = { text="...", opts={ {"知道了"} } } } }
```
→ 加一个 NPC = 加一条数据；**分支用 `goto` 指向同一张表里的 key**（不用写代码）。

#### 2.11 ★ 联机权威规则（不先定，以后会把存档写坏）
- **服务器权威**：角色属性/背包/银子/位置**只有服务器能改**。客户端 `NET.emit` 只发**意图**
  （`move/talk/attack/buy/use`），收到 `NET.on` 的**事件**才改本地显示。
- **单机模式**：`NET` 直通 + `SAVE` 落 NVS；**联机模式**：`SAVE` 只做**离线缓存**，
  且**禁止本地写关键数值**（只在"未连接"时允许），避免"本地改档覆盖服务器"。
- 判定方式：`NET.mode = "local" | "online"`，所有写操作前先问它（一处判断，不散落）。
