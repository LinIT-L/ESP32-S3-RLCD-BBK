# 板型自适应方案（小智模块版 ⇄ 微雪原版）

> 2026-10-16 · 起因：微雪板 GPIO5（LCD RS）"设置不刷新 / 一直 3.3V"。
> 根因不是一根脚，而是**引脚没有一个可切换的归属**：驱动里散着硬编码值、
> `user_config.h` 的 `RLCD_*` 还是死宏，而触摸 I2C 又**无条件**去配 GPIO5。

## 1 两版到底差在哪（决定"自适应"能做多大）

| 功能 | 小智模块 + 新载板（当前实物） | 微雪原板（官方定义表） |
|---|---|---|
| LCD RS/DC | IO7 | **IO5** |
| LCD CS | IO11 | **IO40** |
| LCD SCL(K)/SDA(MOSI) | IO9 / IO10 | **IO11 / IO12** |
| LCD RESET | 无（仅上拉） | **IO41** |
| 触摸 | SDA5 / SCL13 / INT12 / RST6 | **无触摸** |
| 按键 | PWR1 / RIGHT0 / LEFT4 | **KEY=IO18** |
| 电池 ADC | GPIO3（ADC1_CH2） | **GPIO4（ADC1_CH3）** |
| 音频 I2S | MCLK40 / BCLK39 / WS45 / DOUT48 / DIN21 | **MCLK16 / SCLK9 / WS45 / DSDIN8 / ASDOUT10** |
| 音频 I2C | SDA38 / SCL47（ES8311 + ES7210） | **SDA13 / SCL14**（ES8311 + QMI8658C + RTC） |
| SD | SDMMC 1-bit（CLK16/CMD15/D0 17） | **SPI**：MOSI21 / SCK38 / MISO39 |
| 功放使能 | GPIO46 | GPIO46（巧合同脚） |

**结论**：差异是"整张表"级别的（约 20 根脚 + 有/无器件），**不可能逐脚自动猜**，
只能是 **①一张板型表 + ②开机识别一次 + ③全局按表下发**。

## 2 识别：靠 I2C 上的"器件指纹"（不用动硬件）

两版的 I2C **器件组合是互补的**，这就是最可靠的天然指纹：

| 板型 | 在**小智**总线（38/47）上 | 在**微雪**总线（13/14）上 |
|---|---|---|
| 小智模块版 | ES8311(0x18) **+ ES7210** | —（无应答） |
| 微雪原板 | —（无应答） | ES8311(0x18) **+ QMI8658C(0x6A/0x6B) + RTC** |

判定规则：**哪条总线上探到"自家器件组合"就判为那块板**；
只有 ES8311 单独应答（少见）时，再看有没有 QMI8658C / ES7210 做二次判定。

> 探测失败就退回 **NVS 里上次的板型**，再不行默认小智。**不做"设置页手动指定"**（linit 2026-10-16）。
> 探测只用 I2C 开漏、且早于一切外设初始化、探完立刻释放 —— 不主动输出高电平、不碰电源/功放/strap 脚。


## 3 落地结构（三步）

```
① 引脚集中           components/system/board_pins/
   board_pins.h      板型开关 BOARD_XIAOZHI_S3（保留）+ 两张表（LCD/触摸已做，
                     待补：按键/电池/音频/SD）
   运行时取表         const board_pins_t *bp = board_pins_get();   ← 取代所有 #if
② 开机识别一次       app_board_init() **最前面**（任何外设初始化之前）：
                     读 NVS("board_id") → 没有就 board_identify() 探测 → 写回 NVS
③ 全局按表下发       每个驱动都不写死引脚，由上层把表里的值传进去
                     （st7305 已做 · touch 已做；待做：audio / battery / sd / 按键）
```

### 关键约束（踩过才写的）
1. ⛔ **识别必须早于一切外设初始化** —— 触摸 I2C 无条件配 GPIO5 就是这次事故的直接原因。
2. ⛔ **探测用的 I2C 探完立刻卸掉**（`i2c_driver_delete`），否则引脚又被占住。
3. ⚠ 探测会在"错的那组脚"上短暂驱动 I2C：微雪的 38/39 是 SD 的 SCK/MISO
   ⇒ 探测必须放在 **SD 初始化之前**（此时卡没被挂载，不会写坏数据）。
4. ⚠ 器件地址可能撞车 ⇒ 一律用"器件组合"判定，不用单器件。
5. ✅ 没插电池 / 没接喇叭 不影响识别（只看 I2C 器件存在性）。
6. ✅ 识别结果**写 NVS 缓存**：之后每次开机直接读，不再探测（零副作用、启动更快）。

## 4 建议的推进顺序

| 阶段 | 内容 | 价值 |
|---|---|---|
| **P0（今天）** | 板型表补齐（按键/电池/音频/SD 收进 board_pins）+ 运行时 `board_pins_get()` | 换板从"改 4 处"变成"改 1 处"，编译期防撞脚 |
| **P1** | NVS 板型缓存（识别结果落盘，之后开机直接读，不再探测） | 纯软件零风险 |
| **P2** | I2C 器件指纹自动识别（探到哪块算哪块，失败回退默认） | 探测逻辑独立成 `board_identify()`，失败必回退，不会卡机也不会烧板（见 §2.1） |

> ⛔ **不做设置页手动指定**（linit 2026-10-16 定）。
> P0 是前提；P1/P2 一起做完即"插上哪块板都对"。
