# LinTOS App 制作规则

> 面向"给 LinTOS 新增一个 App"的完整规范：需要提供哪些信息、图标/命名/介绍/权限/UI 怎么做、如何注册发布。
> 本文件由 **docs/开发指南.md** 的「应用发布规则」+ `os_app_t` 注册结构 + UI/图标约定 提炼独立出来，作为 App 的唯一标准。
> **单文件 Lua 程序**（放 TF 卡免重编固件运行）走另一套植入规则，见 [docs/Lua单文件程序规则.md](Lua单文件程序规则.md)。

## 1. 一个 App 需要提供哪些信息

| 字段 | 必填 | 说明 |
|---|---|---|
| **id** | 必填 | 全局唯一标识。编译期应用用英文短名（如 `settings`）；商店下载的应用前缀 `wasm:`（如 `wasm:snake`）。 |
| **名称 label** | 必填 | 显示名，UTF-8。主菜单/应用管家/商店显示。建议 ≤ 8 个汉字（图标下放得下）。 |
| **图标 icon** | 必填 | 见第 2 节。进入 `icon_idx` 图标库索引。 |
| **应用介绍 desc** | 建议 | 商店列表里"中文名下方"的一行简介。 |
| **归属分类 cat** | 必填 | 商店/应用管家子分类：`游戏 / 程序 / 软件 / 系统 / 运维 / 学习 / 网络 / 手册`。NULL=不归类（隐藏工具类）。 |
| **入口页 page** | 必填 | 启动后进入的 `os_page_t` 页面，由 `os_module_t` 提供 render/action/touch。 |
| **体积 size** | 可选 | 商店展示的包体大小。 |
| **权限/系统能力** | 按需 | 见第 3 节，用到哪个加哪个。 |

## 2. 图标

### 2.1 规范

- **尺寸：64 × 64 px，1bpp 黑白**（单色点阵，**MSB 在左**）。  
- 主菜单图标默认 **64×64**；被选中（居中）临时放大到 **100×100**（内部三线性插值，不依赖图像源）。  
- 黑白屏反色由 `inverted` 参数控制，不另存反色图。  
- 绘制统一走 `draw_main_icon_stretched()` / `ui_main_icon_bitmap()` —— **不允许在 page 里直接 `st7305_blit_1bit` 一个图标数组**，入口必须经过 `ui_common`。

|---|---|---|---|---|

| 应用管家侧栏 4 个分类图标 | `/Users/linit/Desktop/完美图标/应用管理/` | `tools/image_convert/gen_cat_icons_64.py` | `components/ui/ui_common/cat_icons.inc` | `cat_icons[cat_id_t]` |

| 诊断/工具类零碎图标 | `/Users/linit/Desktop/完美图标/` 散落 | `tools/image_convert/gen_diag_icons.py` 等 | 各自 page 内部 `.h` | 各自 page 局部 |

### 2.3 制作流程（新增 / 修改一个图标）

1. **准备 PNG**：64×64（或更高自由比例），灰度或彩色均可；脚本会灰度化 + 阈值化（`<128` 视为黑像素 = bit=1）。  
   - 建议**纯黑底白线/白字**（黑底图），这样 1bpp 反相后是白底黑字，符合 1bpp 屏阅读习惯。  
   - 透明背景：脚本不处理透明，存盘前**填充白色背景**再交给脚本，否则会被 PIL 当白色、整张图标变全黑/全白。  
2. **放入桌面文件夹**：按用途放到 2.2 表格里对应的目录（如新主菜单图标 → `完美图标/应用管家/应用/XXX.png`）。  
3. **改 MAP**：打开 `tools/image_convert/gen_main_icons_64.py`，在 `MAP` 列表**追加**一行：  
   ```python
   ("ICON_NEWAPP",  "完美图标/应用管家/应用/XXX.png"),   # N 注释名
   ```  
   **顺序即下标**（也即 `ICON_*` 枚举值）；**新图标永远追加在末尾**，不要插队改已有值 —— 已注册的应用 `.icon_idx = ICON_OLD` 是数字硬绑的，插队会让全部已注册图标错位。  
4. **跑脚本**：  
   ```bash
   python3 tools/image_convert/gen_main_icons_64.py
   ```  
   自动重写 `components/ui/ui_common/icons_main.inc` + `icons_main_enum.h`。  
5. **注册到应用表**：`components/apps/apps_registry.c` 的 `s_builtin_apps[]` 写 `.icon_idx = ICON_NEWAPP`（**用枚举名**，不要再写魔法数字）。  
6. **编译**：脚本只动两个文件，下一次 `idf.py build` 自动重编 `icons_main.inc` 所在组件，无需 `fullclean`。  
7. **预览**：`tools/icons_preview_v2.png`（脚本生成的缩略图组）能离线对比当前 33 个图标的视觉效果 —— 调色/线条粗细先在 PNG 阶段反复改，预览满意再烧固件。

### 2.4 删除一个图标（节省 IRAM/Flash）

1. **查引用**：`grep -rn "ICON_XXX" components/` 看哪些页面在用。  
2. **改应用表**：被引用的页面改成别的图标（或新图标），没引用的直接置 `.icon_idx = -1`。  
3. **删 MAP 行** + **删 `components/apps/pages/` 里仅此图标用的辅助头**（如 `mp3_icons_auto.h`）。  
4. **跑脚本 + 编译**：`icons_main.inc` 自动瘦身。  
5. **基准**：每减一个图标省 **64×64/8 = 512 字节** Flash（1bpp 位图）。33→27 减 6×512 = **3KB Flash**；同时省 IRAM 里的 `main_icons[]` 指针表 6×4 = **24 字节**。

### 2.6 常见坑

- **PNG 路径含中文**：`SRC = /Users/linit/Desktop` 在 macOS 上没问题；脚本本身按 UTF-8 解析路径。**不要把 PNG 复制到含空格/特殊符号的目录**（如 `~/Library/Mobile Documents/`），PIL 偶发 read 失败。  
- **PNG 尺寸非 64×64**：脚本自动 `resize(64,64, LANCZOS)`，但建议源图就用 64×64，免缩放糊。  
- **透明 PNG**：脚本不处理 alpha，全透明会被 PIL `convert("L")` 当黑（`getpixel` 返 0），结果图变全黑 —— **务必 PNG 落盘前合成白底**。  
- **改图标后忘记跑脚本**：直接在 C 里改 `.icon_idx` 没用，新图标必须重新生成 `icons_main.inc`。  
- **插队改 MAP**：见 2.3 步 3 的红字警告 —— 已注册应用用枚举名也没用，编译器把枚举当 int 处理，运行时拿 `main_icons[idx]` 的是数字下标。**任何对 MAP 已有行的删/改/插都等于改 ABI**，必须全量改 `s_builtin_apps[]` 的 `.icon_idx` 字段。  
- **"完美图标" 被移走/重命名**：脚本找不到 PNG 会 `FileNotFoundError` 直接挂掉 —— 报错信息直白，按路径恢复即可。

## 3. 权限 / 系统能力（需要哪个就声明哪个）

| 能力 | 使用方式 | 说明 |
|---|---|---|
| 安全凭据 | `components/keyvault`（NVS ns=`ln`） | 密码/密钥/WiFi 口令，统一走 keyvault 接口，不自己明文存。 |

## 4. UI 规范

- **屏**：ST7305，400×300，**1bpp 白底黑字**。
- **字体**：中文统一 `font_zh16`(16×16)；英文 `8×16`；小字用 `am_draw_small` 等。
- **顶部状态栏**：高 24px（y=0..23），内容从 y=24 起。
- **弹窗**：统一 `os_dialog_confirm_ex(ctx,msg,timeout,flags,cb,ud)`；回调 `cb(ctx,result,ud)`，`result=-1`=BACK 取消。弹窗打开时底层不退出，关闭后自动恢复。
- **布局**：左右至少留 4px；行距紧凑、竖排对齐。
- **反色/高亮**：黑白屏用 `inverted=true` 反相实现。
- 一律走 `ui_common` 的统一字体/绘制工具，不自行造字体。

## 4.1 滚动列表渲染规范（离屏预渲染整列 + 滚动只抄可视窗 + 硬裁剪出框）

> **长列表/网格滚动（应用管家、商店、任何可拖动列表）一律用本方案**，不要在逐帧渲染里重画整页。
> 参考实现：`components/apps/pages/page_app_manager.c` 的 `am_col_*` 函数组。

**核心原语**：`st7305_blit_1bit(lcd, x0, y0, w, h, bitmap)` —— 标准 1bpp 位图直抄（每行 `bpr=(w+7)/8`，MSB 在左，1=黑，0=白跳过），**自带屏幕边界硬裁剪、只画黑像素**，是"滚动只抄可视窗"的地基。

**三步走：**

1. **离屏预渲染整列**
   - 内容区整列（宽 `W`、高 `H`，含所有行）一次性预渲染成 PSRAM 里的标准 1bpp 位图：
     `bpr = (W+7)/8`，行号 `y` 对应偏移 `y*bpr`。
   - 渲染函数全部**只写列缓冲**（`am_col_hline/vline/rect_outline/label/text_l/icon/...`），不碰屏幕。
   - 只在此列**内容/焦点/安装状态变化时**才重渲染整列（`dirty` 标记），拖动过程零重渲染。

2. **滚动只抄可视窗**
   - 相机 `cam` 以"行"为单位、可小数（拖动跟手，松手平滑吸附焦点行）。
   - 每帧只算可视窗起点：`src_y = round(cam * row_h)`（**像素级偏移**）。
   - 只把可视窗 `[src_y, src_y+win_h)` 抄到屏幕：
     ```c
     st7305_blit_1bit(lcd, grid_x0, content_top, W, win_h, s_col + src_y * bpr);
     ```
   - `win_h` 按屏高裁剪（超出列底就截断），顶从 `content_top` 起，永不穿透顶部子分类条/状态栏。

3. **硬裁剪出框**
   - 出框内容交给 `st7305_blit_1bit` 的屏幕边界裁剪，代码**不做逐像素判断**。

**效果**：拖动时**半行/半字/半按钮自然可见**（像素偏移，绝不等待"完整行"）；滚动流畅（每帧只抄 ≤400×300/8 的字节）。

**性能要点**：
- 列缓冲放 PSRAM（`EXT_RAM_BSS_ATTR` / `heap_caps_malloc(MALLOC_CAP_SPIRAM)`），不够再退回内部 RAM。
- 不要在 `render` 里做文件 I/O / NVS 读 / 扫描——慢操作一律后台任务 + `dirty` 标记 + 完成后取货重建。
- 图标/位图嵌入用 `ui_main_icon_bitmap(idx,&w,&h)` 取原始 1bpp 数据直写列缓冲，不做逐点缩放。

## 5. 注册与发布

### 5.0 ⚡ 一键脚手架（V1.2 起，推荐）

新应用**不要手写接线**，用生成器（自动处理 6 处）：

```bash
# 创建
python3 tools/new_app.py snake --label "贪吃蛇" --cat "程序"
python3 tools/new_app.py mytool --label "我的工具" --fullscreen   # 全屏(隐藏状态栏)
python3 tools/new_app.py mytool --label "我的工具" --hidden       # 只进应用中心, 不上主菜单
python3 tools/new_app.py mytool --label "我的工具" --icon ICON_TERM   # 指定图标

# 删除 (与创建对称, 撤销全部接线)
python3 tools/new_app.py mytool --remove
```

自动改动的 6 处：

| # | 位置 | 内容 |
|---|---|---|
| 1 | `components/apps/pages/page_<id>.c` | 页面实现（由 `apps/templates/page_app_template.c` 生成，**直接可编译运行**） |
| 2 | `components/apps/CMakeLists.txt` | `SRCS` 追加 |
| 3 | `components/apps/include/apps_pages.h` | `os_page_<id>_register()` 声明 |
| 4 | `components/system/os/include/os.h` | `OS_PAGE_<UPID>` 枚举值（插在 `OS_PAGE_COUNT` 前） |
| 5 | `components/apps/apps_registry.c` | 装配调用 `os_page_<id>_register();` |
| 6 | `components/apps/apps_registry.c` | `s_builtin_apps[]` 应用表条目（图标/分类/隐藏） |

之后：`python3 tools/check_deps.py` 查越层 → `idf.py build`。

> **依赖纪律**：模板只 `#include "os_app_api.h"`（应用层唯一 API 面）。直接 include
> `st7305.h` / `bt_manager.h` / `board_battery.h` 等驱动头 = 越层，守卫脚本会报。

### 5.1 手工注册（了解原理/特殊场景）

**新增一个编译期 App：**
1. 建页面 `components/apps/pages/page_xxx.c`，实现 `os_module_t`（`render/action/touch`）。
2. 提供 `os_page_xxx_register()`。
3. 在 `components/apps/apps_registry.c` 的 `s_builtin_apps[]` 加一条：
   `{ .id="xxx", .label="名称", .icon_idx=N, .page=OS_PAGE_XXX, .hidden=true, .cat="分类" }`
4. 在 `apps_register_all()` 调用 `os_page_xxx_register()`。

> V1.2 分层后：**应用装配在 L4 `apps` 组件**（`apps_register_all()` 由 `main` 在
> `os_init()` 后调用）；`os_page_dialog_register` 仍属 os 内核自带弹窗页。
> `os_page_*_register` 的声明在 `apps/include/apps_pages.h`（不在 os 层）。

### 5.2 分类规则（2026-09-22 定稿，**Lua 应用与 C 应用同一套**）

| 层 | 由什么决定 | 说明 |
|---|---|---|
| **左侧分类** | **文件放在哪个目录** | `apps/lua/apps/app/` → 应用；`ops/` → 运维；`engine/` → 引擎。C 应用则由 `s_engine_order[]` / `cat` 决定 |
| **顶部子分类** | **LAPP 头部的 `cat=`** | `程序`/`软件` → 软件；`系统`/`工具` → 系统；`游戏` → 游戏；`学习` → 学习；`运维` → （应用分类里那一格显示为"壁纸"）。`cat` 为空 → 只出现在「全部」 |

- 规则落地在 `am_lua.c`：扫描时读 `meta.cat` → `app.cat`，再用 `page_app_manager.c` 的
  `am_sub_want_cat()` 过滤（与 C 注册项**同一套判据**，不会两处跑偏）。
- ⛔ **目录与 `cat` 必须自洽**：`ops/` 里的应用一律写 `cat=运维`（曾经 term/wifeprobe/netdect 写成"系统"，
  与目录矛盾，虽然靠白名单兜住了，但语义脏）。
- ⚠ 加了 `cat=运维` 之后，`am_lua.c` 里那份**文件名白名单**只是给"没打包的裸 .lua"兜底，新应用不用去改它。
- 图标：`sync_apps.py --icon-from-main ICON_X` 把主图标表的图打进 LAPP；`am_lua.c` 会**反查**
  出对应下标（`os_app_t` 只有 `icon_idx`，没有"自带位图"字段）；反查不到 → 回退小游戏机图标。

**隐藏/发布规则：**
- 默认 `hidden=true`：只进**应用管家**（按分类），**不上主菜单**；用户"添加到主菜单"才显示。
  **Lua 应用同理**（长按即可加/删桌面上图标，启动走 `am_lua_open_if_entry()` 先设 boot 路径）。
- 分类固定：引擎(`s_engine_order` 固定顺序)/ 游戏 / 应用 / 运维。
- **新引擎**：同时 ① `apps/apps_registry.c` 加 `hidden=true` `.reveal=true` 条目；② `page_app_manager.c` 的 `s_engine_order[]` 加引擎 id。
- **非必须软件**(如修改机)默认**不启动/不加载**；只在应用管家选"后台运行"时才启动。
- **禁止自启动**：后台服务用 `os_register_service`（不占页面栈、不占主菜单图标）。

**商店下载型 App（运行时注册）：**
- store 安装 → `os_app_register(&os_app)`（id 以 `wasm:` 前缀）→ 主菜单自动出现。
- 商店列表 = 注册表中**排除固定系统软件**的应用；“分类可见=已装备→卸载”，不可见→下载。

**固定系统软件**（不进商店、无卸载/下载）：`设置 / 存储 / 音乐 / 阅读器 / 步步高 / 手柄`。

## 7. 退出确认（★ 所有全屏程序/游戏必须遵守，2026-10-03 定案）

全屏程序与游戏在退出时**必须先弹「退出程序?」**，防误触退出丢进度。这是**桥接层统一能力**，
不要在脚本里自己画弹窗。

- **默认已开启**：任何 Lua 程序/游戏的返回键在"脚本没消费"时都会弹确认框，**不用写代码**。
- **它挡不住脚本自己处理 BACK**：脚本把 BACK 当返回键用（关子窗/收菜单/返回上一层）时**依旧优先**，
  不会被确认框抢走 —— 这是故意的，否则游戏内菜单就没法用。
- **要关掉**（纯浏览类、或退出前已自行确认过）：

  ```lua
  app.exit_confirm(false)     -- 关闭
  app.exit_confirm(true)      -- 打开（默认）
  local on = app.exit_confirm()   -- 查询当前值
  ```

- **入口唯一**：`app.exit()` 与"框架 BACK 未消费"都走桥层的 `lua_request_exit()`，
  所以两处行为一致；`app.exit()` 也会先弹确认。
- 实现要点（改桥层时别踩）：弹窗**延迟到下一帧 poll** 才 push（在被 Lua `action()` 间接调用的
  路径里 push 弹窗属于重入）；弹窗回调里**只置标志**，不直接 `os_pop` 页面
  （回调返回后弹窗层才被关闭，直接弹会把弹窗弹掉、应用留着）。
- C 原生应用页（非 Lua）若要同样效果，参照 `page_engine.c` 的 `eng_exit_confirm()` /
  `os_confirm_exit_blocking()`。

> **单文件 Lua 程序**：把一个 `.lua` 丢进 TF 卡（或从应用商店装）就能跑，**免重编固件**。

## 0. 一句话流程

```
写 .lua → 丢 /sdcard/apps/{engine|app|ops}/  （或放商店源后从商店装）
        → 应用中心对应分类自动出现 → 点开运行 → on_exit 释放硬件
```

**核心原则（最重要）**：**核心能力进固件、只对脚本开放 API，脚本绝不手搓核心动作。**

| 层 | 职责 | 例子 |
|---|---|---|
| 固件 (C) | 硬件 / 网络 / HID / 文件 / 持久化 / 算法 | WiFi 扫描与统计、键鼠、存储、NVS、中文点阵 |
| 脚本 (Lua) | 界面布局、状态机、存信息、少量计算 | 页面与 Tab、按钮、进度条、触控板、游戏逻辑 |

程序只该做三件事：**把数据画出来、把输入接起来、把结果存下来**。
> 边界：**画图不进固件**（`line/circle` 等图元由脚本 UI 层实现），但**图元算法与字形数据进固件**。

## 1. 最小可运行模板（复制即用）

```lua
-- myapp.lua — 最小单文件程序
local T = { n = 0 }              -- 私有状态：用局部表，避免污染全局

function on_enter()              -- 进入：读配置 / 准备状态
  T.n = app.nvs.get_int("myapp", "n") or 0
end

function render()                -- 整页渲染：先清屏再全画
  app.clear()
  app.zh(8, 32, "我的程序", false)          -- 中文（固件 16px 字库）
  app.text(8, 64, "count = " .. T.n)        -- ASCII 8x16
  app.text(8, 280, "按 BACK 返回")
end

function action(a)               -- 按键 / 手柄动作
  if a == app.CONFIRM then
    T.n = T.n + 1
    app.nvs.set_int("myapp", "n", T.n)
    app.redraw()
  elseif a == app.BACK then
    app.exit()                   -- 退出本程序（回应用中心）
  end
end

function poll() end              -- 每帧（可选；动画/轮询才用）
function on_exit() end           -- 退出：释放用过的硬件
```

## 2. 契约回调（**签名必须与下面完全一致**）

| 回调 | 时机 | 关键约定 |
|---|---|---|
| `function on_enter()` | 进入程序 | 初始化状态、读 NVS；**不要在此长时间阻塞** |
| `function render()` | 需要重绘时 | **先 `app.clear()`**；一帧画完整；画布 400×300、1bpp 白底黑字；**y<24 是状态栏区，避开** |
| `function poll()` | 每帧调用 | 动画/定时/异步取数据；不需要就不定义 |
| `function action(a)` | 有按键/手柄动作 | `a` 见 §3.1。**返回 `true` = 已消费**（内核不再处理）；`false`/`nil` 交内核 |
| `function on_exit()` | 退出程序 | **必须释放硬件**：`app.wifi.release()` / `app.hid.stop()`；关文件 |

**BACK 语义**：程序内若开了子窗口/弹窗，`action(app.BACK)` 里 `return true` = "我关掉了子窗口，别退出程序"；
真要退出用 `app.exit()`（或 `return false` 让内核处理）。

> 只定义了的回调才会被调用；`poll` / `on_exit` 可省略。

## 4. Lua UI 工具层（纯 Lua，复制即用）

> 固件只给**图元与字形**（`px/fill/rect/hline/vline/text*/big*/zh*`）与**数据**；
> `line/circle` 这类由脚本自备。以下片段拷到 `.lua` 开头即可复用。

```lua
local U = {}
function U.line(x0,y0,x1,y1)                 -- 直线 (Bresenham)
  local dx,dy = math.abs(x1-x0), math.abs(y1-y0)
  local sx,sy = (x0<x1) and 1 or -1, (y0<y1) and 1 or -1
  local err = dx-dy
  while true do
    app.px(x0,y0,true)
    if x0==x1 and y0==y1 then break end
    local e2 = err*2
    if e2 > -dy then err = err-dy; x0 = x0+sx end
    if e2 <  dx then err = err+dx; y0 = y0+sy end
  end
end
function U.circle(cx,cy,r,fill)              -- 圆 / 实心圆
  local x,y,d = r,0,1-r
  while x >= y do
    if fill then
      app.hline(cx-x,cx+x,cy+y); app.hline(cx-x,cx+x,cy-y)
      app.hline(cx-y,cx+y,cy+x); app.hline(cx-y,cx+y,cy-x)
    else
      app.px(cx+x,cy+y,true); app.px(cx-x,cy+y,true)
      app.px(cx+x,cy-y,true); app.px(cx-x,cy-y,true)
      app.px(cx+y,cy+x,true); app.px(cx-y,cy+x,true)
      app.px(cx+y,cy-x,true); app.px(cx-y,cy-x,true)
    end
    y = y+1
    if d < 0 then d = d+2*y+1 else x = x-1; d = d+2*(y-x)+1 end
  end
end
function U.bar(x,y,w,h,ratio)                -- 进度条 (0..1)
  app.rect(x,y,x+w,y+h,true)
  local n = math.floor((w-2)*math.max(0,math.min(1,ratio)))
  if n > 0 then app.fill(x+1,y+1,x+n,y+h-1,true) end
end
function U.signal(x,y,bars,n)                -- 信号条 (亮 n 根)
  for i=1,bars do
    local bh = i*3
    if i <= n then app.fill(x+(i-1)*4, y-bh, x+(i-1)*4+2, y, true) end
  end
end
function U.tabrow(x0,y,tabs,sel)             -- 顶部 Tab 行
  local x = x0
  for i,t in ipairs(tabs) do
    local w = app.textw(t) + 10
    if i == sel then app.fill(x,y,x+w,y+18,true); app.textc(x+w/2,y+2,t)
    else app.rect(x,y,x+w,y+18,true); app.textc(x+w/2,y+2,t) end
    x = x + w + 4
  end
end
return U
```

> 想跨程序共享：存成 `/sdcard/apps/_ui.lua`，程序里 `local U = dofile("/sdcard/apps/_ui.lua")`（需 TF 已挂载）。
> ⚠ `_ui.lua` **不要**放进 `{cat}` 分类目录，否则会被当成一个"应用"列出来。

## 5. 发布与安装（两条路，都不需要重编固件）

### 5.1 路线 A：TF 卡直接丢（最快，开发时用）
```
/sdcard/apps/app/我的工具.lua      ← 应用中心「应用」分类
/sdcard/apps/ops/xxx.lua           ← 「运维」分类
/sdcard/apps/engine/xxx.lua        ← 「引擎」分类
```
放入后进应用中心对应分类即出现。

### 5.2 路线 B：走商店（模拟下载安装）
1. `.lua` 放到**商店源**：`/store`（SPIFFS 根，随固件打包）或 `/sdcard/store_pkg`
2. 应用中心 → **商店**：列出该包 → 点击 → 确认 → 复制到 `/store/apps/app/`（或 `/sdcard/apps/app/`）
3. 复制完成即"已安装"，同时出现在对应分类里，可直接运行；长按可卸载（删副本）

> 商店是**本地源 + 复制安装**：不联网、无 WASM 运行时；`wasm:` 只是预留 id 前缀命名。

### 5.3 显示名规则（**没有映射表**）
- 显示名 = **文件名去掉 `.lua`**；TF 来源会加书名号区分，如 `「我的工具」`。
- **要中文名就给文件起中文名**（FAT 支持 UTF-8）。
- 旧文档写的 `s_pkg_meta[]` 映射表**已于 2026-09-19 移除**。

## 6. 常见坑

| 坑 | 现象 | 正确做法 |
|---|---|---|
| `render` 不打底 | 上次画面残留 / 花屏 | 开头先 `app.clear()` |
| 画到状态栏 | 与时间/电量重叠 | y 从 **24** 起画 |
| 中英混排错位 | 中文后接英文错行 | 中文 `app.zh`、英文 `app.text`，分两次调用 |
| 退出不释放硬件 | WiFi/HID 被占，别的程序用不了 | `on_exit()` 里 `wifi.release()` / `hid.stop()` |
| 滥用 `app.delay` | 界面卡死、按键无响应 | 用 `poll()` + `app.millis()` 非阻塞计时 |
| 回调签名写错 | 回调根本不触发 | 必须是全局函数：无参（`action` 除外的单个 `a`） |
| 忘 `app.redraw()` | 改了状态画面不变 | 状态变更后调用 |
| `_ui.lua` 放错位置 | 应用列表多出一个"程序" | 公共库放 `/sdcard/apps/` 根，不放 `{cat}` 子目录 |
| **`app.mix` 当 `app.texts` 用** | 选中行/反白文字**整行看不见** | `app.mix`/`app.mixc` 是**透明字**（只翻前景色，不铺底）→ `inv=true` 在白底上就是白字画白底。反白必须先 `app.fill(x, y, x2, y2, app.BLACK)` 铺底再画（`app.texts`/`app.textsb`/`app.zhs` 不透明，会自动铺格底，可直接 `inv`） |
| `app.mixc` 当 `app.textc` 用 | 文字跑到屏幕中间 / 坐标错位 | `app.mixc(cx, y, s[, inv])` 按**给定 cx** 居中；`app.textc(y, s[, inv])` 没有 cx，按**屏宽**居中 |
| **`app.fs.listdir` 用 `pairs()` 迭代** | 目录列成 `1 2 3 …`，或"一个存档都找不到" | 它返回的是**数组**（`1..n` = 条目名），不是 `{名=值}` 表。`pairs()` 拿到的是**下标**。必须 `for i = 1, #list do local name = list[i]`（闸门已加自动检查） |
| `s:find("%.bmp", 1, true)` | 永远匹配不到 | `plain=true` 时 `"%.bmp"` 是含 `%` 的**字面量**。判后缀用 `s:sub(-4):lower() == ".bmp"` |
| **`local function f()` 放在调用点之后** | 调用时报 `attempt to call a nil value` / `index a nil value` | Lua 的 `local` 只对**声明之后**的代码可见。函数引用它**后面**才声明的 local（含 `local G = {}`、工具函数）会变成**全局查找** → 运行时 nil。规则：被引用的 local 一律放在使用点之前 |
| 自定义 1bpp 文件格式 | 自己的读写在 Lua 内自洽，但和固件/C 版互不通用 | 要跟既有格式互操作就**逐字节照抄**：块偏移、调色板、位序（画布 `1=墨` ↔ BMP `bit1=白`，是**反的**）、行对齐填充、甚至头部里没用的字段（C 版 `xPelsPerMeter`/`clrImportant` 都留 0）。判据：**载入→保存 逐字节 md5 相同** |

## 软键盘：一律走 kbd_lib 统一入口（2026-09-22）

### 为什么不再在脚本里自己画键盘
项目里"很多键盘 UI"的真相是：**内核只有 `kbd_lib` 一份**（`keyboard.c` = 布局表/档位状态/几何命中；
`kbd_ui.c` = 渲染器），7 个页面共用，但**外观有 4 种形态**。
历史上 `draw` 与 `hit` 是**两组独立函数**，调用方要自己配对 —— 一旦"用 `kbd_draw_edit` 画、
却调 `kbd_hit` 判"，几何就不一致，**命中全错且不报错**。

现已在 `kbd_lib` 加**统一样式入口**（`kbd_style_t` + `kbd_geom_t` + `kbd_draw_style`/`kbd_hit_style`），
draw 与 hit 共用同一个几何结构；Lua 侧同样只暴露这一条路。

### Lua API（`page_lua.c` 的 `app.kbd`）

| API | 说明 |
|---|---|
| `app.kbd.use("std"[, y])` | 5 排全高 145px，布局 `kbd_std`。y 默认贴屏幕底 |
| `app.kbd.use("edit"[, y])` | 排高 19px（压低 1/3），布局 `kbd_edit` |
| `app.kbd.use("rows", n[, y])` | 只画/只判前 n 排，布局 `kbd_std` |
| `app.kbd.use("dialog", x, y, w, row_h)` | 把满宽布局等比缩放平移到 `[x, x+w)`，布局 `kbd_edit` |
| `app.kbd.geom()` | → `{style=,x=,y=,w=,row_h=,rows=}` |
| `app.kbd.height()` | 当前样式占用像素高（用于给它腾地方） |
| `app.kbd.draw([press])` | 用当前几何绘制；`press` = 按下键索引(-1 无) |
| `app.kbd.hit(tx, ty)` | 用**同一几何**命中 → 键索引 / -1。**先 x 后 y** |
| `app.kbd.press(i)` | 动作码，**含档位副作用**（CAPS/SHIFT/FN 在内部翻转） |
| `app.kbd.char(i)` | 当前档位下该键的字符；无则 `nil` |
| `app.kbd.label(i)` / `layer_on(i)` | 当前显示标签 / 是否处于激活档层 |
| `app.kbd.get("caps"/"shift"/"fn")` / `set(k,v)` / `reset()` / `count()` | 档位读写与复位 |

动作码常量与 `KBD_ACT_*` 同值：`app.kbd.CHAR/ENTER/BKSP/SPACE/ESC/TAB/UP/DOWN/LEFT/RIGHT/CAPS/SHIFT/FN/CTRL/ALT`
样式常量：`app.kbd.STYLE_STD/STYLE_EDIT/STYLE_ROWS/STYLE_DIALOG`；几何：`app.kbd.H/ROW/ROW_EDIT/ROWS`

### 推荐写法（一次 `use` 定样式，之后 draw/hit 同源）
```lua
function on_enter()
  app.kbd.use("std")          -- 或 "edit" / "rows",3 / "dialog",x,y,w,16
  app.kbd.reset()
end

function render()
  app.kbd.draw(press_index)   -- 画
end

function poll()
  local tx, ty = app.touch()
  if tx and ty and not was then
    local i = app.kbd.hit(tx, ty)        -- 判命中：与 draw 同一几何
    if i >= 0 then
      local act = app.kbd.press(i)
      local c   = app.kbd.char(i)
      if act == app.kbd.ENTER then ... elseif act == app.kbd.CHAR and c then ... end
    end
  end
end
```

> ⚠ 模拟器（`tools/lua_sim.py` + `tools/fw_kbd.py`）**直接从 `keyboard.c` 解析布局**并实现同一套
> 内核语义，所以本机截图与设备一致，不会分叉。

## 应用一致性口径（2026-09-22 linit 定案，放宽视觉）

> **Lua 应用不必与 C 版像素级一模一样，"差不多"即可；但这三条必须完全一致：**
> 1. **菜单选项与规则分类一致** —— 条目、层级、分类归属、取值范围/步进照抄 C 版
> 2. **处理逻辑一致** —— 同样的输入得到同样的结果与提示（分发/分支/边界/超时）
> 3. **点击逻辑一致** —— 点哪里做什么、拖动/长按的判定与阈值、命中区域

理由：视觉细节（自绘小字、圆角、图标像素）属表现层，允许用固件字模近似；
而**菜单结构 + 逻辑 + 交互**是用户的操作契约，改了就是另一个软件。


## 弹窗一律用 `app.dlg.*`（禁止自绘）

```lua
      if r == 0 then ...确定... end
    end
  end
end
```

```c
#define APPPACK_ICON_BYTES 512u          /* 64x64/8 */
```

### 4. 为什么这样设计（而不是自定义二进制容器）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **注释头部（本方案）** | 纯文本、可直接阅读编辑；普通 `.lua` 兼容；固件静态解析简单；git diff 友好 | 头部 ~700 字节冗余（图标 base64 比二进制大 33%） | ✅ **采用** |
| 自定义二进制容器（`LAPP\0` + 段表） | 体积最省 | 不能直接当脚本跑；不打包就无法用；工具链复杂；调试困难 | ❌ |
| 附随文件夹（`app/` + `icon.png` + `meta.json`） | 结构清晰 | **违背"一个文件"目标**；拷贝/安装要处理多文件；旧扫描逻辑要重写 | ❌ |

**核心权衡**：宁可多 700 字节，也要保住"**就是普通 Lua 文件**"这一性质 ——
写、改、调、diff、丢 TF 卡直接跑，全都不需要额外工具；打包只在你想要图标和商店元信息时做一次。

```c
    uint8_t  icon[APPPACK_ICON_BYTES];   /* 64x64 1bpp, MSB first, 1=黑 */
} apppack_meta_t;

/* 读取文件头若干行解析元信息; 无 LAPP 头部时返回 ESP_ERR_NOT_FOUND (调用方回退老逻辑) */
esp_err_t apppack_parse(const char *path, apppack_meta_t *out);
```

**接入点（各 3~5 行）：**

| 位置 | 改动 |
|---|---|
| `apps/pages/am_lua.c` 扫描 | 每发现一个 `.lua` → `apppack_parse()`；有元信息则用 `name` 作显示名（替代文件名）、带 `desc`、`icon` |
| `apps/pages/am_store.c` 扫描 | 同上（商店列表显示真图标 + 简介，而不是统一 `ICON_MINI_GAMES`） |
| 列表渲染（`page_app_manager.c`） | 若列表项带位图 → `st7305_blit_1bit()` 直画 64×64；否则回退现有 `icon_idx` |
| `os.h` 的 `os_app_t` | 可选加 `const uint8_t *icon_bmp`（非 NULL 时列表优先用位图） |

**成本估计**：新组件 ~150 行 + 三处接入各几行；无 Lua 侧改动、无破坏性（无头部即回退现状）。

---

## 4. 为什么这样设计（而不是自定义二进制容器）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **注释头部（本方案）** | 纯文本、可直接阅读编辑；普通 `.lua` 兼容；固件静态解析简单；git diff 友好 | 头部 ~700 字节冗余（图标 base64 比二进制大 33%） | ✅ **采用** |
| 自定义二进制容器（`LAPP\0` + 段表） | 体积最省 | 不能直接当脚本跑；不打包就无法用；工具链复杂；调试困难 | ❌ |
| 附随文件夹（`app/` + `icon.png` + `meta.json`） | 结构清晰 | **违背"一个文件"目标**；拷贝/安装要处理多文件；旧扫描逻辑要重写 | ❌ |

**核心权衡**：宁可多 700 字节，也要保住"**就是普通 Lua 文件**"这一性质 ——
写、改、调、diff、丢 TF 卡直接跑，全都不需要额外工具；打包只在你想要图标和商店元信息时做一次。

## 5. 与现有流程的关系

| 环节 | 未打包 `.lua` | 打包后（LAPP） |
|---|---|---|
| TF 卡丢包运行 | ✅ 直接跑 | ✅ 一样 |
| 商店源扫描 | 显示"文件名" | 显示**真名 + 简介 + 真图标** |
| 应用中心列表 | 统一占位图标 | 各自真图标 |
| 应用内自绘图标 | 需自己画 | 调 `blit_app_icon(x, y)` 一行 |
| 固件改动需求 | 无 | 需按 §3 加 `apppack` 服务（可选增强） |
