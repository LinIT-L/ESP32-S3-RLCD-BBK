# LinTOS 开发指南（新功能/新 App 全流程）

> 处理对象：任何新功能、新软件、新页面的完整开发流程——咨询清单 → 分类归位 → 选弹窗 → 复用能力 → 注册 → 编译烧录；以及字体/键盘/双方案/布局等 UI 规范。
> 架构/工程约定 → 《架构与工程约定》；硬件 → 《硬件与IO》。
> 平台：ESP32-S3（`components/os` 内核 + 独立组件）。

## 0. 一句话流程

**提需求 → 按 §1 咨询清单问清 → 按 §2 归类 → 按 §3 选弹窗 → 按 §4 查系统能力 → 复用已有组件 → 注册 → 编译烧录回归。**

## 0.1 硬性协作铁律

1. **先给选项问用户**（除非明确"全自动"），不擅自决定。
2. **一律复用已有字体/资源/UI/模块**；确实没有才新建（新建前说明"复用哪个会破坏什么"）。
3. **不擅自改字体**；只改被要求的东西。
4. **内存优先 PSRAM(8MB)**，非必须不留内部 RAM。
5. 需求改完、或未完成需确认方案后，才「编译+merge+烧录」；不逐小改反复烧。
6. 诊断优先串口实时日志，不轻易为排查改固件/反复烧录。

## 2. 功能分类与「归位」规则

| 分类   | 统一载体                                   | 归位规则             | 示例                     |
| ---- | -------------------------------------- | ---------------- | ---------------------- |
| 全屏应用 | `os/pages/page_xxx.c` + 注册             | 主菜单一个图标→全屏→退出回菜单 | 音乐/阅读/番茄钟/计算器          |
| 引擎游戏 | `engine_manager` 注册表 `s_engines[]`     | 加一行，不写菜单         | GB/GBC/NES/ArduBoy/文曲星 |
| 设置项  | 设置页子项                                  | 归属设置容器，不占主菜单图标   | 显示/时间/蓝牙/TF卡/音量        |
| 菜单工具 | 应用管理页列项                                | 复用 os\_app       | 计算器/密钥管理器/终端           |
| 后台服务 | `os_register_service`（不占页面栈）           | 任意页叠加渲染          | 状态栏/WiFi连接提示           |
| 商店应用 | 本地应用源 + **复制安装**（`am_store.c`） | 商店里装/卸后进对应分类 | 目前只有 Lua 单文件包（`*.lua`） |

**应用发布规则**：

- 默认 `hidden=true` 只进应用管家（按分类），不上主菜单；用户手动"添加到主菜单"才出现。

- 分类固定：引擎（s\_engine\_order 固定顺序）/ 游戏 / 应用 / 运维。

- 非必须软件（如修改机）默认不启动/不加载，只有应用管家选"后台运行"才启动。

- 新增引擎必须同时：①os\_pages.c 加 hidden=true,+reveal=true 条目 ②page\_app\_manager.c 的 s\_engine\_order\[] 表加该引擎 id。

## 3. 弹窗（唯一源头 os\_dialog，不自画）

| 类型   | API                                                          | 行为                              | 用途                    |
| ---- | ------------------------------------------------------------ | ------------------------------- | --------------------- |
| 提示   | `os_dialog_toast` / `os_dialog_toast_ms`                     | 居中提示，默认 1s 自动关，任意按键/触摸立即关       | 成功/失败/IP/已输入/生效       |
| 确认   | `os_dialog_confirm_ex`                                       | 确定/取消两键，等用户选择，可配 timeout 超时自动完成 | 删除/格式化/恢复/关机          |
| 列表   | `os_dialog_list` / `os_pane`                                 | 单选+底部返回行，触屏点哪选哪+手柄方向键           | 选择/浏览（文件/WiFi/蓝牙/PIN） |
| 复杂交互 | `os_dlg_stack` custom（on\_render/on\_touch/on\_key/on\_poll） | 自定义渲染/触摸/轮询                     | 滚轮/连接中/抽屉/按键映射        |

回调约定 `cb(ctx, result, ud)`；result=-1 表示 BACK 取消。弹窗打开时底层页面不退出，关闭后自动恢复。

**提示 vs 确认必须分清**：提示（结果告知）一律 toast；确认（需用户拍板）一律 confirm\_ex；严禁混用。

## 5. 添加新功能的落地步骤

**0) 先问清单**：§1 咨询清单 → §2 定分类 → §3 定弹窗 → §4 查系统能力（先查再用，不重复造）。

**1) 建页面**（C 应用）：

```bash
# 推荐: 一键脚手架 (自动接线 6 处: 页面/CMakeLists/入口声明/OS_PAGE_ 枚举/装配/应用表)
python3 tools/new_app.py myapp --label "我的应用" --cat "程序"
# 选项: --fullscreen (隐藏状态栏) / --hidden (只进应用中心) / --icon ICON_XXX
# 删除: python3 tools/new_app.py myapp --remove
```

手工等价操作：建 `components/apps/pages/page_xxx.c` 实现 `os_module_t`
（`on_enter/on_exit/render/action/touch/poll`），并在
`components/apps/apps_registry.c` 的 `apps_register_all()` 里注册、
`apps_pages.h` 加入口声明、`s_builtin_apps[]` 加一条（引擎另加 `s_engine_order[]`）。
> V1.2 起应用页在 **L4 `components/apps/`**（原 `components/os/pages/` 已废弃）。

**2) 依赖**：`components/apps/CMakeLists.txt` 的 `REQUIRES`（脚手架只在新页需要新能力时改）。
应用**只许** `#include "os_app_api.h"`，不要直连驱动/服务头。

**3) 自检**：`python3 tools/check_deps.py` —— 分层违例/隐藏依赖会在这里暴露
（不跑也行：**构建已内置守卫**，违例会直接让 `idf.py build` 失败）。

**4) 编译烧录 → 串口验证**（`bash build.sh` → `merge_flash.sh` → esptool；见《架构与工程约定》§8）。

## 7. UI 规范（字体 / 键盘 / 双方案 / 布局 / 弹窗外观）

### 7.1 字体

| 场景      | 字库/函数                                                                  |
| ------- | ---------------------------------------------------------------------- |
| 正文/标签首选 | `font_zh16` 16×16（`font_zh16_find_utf8`+`get_bitmap_by_index`，6813 字全） |
| 大字/强调   | `draw_text` 24px（`font_zh`粗/`font_zh_light`细）                          |
| ASCII   | `FONT8X12` 8×12                                                        |

- 16px 中英混排整行绘制已封装：`ui_text16/ui_text16c/ui_text16w`（中16宽/英8宽）。

- 不擅自改字体；"用16px/应用管家字体"即 `font_zh16`（6813 字全，非子集）。

### 7.2 键盘（不重造）

- 文本输入 → `kbd_lib`（52 键标准/编辑键盘/弹窗缩放）

- 密码输入 → WiFi 密码模板（明文显示）

- 纯数字 → 九宫格

### 7.3 输入/选择双方案（任何选择界面必做）

- 触屏（优先）：默认都不加黑，点哪个立即选中生效；按压需即时反馈（按住反黑、松手恢复）；点无效区不震动、无反应。

- 手柄（兜底）：默认加黑选中一项，方向键切换，CONFIRM=选当前，BACK=返回。

- **接上手柄时手柄优先**（V1.6.x 调整）：只要手柄处于已连接状态，就用"手柄方案"（默认加黑选中一项 + 方向键导航），即使设备同时带触屏；
  未接手柄且有触屏时用"触屏方案"（默认不加黑、点哪算哪）。渲染统一查 `input_scheme_touch()` 区分。
  两方案只是渲染差异，触屏点击/滑动/拖动逻辑独立并存 —— 手柄黑块在时手指点哪一项照样直接选中。

### 7.4 布局精简

- 界面尽量简洁，少提示/标题/下划线/分隔装饰。

- 功能按钮贴死左右边缘、底边贴住下方元素顶部不悬空。

- 弹窗几何统一居中；按钮文字 22px 普通字体；提示文字在上方空白处水平居中。

- 应用图标优先用用户指定路径图标 → 转 64×64 1bpp 黑白位图入图标库。

- **状态开关乐观更新**：蓝牙/WiFi 等开关点击时**先刷新显示目标状态**（如"蓝牙:关"），真正操作（启动/停止）在后台完成；失败再回滚显示（`os_hw_request/release` 已内置：request 先亮后验、release 先灭后清）。

### 7.5 弹窗外观速查（行为契约见 §3）

| 类型         | 外观                          |
| ---------- | --------------------------- |
| 提示 toast   | 居中提示框，3px 黑边框，自适应宽，高 36     |
| 确认 confirm | 小窗：标题居中在上，横杠连左右边框，确定/取消两键   |
| 列表 list    | 固定窗/自适应高，行高 40，底部固定返回行      |
| 复杂交互       | 调用方自定义 on\_render/on\_touch |

## 8. 软件内存与生命周期规范（每个软件必过）

1. **数据/缓冲优先 PSRAM（8MB）**：大数组/表/帧缓冲/列表一律 `EXT_RAM_BSS_ATTR` 或动态分配放 PSRAM；核心内部 SRAM 只留热路径与性能关键（如 MD 逐像素查表、USB DMA 缓冲）。
2. **打开才加载，退出就释放**：软件进入（on\_enter）时加载资源/初始化，退出（on\_exit）时释放自己申请的资源（任务/堆/外设/后台线程），不遗留后台占用。
3. **退出关闭检测**：软件退出后由管家（os\_housekeeper）检查是否关闭干净（任务栈/内存/外设）；发现泄漏/残留应处理并报告。
4. **懒加载**：非必须模块（蓝牙/WiFi/USB/字体）按需 `os_hw_request/release`，不默认常驻。
5. **禁止自启动**：非必须软件（如修改机）默认不加载/不启动，仅应用管家选"后台运行"时才启动。
6. **大缓冲动态化**：游戏/引擎等大内存组件可进入时动态分配、退出释放，平时不占核心 RAM。
7. **联网速度优先**：WiFi 开启/连接/扫描全程 `esp_wifi_set_ps(WIFI_PS_NONE)` 禁省电，保证联网与扫描快速稳定。

## 9. 软件统一 PIN 安全规范（受保护软件必读）

> 需要 PIN 保护的软件（密钥管理器、本地收藏夹等）必须遵守，**杜绝各软件私存 PIN / 各用一套验证**。

1. **统一凭据 = 系统 keyvault 组件**（`components/keyvault`，NVS ns=`ln`）。应用只用这些接口：

   ```
   keyvault_init()             进入时调用一次（幂等）
   keyvault_has_pin()          是否已设置统一 PIN
   keyvault_set_pin()          首次设置（≥4 位）
   keyvault_verify_pin()       验证（0 正确/1 错/2 锁定中）
   keyvault_unlock_secret(...) 验证通过后用 PIN 派生解密密钥
   ```
2. **强制进入，不可跳过**：on\_enter 置 `s_pin_set = !keyvault_has_pin(); s_authed = false;` —— `s_authed` **必须为 false**（否则未设 PIN 会被放行）。未设→强制设；已设→强制输。
3. **规范**：PIN ≥4 位；连续错达 keyvault 阈值即锁定等待；**备份/恢复不迁移 PIN**；**禁止回读 PIN 明文**（热点密码等不准自己存明文）。
4. **新软件接入步骤**：`REQUIRES keyvault` → on\_enter 调 `keyvault_init` + 上面那句状态 → verify/set 直调 keyvault → 备份不含 PIN。


## 8. 软键盘：统一走 kbd_lib 的样式入口（2026-09-22）

`kbd_lib` 是**唯一**键盘内核（布局表 + 档位状态 + 几何命中），渲染器可换。
历史问题：对外有 4 个 `kbd_draw*` 与 4 个 `kbd_hit*`，**draw/hit 要调用方自己配对**，
配错就"画一种几何、判命另一种" → 命中全错且不报错。

现状：已加**统一样式入口**，draw 与 hit 共用同一个 `kbd_geom_t`：

| 样式 | 用途 | 对应旧 API |
|---|---|---|
| `KBD_STYLE_STD` | 5 排全高 145px（终端/网络检测/密钥管理器）| `kbd_draw` / `kbd_hit` |
| `KBD_STYLE_EDIT` | 排高 19px 压低 1/3（收藏夹/编辑）| `kbd_draw_edit` / `kbd_hit_edit` |
| `KBD_STYLE_ROWS` | 只前 N 排（摩斯码）| `kbd_draw_rows` / `kbd_hit_rows` |
| `KBD_STYLE_DIALOG` | 缩放进 `[x,x+w)`（WiFi 密码等弹窗）| `kbd_draw_edit_at` / `kbd_hit_edit_at` |

```c
kbd_geom_t g;
kbd_geom_default(&g, KBD_STYLE_STD, ST7305_HEIGHT - KBD_H);  /* 选样式 + 顶边 */
kbd_draw_style(lcd, &g, &kbd, press);                         /* 画 */
int i = kbd_hit_style(&kbd, &g, sx, sy);                      /* 判 —— 同一几何 */
```

- 旧 API **保留**（不动正在跑的页面），**新代码一律用统一样式入口**。
- Lua 侧同样只暴露这一条路：`app.kbd.use("std"/"edit"/"rows"/"dialog", ...)` → `draw` / `hit`。
  详见 `docs/Lua单文件程序规则.md`。
