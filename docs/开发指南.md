# LinTOS 功能添加指导手册

> 目标：任何新功能/新软件都能**自动化归位** —— 先查手册、问清单、复用现有模块；确实不兼容才新增模块。
> 适用对象：LinTOS 模块化 OS（ESP32-S3，components/os 内核 + 独立组件）。
> 版本基线：commit 2b366ce（统一弹窗 os_dialog + 应用注册表 os_app 已落地）。

---

## 0. 一句话流程

**提需求 → 我按 §1 清单问你 8 问 → 按 §2 归类定「软件 / 引擎 / 设置 / 工具」→ 按 §3 选弹窗 → 按 §4 查系统能力模块 → 复用已有组件 → 不兼容才新增 → 注册进 os_app/os_register → 编译烧录回归。**

## 1. 新功能添加「咨询清单」（每次添加前必问）

每次你说"添加 XX 功能"，我会先确认以下信息（可一次答完，避免反复追问）：

| # | 问题 | 用途 |
|---|---|---|
| 1 | 功能/软件类型？`全屏应用` / `引擎游戏` / `设置项` / `菜单工具` / `后台服务` | 决定归位到哪张表 |
| 2 | 从哪进入？`主菜单图标` / `应用管理` / `设置子页` / `独立按键` | 决定 os_app 注册 or 子项 |
| 3 | 需要什么弹窗？`提示` / `确认` / `操作列表` / `全屏覆盖` / `无` | 决定用 os_dialog 哪个 API |
| 4 | 是否用状态栏？全屏时隐藏还是保留顶部状态栏 | 决定 fullscreen 标志 |
| 5 | 是否联网？`WiFi STA` / `HTTP 下载` / `热点上传` / `不联网` | 决定网络模块依赖 |
| 6 | 是否用蓝牙？`手柄连接` / `设备发现` / `不涉及` | 决定蓝牙模块依赖 |
| 7 | 是否用触摸/触控板/多点？`仅按键` / `单点` / `拖动/触控板` | 决定 input/touch 处理 |
| 8 | 是否用 USB？`键鼠仿真` / `U盘读写` / `不涉及` | 决定 usb_hid/usbh_msc 依赖 |

> 自动化归位：答案 1 决定"同一类功能尽量复用同一模块"（详见 §2）；答案 3/5/6/7/8 决定"系统能力尽量复用现有组件，不兼容才新增"（详见 §4）。

## 2. 功能分类与「归位」规则

新功能按用途归入下列**统一模块**，同一类一律复用同一实现，不重复造轮子：

| 分类 | 统一载体 | 归位规则 | 示例 |
|---|---|---|---|
| **全屏应用** | `components/os/pages/page_xxx.c` + `os_app_register` | 主菜单一个图标 → 全屏运行 → 退出回菜单 | 音乐/阅读/番茄钟/壁纸/键鼠 |
| **引擎游戏** | `components/engine_manager` 注册表 | 在 `s_engines[]` 加一行，不写进菜单 | GB/GBC/NES/ArduBoy/文曲星/暴龙机 |
| **设置项** | 设置页子项（`page_settings` 迁移后） | 归属设置容器，不占主菜单图标 | 显示/时间/蓝牙/TF卡/音量 |
| **菜单工具** | 应用管理页列项 | 复用 os_app，应用管理可见 | 图标编辑器/键盘工具 |
| **后台服务** | `os_register_service`（不占页面栈） | 任意页面可叠加渲染 | 状态栏 |
| **商店应用** | `os_app_register` 运行时注册（id 前缀 `wasm:`） | WASM 商店安装后动态加入主菜单 | 商店下载的小程序 |

**不兼容才新增**：只有现有组件无法满足（功能、内存、性能、外设），才新建 `components/xxx` 独立组件；新增前必须先说明"复用哪个组件会破坏什么"。

## 3. 弹窗类型选择指南（统一 os_dialog）

所有弹窗一律走 `components/os/kernel/os_dialog.c`，**不要**各页面自己画弹窗。

| 弹窗类型 | API | 行为 | 适用场景 |
|---|---|---|---|
| **提示弹窗** | `os_dialog_toast(ctx, "已收藏")` | 居中提示，1 秒自动关闭 | 收藏成功/操作结果/短暂提示 |
| **确认弹窗** | `os_dialog_confirm(ctx, "确定退出?", cb, ud)` | 确定/取消两键，cb(result=0 确定, 1 取消, -1 返回) | 删除确认/危险操作 |
| **操作弹窗** | `os_dialog_list(ctx, 标题, items, n, sel, cb, ud)` | 选项列表选择，cb(result=选中索引/-1 取消) | 布局选择/列表选择/操作菜单 |
| **全屏弹窗** | `os_module.modal = true` 的覆盖页 | 模态覆盖，不退出底层页面 | 大内容设置/二级全屏覆盖 |
| **全屏应用** | `os_module.fullscreen = true` 的应用页 | 隐藏状态栏，整屏运行 | 游戏/阅读器/键盘/白板 |

回调约定：`cb(ui_ctx_t *ctx, int result, void *ud)`；result=-1 表示 BACK 取消。弹窗打开时底层页面**不退出**（内核已支持模态覆盖语义），关闭后自动恢复底层。

## 4. 系统能力模块矩阵（复用映射）

新功能需要系统能力时，**先查下表用现成组件**，不要自己重新实现：

| 系统能力 | 模块/接口 | 说明 | 是否已接入 os |
|---|---|---|---|
| **状态栏** | `services/svc_statusbar.c` + `os_platform_ops` | 电量/音量/蓝牙/WiFi/USB 状态挂钩（由 main.c 注入 getter） | ✅ 全局服务 |
| **网络(WiFi)** | `wifi_manager`（menu 组件内）+ `esp_http_client` + `dns_server` | STA 连接、HTTP 下载、热点上传 | ⚠️ 未抽象为 os 服务（商店阶段接入） |
| **蓝牙** | `bt_manager`/`bt_core`/`bt_map`（menu 组件内）+ `esp_hid` | BLE HID 手柄、设备发现 | ⚠️ 未抽象（P3 手柄页接入） |
| **触屏** | `input` + `touch_panel` | 触摸点/拖动/多点；`input_get_touch_pos` 轮询 | ✅ 页面 touch/poll 直接可用 |
| **USB 键鼠** | `usb_hid` 组件 | 键盘/鼠标仿真（TinyUSB） | ✅ page_usb_hid 已接入 |
| **USB 存储** | `usbh_msc` 组件 | U 盘读写 | ⚠️ 未接入 os 页面 |
| **显示** | `st7305` + `ui_common` | 屏句柄、fill_rect/draw_text/图标/弹窗外框 | ✅ 全部页面依赖 |
| **音频** | `audio_player` + `tone_player` | PCM 播放 / 和弦提示音 | ✅ 番茄钟/音乐已用 |
| **引擎** | `engine_manager` | 游戏引擎统一 load/unload 注册表 | ✅ 游戏分栏已用 |
| **存储/TF卡** | `sdmmc`/`fatfs` + `sd_scan`/`file_browser`/`favorites` | 挂载、扫描、文件浏览、收藏 | ⚠️ 组件就绪，os 页面待接 |
| **壁纸** | `wallpapers` 组件（已从 menu 拆出） | 内置壁纸程序渲染 | ✅ 壁纸页已用 |
| **震动** | `vibrator` 组件 | 震动反馈 | ✅ 番茄钟已用 |

> 网络/蓝牙目前封装在旧 menu 组件内，尚未抽象为 os 服务。新功能若需要，**先评估复用**（等对应页面迁移时抽象），确实无法复用再说明原因。

## 6. 添加新功能的「落地步骤」（对照本手册执行）

1. **问清单**（§1 的 8 问）。
2. **定分类**（§2 表格）→ 决定载体。
3. **定弹窗**（§3）→ 需要哪个 API。
4. **定系统能力**（§4）→ 复用哪些组件。
5. **建页面**：在 `components/os/pages/` 新建 `page_xxx.c`，实现 `os_module_t`（render/action/touch/on_enter/on_exit/poll/fullscreen）。
6. **注册**：
   - 页面：`os_page_xxx_register()` 加入 `os_pages.c`；
   - 应用：在 `s_builtin_apps[]` 加一行（主菜单/应用管理自动出现）；商店应用运行时 `os_app_register`。
7. **CMake**：`components/os/CMakeLists.txt` 加源文件 + 需要的 REQUIRES。
8. **编译**（见 §7）→ **烧录** → **串口验证**启动/页面/内存基线。

## 7. 工程约定

- **编译环境**：IDF v5.5（`/Users/linit/esp/esp-idf-v55`）；项目用 py3.13 venv。编译命令：
  ```bash
  source /Users/linit/esp/esp-idf-v55/export.sh
  /Users/linit/.espressif/python_env/idf5.5_py3.13_env/bin/python3 $(command -v idf.py) build
  ```
  （直接跑 `idf.py build` 会因 python 环境不匹配报错，需用上面方式。）
- **烧录**：`idf.py -p /dev/cu.usbmodem101 flash`（用同 py3.13 方式调用）。
- **内存策略**：关键状态放内部 RAM；帧缓冲/大块数据/壁纸缓冲放 PSRAM（`MALLOC_CAP_SPIRAM` 或 `EXT_RAM_BSS_ATTR`）。
- **界面风格**：简洁原生、白底黑线、避免花哨装饰；弹窗按钮 22px；字体 Apple 风格；图标实心位图。
- **回退**：全程保留旧 `menu_system`（`CONFIG_OS` 开关），新 os 与旧版可切换回退。
- **提交**：每个页面/功能迁移完成 + 编译烧录验证后，单独 commit（信息格式：`P3 xx页迁移: ...` / `架构整合: ...`）。
