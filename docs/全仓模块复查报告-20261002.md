## 1. 已修的三处

### 1.1 ⚠ 真 bug：WiFi 引用计数泄漏 —— 三个页"多 request 一次"，取消后射频**再也不关**

**证据链**

- `os_hw.c` 语义：`request` 首次才 `start`，之后只 `++ref`；`release` 到 0 才 `stop`（有下溢保护）。
- `page_settings.c:828-831` `settings_wifi_connect_open()`：
  ```c
  if (!os_hw_is_active(OS_HW_WIFI)) { os_hw_request(OS_HW_WIFI); s_wifi_conn_we_opened = true; }
  ```
  只有**它自己开的**才记 `s_wifi_conn_we_opened`；取消/返回时靠这个标志 `release`（`:979`、`:1128`）。
- 但 `page_fav.c:807`、`page_keymanager.c:267`、`page_gamepad.c:91` 都在**调用它之前**先
  `if (!os_hw_is_active(...)) os_hw_request(...)` → 轮到settings 时 `active` 已是 true →
  **不记标志** → 用户取消后没有任何人 `release` → **WiFi 常开**（违背"按需启停"）。

**修法**：删掉这 3 行重复 request，把所有权交回 `settings_wifi_connect_open()`（它本来就是这个设计）。

**复现**：WiFi 关着 → 进「收藏夹 / 密钥管理器 / 手柄」→ 选需要联网的那项 → 弹出连 WiFi → 返回取消。

### 1.2 Lua 页 4KB 缓冲进 PSRAM（省内部 RAM）

`page_lua.c:892` `lua_net_http_get()` 里的 `static char body[4097]` 原本在**内部 RAM BSS**。
它是纯 socket 读（`esp_http_client_read_response`，无 DMA、无禁 cache 窗口）→ 可安全放 PSRAM。

**改后已用工具验证**（不是猜）：

```
xtensa-esp32s3-elf-readelf -sW page_lua.c.obj
  body$5   4097  OBJECT  → 段 [548] .ext_ram.bss.8   ← PSRAM ✓
  s_bmp$0  2048  OBJECT  → 段 [539] .bss.s_bmp$0     ← 内部 RAM（故意保留）
```

`s_bmp[2048]` **故意留着**：`st7305_draw_bitmap_1bit()` 是逐像素 CPU 读源位图，放 PSRAM 会变慢。

### 1.3 BLE 扫描回调里的 `assert` 改为截断（防被对端打崩）

`esp_hid_gap.c:871`：
```c
assert(fields.name_len < sizeof adv_name - 1);   /* 旧 */
```
`adv_name[BLE_HS_ADV_MAX_SZ]`(=31)。邻近设备若发**超长/扩展广播**名字，`name_len` 可越界 →
`assert` 直接 `abort` → **整机重启**。名字只是列表显示用，不值得拿稳定性换 → 改成按 `sizeof` 截断。

（同文件 `:957`、`:977` 两个 `assert(rc==0)` 是 `ble_gap_conn_find` 自身连接句柄，风险极低，**未动**。）

### 8.7 应用管家「焦点无指示」修复（linit 反馈，方案 A 已实施）

**现象**：手柄控制时，方向键把焦点移到「左侧分类栏」**没有任何指示**，而右侧内容第一个仍显示为
选中（反色）→ 分不清焦点在哪一层、不知道按 UP/DOWN 会切分类还是滚内容。

**根因（渲染与导航不同源）**：`page_app_manager.c` 的 `s_focus_bar`（0=内容/1=子分类/2=左栏）
**只驱动导航**；渲染侧原先只有 `am_draw_subbar()` 里那处（子分类 U 形括号）用了它：
- 内容选中 `sel = !input_scheme_touch() && (i == s_focus)` —— 与 `s_focus_bar` 无关 → 焦点在左栏时仍反色
- 左栏选中框几何跟的是 `s_cat`（当前分类），**不是焦点** → 焦点移过去画面零变化

**修法（方案 A：焦点唯一 + 另一侧降级）**
1. 新增 `am_focus_on_content()` / `am_weak_mark()`，**渲染与导航同源**；
   4 处 `sel` 加上 `am_focus_on_content()` 条件（列缓冲路径 2 处 + 直绘路径 2 处）
2. 焦点不在内容区时，给 `s_focus` 那一项画 **1px 下划线"弱定位"**（不反色），
   表示"按 RIGHT/DOWN 会回到这里"（两条渲染路径都补了）
3. 焦点在左栏时，把左栏包围框**向外加粗 2px**（2px 水管 → 4px）——纯附加绘制，不动原几何
4. 焦点分层变化时补 `s_col_dirty = true`（内容要改画成弱定位/恢复反色）

**同源第二问题一并修**：`s_focus_bar = 1`（顶部子分类层）**全文件从未被赋值** →
手柄/键盘永远够不到子分类层，492 行的"子分类聚焦 U 形括号"是**死代码**；
而 993/997 的注释写「已无顶部子分类条」与实现（760 行确实画了）**相反**。
现在内容第一行按 **UP** → 进子分类层（`am_has_sub()` 为真时），LEFT/RIGHT 切
应用/运维/壁纸，DOWN 回内容 —— 三层贯通，注释也改正了。
