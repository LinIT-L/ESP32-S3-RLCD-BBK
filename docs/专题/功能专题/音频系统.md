# 功能专题 · 音频系统

> **这个功能回答"声音从哪来、谁在算、为什么卡"。**
> 源码入口：`components/services/audio_player/`（PCM→I2S 输出、MP3 解码、录音）、
> `components/services/tone_player/`（提示音/旋律）、各引擎内部的音频合成。
> 引脚（I2S / codec I2C / PA）见[硬件与接口手册](../../手册/硬件与接口手册.md)。

## 1 机制：三条通路

```
① 提示音   app.tone_async ──▶ tone_player ──┐
② 文件播放 app.rec.mplay  ──▶ audio_player ─┼──▶ PCM 环形缓冲 ──▶ I2S ──▶ codec/PA
   (MP3/WAV)                  (minimp3/内建)  │      (audio_out 任务)
③ 引擎音频 模拟器任务内合成 ──▶ feed_pcm ───┘
```

| 通路 | 谁产生 PCM | 特点 |
|---|---|---|
| `tone_player` | 自己算方波 | 单音/≤48 音的短旋律；非阻塞版给按键音用 |
| `audio_player` | 解码 MP3/WAV 文件 | 独立任务，边解边喂环形缓冲 |
| 引擎 | **模拟任务内**合成 | 见 §2 的分核规则 |

## 2 分核规则（最重要的一条）

> 起因：仙剑接 RIX 音乐后整机死机，日志 `task_wdt: CPU 0: sdl_aud` / `IDLE0 (CPU 0)`。
> 根因不是"算不动"，而是**音频合成与模拟任务抢同一个核，把 IDLE 饿死**触发 TWDT 重启。

| 规则 | 内容 |
|---|---|
| **R1** | 引擎音频合成**必须在模拟任务内**完成，只把 PCM 塞进 `audio_player_feed_pcm()` 的环形缓冲。⛔ 不要为引擎另起"音频任务" |
| **R2** | 必须独立音频任务时（SDL 回调模型）：钉 **CPU1**、优先级 **≤ 8**（不得高于 `audio_out`），并且**必须带超时自保**：单次回调 >120 ms 连续 2 次 → 关掉该模块（如音乐），保留系统 |
| **R3** | 高优先级只允许给"被信号量驱动"的任务（如 `genesis_snd` prio 20 收到帧信号才短暂运行）；⛔ 自由跑的任务 >8 会饿死 `audio_out` |
| **R4** | 贵合成先降级：OPL/MIDI 软合成实测单核实时因子 <1，**不是调参能救的**；正解是预渲染成 MP3/ADPCM 交给 `audio_player` |

当前各引擎的执行体/核/优先级全表见[系统整体设计手册](../../手册/系统整体设计手册.md) 第一部分 §9.1。
`audio_out` 固定 **CPU1 prio 8**，不要改。

## 3 接口

| 接口 | 作用 | 备注 |
|---|---|---|
| `audio_player_feed_pcm(buf, len, rate)` | 引擎喂 PCM | 环形缓冲，生产端不足会导致 underrun |
| `audio_player_play(path)` | 播放音频文件 | 返回 int；`app.rec.mplay` 就是它 |
| `audio_player_stop()` / `is_running()` | 停止 / 查询 | `app.rec.mstop` / `mplaying` |
| `audio_player_set_volume(pct)` / `is_muted()` | 音量 / 静音 | 与系统音量**同源**，别两处各调 |
| `tone_player` 系列 | 提示音 | `app.tone` 阻塞、`app.tone_async` 非阻塞 |

## 4 硬件依赖

- I2S：小智 `40/39/45/48/21`，微雪 `16/9/45/8/10`，标准 `-/9/45/8/-`（无 MCLK、无录音）。
- codec：小智/微雪 ES8311（I2C `38/47` / `13/14`）；标准版 NS4168 纯功放（无 I2C）。
- 功放使能 **GPIO46 低有效**：46 是 strapping，⛔ 禁内部上拉；③ 有 100k 上拉，上电默认导通，固件要尽早拉低。

## 5 异常处理与红线

| 情况 | 表现 | 处理 |
|---|---|---|
| 生产端供不上 | `underruns` 持续涨、`play` 远低于 `want` | 先查是不是合成太重（R4）|
| 马达/音频同时响 | 功放峰值电流与屏刷新叠加 | 考虑给屏单独 LDO（见硬件手册）|
| **"没声音"** | 合成正常、音量正常、播放器探针满幅，但一帧都没有 | 查**调用链末端**的桩函数是否动了 buffer |

> ⛔ **桩函数红线（2026-10-25 血案）**：SDLPal 的 `AVI_FillAudioBuffer` 在 `AUDIO_FillBuffer()`
> 调用链的**末端**，曾被写成 `memset(stream,0,len)`，把音乐和音效整块清零。
> 规则：空实现的桩只允许 `(void)参数;`，**禁止 memset / 写缓冲区**。
> 排查顺序：播放器探针 → 完整回调探针 → 两者不一致就查链路里谁动了 buffer。

## 6 怎么验证（不要靠耳朵）

```bash
remcon audio     # 看 PCM ring: underruns=N  play=xxxxHz  want=xxxxHz
remcon tasks     # 看任务名/优先级/核
```

- `underruns` 持续增长 + `play` 远低于 `want` ⇒ 生产端供不上。
- 死机后看串口：`task_wdt` 会打印 `CPU x: <taskname>`，直接指认饿死 IDLE 的任务。

## 7 已知问题

- 蓝牙耳机通路未验证（`app.bt()` 注释提到"手柄/耳机"，实际只验过手柄）。
- 标准扩展版无麦克风（`i2s_din = -1`），录音类应用在该板上不可用。
