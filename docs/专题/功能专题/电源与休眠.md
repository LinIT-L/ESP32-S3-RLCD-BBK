# 功能专题 · 电源与休眠

> **这个功能回答"电怎么省、睡怎么睡、醒怎么醒"。**
> 源码入口：`components/system/power_mgr/`（深睡与关机的**唯一实现**）、
> `components/ui/wallpapers/`（屏保与空闲）、`main/main.c`（唤醒门控与主循环关机判定）。
> 引脚与电气特性见[硬件与接口手册](../../手册/硬件与接口手册.md)。

## 1 机制

### 1.1 三个耗电状态

| 状态 | 谁在跑 | 怎么进 | 怎么出 |
|---|---|---|---|
| **运行** | 主循环 + 各页 | 上电 / 唤醒 | 空闲超时 → 屏保；长按 PWR → 关机 |
| **屏保** | 主循环只轮询物理键 + 独立壁纸任务 | 空闲到 `wp_run` 时间 | 任意键 / 触摸（若未被 block）|
| **深睡** | 只剩 RTC 与 EXT1 唤醒源 | PWR 长按 2s → 确认 → `power_mgr_off()` | PWR 按住 ≥0.5s |

- 屏保态主循环 `continue`，**不跑 `os_tick`、不渲染、不碰 I2C/flash**（`main.c` 屏保分支）。
- 深睡是全系统唯一"断电级"操作，实现在 `power_mgr`，别处不许自己调 `esp_deep_sleep_start`。

### 1.2 唤醒门控（第一道防线）

`power_mgr_wake_gate()` 是 `app_main()` 的**第一条语句**：

- 手动关机唤醒：要求 PWR 键**保持按住 ≥0.5s**，不足判误触，**直接回深睡不返回**。
- 自动关机（休眠到点）/ 冷启动：直接放行。
- 理由：放进裤兜误触一下不该点亮整机。

唤醒来源由 `power_mgr_wake_origin()` / `power_mgr_woke_from_off()` 提供，**只用于日志与诊断**，
不再影响开机观感（2026-10-27 起两种唤醒都画 Logo）。

### 1.3 电源统计

`power_stat_init()` 在门控之后、其他初始化之前结算上次深睡时长，
避免把初始化耗时算进睡眠段。数据供「设置 → 休眠与电源 → 电池信息」使用。

### 1.4 外设能关到什么程度

| 部件 | 能不能软件关 | 手段 |
|---|---|---|
| ESP32-S3 + PSRAM | 只能深睡 | `power_mgr_off()` |
| 功放（PA） | 能 | GPIO46 拉低 + hold |
| 屏 ST7305 | 能 | 送 SLPIN（记忆屏断电保画面）|
| 触摸 IC | 能（需 RST 或寄存器）| `touch_panel` |
| SD 卡 | 能 | 卸载 + 停时钟（**必须先 `gpio_hold_dis`**，否则下次认不到卡）|
| WiFi / BT 射频 | 能 | `os_hw_release()` / `wifi_manager_disable()` |
| GPS | 能（待机 ≈46 µA）| `UBX-RXM-PMREQ` |
| 模组内部 DC-DC | **关不掉**（除非拉 EN）| 硬件限制 |

### 1.5 屏保壁纸的刷新与调频（2026-10-31）

壁纸不是"每帧都画"，省电靠两层：

| 层 | 手段 | 谁决定 |
|---|---|---|
| 送不送屏 | `wp_render_fn` 返回 `1`=有新内容要 flush，`0`=没有变化 | 壁纸模块自己 |
| 多久问一次 | `wp_module_t.idle_ms`：`0`=动态（有内容 62ms / 无内容 1000ms），`>0`=静态按该值轮询 | 注册表 |

**静态壁纸恒 80MHz**，不因"偶尔画一帧"升到 240MHz。

改之前：`want = drew ? 1 : 0` —— 人生指南每 60 秒换条那一帧 `drew=1`，立刻
`esp_pm_configure(240MHz)`，62ms 后下一帧 `drew=0` 又切回 80MHz，即**每分钟整机调频两次**。
画 20 行 16px 汉字在 80MHz 下只要几 ms，为这一帧升频完全不划算，而 DFS 重配置本身有代价。

现在按**壁纸类型**定档（`wallpapers.c` 屏保分支）：
- 静态（`idle_ms>0`，人生指南）→ 恒 `max=80/min=80 + light_sleep`，按 `idle_ms` 轮询
- 动态（星空，每帧 `return 1`）→ 保持原样（有内容 240MHz / 62ms，偶尔空帧回落）

**30 分钟屏保的送屏量对比**（每帧 15000 B）：

| 壁纸 | 刷新次数 | SPI 传输 |
|---|---|---|
| 人生指南（60s 一条）| 30 | ≈ 450 KB |
| 星空（62ms 一帧）| ≈ 29000 | ≈ 435 MB |

⚠ 数据必须**在内部 RAM 栈的上下文**预加载（`wp_lifeguide_preload()`）：屏保监督任务的栈在
PSRAM，那里碰 SPIFFS/NVS 会触发 spi_flash 禁缓存断言 → panic → 重启循环。
所以渲染函数只消费内存，从不 fopen。

**壁纸数据在设备上的实际位置**：`/store/apps/app/人生指南.lua`
（`am_store.c:352` 的 `dst = AM_STORE_DST/pcat/nm`，`nm` = **包文件名**，即显示名；
`am_pkg_prefer()` 返回 1 但被 `(void)` 丢弃，`pref = 0` ⇒ 一律装内置）。
判据与实际位置必须同源：`wp_lifeguide_installed()` 与 `wp_lifeguide_preload()` 都走同一个 `lg_probe()`。

**切换壁纸立即生效**：`s_ss_prog` 只在开机读一次 NVS，所以页面改完 `os_wp/prog` 后必须调
`wp_set_program()`（只改一个 int + 复位 `s_ss_pm_mode`，不碰 NVS），否则要重启才换。
**卸载联动**：`am_uninst_do()` 删完文件后判 `wp_lifeguide_installed()` 为假 ⇒
`wp_lifeguide_release()` + `prog` 回星空 + `wp_set_program(STARS)`，不重启也立即生效。

## 2 接口

| 接口 | 作用 | 谁调 |
|---|---|---|
| `power_mgr_wake_gate()` | 唤醒合法性门控（可能不返回）| `app_main` 第一句 |
| `power_mgr_off(origin)` | 关机 / 进深睡（唯一实现）| 主循环关机流程 |
| `power_mgr_boot_diag()` | 复位/唤醒诊断打印 | `os_boot_shell` |

| `power_mgr_set_stage(mask)` / `get_stage()` | 标记当前阶段（诊断用）| 启动流程 |
| `os_hw_request/release` | 引用计数式征用射频 | 联网/蓝牙页面 |

## 3 配置与持久化

| 键 | 命名空间 | 含义 |
|---|---|---|
| `wp_run` | `os_wp` | 空闲多久进屏保（分钟）|
| `wp_shut` | `os_wp` | 空闲多久自动关机（分钟）。**唯一入口 = 设置 → 休眠与电源** |
| `min` | `os_wp` | 屏保最短间隔 |
| `rst` | `pst` | 深睡复位历史（RTC + NVS 双份，判"是否被反复唤醒"）|
| `hmeta` / `hd00`..`hd06` | `batcal` | 电池 **7 天**分钟级波形（按天分块，落盘 1 小时/次）。**画图用，不参与电量计算** |
| `div` | `batcal` | 分压比标定值（`batcal <真实mV>` 写入，见 §3.1）|
| ~~`daywin`~~ | `batcal` | **已废弃（2026-10-31）**：31 天日档随动态锚点一起删除。旧数据留在 NVS 里不再读写，不影响启动 |

## 3.1 电池电压与电量估算（2026-10-31 精简版）

**数据链 —— 五步，没有第六步**：

```
ADC raw ──IDF curve-fitting 校准──> 脚上 mV ──×分压比──> VBAT
        ──8 次采样去极值平均(两端各丢 2)──> 电压
        ──固定 17 点查表(4100=100% / 3300=0%)──> 电量%
```

| 项 | 值 | 位置 |
|---|---|---|
| ADC | ADC1_CH2（GPIO3），12 dB，12 bit，One-shot Driver | `board_battery.c` |
| 校准 | IDF `adc_cali` **curve-fitting**；失败退 line-fitting；再失败才 3.3V 线性并打 `未校准` | 同上 |
| 采样 | **丢首个转换** + 8 次采样**排序后两端各丢 2** 求平均（唯一滤波环节） | `bm_despeckle_avg()` |
| 分压比 | 默认 **3.100**，`batcal <真实mV>` 现场标定写 NVS（`batcal/div`） | `board_battery.c` |
| 电量 | 17 点**固定端点**非线性查表，段内线性插值，纯函数 | `bm_soc_from_mv()` |
| 节拍 | **60 秒一次**（全系统单一节拍器：状态栏/低电量/网页/终端/Lua 全走它） | `BOARD_BATTERY_CACHE_MS` |
| 充电 | 只读 CHRG（GPIO42，开漏低有效），连续 3 次一致才翻转，**上电首读即采信** | `bm_chrg_update()` |

**电量曲线（关键点）**：4.10V=100%、3.90V=65%、3.82V=50%、3.70V=28%、3.30V=0%。
不是 `(mv-3300)/800` 的线性——线性会把 3.7V 显示成 50%，实际只剩约 30%。

### 3.1.1 这一版删掉了什么、为什么

| 删掉的 | 原因 |
|---|---|
| 动态满电锚点（最近 30 天电压峰值） | 锚点被**充电/带载**时的高读数顶高（实测 4116mV），而静置满电 4.10~4.15V ⇒ 平时读数系统性偏低，且随"这个月充没充过电"漂移。改成固定 4100，口径唯一可复现 |
| 5 点峰值窗口（取最高值当 OCV） | 把带载压降当噪声消掉 ⇒ 电量系统性偏高，最长滞后 4 分钟。删掉后显示的就是实测电压对应的电量 |
| SOC 稳定器（迟滞/限速/低电直落） | 调参黑盒，用户看到的是"被限速后的数字"。现在电量 = 查表(本次电压)，不修饰 |
| 9 点跨轮滑动滤波 | 与单轮 8 次平均叠加 = 多层滤波；且带来"休眠后沿用睡前值"的问题（要额外写重置逻辑） |
| 电压趋势推断充电 | 关游戏时端电压弹回 100~200mV 会被判成"正在充电"。本机有真实 CHRG 脚，不需要猜 |
| 31 天日档（`batcal/daywin`） | 唯一用途是动态锚点，锚点删了它就没人用 |

**保留的**：7 天分钟级电压波形（设置→休眠与电源→电池信息 的曲线图，10KB PSRAM + 按天 NVS），
它是**画图用的历史**，不参与电量计算。

### 3.1.2 已知边界（必须在真机上确认的）

1. **分压比 3.100 未用万用表复核**。2026-10-14 两点标定（3.113/3.089）之后没重量过。
   `bat` 打印"脚上 mV × 系数 = VBAT"，拿万用表同刻对照即可判定；要用 `batcal <真实mV>` 重标。
2. **CHRG 极性未真机逐项验证**：手册说低=充电中。若实测相反，改 `board_battery.c` 取反一处。
3. 曲线是**通用估算**，不是本电芯实测放电曲线：低温/重载/老化都会让同一电压对应不同真实容量。
   对用户一律称"电量估算"。

### 3.1.3 诊断

`bat`（别名 `batdiag`）一行看全 —— 注意这两个命令**必须同时在 remcon 的命令白名单**里，
否则永远 "unknown cmd"（踩过两次）：

```
BAT raw=1576[1571..1581]/4095 校准=ok(curve-fitting) 脚上=1338mV 分压=x3100/1000 VBAT=4147mV soc=100% CHRG=高(未充电) | 正常
```

`batlog on|off|dump|clear`：把每次真采样记成一条（`t_s,mv,soc,flags,chg`），
120 条 = 1.4KB 放 PSRAM，关闭时零开销、不额外采样、不写 Flash。

## 4 电流账（估算，**非实测承诺**）

电池 500 mAh，要过两周（336 h）⇒ 平均必须 ≤1.4 mA。

| 状态 | 电流（估）| 500 mAh 能撑 |
|---|---|---|
| 亮屏静止 | 70~90 mA | ~6 h |
| **亮屏屏保** | 35~50 mA | **10~14 h** ← 比深睡更致命 |
| 熄屏深睡（现状）| 5~7 mA | 3~4 天 |
| 熄屏深睡（codec 等掉电）| 1.5 mA | ~14 天 |
| EN 拉低全断 | 10 µA | 一年以上 |

> ⚠ 这些数字是 2026-10 前后的**估算与实测混合**，标"缺"的项后续可能已实现。
> 拿仪器实测为准，别把本表当验收结论。
> 两条路线（软件逐个掉电 / EN 断电 + 外挂 RTC）的取舍已在上文保留，旧过程记录不再存。

## 5 异常处理

| 情况 | 行为 |
|---|---|
| 唤醒时 PWR 没按够 | 直接回深睡，不返回 `app_main` |
| 深睡前 SD 引脚被 hold | 下次开机认不到卡，**只能断电恢复** → 开机必须 `gpio_hold_dis` |
| 屏保态长按关机 | 先退屏保（解除 LCD 独占 + 开刷屏门禁 + 恢复触屏）再弹确认框 |
| 关机确认框被别的路径关掉 | 主循环每帧对齐"标志 vs 实际弹窗深度"，以实际为准 |
| 自动关机与长按关机观感不一致 | 已统一：两种都画 Logo、都要按 PWR ≥0.5s |

## 6 已知问题

- **屏保亮一夜 = 没电**：40 mA 亮 10 小时就空。默认配置要注意 `wp_run`。
- `esp_pm_lock` 必须配对 release、最小持有、不在 ISR 里操作（架构约束）。
- 待机电流是否达标**没有自动化判据**，目前靠实测（见 §7）。

## 7 怎么验证

```bash
# 设备侧
remcon heap      # 看内存
remcon bat       # 电池电压/百分比
remcon wpss      # 屏保/关机剩余分钟
remcon rst       # 复位历史（判是否反复唤醒）

# 硬件侧
# USB 电流表串在电池与模组 VBAT 之间，熄屏静置 2 分钟后读数
```

判据：实测 ≤1.4 mA 才算"两周达标"；1.4~3 mA 只有 7~14 天；≥3 mA 说明模组内部关不干净。
