# 功能专题 · 电源与休眠

> **这个功能回答"电怎么省、睡怎么睡、醒怎么醒"。**
> 源码入口：`components/system/power_mgr/`（深睡与关机的**唯一实现**）、
> `components/ui/wallpapers/`（屏保与空闲）、`main/main.c`（唤醒门控与主循环关机判定）。
> 引脚与电气特性见[硬件与接口手册](../../手册/硬件与接口手册.md)。

## 1 机制

### 1.1 三个耗电状态

| 状态 | 谁在跑 | 怎么进 | 怎么出 |
|---|---|---|---|
| **运行** | 主循环 + 各页 | 上电 / 唤醒 | 空闲超时 → 屏保；长按 PWR → 关机 |
| **屏保** | 主循环只轮询物理键 + 独立壁纸任务 | 空闲到 `wp_run` 时间 | 任意键 / 触摸（若未被 block）|
| **深睡** | 只剩 RTC 与 EXT1 唤醒源 | PWR 长按 2s → 确认 → `power_mgr_off()` | PWR 按住 ≥0.5s |

- 屏保态主循环 `continue`，**不跑 `os_tick`、不渲染、不碰 I2C/flash**（`main.c` 屏保分支）。
- 深睡是全系统唯一"断电级"操作，实现在 `power_mgr`，别处不许自己调 `esp_deep_sleep_start`。

### 1.2 唤醒门控（第一道防线）

`power_mgr_wake_gate()` 是 `app_main()` 的**第一条语句**：

- 手动关机唤醒：要求 PWR 键**保持按住 ≥0.5s**，不足判误触，**直接回深睡不返回**。
- 自动关机（休眠到点）/ 冷启动：直接放行。
- 理由：放进裤兜误触一下不该点亮整机。

唤醒来源由 `power_mgr_wake_origin()` / `power_mgr_woke_from_off()` 提供，**只用于日志与诊断**，
不再影响开机观感（2026-10-27 起两种唤醒都画 Logo）。

### 1.3 电源统计

`power_stat_init()` 在门控之后、其他初始化之前结算上次深睡时长，
避免把初始化耗时算进睡眠段。数据供「设置 → 休眠与电源 → 电池信息」使用。

### 1.4 外设能关到什么程度

| 部件 | 能不能软件关 | 手段 |
|---|---|---|
| ESP32-S3 + PSRAM | 只能深睡 | `power_mgr_off()` |
| 功放（PA） | 能 | GPIO46 拉低 + hold |
| 屏 ST7305 | 能 | 送 SLPIN（记忆屏断电保画面）|
| 触摸 IC | 能（需 RST 或寄存器）| `touch_panel` |
| SD 卡 | 能 | 卸载 + 停时钟（**必须先 `gpio_hold_dis`**，否则下次认不到卡）|
| WiFi / BT 射频 | 能 | `os_hw_release()` / `wifi_manager_disable()` |
| GPS | 能（待机 ≈46 µA）| `UBX-RXM-PMREQ` |
| 模组内部 DC-DC | **关不掉**（除非拉 EN）| 硬件限制 |

## 2 接口

| 接口 | 作用 | 谁调 |
|---|---|---|
| `power_mgr_wake_gate()` | 唤醒合法性门控（可能不返回）| `app_main` 第一句 |
| `power_mgr_off(origin)` | 关机 / 进深睡（唯一实现）| 主循环关机流程 |
| `power_mgr_boot_diag()` | 复位/唤醒诊断打印 | `os_boot_shell` |
| `power_mgr_set_pre_sleep_hook(cb)` | 深睡前回调（各模块在此关自己）| 模块注册 |
| `power_mgr_set_stage(mask)` / `get_stage()` | 标记当前阶段（诊断用）| 启动流程 |
| `os_hw_request/release` | 引用计数式征用射频 | 联网/蓝牙页面 |

## 3 配置与持久化

| 键 | 命名空间 | 含义 |
|---|---|---|
| `wp_run` | `os_wp` | 空闲多久进屏保（分钟）|
| `wp_shut` | `os_wp` | 空闲多久自动关机（分钟）。**唯一入口 = 设置 → 休眠与电源** |
| `min` | `os_wp` | 屏保最短间隔 |
| `rst` | `pst` | 深睡复位历史（RTC + NVS 双份，判"是否被反复唤醒"）|
| `hmeta` / `daywin` | `batcal` | 电池 7 天分钟级波形 + 31 天日档（落盘 1 小时/次）|

## 4 电流账（估算，**非实测承诺**）

电池 500 mAh，要过两周（336 h）⇒ 平均必须 ≤1.4 mA。

| 状态 | 电流（估）| 500 mAh 能撑 |
|---|---|---|
| 亮屏静止 | 70~90 mA | ~6 h |
| **亮屏屏保** | 35~50 mA | **10~14 h** ← 比深睡更致命 |
| 熄屏深睡（现状）| 5~7 mA | 3~4 天 |
| 熄屏深睡（codec 等掉电）| 1.5 mA | ~14 天 |
| EN 拉低全断 | 10 µA | 一年以上 |

> ⚠ 这些数字是 2026-10 前后的**估算与实测混合**，标"缺"的项后续可能已实现。
> 拿仪器实测为准，别把本表当验收结论。
> 两条路线（软件逐个掉电 / EN 断电 + 外挂 RTC）的取舍已在上文保留，旧过程记录不再存。

## 5 异常处理

| 情况 | 行为 |
|---|---|
| 唤醒时 PWR 没按够 | 直接回深睡，不返回 `app_main` |
| 深睡前 SD 引脚被 hold | 下次开机认不到卡，**只能断电恢复** → 开机必须 `gpio_hold_dis` |
| 屏保态长按关机 | 先退屏保（解除 LCD 独占 + 开刷屏门禁 + 恢复触屏）再弹确认框 |
| 关机确认框被别的路径关掉 | 主循环每帧对齐"标志 vs 实际弹窗深度"，以实际为准 |
| 自动关机与长按关机观感不一致 | 已统一：两种都画 Logo、都要按 PWR ≥0.5s |

## 6 已知问题

- **屏保亮一夜 = 没电**：40 mA 亮 10 小时就空。默认配置要注意 `wp_run`。
- `esp_pm_lock` 必须配对 release、最小持有、不在 ISR 里操作（架构约束）。
- 待机电流是否达标**没有自动化判据**，目前靠实测（见 §7）。

## 7 怎么验证

```bash
# 设备侧
remcon heap      # 看内存
remcon bat       # 电池电压/百分比
remcon wpss      # 屏保/关机剩余分钟
remcon rst       # 复位历史（判是否反复唤醒）

# 硬件侧
# USB 电流表串在电池与模组 VBAT 之间，熄屏静置 2 分钟后读数
```

判据：实测 ≤1.4 mA 才算"两周达标"；1.4~3 mA 只有 7~14 天；≥3 mA 说明模组内部关不干净。
