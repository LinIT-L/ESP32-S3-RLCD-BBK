# 功能专题 · 网络连接

> **这个功能回答"怎么联网、射频什么时候开、为什么 TLS 会失败"。**
> 源码入口：`components/services/wifi_manager/`（连接管理）、`components/services/net_client/`（HTTP 客户端）、
> `components/services/espnow/`（点对点）、`components/system/os/include/os_hw.h`（射频引用计数）。
>
> ⚠ 本项目**按需启停射频**：开机不拉 WiFi/BT，谁要联网谁申请，用完必须归还。

## 1 机制

```
页面/应用 ──os_hw_request(HW_WIFI)──▶ 引用计数 +1 ──▶ wifi_manager_enable() ──▶ 射频上电
                                                          │
                                    netc_start(req) ──────┼──▶ HTTP(S) ──▶ 环形/落盘回调
                                                          │
页面退出 ──os_hw_release(HW_WIFI)──▶ 计数 -1，归零才真关
```

**三条设计约束**：

1. **引用计数**：多个页面同时要 WiFi 时计数叠加，最后一个释放才真关射频。
2. **别重复申请**：历史上收藏夹/密钥/手柄三页各 `os_hw_request` 一次却没配对 release，
   导致"用户取消连接后射频常开"（违背按需启停）。
3. **射频开 = 内部 RAM 变紧**，TLS 需要一整块连续内存（见 §4）。

## 2 接口

### 2.1 连接管理 `wifi_manager`

| 接口 | 作用 |
|---|---|
| `wifi_manager_enable()` / `disable()` | 开/关射频（**推荐走 `os_hw_request` 而非直接调**）|
| `wifi_manager_is_enabled/connected/connecting()` | 状态查询 |
| `wifi_manager_connect(ssid, pass)` | 连接指定 AP |
| `wifi_manager_get_ip(buf, sz)` | 取 IP |
| `wifi_manager_has_saved()` / `autostart()` | 是否存过配置、开机自连 |
| `wifi_manager_set_want_on(bool)` | 期望状态（持久化用）|
| `wifi_manager_consume_connected_event()` | 消费"刚连上"事件（一次性）|
| `wifi_manager_get_status()` | 人类可读状态串（UI 用）|

凭据存 NVS `wifi_cfg`（owner = wifi_manager，别在别处另存）。

### 2.2 HTTP 客户端 `net_client`

| 接口 | 作用 |
|---|---|
| `netc_start(&req)` | 发起请求（异步任务执行）|
| `netc_state()` / `netc_busy()` | 状态机 / 是否在跑 |
| `netc_http()` / `netc_err()` | HTTP 状态码 / `esp_err_t` |
| `netc_len()` / `netc_got()` | 总字节 / 实时已收（进度条用）|
| `netc_crc32()` | 边收边算的 CRC32（与 `binascii.crc32` 一致，需 `want_crc`）|
| `netc_reset()` | 复位状态 |

特点：8 KB 读缓冲；支持"写文件"与"内存"两种落点；**无断点续传**（失败从头重下）。

### 2.3 点对点 `espnow`

局域网内不用路由器的广播/单播（≤250 字节/包），用于双机联机、遥控、信标。
Lua 侧封装为 `app.espnow.*`（见 API 手册）。

## 3 超时与参数

| 场景 | 超时 | 来源 |
|---|---|---|
| 商店索引 | 10 s（外层 15 s）| 应用中心 |
| 商店下载 | 15 s，`.lua` 总 180 s / `asset` 600 s | 同上 |
| Lua `app.net.http_get` | 阻塞、只支持 http、≤4 KB | 桥实现限制 |

## 4 为什么 TLS 会失败（最常见的坑）

**症状**：联网取数一直失败，错误码 **28674**（`ESP_ERR_HTTP_CONNECT`），**200 µs 内**就返回。

**根因**：mbedtls 的 TLS 收发缓冲默认在上下文里**一次性 calloc**，要求一整块**连续内部 RAM**。
蓝牙 + WiFi 同开时内部堆最紧，最大连续块只剩 7.6 KB → 分配失败。

**已做的缓解**：`CONFIG_MBEDTLS_DYNAMIC_BUFFER=y`、`IN_CONTENT_LEN 16384→4096`、
`OUT 4096→2048`、`esp_http_client buffer_size 2048→1024`。

**验收门槛**：`remcon audit` 看内部堆，**`largest` 不得低于 8 KB**（低于就没法做 TLS）。

## 5 异常处理

| 情况 | 行为 |
|---|---|
| 没连网就取数 | `app.net.fetch_start` 直接返回 false（不是 bug）|
| 商店索引拉不到 | 有内置索引 → 静默降级离线；无 → 提示"无法获取应用列表" |
| 下载失败 | 逐个镜像重试，全失败删残文件 → "下载失败" |
| 空间不足 | **下载前不预检**，写失败会被归成"连接失败"（已知缺陷）|
| HTTPS 证书 | 走 `esp_crt_bundle`，不强制校验 scheme |

## 6 怎么验证

```bash
remcon wifi          # WiFi 状态与 IP
remcon audit         # 内部堆 free / largest（判 TLS 可行性）
remcon heap          # 开关射频前后对比，确认射频真的关了
```

- 判"射频是否真关"：页面退出后用 `remcon heap` 对比进入前的数字，同外设状态下应回到基线。
- 判"TLS 能否用"：蓝牙+WiFi 同开时 `largest ≥ 8KB`。

## 7 已知问题

- 下载**无空间预检**；写盘失败被归为连接失败（错误码 3 从未被赋值）。
- `app.net.http_get` 只支持 HTTP、≤4 KB，超出静默截断。
- 无断点续传，大包失败要从 0 重下。
- 蓝牙耳机等 BT 音频通路未验证。
