# 应用资料 · 频谱仪（espsdr）

> 适用：LinTOS 1.0。C 应用，注册 id `sdr`，分类「运维」，`hidden=true`（默认不进主菜单，管家里可添）。
> 源码：`components/apps/pages/page_sdr.c`（UI/FFT）+ `components/drivers/espsdr/`（驱动）。
> 本文只写**当前实现**，依据 2026-10-30 的源码；硬件行为未经真机验证的已标注。

## 1 用途

用 ESP32-S3 未公开的射频调试出口抓**原始 I/Q**，在设备上做 FFT，得到 2.4G 频段的波形 / 信道 / 蓝牙广播 / 音频四类视图。不需要外加任何硬件。

## 2 源码与分层

| 文件 | 层 | 职责 |
|---|---|---|
| `drivers/espsdr/espsdr.c` `.h` | L1 驱动 | 64KB 采集区、PHY 准备、调谐、增益、突发采集寄存器序列 |
| `drivers/espsdr/sram_guard.ld` | — | 链接期断言：静态段不得侵入 `0x3fcd0000` |
| `apps/pages/page_sdr.c` | L4 应用 | UI、FFT、四页渲染、射频征用与归还 |
| `system/os/include/os_app_api.h` | 门面 | 导出 `espsdr.h`（与 `st7305` / `sd_scan` 同惯例） |

## 3 四页结构

`SDR_NPAGE = 4`，左右键轮播，底栏软键为「设置 / 继续·冻结」：

| 页 | 标题 | 内容 |
|---|---|---|
| 1 | 2.4G 波形 | 每列从底填到该列 dB，上半屏频谱 + 下半屏瀑布 |
| 2 | WiFi 信道 | 按信道聚合成柱状 |
| 3 | 蓝牙广播 | BLE 广播信道分布 |
| 4 | 音频 | 麦克风对数频率轴 + 电平条 + 瀑布（进第 4 页才开 codec）|

信号链（第 1 页）：

```
espsdr_capture(2048, 80MSa/s)   ← 分辨率 ≈ 39 kHz
  → 取 I/Q（bit19–10=I，bit9–0=Q，有符号 10bit，/512）
  → 去 DC（减均值）+ Hann 窗
  → dsps_fft2r_fc32 + dsps_bit_rev_fc32   （esp-dsp，走 S3 向量指令）
  → dB = 10log10(|X|²)，fftshift：bin k ↔ f = (k−N/2)·80M/N
  → 2048 bin → 368 列（每列取区间**最大值**，窄带信号不会被抽掉）
  → 中心 ±1 列做 DC 修补 → 指数平均
```

缓冲全部在 **PSRAM**（`s_fft` / `s_bin` / `s_win` / `s_wf` / `s_col` / `s_avg` / `s_hold`），不占内部 RAM。

## 4 64KB 采集区：默认不占

硬件把这块 aperture 钉在 `0x3fcd0000`（整窗 64 KB），modem 只写前 n 个字。

| 项 | 行为 |
|---|---|
| 默认 | **关闭**。开机 `espsdr_reclaim_boot()` 把 64 KB **加回内部堆** |
| 启用 | NVS 标记 `espsdr_set_enabled(true)`，**重启后才改变归属** |
| 关闭 | 下次开机重新回收，`+64KB @0x3fcd0000` 回堆 |
| 不可用情形 | 本机无触摸 → 全触屏操作无法用，只提示不可用（图标仍显示）|

> 所以「装了这个应用但不用」不付 64 KB 代价。这是本应用对内存预算最重要的设计。

## 5 射频征用：顺序有讲究（三条实测教训）

进页时按此顺序，**顺序本身就是修 bug 的结果**：

1. **先让蓝牙让出射频**。蓝牙和它抢同一根天线 —— 实测（2026-10-01）手柄连着时直接抢，约 2.4 s 后 `TG1WDT` 复位。`bt_manager_disable()` 会拆栈，顺带还回约 97 KB 内部 RAM。
2. **再确保 WiFi 处于 init+start**（PHY 靠它拉起来）。**不能先 `wifi_manager_disable()`** —— 它会 `esp_wifi_deinit()`，而采集区已从堆里挖走一块，重新 init 极易 `NO_MEM`。
3. **不要用 `os_hw_request(OS_HW_WIFI)`** —— 管家那条路的 stop 就是 `wifi_manager_disable()`，而用户自己开的 WiFi 没走过管家（ref 从 0 起），退出时会把用户的 WiFi 关掉。这里自己做「开了才关」的存档/还原。

退出顺序反过来：先松麦克风/codec → `espsdr_exit()`（此时 WiFi 必须还活着，射频要交回 STA）→ 还原 WiFi → 还原蓝牙 → 释放缓冲。

## 6 采集寄存器序列（**顺序不能改**）

逐行对应官方 `esp-sdr` 的 `receiver.c`：

1. 缓冲填哨兵 `0xa5a0055a`（判断 DMA 是否真写满）
2. `REG_WRITE(0x60033d90, …)` 配 pack / agc 字段
3. 把 `0x600c101c` 的 `MAC_DUMP_USAGE` 置 4 → **这块 SRAM 交给 modem**
4. `REG_WRITE(0x60033d5c, ctrl)` 写控制字
5. 再写一次 `ctrl | (1<<19)` ← 触发
6. 轮询 bit18 = 完成（超时 20 ms）
7. 关控制字，**把 SRAM 还给 CPU**（异常路径也必须还，否则下次抓不到）

配套坑：

- `SOC_RESERVE_MEMORY_REGION` 的宏在 IDF 的 **`heap_memory_layout.h`** 里，官方那行 include 很容易漏，漏了报 `expected declaration specifiers before numeric constant`。
- 增益函数：官方用 `librftest.a` 的 `force_rx_gain()`，但 IDF **默认不挂 `librftest.a` 进链接** → 链不过。用 `libphy.a` 里等价的 **`phy_force_rx_gain(manual, code)`**。
- **采集窗口内不写 flash**（NVS/日志落盘会禁 cache）→ 本页热路径刻意不打日志。

## 7 采样率与分辨率

| `espsdr_rate_msps(divider)` | divider | 速率 |
|---|---|---|
| 0 | 80 MSa/s | 分辨率 ≈ 39 kHz（`80M / 2048`）|
| 1 | 40 MSa/s | — |
| 6 | 16 MSa/s | — |

UI 当前固定用 `ESPSDR_DIV_80M`。

## 8 已知限制

- **量化 10 bit** → 动态范围有限，强邻道 + 弱信号会吃力
- 模拟带宽约 13–54 MHz，两端有滚降 → 显示跨度默认避开边缘
- **零中频固有毛病**：正中一根 DC 尖刺 + 镜像 → 去均值 + 中心 ±1 列修补；增益跳变会毁幅度，想稳定就切**手动固定增益**
- **单芯片单天线 → 做不了测向**（那要 ESPARGOS 那种多天线相位相干）
- **与 WiFi/BT 互斥**（射频独占），期间不能联网、不能用手柄
- 幅度是**相对的**，没做绝对 dBm 校准，「比较大小 / 找干扰」够用
- 寄存器属**未文档化**功能，Espressif 未承诺 → 换 IDF 或芯片版本必须重验

## 9 验证状态

| 项 | 状态 |
|---|---|
| 编译 / 链接 | ✅（`check_deps.py` 0 隐藏依赖）|
| 静态序列与官方实现逐行对照 | ✅ |
| **真机功能验证** | **❌ 未记录**（原始记录只列了"上机必验清单"，无验收结论）|
| 音频页（第 4 页，麦克风） | **❌ 未验证** |

上机必验：

1. 启动日志有 `ESPSDR: PHY 就绪` → PHY 接管成功
2. 状态行显示频率/增益 → 渲染链通
3. 不出现"采集超时" → 寄存器序列与实际芯片相符
4. 能看到 2.4G 的 WiFi/BLE 能量包 → 采集 + FFT 正确
5. 退出后 WiFi 恢复、手柄能重连 → 归还链正确
6. 手机热点或遥控器靠近，瀑布出现竖线 → 全链路可用

**若第 3 项失败**，最快的二分：把哨兵检查结果（`IQ_BUFFER[0]`）打出来，区分「没触发」（寄存器不对）与「触发但没写」（SRAM owner 没交出去）。
