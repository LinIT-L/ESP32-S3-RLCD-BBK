# 英雄坛说（Lua 单机武侠）

> 一句话：把 gmud.online《英雄坛说》的**原版地图/人物/数据**搬进掌机，做成**本地优先**的单机游戏，
> 另外留了一个只做自检的"在线(实验)"入口（未接未验证接口）。
> 应用入口：应用管家 → 应用 → 英雄坛说（商店包同名）。
> 源码：`apps/lua/apps/app/wuxia.lua`　素材：`apps/lua/wuxia/`（70 个文件，1.69 MB）

## 1. 一个包，一次安装，自动解压

| 包 | 内容 | 解压到 |
|---|---|---|
| `wuxia.zip`（商店**唯一**一条，`type=asset`） | `英雄坛说.lua`（LAPP，~93 KB）+ `wuxia/` 下 70 个素材文件（63 张场景 + 4 张图集 + `data/world/map.lua`） | `/sdcard/apps/app/` |

2026-10-31 定案（linit：**"固定成一个安装，自动解压"**）：
商店里只保留**一条**「英雄坛说」，点一次 = 下载 zip → `am_asset_install()` 解压 →
`/sdcard/apps/app/英雄坛说.lua`（应用管家立刻可见）+ `/sdcard/apps/app/wuxia/`（游戏素材）。
**不需要第二次点击，也不需要用户手动解压。**

- 索引条目：`type=asset`、`target=/sdcard/apps/app`、`path=pkgs/wuxia.zip`。
- 为什么敢解到共享目录：`am_asset` 会写 `.pkg.wuxia.lst` 清单，**卸载只删清单里的文件**，
  目录非空不删目录（`am_asset.c:249`）⇒ 同目录下别的应用不受影响。
- 卸载：删 `英雄坛说.lua` + `wuxia/*`，**不碰存档**（存档在 NVS 的 `wxs1..3`）。
- 升级：asset 条目没有"更新"角标（那是本地 .lua 包才有的判定）⇒ 先卸载再安装，
  或者等固件补上 asset 的版本标记。⚠ 这是当前方案的已知取舍。
- 失败提示：商店用确认框显示失败原因（HTTP/连接/写盘/校验），左"重试"右"取消"。

> 历史：更早是"主程序 .lua + 资源包 zip"**两条**，靠索引里的 `"requires"` 让装完主程序
> 再自动拉资源包（`am_store.c` 的 `am_req_ensure`）。现在单包后就地解压，不再需要它；
> `requires` 机制保留在固件里给别的"主程序 + 素材包"组合用。

应用启动时按**优先级**找素材（`ROOTS`），第 1 条与解压目录**完全一致**：

1. `/sdcard/apps/app/wuxia/` ← 商店单包解压位（常规）
2. `/sdcard/wuxia/` ← 手工拷卡
3. `/store/wuxia/` ← 整片烧写时 SPIFFS 里带的开发位

三个都没有 → 进入**「缺少素材包」整屏提示**（写清缺什么、该放哪儿），不会再白屏。

## 2. 操作键

| 场景 | 键位 |
|---|---|
| 走路 | 方向键（单击走一格；按住连走） |
| 交互 / 开门 | 确认 |
| 呼出顶部菜单 | 返回（菜单里再按返回 = 退出程序，走系统确认框） |
| 对话 | 左右=选项　上下=翻页　确认=执行　返回=关闭 |
| 集市 | 左右=买入/卖出　上下=选择　确认=成交 |
| 创建角色 | 第一步左右切性别；第二步键盘输名字（返回=输入完毕）；第三步确认加点/左键减点/**右键开始** |

## 3. 存档

- 三槽：NVS 键 `wxs1`/`wxs2`/`wxs3`，**不同角色互不覆盖**。
- 格式 `WX2|<fnv1a>|<body>`：带格式版本 + 校验和；校验不过**不加载**（不会把半截数据读进游戏）。
- 写入后立刻回读比对，不一致当次就报"存档校验失败"。
- 自动存档：脏标记后每 3 秒一次；`on_exit` 与菜单"退出"各强制存一次。
- 旧版单槽 `wxsave`（逗号分隔）首次进游戏自动迁移到 1 号槽，原键保留不删。

## 4. 已实现 / 未实现

**已实现**（数据全部来自原站 json，不编造）

- 标题页（本地 / 在线实验双入口）/ 读档页 / 创建角色（性别、姓名、5 点属性分配）
- 63 张原版场景、原版碰撞表、152 扇门、原版人物图集与玩家四向三帧
- NPC 对话（原站 `msg` 原文，长文本 3 行/页分页）、拜师（师承记真实 NPC 名）、请教、切磋
- 回合战斗（普攻/武功/服丹/逃跑）、经验升级、修为点、武功升级
- 行囊（20 格）、装备武器/防具、丹药、书籍研读
- 集市买卖（171 种有标价物品，卖出半价）
- 三槽存档 + 版本 + 校验 + 迁移
- **在线(实验)页**：固件能力自检 + 服务器可达性 + 公开统计（`GET /api/stats`，只读）

**未实现（且不打算用空壳顶替）**

| 项 | 原因 |
|---|---|
| 官方登录 / 角色列表 / 云端存档 | 协议已摸清（见 §7），但**固件没有 WebSocket 客户端**，现在做不了；不摆假登录框 |
| 门派名表 | 原站 `npc.json` 只有 `pai` 数字编号，**没有门派名**；本版只记"师承=某 NPC"，界面显示 `门派#编号` |
| 任务系统 / 每日看板 | 原站任务在服务端下发，公开数据里没有任务定义 |
| 赌博 / 物品强化 / 仓库 / 红莲密室 / 铸剑谷 | 同上：`data.lua` 里只有这些功能点的**图标与名字**（`D.MAP` 交互点），逻辑在服务端 |
| 开场剧情 | 公开数据里没有剧本文本，不编造 |

**属于单机化折算（不是原版规则，写在这里以防被当成原版）**

- 属性分配 5 点、气血 = 30+力量×2、内力 = 10+悟性×2
  （⚠ 原版 `create_char` 是 **str/dex/int/con 四项**；本地版用 力量/身法/悟性 三项 + 气血公式，
   缺 体质(con)。要完全对齐需要改存档格式，**尚未做**）
- 武器/防具攻防 = 价格/15（原站没有独立攻防字段）
- 切磋对手气血按玩家等级缩放（原站高手 400+ 血，新手必死）
- 书籍按书名/描述关键词匹配同"类型"的功夫（原站是服务端技能组名，无公开映射）

## 5. 素材重建

```bash
python3 tools/wuxia_pack.py  --src <原站素材目录> --data <maps.json 目录> --out apps/lua/wuxia
python3 tools/wuxia_world_gen.py            # world.lua（碰撞/门/NPC 布点）
python3 tools/wuxia_gen_data.py             # data.lua（物品/功夫/NPC）
python3 tools/pack_app.py pack apps/lua/apps/app/wuxia.lua \
        --name 英雄坛说 --cat 游戏 --desc "..." --version 3 --icon-from-main ICON_MINI_GAMES
# 打成"应用+素材"单包，并更新索引里唯一那条 asset 条目
python3 tools/wuxia_bundle.py            # 或 --check 只校验
python3 tools/gen_store_index_builtin.py # 改过 store/index.json 后必跑，再编固件
```

- 单包里 `英雄坛说.lua` 取的是 **`apps/lua/apps/app/wuxia.lua`（已打 LAPP 头的那份）**，
  所以"内置版 = 商店版"这条约束现在等同于"zip 里那份 == 源码目录那份"，
  `tools/wuxia_bundle.py` 打包时逐字节复制，`--check` 会回验。
- `tools/store_build.py` 的 `EXCLUDE = {"wuxia"}` 会让它**跳过**这个应用，
  避免重新生成"主程序一条 + 资源包一条"的老结构。

## 6. 已知限制

- **内存**：PSRAM 常驻 = 图集 128 KB + 玩家图集 9 KB + 当前地图 8…200 KB（只留一张）；
  `data.lua` 折叠进 `DATA.*` 后原表即丢弃，不再常驻。
- 场景比屏小（如 288×288）时居中显示，四周留白，不放大（保持原版 32px 瓦片比例）。
- NPC 位置是按"有图形 + 不割裂通路"确定性生成的，**不是原站坐标**（原站由服务端下发）。
- 门派/任务/赌博等以服务端逻辑为准的功能，设备上不可能"断网也有"。

## 7. 在线模式（实验）与官方接口调查

> 结论先给：**能查到协议，但当前固件跑不了** —— 官方全部交互走一条 WebSocket，
> 而固件没有 WS 客户端。所以本轮只交付"能力自检 + 公开只读统计"，
> 登录/角色/存档等一律不接，也不摆假界面。

### 7.1 调查方式（只读、有限）

- 抓取官网首页（324 KB，逻辑全内联在一个 HTML 里）→ 读**客户端脚本**得出协议；
- 只对公开接口发过一次 `GET /api/stats`；**没有**尝试登录、爆破、绕过验证码或访问管理接口。

### 7.2 已确证（来自公开页面与客户端代码）

| 问题 | 结论 |
|---|---|
| 第三方 API / 公开文档 | **没有**。只有 `GET /api/stats`（注册数/在线数，公开只读） |
| 登录方式 | WebSocket `wss://www.gmud.online/`（同域、无路径），首包 `{"type":"login",username,password}` |
| 登录返回 | `{"type":"login_ok","player":{...}}` —— **角色整包下发，没有 Token** |
| Cookie / Session | 没有 Cookie（脚本里 cookie 出现 0 次）；会话绑在 WS 连接上 |
| 游戏逻辑 | **服务端权威**：移动/战斗/交易/任务全部是 WS 消息往返，客户端只画 |
| WebSocket | 是，唯一的业务通道；约 90 种消息类型（`login/register/create_char/move/npc_*/fight_*/warehouse_*/auction_*/pvp_*`…） |
| 存档上传/下载 | **协议里不存在**。进度就是服务端那份角色，客户端拿到的是快照 ⇒ "云端存档备份/上传"无法按原样实现 |
| 第三方客户端许可 | **未知**（未见公开条款）。因此不作为正式接入依据 |

### 7.3 固件能力对照（这就是"还不能登录"的真实原因）

| 能力 | 现状 |
|---|---|
| HTTPS + 证书校验 | ✅ `net_client` 带 `esp_crt_bundle_attach`；`app.net.http_url` 走完整 URL |
| WebSocket 客户端 | ❌ 全仓无 `ws_client`/`esp_websocket` |
| 长连接/心跳/自动重连 | ❌ 无（`ping` 消息、`lastPongAt` 那套要自己实现） |

### 7.4 分阶段计划（每阶段独立验收）

1. **已完成**：协议调查 + 双模式入口 + 能力自检 + `/api/stats` 只读探活。
2. 待做：固件加 WS 客户端（含 TLS、心跳、重连、超时）→ 再做 `login` 只读验证。
3. 之后：`player_view`/`player_items` 只读拉取。
4. 之后：写操作（移动/战斗）—— 必须先在单机侧做"在线态不影响本地档"的隔离。
5. 云端备份：协议不支持，只能"本地导出到 TF 卡"，**不冒充云同步**。

### 7.5 安全约定（已落地的）

- 只走 https（`http_url` 拒绝其它 scheme，也不提供跳过校验的开关）。
- 不收集、不落盘任何密码；`has_call`+`pcall` 探测能力，失败只显示原因，不崩主循环。
- 网络请求只在"在线(实验)"页、由用户按键触发，**本地模式任何路径都不发请求**。
- 不使用未验证的接口；`/api/stats` 是唯一已确证的端点。
