# 白板模块说明（Whiteboard / `page_wb.c`）

> 适用：LinTOS 1.0，ESP32-S3 + 400×300 单色反射屏（ST7305），ESP-IDF 6.0.3。
> 本文只描述**代码现在是什么样**，不写计划。计划和已知缺陷登记在文末 §8。
> 最后更新：2026-10-30（A1–A10 / B1 / B2 / B4 / B7 修复后）

---

## 1. 它是什么

白板是**内置 C 页面模块**，不是 Lua 应用。

| 项 | 值 |
|---|---|
| 实现文件 | `components/apps/pages/page_wb.c`（单文件，全部 private state 在本文件） |
| 注册 | `apps_registry.c` 应用表 `id="wb"`，页面 `OS_PAGE_WHITEBOARD`；`os_page_wb_register()`（`page_wb.c` 末尾） |
| 默认可见性 | `.hidden=true`（不进桌面，需在应用管家长按加入主菜单）+ `.touch_only=true`（无触摸机型不显示） |
| 页面契约 | `os_module_t`：`on_enter / on_exit / render / action / touch / poll` |
| 全屏 | `.fullscreen=true`（隐藏状态栏） |
| 返回键 | `.exit_confirm=true` → 内核弹"退出程序?"，确认后才退出 |
| 底部上滑 | `.swipe_back_disabled=true`（屏蔽，防误退） |
| 底部拖动屏蔽带 | `.no_bottom_shield=true`（本页放行，否则画布下沿会断笔） |

## 2. 屏幕布局

```
┌──────────────────────────────────────────────┐ y=0
│ 撤销 │ 重做 │ 清空 │ 保存 │ 加载   顶栏 400×32 │
├──────┬───────────────────────────────────────┤ y=32
│ 铅笔 │                                       │
│ 马克 │                                       │
│ 橡皮 │        画布 336×268                   │
│ 直线 │        (x 64..399, y 32..299)         │
│ 矩形 │                                       │
│ 椭圆 │                                       │
│ ●粗细│                                       │
└──────┴───────────────────────────────────────┘ y=300
 x=0   x=64
```

- 顶栏 5 个操作各占 80px；左列 6 个工具 + 第 7 格"粗细预览"各占 38px 高。
- 工具栏共占 29,952px²（25.0% 屏），可用画布 90,048px²（75%）。
- 图标是 13 个 20×20 的 1bpp 位图（`s_icon[13][60]`），存 flash rodata，780B。

## 3. 绘图通路

### 3.1 三种笔 + 三种形状

| 工具 | 枚举 | 半径 | 说明 |
|---|---|---|---|
| 铅笔 | `WB_PEN` | `size` (1..6) | 实心圆盘笔，1px 到 13px |
| 马克 | `WB_MARK` | `size*2` | 半径翻倍 |
| 橡皮 | `WB_ERAS` | `size+4` | **像素级擦除**（清画布 bit），不是整笔删除 |
| 直线 | `WB_LINE` | 固定 1px | 松手才落笔 |
| 矩形 | `WB_RECT` | 固定 1px | 仅描边，无填充 |
| 椭圆 | `WB_OVAL` | 固定 1px | 中点椭圆，仅描边 |

半径只有一份实现：`wb_radius(tool, size)`。**实时绘制与撤销重放都必须调它**（A5 修复前重放用的是另一套，橡皮痕迹撤销后会变窄）。

### 3.2 一笔是怎么画出来的

白板**不用触摸事件回调**（`p_wb_touch()` 恒 `true`，只用于内核判定是否震动）。真正的绘图是每帧轮询：

```
内核 os_tick → p_wb_poll()
   ├─ input_get_touch_pos(&tx,&ty)   ← 每帧拿"当前实时坐标"
   ├─ 落笔边沿: 记 s_ax/s_ay、起 s_pend 命令、画首个圆盘
   ├─ 拖动: 从上一点到本点做 Bresenham + 圆盘笔刷 (wb_line)
   └─ 抬笔边沿: 提交命令
```

- 采样率 = 帧率。脏帧预算 8ms（`main.c`），实际受"绘制 + 15KB 送屏"限制。
- 相邻采样点之间**一定连线**，所以几何上不留空隙；断笔只来自外部因素（见 §8）。
- 笔迹点按 `uint16 x, uint16 y` 存（2026-10-30 前是 `uint8`，x>255 / y>255 会被截断）。

### 3.3 形状的拖动预览

拖动期间 `s_pv=true`：`wb_ppx()` 只写屏幕不写画布，所以预览是"橡皮筋"，抬笔才真正落进画布并记命令。
预览与落笔共用 `wb_draw_shape()`，不会出现"预览和结果不一样"。

## 4. 撤销 / 重做

### 4.1 数据结构

```
wb_arena_t (一次 calloc 在 PSRAM, 38,960B)
├── canvas[15000]   当前画面 (1bpp, 1=黑)
├── snap[15000]     基线快照
├── pts[4096]       笔迹点池: 2048 点 × (x,y) 各 uint16
├── ulog[24]        undo 命令日志 (每条 16B)
└── rlog[24]        redo 命令日志
```

命令只有三种：

| 类型 | 内容 |
|---|---|
| `WB_CMD_FREE` | 工具 + 笔粗 + 点池起点 + 点数 + 首末点 |
| `WB_CMD_SHAPE` | 工具 + 起终点 |
| `WB_CMD_CLEAR` | 无参数（重放 = memset 画布） |

### 4.2 三个不变量（改动这块前必须守住）

1. **画布 == snap + 重放(前 N 条命令)**。任何改动画布的地方都要同步日志，反之亦然。
2. **点池只能和日志一起清空**。压缩（`wb_compress()`）会同时清 ulog/rlog/pts；如果单独清 pts，旧命令的 `pts_idx` 立刻指向错位置。
3. **容量检查只在操作开始前做**（`wb_reserve_log()`），提交时（`wb_commit()`）不再压缩 —— 压缩会清空点池，让正在攒点的 `s_pend.pts_idx` 失效。

### 4.3 容量满了怎么办

| 情况 | 处理 | 用户感知 |
|---|---|---|
| 命令日志满 24 条 | 下一次操作开始前把当前画面压成新基线，日志/点池清零 | 更早的步骤不能再撤销（最多回退 24 步） |
| 点池 2048 点用尽（一笔太长） | 停止记点、画面照画；抬笔时这一笔并入基线 | 画面不丢，但这一笔不可撤销（`ESP_LOGW("WB","笔迹点池已满…")`） |

### 4.4 撤销/重做的动作

- 撤销：命令从 `ulog` 移到 `rlog`，`canvas = snap` + 重放剩余命令。
- 重做：命令移回 `ulog` 并**增量重放**这一条。
- 新操作提交时 `rlog_n = 0`（截断 redo 分支）。这条不做就会出现"撤销 → 新画 → 重做 = 幽灵笔迹"。

## 5. 内存

| 项 | 大小 | 位置 | 何时 |
|---|---|---|---|
| `wb_arena_t` | **38,960B** | PSRAM（`heap_caps_calloc`） | 首次进入白板时分配，**退出不释放** |
| 文件名缓存 `s_names/s_paths/s_cur` | 4,068B | PSRAM `.ext_ram_bss` | 静态常驻 |
| 图标 | 780B | flash rodata | — |
| 代码 | ≈42.5KB | flash | 工程内记录值 |
| 加载列表弹窗 | ≈1.9KB | 主任务栈 | 打开列表时瞬时 |
| 加载 BMP 的临时缓冲 | 15,000B | PSRAM | 只在读盘那一瞬 |

- 400×300 单色画布的**理论下限**是 15,000B；本模块实占 2.6 倍（画布 + 快照 + 点池 + 日志）。
- 分配失败是**硬失败**：不绘图、不存盘、屏上提示"内存不足"，**绝不用空画布覆盖存档**（2026-10-30 前的实现会退回 8 字节 dummy 缓冲，随后 15KB 读写直接踩内存）。
- 退出后 PSRAM 仍保留 38,960B（下次进入直接复用）。这是刻意选择，不是泄漏；但**不符合"退出即释放"的约定**，见 §8。

## 6. 存档

| 项 | 值 |
|---|---|
| 格式 | 1bpp BMP：54B 文件头 + 8B 调色板（黑/白）= 偏移 62，行 stride 52，自底向上，共 15,662B |
| 目录 | `/sdcard/apps/data/图片/`（挂载时由 `sd_scan.c` 建；本模块写盘前会再 `mkdir -p` 一次） |
| 文件名 | `wbHHMMSSSS.bmp`（时 2 位 + 分 2 位 + 序号 4 位，序号 = 现有最大值+1） |
| 保存 | 顶栏"保存"= 新建一份；**退出白板自动保存当前这张**（含未修改） |
| 加载 | 进入时自动接着"序号最大"的那张；顶栏"加载"弹列表（长按/点× 删除，带确认） |
| 原子性 | 先写 `xxx.bmp.tmp` → `fflush` + `fsync` → `fclose` → `rename` 覆盖。任一步失败就删掉 tmp，原文件不受影响 |
| 加载检查 | `'BM'` + `biBitCount==1` + 400×300 + 偏移 ≥62 + **文件大小 ≥ 偏移 + 15600**；任意一项不过就返回失败，**当前画布原样保留** |
| 兼容性 | 只认本机写出的格式。既有存档全部满足，读取逻辑未变（bit=0 → 画布墨点） |

**已知边界**：读写都是"每行一次 fseek + 52B"，300 行 = 300 次 seek。不是流式顺序读，SD 卡上耗时未实测。

## 7. 渲染与送屏

每帧（`p_wb_render`）：

1. `st7305_clear(白)` → 整屏 `memset(fb,0xFF,15000)`
2. `st7305_blit_1bit(0,0,400,300,canvas)` → 只写黑像素（120,000 次循环）
3. 顶栏 + 工具列：实心区域用 `filr()`，内部改成了**按行批量 blit**（每行 1 次调用，而不是每像素 1 次 `draw_pixel`）
4. 形状拖动时叠一层预览
5. 内核 `st7305_flush()` → 15,000B 整帧 SPI（内容指纹相同则跳过）

**没有局部刷新**：任何一次绘制都走完整帧。驱动的 `st7305_set_window()` 具备局刷能力，但本模块没用（见 §8 B3）。

## 8. 已知限制与待办

### 8.1 行为限制（当前设计）

1. 撤销深度最多 24 步；单一超长笔迹（>2048 采样点）不计入撤销。
2. 没有"新建白板"按钮：新画布只在卡上没有存档时出现；"保存"永远新建文件（同内容会产生副本）。
3. 异常退出（掉电/复位/看门狗）会丢掉未保存的本次内容 —— 落盘只发生在退出时。
4. 触摸屏没有退出入口：顶栏无返回键，底部上滑被屏蔽，只能用物理返回键（+ 内核确认框）。
5. 形状粗细固定 1px（六档粗细只作用于三种笔）。
6. 无颜色/灰阶（单色屏）。

### 8.2 尚未验证（无真机/无编译环境时不得当成"通过"）

- 完整固件编译与链接、`page_wb` 的 flash/IRAM 实际占用。
- 真机：六种工具 × 六档粗细、>255 坐标的撤销重做、长笔画、多次进出页面、SD 拔插。
- 每帧耗时（可用 `remcon fps` 或 `os_core.c` 的 `render 慢` 日志 ≥20ms 采集）。

### 8.3 B3 局刷可行性（仅调查，未实施）

- 驱动侧已具备：`st7305_set_window(x,y,w,h)` + `flush()` 只送该矩形。
- 障碍：① `st7305_set_partial()` 是空实现；② 整帧指纹跳过是按整帧算的，局刷要另配脏矩形记账；③ 面板自刷新档位（HPM/LPM 切换）与局部窗口的交互未经验证；④ 16Hz 档位下省字节的收益有限。
- 结论：改动集中在白板（维护"上一笔包围盒"）而不是驱动，但必须先有真机长测，否则容易出现残影/半帧。**当前未实施。**

### 8.4 未来规划（未写代码）

- C1 撤销深度 24 → 64；C4 多白板管理/新建/重命名/覆盖；C5 自动草稿；C3 整笔删除橡皮。
