# 文曲星模拟器（LavaX 引擎 / `components/engines/lavax/`）

> 适用：LinTOS 1.0+，ESP32-S3 + 400×300 单色反射屏（ST7305），ESP-IDF 6.0.3。
> 本文只描述**代码现在是什么样**，不写计划；未验证项与已知缺陷集中登记在 §9。
> 最后更新：2026-10-31（求值栈平衡 / `write8` 越界 / 4 色清屏 / 主循环 poll 降频 / 渲染定点化）

---

## 1. 它是什么

文曲星是**游戏引擎**（不是 Lua 应用），跑文曲星 LavaX 语言编译出的 `.lav` 字节码。

| 项 | 值 |
|---|---|
| 组件目录 | `components/engines/lavax/` |
| 游戏根目录 | `/sdcard/roms/lava`（`page_engine.c` 的 `LAVAX_ROOT`）|
| 上层入口 | `components/apps/pages/page_engine.c`（`engine_lavax` 模块）|
| 生命周期 | `components/system/engine_manager/engine_manager.c`（`ENGINE_LAVAX`）|
| 显示目标 | ST7305，400×300，1bpp；VM 逻辑分辨率 256×192 |
| 虚拟机来源 | [LavaXVM](https://github.com/leesoft-mirage/LavaXVM)（李杰，**MIT**，见 `lavax/LICENSE`）|
| 第三方依赖 | **无**（retro-go 已剥离，只剩 `rg_stub.h` 接口桩）|

## 2. 代码分层

```
core/source/lava.c        解释器核心: 204 个 opcode、求值栈、内存访问、绘图原语    ← 原始 VM
core/source/file.c        文件系统: fopen/fread/listfile/getfilenum、路径解析        ← 原始 VM
core/source/hardware.c    按键状态 cur_keyb、tick(Hz128/TickCount)、本地时间        ← 原始 VM
core/source/lcd.c         屏平面 BmpData、调色板、DmaRefresh                        ← 原始 VM
core/source/gmode16.c     16 位色模式辅助                                          ← 原始 VM
core/source/pinyin.c      GB2312 拼音表(输入法)                                    ← 原始 VM
core/source/py2gb.c       拼音→GB 码                                              ← 原始 VM
core/source/myctype.c     LavaX 内置的 ctype 实现                                   ← 原始 VM
core/source/font.c        字库数组 2.5MB —— **不参与编译**，已迁 appdata/lav_font.bin

core/source/main.c        lavaxvm_init/load_shell/run/shutdown + TaskOpen/TaskClose  ← LinTOS 新增
core/source/platform.c    呈现/输入/tick/退出/路径翻译 (原 retro-go 版改 ST7305)      ← LinTOS 移植
core/source/lavax_platform_api.c  rg_* 平台桩 (retro-go 替代)                        ← LinTOS 移植
lavax_emu.c               PSRAM 分配、加载运行、修改机内存 region                     ← LinTOS 移植
```

**判定依据**：`core/source/*.c` 除 `main.c` 外都能在 LavaXVM 仓库找到同名同名函数；
`lavax_emu.c` / `platform.c` / `lavax_platform_api.c` 在上游不存在。

### 2.1 与上游的差异（只有四类）

1. 文件系统函数从 `lava.c` 拆到 `file.c`；
2. 主循环 `lavRun()` → `main_loop()`（去掉 1000 条指令预算，见 §3.3）；
3. 新增 `vm_memory_pointer` 边界检查、`write8/write81/write86` 位图通路；
4. 删除 `verify()`（程序退出时的"LavaX 认证"画面，模拟器不需要）。

**指令集与上游完全一致**：`codes[117]` + `codes2[87]`，逐项同序。

## 3. 执行模型

### 3.1 指令分发

单字节 opcode，函数指针表分发：

```
t = *(lPC++)
t & 0x80 → codes2[t & 0x7f]   (87 个系统调用)
否则      → codes[t]           (117 个基本指令)
```

`codes` 表用 `//0` … `//116` 注释标了序号；**新增/删除表项会让所有后续序号错位**，改动时必须同步注释。

### 3.2 求值栈与地址栈

| 结构 | 基址 | 容量 | 实现 |
|---|---|---|---|
| 求值栈 | `eval_stack = 0x1b00` | 256B（`eval_top` 是 `byte`）| 4 字节/项，`get_val`/`put_val` |
| 字符串栈 | `string_stack = 0x1c00` | 1KB | `string_ptr` 递减分配 |
| 文本缓冲 | `TextBuffer = 0x1400` | — | `setscreen()` 用它清屏 |
| 调用栈 | `func_stack` | **16KB**（4096 × int）| 内部 DRAM，防深递归溢出 |

三者在 VM RAM 的**固定低地址**，与原版一致。地址栈（`eval_top`）与数据栈共用 `eval_top` 变量。

**栈平衡是硬约束**：任何 `get_val()/get_val2()` 之后提前 `return` 的路径，都必须 `put_val()` 补齐，
否则后续所有表达式的数据栈整体偏移 4 字节。2026-10-31 修掉的三处即此类（§8.1）。

### 3.3 主循环与指令预算

```c
poll_step = 0;
for (;;) {
    if (poll_step == 0) {            /* 每 LAVAX_POLL_STRIDE 条回一次平台 */
        lavax_platform_poll();       /* 输入采样/硬件 tick/15fps 送屏/退出检测 */
        if (CheckExitKey()) return;
        CheckAppExit();              /* exec 子程序的组合键退出 */
    }
    if (++poll_step >= LAVAX_POLL_STRIDE) poll_step = 0;

    t = getcode();  ...  (*codes[t])();
}
```

| 宏 | 默认 | 作用 |
|---|---|---|
| `LAVAX_POLL_STRIDE` | 32 | 每 N 条指令 poll 一次。置 1 = 恢复"每条都 poll"的旧行为 |
| `LAVAX_DEBUG_PC_RING` | 0 | 指令地址环（1024 × size_t，PSRAM）。开启后**每条指令写一次 PSRAM** |

原版是每 **1000 条**回一次主循环（`xx=1000; goto xxx`）。我们取 32：单条指令约 1µs，
32 条 ≈ 40µs，远小于输入（5ms）/tick（3.9ms）/刷新（66ms）的节流粒度。

> **不要把它调得很大**：`c_getchar()` / `c_delay()` 内部各自阻塞轮询 `lavax_platform_poll()`，
> 不受此值影响；但如果某条指令自身是长循环（如 `c_printf` 批量输出），poll 间隔会随之变长。

### 3.4 时间与倍速

- 硬件 tick 固定 **256 Hz**（`platform.c` 每 3906µs 推进一次）。
- 每次 tick 推进 `lavax_game_speed`（默认 **8**）个内部 tick → 等效 ×8 倍速，
  对齐步步高 `gam4980` 的 `timer_rate≈8`。`Hz128` 是 `byte`，每 tick +1 自然回绕。
- `c_delay(ms)` 换算成 `ms*256/1000` 个 tick 忙等；`c_getms()` 返回 `Hz128`。

## 4. 内存

| 项 | 大小 | 位置 | 生命周期 |
|---|---|---|---|
| VM RAM（`MY_DATA_SIZE`）| **1,048,576** | PSRAM | 进文曲星时分配，退出释放 |
| local_ram（`ram_base`）| 49,152 | PSRAM | 同上 |
| 屏平面 `BmpData` | 98,304 | PSRAM | 同上（双平面，`SCROLL_CON=49152` 供滚动）|
| 灰度缓冲 `g_gray` | 49,152 | PSRAM | 同上 |
| `present_rgb555` 临时缓冲 | 49,152 | PSRAM（`.ext_ram_bss`）| 静态常驻 |
| 渲染行缓冲 `rows` | 15,000 | **PSRAM** | 首次送屏时分配，不释放 |
| `func_stack` | 16,384 | **内部 DRAM** | 进文曲星时分配，退出释放 |
| `circle_buf` / `patbuf` | 1,280 / 1,024 | 内部 DRAM | 同上 |
| `task[8]`（`struct TASK`）| ≈8 × 1.1KB | PSRAM（`.ext_ram_bss`）| 静态常驻 |

**PSRAM 合计 ≈ 1.25 MB，内部 DRAM ≈ 18 KB。**

三条硬约束：

1. **VM RAM 就是 1 MB，不要加大**。原作者 `main.c` 也是 `malloc(0x100000)`，注释写着
   "为 LAVA 程序分配 1M 内存, 以后再加大" —— 游戏按 1 MB 地址空间设计，加大没有收益。
2. `func_stack/circle_buf/patbuf` **必须放内部 DRAM**（热访问，PSRAM 会拖慢解释器）。
3. 渲染行缓冲、灰度缓冲、屏平面都放 PSRAM（CPU 顺序读写，且不参与 SPI 发送）。

**分配失败一律硬失败**：`lavax_emu_background_init()` 任一步失败就回滚已分配的块并返回错误，
不会带着半套缓冲继续跑。

## 5. 文件系统与路径

### 5.1 根目录规则

`lavax_emu_load_and_run(path)` 取 `.lav` 的**所在目录**作为 LavaX 文件根：

```
/sdcard/roms/lava/<游戏>/Lava/x.lav   → 根 = /sdcard/roms/lava/<游戏>
/sdcard/roms/lava/<游戏>/x.lav        → 根 = /sdcard/roms/lava/<游戏>
```

若目录名本身是 `Lava`/`lava`，**再上移一级**（存档在同级 `LavaData/`）。

### 5.2 路径翻译

```
VM 内部路径 (GBK)  ──append_host_path()──▶  UTF-8 宿主路径
   ├─ 以 /sd/ 或 /sdcard/ 开头且 stat 成功 → 原样透传（菜单传进来的 UTF-8 中文名）
   └─ 否则补 /sdcard 前缀 + GBK→UTF8 转换
```

`lavax_host_path()` 的"先 stat 再决定是否转码"是为了区分两种来源：菜单给的是 UTF-8，
VM 内部拼出来的是 GBK，两者前缀相同、无法只看内容判断。

### 5.3 存档目录与共享回退

- 每个游戏的数据在**自己目录下的 `LavaData/`**（社区规范，不存在"多游戏共享一份"的官方做法）。
- 只读打开且本游戏目录缺文件时，回退到 `/sdcard/roms/lava/LavaData/<同名>`。
- **写操作绝不回退**（`lavax_set_map_write_intent(1)`）—— 否则两个游戏写同名存档会互相覆盖。

### 5.4 不支持的格式

**`.pac`（PACK）格式不支持**。原版 `UnPac()` 能解 `"PAC "` + 条目数 + `(u32 len + 60B 路径)` 的打包文件，
本移植未实现，游戏列表也只认 `.lav`。见 §9.2。

## 6. 显示通路

```
VM 绘图原语 (write_comm/write8/font_*)  →  BmpData (256×192 索引, PSRAM)
        ↓ DmaRefresh()  ← 15fps
present_to_gray()                        灰度化 (graph_mode 决定映射)
        ↓
g_gray (256×192 灰度, PSRAM)
        ↓ 帧哈希变化才继续 (FNV-1a)
render_to_lcd()                          定点缩放表 → 1bpp 行缓冲 (400×300)
        ↓
st7305_blit_1bit()                       逐像素写驱动 fb
        ↓ st7305_flush()  (驱动层还有一道"已送屏内容指纹")
15,000B SPI @26.7MHz ≈ 4.5ms
```

### 6.1 灰度映射规则

| `graph_mode` | 映射 | 说明 |
|---|---|---|
| 1（单色）| `idx==1 → 黑`，其余白 | 1 = 墨点 |
| 4（16 色）| `lum = 255*(15-(idx&15))/15` | 0 = 白，15 = 黑 |
| 8（256 色）| `lum = RGB 亮度`（`palette[idx*3..]`）| 调色板由 `lav_setpalette` 更新 |

阈值固定 `lum < 90` 判黑（约 35% 亮度）。**没有任何抖动**：在 1-bit 反射屏上抖动会变成棋盘噪点。

### 6.2 缩放的三种模式

`lavax_set_display_mode(m)`（由引擎优化页的"显示模式"写入）：

| 值 | 模式 | 行为 |
|---|---|---|
| 0 | 点对点 | 1:1 居中，四周留白 |
| 1 | 全屏（默认）| 等比 cover 放大到铺满 400×300，超出部分裁掉 |
| 2 | 拉伸 | 非等比填满整屏（变形）|

缩放用**两张预计算映射表**（`s_map_x[400]` / `s_map_y[300]`，`0xFFFF` = 留白），
布局或源尺寸变化时才重建。旧实现是逐像素浮点除法（每帧约 12 万次）。

### 6.3 两道帧去重

1. **引擎侧**：`platform.c` 对 `g_gray` 有效区做 FNV-1a 哈希，与上一帧相同则不重绘。
2. **驱动侧**：`st7305_flush()` 对 fb 内容算指纹，相同则跳过 SPI 传输。

两层都会在退出确认浮层激活时被强制打破（保证"按返回"立刻看到确认框）。

### 6.4 没有局部刷新

每帧都是 `st7305_clear(白)` + 整屏 blit。原因：SPI 只占帧预算的 7%（4.5ms / 66ms），
收益小于"脏矩形记账 + 残影风险"。驱动侧 `st7305_set_window()` 具备局刷能力，本引擎未用。

## 7. 输入

| 位置 | 实现 |
|---|---|
| 物理键 → 手柄位 | `rg_input_read_gamepad()` ← `input_get_held_gb_joypad()`（低电平有效）|
| 手柄位 → `cur_keyb` | `GetKeyboardState()`，**值为 0/1**（上游是 0x80 标志位）|
| 边沿 → `lav_key` | 按下瞬间置 `code | 0x80`，`c_getchar/c_inkey` 消费后清最高位 |
| 屏幕虚拟手柄 | `virtual_keys_set_layout(VK_LAYOUT_STANDARD)`，与步步高/GB 一致 |
| 退出 | `lavax_set_exit_check()` 回调 → menu 层检测返回键；确认浮层由宿主绘制 |

> ⚠ **不要改 `cur_keyb` 的 0/1 语义**。`c_checkkey()` 按"非零即按下"判断，
> 与上游的 `& 0x80` 判断是一一对应的改写；改回 0x80 会让所有按键失效。

键位映射（`key_code[]`，可由 `Config.ini` 覆盖）：`0x14/0x15` 上下、`0x17/0x16` 左右、
`0x0d` 回车、`0x1b` ESC、`0x1c~0x1f` F1-F4、`0x19` HELP。

## 8. 本轮修改（2026-10-31）

### 8.1 确定性 Bug

| # | 位置 | 问题 | 处理 |
|---|---|---|---|
| 1 | `c_strchr()` | 指针越界时 `return` 未 `put_val()`，求值栈少压一项 | 改为 `a1=0; put_val();` |
| 2 | `c_strcmp()` | 同上（两个指针任一越界）| 同上 |
| 3 | `c_strstr()` | 同上 | 同上 |
| 4 | `write8()` | `negative` 分支 `memcpy` 在裁剪**之前**，图块大于 49,152B 时越界写 PSRAM 堆 | 纵向裁剪前置 + 容量校验，超限放弃绘制并留日志 |
| 5 | `ClearNdsScreen()` | `graph_mode==4` 时清 255 → 映射成 idx15 → **整屏黑** | 统一清 0（1 色/8 色结果不变，只修 4 色）|
| 6 | `lavReset()` | 32 位程序 `exec` 后 `lRam` 上移，`(VRam+MY_DATA_SIZE)-(lRam+0x2000)` 可能为负，转 `size_t` 后**越界 memset** | 先做区间判断，越界跳过并限流记日志 |

第 4 条的裁剪是**等价变换**：屏幕外的行本来就不绘制，提前算出来的 `height` 与旧实现完全相同，
只有 `skip` 行的源偏移需要跟着补上（`data + skip*widths`）。

### 8.2 性能

| 位置 | 改动 | 依据 |
|---|---|---|
| `main_loop()` | 每 32 条指令 poll 一次（原：每条）| poll 内含 `esp_timer_get_time()` + 多组 64 位比较 |
| `dbg_pcs[]` | 编译期关闭（原：每条指令写一次 PSRAM）| 纯调试设施，跑在热路径上 |
| `pop_address_offset()` | 2~3 次 `lRamRead` → 1 次 `vm_memory_pointer` | 地址栈连续，合并安全 |
| `render_to_lcd()` | 浮点除法 → 预计算映射表 | 每帧约 12 万次 float 除法 |
| `render_to_lcd()` | 行缓冲 `malloc`(内部) → PSRAM | 省 15KB 内部 RAM，且它是 CPU 只读源 |

`render_to_lcd` 的布局公式与旧实现**逐字一致**，输出像素完全相同 —— 这是优化不是近似。

### 8.3 保留不动

- `page_engine.c` 的 `wqx_exclude_lava()` / `wqx_is_res_dir()`：`Lava`、`LavaData`
  精确名单（`strcasecmp`），左栏不显示、右栏不列为游戏。**引擎升级不得改动这里。**
- `cur_keyb` 的 0/1 语义、`codes/codes2` 表顺序、`MY_DATA_SIZE`。

## 9. 已知限制与未验证项

### 9.1 行为限制（当前设计）

1. 15 fps 固定上限（`platform.c` 的 66000µs）；无动态帧率。
2. 无局部刷新，每帧整屏。
3. 无存档即时快照（`saveState` 未接）：靠游戏自己的 `LavaData/` 存档。
4. `.lav` 文件大小无上限校验（`TaskOpen` 按文件长度 malloc，失败即拒绝加载）。
5. `c_getchar()` 在等待按键期间是**阻塞**的（内部轮询 poll），与上游 `wait_key` 状态机实现不同但行为等价。

### 9.2 未支持 / 未验证

| 项 | 状态 |
|---|---|
| **`.pac`（PACK）打包格式** | **未实现**。原版 `UnPac()` 可解，本移植没有。需要真实 `.pac` 样本才能验证，且涉及解包写 SD 的路径决策 |
| 4 色（`graph_mode==4`）游戏 | 清屏反色已修，但**没有 4 色游戏样本做实机验证** |
| `write8` 容量上限 | 修复后行为是"超限不绘制"，但正常游戏不会触发，未用真实异常数据验证 |
| 长时间运行内存泄漏 | `engine_manager` 有基线检测（返回主菜单时对比），未做 >1 小时连续进出压测 |
| 真机帧耗时 | `[LAVAX-RENDER] frame total=%lld ms` 仅在 >20ms 时打印；本轮优化前后的实测对比**未在真机采集** |

### 9.3 明确不做

| 想法 | 为什么不做 |
|---|---|
| 换用 C1-Slim 的 `lavax_vm` | C++/STL 重写，每条指令 `unordered_map` 查表，体积 +150KB、性能更差；且 `port/` 是 GPL-3.0 |
| 稳定帧合并（140ms 静止才提交）| 那是 e-paper 防中间帧污染的手段；ST7305 无残影，只会凭空加 140ms 延迟 |
| 抬高 `MY_DATA_SIZE` 到 8MB | 原作者就是 1MB，游戏按此设计 |
| 改 `cur_keyb` 表示 | 全线按键崩 |
| 脏矩形局部刷新 | SPI 只占 7% 帧预算，收益小于风险 |

## 10. 改动这块代码的检查清单

- [ ] 动 `codes`/`codes2` → 表项序号注释同步，且**不要在中间插入**（会错位后续所有 opcode）
- [ ] 动求值栈 → 每条提前 `return` 的路径都问一遍"`put_val()` 了吗"
- [ ] 动 `write8`/`write_comm` → `td` 的源偏移、裁剪顺序、临时缓冲容量三者一起看
- [ ] 动显示映射 → 三种模式都要过一遍，且**不能用抖动**（1-bit 屏会变噪点）
- [ ] 动 `cur_keyb` → 同步 `c_checkkey` / `c_releasekey` / `GetKeyboardState` 三处
- [ ] 动内存分配 → 失败路径必须回滚**已分配的**块（`lavax_emu_background_init` 的模式）
- [ ] 动游戏目录规则 → `page_engine.c` 的 `wqx_*` 与 `platform.c` 的 `SetRoot` 是两套，别只改一边
