# 第三方组件与许可证

> 目的：说清「项目里哪些代码不是自己写的、各自什么许可证、分发时要做什么」。
> **本文只做事实梳理，不构成法律意见。** 标 ⚠ 的条目在商业分发前必须人工或法律复核。
> 核查依据：仓库内 `LICENSE` / `COPYING` 文件 + 源码头部声明（2026-10-30 实查）。

## 3 构建与分发事实

> **本节是"技术事实"，不是法律结论。** 下面每个数字都是 **2026-10-30 一次核验**时
> 从构建产物里数出来的，**不是永久不变的性质** —— 组件可能被裁掉、被替换、或构建方式改变。
> 复核方法：重新数 `build/esp-idf/<组件>/` 下的 `.obj`，或看该组件 `CMakeLists.txt` 的 `SRCS`。
> 法律定性见 §4（兼容性）与 §6（待补齐），两者不要混着读。

### 3.1 这些组件到底有没有编进固件

| 组件 | 是否参与构建 | 核验办法与结果（2026-10-30） |
|---|---|---|
| `md_emu`（含 **gwenesis**）| **是** | `components/engines/md_emu/CMakeLists.txt` 用 `SRC_DIRS` 收了 `gwenesis/src/*`；`build/esp-idf/md_emu/` 下共 **18** 个 `.obj`，其中 **12** 个在 `gwenesis/` 子目录 |
| `sdlpal_port`（含 **sdlpal**）| **是** | CMakeLists 显式列出 `SDLPAL_SRCS`；`build/esp-idf/sdlpal_port/` 下 **38** 个 `.obj`，**38 个**全部来自 sdlpal 树 |
| `sms_emu`（含 **smsplus**）| **是** | `build/esp-idf/sms_emu/libsms_emu.a` 存在，CMakeLists 收 `smsplus/` |
| `libs/lua` | **是** | `build/esp-idf/lua/liblua.a` |
| `services/miniz`（`lmz.*`）| **是** | 资源包解压依赖它（`am_asset.c` 的 `#include "lmz.h"`）|
| `espressif__esp-dsp` / `esp_tinyusb` / `tinyusb` | **是** | `managed_components/` 由 IDF 组件管理器拉入并参与构建 |

### 3.2 怎么链进固件的

- 每个组件先编成**静态库** `lib<组件>.a`（ESP-IDF 默认行为），
  再由链接器**静态链接**进单一固件镜像 `build/LinTOS.bin`。
- 核验：`build/esp-idf/*/lib*.a` 存在（如 `libmd_emu.a` 8.3 MB、`libsdlpal_port.a` 3.3 MB），
  且 `partitions.csv` 只有**一个** `factory` 应用分区 —— 不存在第二个可执行体。
- **不是独立进程、不是独立可执行程序**：没有单独的 ELF、没有运行时加载。
  这些代码与 LinTOS 自己的代码在同一个地址空间里执行。

### 3.3 怎么分发的

- `dist/merged_16mb.bin` 是 **16 MB 整片镜像**（16,777,216 字节），
  按 `partitions.csv` 拼装：`0x0` bootloader、`0x60000` factory 固件、`0xC00000` apps 分区等。
  **含上面所有第三方代码。**
- 在线刷机页 <https://linit-l.github.io/ESP32-S3-RLCD-BBK/flash/> 分发的是同一个镜像，
  同样构成分发行为。

### 3.4 许可证原文有没有跟着走

| 位置 | 现状 |
|---|---|
| 仓库内 | **有**：`gwenesis/LICENSE`、`sdlpal/LICENSE`、`smsplus/LICENSE` + `COPYING`、`libs/lua/LICENSE`、三个 `managed_components/*/LICENSE` |
| **分发包（`dist/`）** | **没有** `LICENSE` / `NOTICE` 文件（实查 `ls dist/`）|

⚠ 这两栏不能互相替代：**"仓库里有许可证文件"≠"分发包已经附带许可证"。**
GPL/AGPL 要求在分发时随附许可证全文与版权声明；Apache-2.0 要求保留 `NOTICE`（若有）。
当前分发包两者都缺。

### 3.5 三类许可证的义务不同（分开说）

| 类型 | 本项目涉及 | 义务要点（**文本要求，非法律意见**）|
|---|---|---|
| **AGPL-3.0** | gwenesis | 分发二进制须提供完整对应源码；若提供网络交互服务，须向网络用户提供源码（§13）|
| **GPL-2.0 / GPL-3.0** | smsplus、sdlpal、主项目自身 | 分发二进制须提供完整对应源码 + 保留版权声明与许可证全文 |
| **Apache-2.0** | esp-dsp、esp_tinyusb | 保留版权与许可证；**保留 `NOTICE`**（若上游提供）；修改过的文件须标明 |
| **MIT / Public Domain** | lua、tinyusb、miniz | 保留版权与许可声明（MIT）；Public Domain 无强制要求 |

### 3.6 待核实（本节不下的结论）

| 项 | 状态 |
|---|---|
| gwenesis 上游代码是否被改动 | **待核实**。仓库内没有上游原始副本可比对，无法用 diff 证明"原样引入" |
| sdlpal 是否被改动 | CMakeLists 注释声明「GPLv3，原样引入，不改它的代码」（`sdlpal_port/CMakeLists.txt:5`），属**项目自述**，未做逐文件比对 |

| 分发包该附哪些文件、放哪里 | 需人工决定（GPL 通常要求随二进制提供源码获取方式）|

## 4 兼容性分析

| 组合 | 结论 |
|---|---|
| 主项目 GPL-2.0-**or-later** + sdlpal GPL-3.0 | ✅ 可行。or-later 允许整体按 GPLv3 分发 |
| 主项目 + smsplus GPL-2.0 | ✅ 可行 |
| 主项目 + Lua MIT / miniz Public Domain / tinyusb MIT / esp-dsp Apache-2.0 | ✅ 可行（宽松许可可与 GPL 共存）|
| 主项目 + gwenesis **AGPL-3.0** | ⚠ **需要复核**。AGPL 的网络交互条款比 GPL 更严；混入后整个分发物可能被要求按 AGPL 处理。当前固件是本地设备、不提供网络服务，实际风险较低，但**分发前应取得明确意见** |

> ⚠ 结论：**不要假定「主项目是 GPLv2 所以所有组件都是 GPLv2」**。
> 上表里至少有一个 AGPL 组件、两个 GPLv3 组件，许可义务并不相同。

## 5 分发时要做什么

发布固件二进制（含 `dist/merged_16mb.bin`、在线刷机页）时，GPL 要求：

1. **提供完整对应源码**（含本次构建所用的修改，即工作区状态而非仅 tag）。
2. 保留所有版权声明与许可证原文（各组件 `LICENSE` / 源码头注释不得删改）。
3. 标明修改（本项目对上游内核有大量裁剪与适配，属"修改版"）。
4. AGPL 组件若被分发，额外注意 §13 网络条款。

在线刷机页 <https://linit-l.github.io/ESP32-S3-RLCD-BBK/flash/> 属分发行为，同样适用。
