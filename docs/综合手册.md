## 1 构建 · 烧录 · 传文件

```bash
PYTHONPATH= ./tools/build.sh          # 编译（含内置商店索引 + system.bin + 整片合并）
bash tools/flash_safe.sh [port]       # 日常：只写 factory + apps，保留 nvs
bash tools/merge_flash.sh             # 出整片镜像 dist/merged_16mb.bin（烧 0x0 会清 nvs，仅改分区/bootloader 时）
```

- 波特率**必须 460800**（921600 长写必掉）；掉线重烧即可。设备在 app 运行态直连报 `No serial data received` ⇒ 进下载模式或趁 USB 重新枚举窗口。
- 分段：只改 C 刷 `0x60000`；只改 Lua → `LINTOS_LUA_SRC=<dir> python3 tools/sync_apps.py` 后刷 `0xC00000`。
- 版本唯一来源 `lintos_version.h`；改完跑 `tools/version_check.py` 并 `touch components/system/os/CMakeLists.txt`（git 描述是配置期取的）。macOS 的 git 用 `/opt/homebrew/bin/git`。

### 1.1 热部署到 TF 卡（不拔卡、不复位）

`/sdcard` 是 SDMMC 上的 FAT 挂载点，remcon 的 `put` 把串口字节直接写进该路径：

```bash
python3 tools/hw_put.py "apps/lua/apps/app/X.lua" "/sdcard/apps/app/X.lua" /dev/cu.usbmodem*
```

协议：`put <path> <总字节>` → `RC_PUT_READY`；每 ≤4096 B 等 `RC_PUT_ACK`；末尾 `RC_PUT_DONE <字节> <crc32>`。
**成功判据 = 字节数与 crc32 都和本地一致**，其它一律不算成功。

- 不需要特殊固件（`remcon_init()` 无条件调用）；传完**退出应用重进**才加载；`.lbc` 按源文件大小+mtime 自动失效。
- ⛔ `write_flash` 写的是 flash 分区，与 TF 卡文件无关。速度约 10 KB/s，大包别走串口。
- 备用通路（都有代价）：USB MSC 会卸载 USB-Serial/JTAG（串口消失，要「卸载」才恢复）；网页 `/files/` 必须先连 WiFi；`sync_apps.py` + 刷 apps 分区适合内置发布。

### 1.2 两个部署坑

- **nginx `open_file_cache`**（inactive 60s / valid 90s）：`index.json` 同名原地重写 inode 不变 ⇒ 磁盘是新版、HTTP 一直返回旧版，设备下到坏索引。改完必须 `nginx -t && nginx -s reload`；排查先排除本机代理（出现 `200 Connection Established` ⇒ 加 `--noproxy '*'`）。`store/index.json` 还会被 `build.sh` 嵌进固件，改完要重编。
- **IDF 6.0**：`idf.py` 启动失败多因 tarball 无 `.git` ⇒ `export ESP_IDF_VERSION=6.0.3`；配置冲突用 `sdkconfig.defaults` 重生成；公共驱动头不再隐式包含 FreeRTOS 头；`xTaskGetAffinity` 已移除改 `xTaskGetCoreID`。
  **未决**：keyvault 的 PSA Crypto 迁移**无法静态验证**（编译过只证明 API 用对，不能证明同一 PIN 能解开历史密文），必须真机验证；解不开可单独回退该文件。

## 2 按症状查（别重复调研）

| 症状 | 根因 / 处理 |
|---|---|
| `PermissionError sitecustomize`、构建中奇怪删除失败 | 环境有 Python 注入（Agent shim）⇒ 命令前加 `PYTHONPATH=` |
| `check_deps.py` 报分层违例 | 改 `REQUIRES`/`PRIV_REQUIRES` 或走回调注入；⛔ 不要塞进 `ALLOW_INVERSIONS` 了事 |
| 找不到 `miniz.h` 符号 | IDF 自带 `miniz.h` 只声明 ROM tinfl ⇒ 本项目用 `lmz.h` |
| 固件超 factory 分区 | `idf.py size-components` 找增长点，大块静态数据迁 PSRAM |
| 联网必失败、错误码 **28674**、200µs 内返回 | 内部 RAM 无整块连续 ⇒ §3.1 |
| 触摸没反应 / 偶发失灵 / 坐标偏移 | ① 微雪原版本来无触摸 ② 探测前必须给 RST 低→高脉冲 ③ I2C 无外部上拉要补 4.7k ④ 旋转页必须走 `ctx->map_touch` |
| 深睡后认不到 TF 卡（只能断电） | 深睡 hold 了 SD 三脚、开机没 `gpio_hold_dis` |
| 存储信息全空 / 引擎读不到卡 | 挂载未完成就扫目录 ⇒ 消费者等 `sd_wait_ready()` |
| 渲染/轮询里写 NVS 卡顿 | 写 NVS 关 flash cache ⇒ 只在交互触发时写，连续调节要防抖 |
| 应用中心看不到内置 Lua 应用 | `/store` 未挂载，看开机日志 `SPIFFS /store 挂载` |
| 「下载失败」 | 三类原因同一提示，看串口错误码：`1`=HTTP 非 200，`2`=连接/超时，`4`=校验失败 |
| 装完显示"已安装"却打不开 | 自动安装失败被误报成功（已知缺陷）⇒ 看 `ESP_LOGW`，重下一次 |
| 资源包装完不可见 | 判据是 `target/.installed`；确认条目 `.requires` 指向同一目录 |
| 开机直接关机 | 手动关机唤醒门控要求 PWR 按住 ≥0.5s（设计如此） |
| 屏保态长按关机不弹框 / 解锁停在旧壁纸 | 屏保期 LCD 被壁纸独占、主循环 `continue` 未渲染 ⇒ 先退屏保（解独占+开刷屏门禁+恢复触屏），退出时作废送屏指纹+置脏+1 秒强制重绘 |

崩溃定位：`xtensa-esp32s3-elf-addr2line -pfiaC -e build/LinTOS.elf <地址>`；黑屏先看 `Loaded app` 与 `ST7305: ★送屏 #n` 是否在涨。
周期性指标打印只走编译期诊断宏（§9）；`ESP_LOGE/W` 永远保留。

## 3 网络与射频

**按需启停**：开机不拉射频，谁要联网谁 `os_hw_request`，用完必须 `os_hw_release`（引用计数归零才真关）。历史上三个页面申请后没配对释放 ⇒ "取消连接后射频常开"。

### 3.1 TLS 失败（最常见）

mbedtls 的 TLS 缓冲要求在**一整块连续内部 RAM** 里分配；蓝牙+WiFi 同开时最大连续块只剩约 7.6 KB ⇒ `ESP_ERR_HTTP_CONNECT`。
已缓解：`MBEDTLS_DYNAMIC_BUFFER=y`、`IN_CONTENT_LEN 16384→4096`、`OUT 4096→2048`、`http_client buffer_size →1024`。
**验收门槛：`remcon audit` 的 `largest` 不得低于 8 KB。**

### 3.2 下载期间不许进 DTIM 省电（铁律）

取数期间射频必须 `WIFI_PS_NONE`（`wifi_manager_ps_hold()` 引用计数）；结束/失败/取消/超时都要放掉，8 秒延迟后恢复 `MIN_MODEM`。
实测：`MIN_MODEM` 丢包 12.5~37.5%、530 KB 要 33 s；`NONE` 丢包 0%、12~14 s（表现为"点下载一直 0%"）。

- `WIFI_EVENT_STA_CONNECTED` 分支里若 `s_ps_hold>0` **不得**开省电，否则一次重连就破坏规则。
- 计数只在 `netc_task` 增减，**单一出口释放**（正常/失败/取消/超时同一路径）。
- `wifi ps 0/1` 只用于测量，⛔ 业务代码不许拿它代替 hold。

### 3.3 吞吐由 TCP 窗口决定

`吞吐 ≈ 窗口 / RTT`。默认 5760 ⇒ RTT 22ms 约 262 KB/s，抖动到 216ms 只剩 27 KB/s（"8.5 KB/s"就是这个机制）。
已调 `TCP_WND_DEFAULT 20480`、`TCP_RECVMBOX_SIZE 24`、`ESP_WIFI_RX_BA_WIN 16`；窗口内存来自内部 RAM pbuf，实测空闲约 105 KB、最大连续 31 KB ⇒ **再加要先压别的模块**。
三处纯开销，改回去速度立刻掉：`http_client buffer_size` 1024（每 KB 一轮 select+read+memcpy）· stdio 默认 1 KB 缓冲改 `_IONBF`（⛔ 不可用 `setvbuf` 复用落盘缓冲，重叠会写坏数据）· CRC32 半字节表改 256 项整字节表。
**完整性设计不许动**：`.part` 临时文件 → 200+长度+CRC32 三道闸门 → 才替换正式文件；增量 CRC；已存在且 CRC 正确则跳过；进度回调 UI 侧节流 ~0.5 s。

### 3.4 应用中心联网门禁

唯一入口 `page_app_manager.c: am_store_wifi_gate()`，**必须幂等**。`IDLE→ASKING→CONNECTING→UP`（取消→DECLINED，20s 未连上→FAILED）。
`CONNECTING`/`UP` **粘性**：`on_exit` 不复位，被意外 pop 后重进不再问；只有取消/失败（失败另加 10s 冷却）才回 IDLE；连上后自动后台刷索引。
⛔ 两个坑：用计数器表达"本次只问一次"会被别处清 0 而失效；`os_dialog_push` 置 `s_cb_handled` 后确认框不自动关，随后 `os_dialog_pop` 在 `s_top==0` 时会**弹掉应用中心页面本身**（现改为确认框原位改写成扫描列表，全程一层弹窗）。

### 3.5 时间服务 `svc_time`

全系统**唯一**允许 `settimeofday` / 建 SNTP 的地方；其它模块查 `svc_time_state()`。`TZ=UTC-8`，系统内一律 UTC。
完整校准间隔 6 小时；本地无效 ⇒ **无条件采纳**网络时间；本地可信且偏差 >30 分钟 ⇒ **拒绝并回滚**；NVS `time/rec` 只在校时成功时写。
刷机识别（`time_logic.c` 纯函数）：`now<2025-01-01` 或 `now+60<last_sync` ⇒ INVALID；`now>last_sync+1年` 或无记录 ⇒ PROVISIONAL。
⛔ **不再伪造默认时间**（旧实现把"<2025"改写成 2026-09-01，让"时间未知"看起来像"时间正确"）。诊断 `remcon timed`。

## 4 电源与休眠

- 深睡/关机**唯一实现** `power_mgr_off()`；⛔ 别处不许调 `esp_deep_sleep_start`。
- `power_mgr_wake_gate()` 是 `app_main()` 第一句：手动关机唤醒要求 PWR 按住 ≥0.5s，不足直接回深睡**不返回**；自动关机/冷启动放行。
- 屏保态主循环 `continue`：不跑 `os_tick`、不渲染、不碰 I2C/flash。
- 可关程度：PA（GPIO46 低+hold）· 屏（SLPIN，记忆屏断电保画面）· 触摸 · SD（卸载+停时钟，**必须先 `gpio_hold_dis`**）· 射频 · GPS（PMREQ ≈46µA）；模组内部 DC-DC 关不掉。

### 4.1 省电模式（NVS `os_settings/eco`，默认开）

一个开关管四件事，**唯一判定点 = 屏保监督任务的 `wp_eco_tick()`（每秒）**：
① 无操作 1 分钟进壁纸 ② 屏保播满「关机时间」（`os_wp/wp_shut`：不关机/1/3/5/10/20/30 分/1/2/3/6/12 小时，默认 3 分）自动关机 ③ WiFi 闲置 3 分钟关射频 ④ 蓝牙闲置 3 分钟深拆栈。关掉=四件全停，手动锁屏/关机/USB 保护照旧。
忙口径：`wp_activity_busy()`（音乐/录音 · 按游戏键 · `netc_busy` · `wp_idle_hold`）、`wp_shutdown_busy()`（再加 `input_is_game_mode()`）、`wifi_manager_is_busy()`、`bt_manager_is_busy()`。
⛔ 关蓝牙必须走 `bt_manager_release_async()`：深拆栈要在**内部 RAM** 任务里做，监督任务栈在 PSRAM，直接拆触发禁缓存断言。

### 4.2 壁纸刷新与调频

`wp_render_fn` 返回 `1`=要 flush；`idle_ms` 为 `0`=动态（62ms/1000ms），`>0`=静态按该值轮询。静态壁纸**恒 80MHz**（旧实现按"这帧画了没"切 240/80，导致每分钟调频两次）。
30 分钟送屏量：人生指南 30 次 ≈450 KB；星空 ≈29000 次 ≈435 MB。
⚠ 壁纸数据必须在**内部 RAM 栈上下文**预加载（`wp_lifeguide_preload()`）：监督任务栈在 PSRAM，那儿碰 SPIFFS/NVS 触发 spi_flash 禁缓存断言 ⇒ panic 重启循环 ⇒ 渲染函数只消费内存，从不 fopen。
切壁纸后必须 `wp_set_program()`（`s_ss_prog` 只在开机读一次 NVS）。

### 4.3 电量估算（五步，没有第六步）

`ADC raw → curve-fitting 校准 → 脚上 mV → ×分压比 → VBAT → 8 次采样两端各丢 2 求平均 → 17 点固定端点查表`

- ADC1_CH2(GPIO3)，12dB/12bit；校准失败退 line-fitting，再失败才 3.3V 线性并打"未校准"。分压比默认 **3.100**，`batcal <真实mV>` 标定写 `batcal/div`。
- 节拍 **60 秒**（全系统单一节拍器：状态栏/低电/网页/终端/Lua 全走它）；充电只读 CHRG，连续 3 次一致才翻转，上电首读即采信。
- 曲线关键点：4.10V=100%、3.90=65%、3.82=50%、3.70=28%、3.30=0%。⛔ 不是线性（线性会把 3.7V 显示 50%，实际约 30%）。
- 已删且**不要恢复**：动态满电锚点、5 点峰值窗口、SOC 稳定器、9 点跨轮滤波、电压趋势推断充电、31 天日档。7 天分钟级波形**只画图不参与计算**。
- 已知边界：分压比未用万用表复核；CHRG 极性未逐项真机验证；曲线是通用估算 ⇒ 对外只说"电量估算"。诊断 `bat`（=`batdiag`，两个名字都必须进 remcon 白名单）。

电流账（估算，500mAh）：亮屏静止 70~90mA（~6h）· **亮屏屏保 35~50mA（10~14h，比深睡更致命）** · 熄屏深睡 5~7mA（3~4 天）· codec 等掉电 1.5mA（~14 天）· EN 拉低 10µA。

## 5 数据格式

### 5.1 地图 `.ltm v3`（小端，与 Lua `string.unpack` 对齐；读写 `tools/mapgen/ltm_*.py`）

头 64B：`4s LTM1` | ver=3 | layer(1路/2等高/3POI) | nlod | bbox 4×i4(1e-6°) | 8×I(off_lod/off_feat/off_pt/off_str/npt/nfeat/crc/rsv) | off_idx | 保留。
LOD 20B：`cmax w zmin(H) f0 f1`（zmin 档位 0/13/14/15/17）。要素 24B（按 `cls` 升序）：`cls npts noff poff` + `bbox(相对 min)`。
点段：首点 `i4 lat/lon`，后续 **i2 增量**按 8/4/2/1 分批；单点跳变须 ≤±0.0327°。

省包 = 1 个 `.bin` + 1 个 `.json`：⛔ 不要一瓦片一文件（福建 1171 个请求，每个重来 TLS），也不要整省一个 `.ltm`（18MB 超过 `app.fs.read` 512KB）。设备端 `z<=ztile-1` 用概览、`z>=ztile` 按视口 `read_at` 读块。
生成侧必做：同名 way 溶解（无名路走 strict，46 065→13 110 条）、概览 `--ovcls 1`、块缩到 0.15°（最大块 555→364KB）。

索引段（头 `off_idx` 定位）：`u8 iver | u8 pad | u16 nx | u16 ny`（**6B**）`| i4 ox,oy,cw,ch | u32 nsid | u32 gcount | u32 cell_start[nx*ny+1] | u16 fid[nsid] | u16 gid[gcount]`

- ⛔ 前 6 字节是 `<BBHH` 不是 4（`ox` off6、`nsid` off22、`cell_start` off30）；算错 2 字节 ⇒ `data string too short`。
- 要素只登记在 bbox 的**最小格**，查询外扩 2 格 ⇒ 天然不重复（否则要在 Lua 维护 `nfeat` 大小去重表）。跨格 >3 格的进 `gid` 每帧扫。`nx=ny=⌈√(nfeat/3)⌉` 上限 64，**格数别小**（16×16 只过滤 81%，50×50 过滤 93%）。
- ⛔ `table.sort` **不是稳定排序**：任何"改变遍历顺序"的优化都会让并列名次换人、画面像素变。修法：排序键补成全序 `(p,y,x,s)`，`collect_road_labels` 先 `table.sort(names)`。
- 等价性必须**逐像素验**：`LTM_NOIDX` 退回线性扫，六档 zoom 帧缓冲全一致才算过。
- 分发：入口 `/bbk/maps.json`（老设备硬编码，不得改）；生成只走 `tools/map_prov.py`，规则放 `tools/map_rules.json`；⛔ 不可破坏 `.ltm` 格式、已发布包、商店 `index.json`；`*.bak.*/*.prev/*.tmp` 必须 403/404。

### 5.2 离线维基（格式**冻结**，改了设备上已有库全废）

`/sdcard/wiki/<库名>/`：`metadata.json`（version=2 + articleCount + chunks.pattern）、`index.bin`（80B/条：`title[64]|chunk|off|clen|ulen`，按标题 UTF-8 升序）、`articles_%04d.dat`（`WK1\0|ulen:u32|clen:u32|crc:u32|lz4_block`）、`py.bin`/`pyi.bin`（64B/条：`key[60]`+`id:u32`，各自升序且 **id 必须一致**）。
`index.bin` 大小必须严格 = `articleCount × 80`，否则 `wiki_open` 拒读。
⛔ 不改格式与 `app.wiki.*` 10 个 API 语义；索引**不常驻内存**（8MB PSRAM 优先给引擎）；数据目录与应用安装目录完全分离（卸载不删数据）；不改 `DIR_ROOT`；搜索只走拼音（软键盘 52 键 ASCII 打不了中文）；单篇上限 4MB × 2 缓冲 > PSRAM 可用量，必须按真实分布收紧并复用缓冲。

### 5.3 故障码库 `故障信息库.lua`

DB 是位置数组的数组，**固定 16 字段顺序不可变**：`code en zh cat scope cause steps advice risk severity source note keys layer vendor verify`（位置数组控内存：1000 条具名表约 1MB，位置数组约 1/3）。

- ⛔ **不用 `nil`**（会让数组出洞，`#DB` 直接截断），空值写 `""`。
- ⛔ 文本里不许出现 `①②③`（字库无此字形，真机显示空白）⇒ 一律 `1) 2) 3)`。
- 枚举：`layer`=POST/BEEP/BOOT/BSOD/DEVMGR/SYS/SELF；`severity`=现场可修/需备件/必须返厂（按 `advice`/`steps` 实际动作判）；`source`=HMM/KB/SUP/X390/MS/OEM/经验（**`经验` ≤10%**，查不到官方出处不入库）；`vendor`=AMI/Phoenix/Insyde/Award/Microsoft/通用/品牌名（蜂鸣码含义由 BIOS 厂商定，⛔ 无证据不要臆断 AMI）。
- `verify` 要能直接照做：分条动作、先给"区分 A 还是 B"的办法、写清结论指向；⛔ 不许写"观察一下"。
- 码写法：`0175`（留前导零）/`0x0000007B`（8 位大写）/`Code 56`/`1-3-1`；库里存规范写法，归一化只在搜索侧。
- ⛔ 归一化必须带命名空间：`dev:56`/`hex:1ca`/`raw:1ca`/`txt:` —— `0x1CA`(蓝屏) 与 `01CA`(POST) 数字相同但两类，不带命名空间会互相覆盖；Lua `norm_code()` 与 `tools/faultcode_lint.py` 必须逐字一致。
- 文本裁剪用 `[ \t\r\n]`，⛔ 不用 `%s`（某些构建把 0xA0 当空白，会截掉「池」这类字的半个字节 ⇒ 非法 UTF-8）。
- 详情滚动上限用 `det_maxtop()` 按页对齐；用 `#lines-DET_ROWS` 会多算一页、末页永远翻不到。
- 改代码**只改 `store/pkgs/故障信息库.lua`**（生成器以它为准整份覆盖 app 版）；改完重算 `store/index.json` 的 size/crc32/sha256 并跑 `tools/gen_store_index_builtin.py`。

### 5.4 设备接入协议（服务端已实现，**固件未实现**）

`POST https://bbk.linit.cn/?rest_route=/lp/v1/{register,heartbeat}`（用 `?rest_route=` 不依赖固定链接配置）。设备端只碰这两个 route，**不持有后台凭据**。

- `dev_id = "LNT" + MAC 去分隔符并大写`；服务端按 MAC 重算比对 ⇒ 改 dev_id 冒充不成立。
- 两把密钥：产品级 key（注册签名，32B，泄露只污染统计）· 设备 secret（心跳签名，24B，注册应答下发、**每次注册轮换**）。
- 签名串逐字节一致：`register\n{dev_id}\n{mac}\n{board}\n{chip}\n{fw}\n{proto}\n{ts}\n{nonce}` / `heartbeat\n{dev_id}\n{ts}\n{nonce}`，`sig = 小写 hex(HMAC_SHA256(key, 串))`。签名针对**原始字符串**（不裁剪、不改大小写），服务端验签后才截断/过滤（否则诚实设备永远验签失败）；MAC 必须大写+冒号。
- 防重放：`ts` ±300s；`nonce` 16 hex 一次性（否则 400 BAD_TS / 409 REPLAY）；限频 register 30/min、heartbeat 240/min（超限 429）。离线判定靠 `last_hb >= now - 900s`，不靠设备发消息。
- 重复注册（同 MAC）不新建、不覆盖 `first_seen`、**轮换 secret** ⇒ 重刷丢 NVS 能自愈。已知限制：`secret` 明文存库（HMAC 需原值）；"在线趋势"是按最后心跳日聚合的去重数。

## 6 引擎与应用的特殊约束

### 6.1 文曲星 LavaX（`components/engines/lavax/`，游戏根 `/sdcard/roms/lava`）

- 指令集与上游逐项同序（`codes[117]`+`codes2[87]`）；`codes` 表用 `//0…//116` 标序号 ⇒ **增删表项会让后续序号全部错位**。
- ⛔ **栈平衡是硬约束**：任何 `get_val()/get_val2()` 后提前 return 的路径都必须 `put_val()` 补齐，否则后续表达式整体偏移 4 字节。
- 主循环每 `LAVAX_POLL_STRIDE`(32) 条指令回一次平台（原版 1000，⛔ 别调大）；硬件 tick 256Hz，每 tick 推进 8 个内部 tick（等效 ×8）。
- 内存：VM RAM **就是 1MB 不要加大**（游戏按 1MB 地址空间设计）；`func_stack/circle_buf/patbuf` **必须内部 DRAM**（热访问）；屏平面/灰度/行缓冲放 PSRAM；分配失败一律硬失败并回滚。
- 路径：以 `.lav` 所在目录为根（目录名是 `Lava` 时再上移一级）；VM 内部 GBK、菜单传来 UTF-8 ⇒ `lavax_host_path()` 先 stat 再决定是否转码。存档在各自 `LavaData/`；**只读可回退**到共享目录，**写绝不回退**（否则两游戏互相覆盖）。不支持 `.pac`。
- 显示：`graph_mode` 1/4/8 三档，阈值固定 `lum<90` 判黑，**无任何抖动**（1bpp 反射屏上抖动变棋盘噪点）；缩放用两张预计算映射表；两道帧去重（引擎 FNV-1a + 驱动指纹）；**无局部刷新**（SPI 只占帧预算 7%）。
- ⛔ **不要改 `cur_keyb` 的 0/1 语义**（`c_checkkey()` 按非零判按下）；改回 0x80 会让所有按键失效。

### 6.2 白板 `page_wb.c`

- ⛔ 三个不变量：① 画布 == `snap`+重放前 N 条命令（改画布必须同步日志，反之亦然）② 点池只能和日志一起清空 ③ 容量检查只在操作开始前做（提交时压缩会让 `pts_idx` 失效）。
- 日志满 24 条 ⇒ 压成新基线（最多回退 24 步）；点池 2048 点用尽 ⇒ 这一笔不可撤销（画面不丢）。新操作提交时 `rlog_n=0`，否则"撤销→新画→重做"出幽灵笔迹。
- 半径只有一份 `wb_radius()`：实时绘制与撤销重放**都必须调它**（否则橡皮痕迹撤销后变窄）；笔迹点必须 `uint16`。
- 38,960B 单次 calloc 在 PSRAM，**退出不释放**（刻意复用，与"退出即释放"约定不符）；分配失败是硬失败，⛔ 绝不用空画布覆盖存档。
- 存档 1bpp BMP（偏移 62、stride 52、15,662B）：先写 `.tmp`→fsync→rename；加载校验 `BM`+1bpp+400×300+大小，任一项不过就**保留当前画布**。无局部刷新。

### 6.3 频谱仪 `espsdr`

- **64KB 采集区默认不占**：开机 `espsdr_reclaim_boot()` 把它加回内部堆；启用要写 NVS 且**重启**才改变归属。
- 射频征用顺序是修 bug 的结果：① 先 `bt_manager_disable()` 让蓝牙让出天线（直接抢约 2.4s 后 `TG1WDT` 复位，顺带还回约 97KB）② 再确保 WiFi 处于 init+start（⛔ 不能先 `wifi_manager_disable()`，会 deinit，重 init 极易 `NO_MEM`）③ ⛔ 不要用 `os_hw_request(OS_HW_WIFI)`（管家 stop 会关掉用户自己的 WiFi），自己做"开了才关"。退出顺序相反。
- 采集寄存器序列**不能改**：填哨兵 `0xa5a0055a` → 配 pack/agc → `0x600c101c` 的 `MAC_DUMP_USAGE` 置 4 → 写 ctrl → 再写 `ctrl|(1<<19)` 触发 → 轮询 bit18（超 20ms）→ 关控制字并**把 SRAM 还给 CPU**（异常路径也必须还）。
- 配套坑：`SOC_RESERVE_MEMORY_REGION` 在 `heap_memory_layout.h`；增益用 `libphy.a` 的 `phy_force_rx_gain()`（官方 `librftest.a` 默认不挂链接 ⇒ 链不过）；**采集窗口内不写 flash** ⇒ 热路径不打日志。
- 限制：量化 10bit；零中频有 DC 尖刺+镜像；单天线做不了测向；与 WiFi/BT 独占互斥；寄存器未文档化 ⇒ 换 IDF/芯片必须重验。

### 6.4 阅读器（`page_book.c` + `book_reader/`）

- 字体分层：**弹窗一律系统字体**；正文/页码/进度/章节名跟随阅读字体；只有两个绘制入口（`read_draw_text`/`ui_draw_text`），⛔ 不许用 `font_book_select()` 临时改全局字号再改回来。字号列表来自 `font_book_size_count()`。
- NVS `os_book`：进度 `last_page/last_path`、显示设置 `fs/pn/mg/lh/gp/in/rt`、字体 `ftn` 存**文件名**（空=内置，**不再存序号**——目录增删会错位）。`fs` 存**档位下标**不是像素，读回按当前字体字号表重新解释、越界收敛。位置优先 TF 卡 `.pos`，读不到且是"最近阅读"才用 NVS 页号兜底。
- ⛔ **书签与排版解耦**：书签在 `.pos` 尾部（42B/条，上限 8 条），锚点是 `off`（源文件字节偏移，**永远有效**），`page` 只在布局未变时可用。加载时书签**必须无条件读入**（只判 `bm_count`）；布局变化把 `page` 置 `0xFFFFFFFF` 走 `book_page_for_offset(off)`；改任何阅读优化项**不得**清空书签区。
  曾经的 bug：书签读取写成 `if (layout_match && …)` ⇒ 改字号/行距任一项即一条都不进内存 ⇒ 退出时用 0 条重写 `.pos` ⇒ **磁盘书签被真正抹掉**（丢数据，不是显示问题）。
- 限制：页表上限 524288 页；PSRAM 2MB/3MB 是推算未实测；GBK 避头尾只覆盖 GBK；竖屏未真机验证。

### 6.5 其他应用的关键点

- **数独**：300 不能被 9 整除 ⇒ 格边界 `EDG[k]=round(k*300/9)`（33/34 交替，累计正好 300）；⛔ 不要用 297（反射屏上表现为白线）。题库 60 题内嵌、离线生成（唯一解 + 人类技巧可解），难度 = 实际用到的最高技巧等级。存档三键 `sdk.meta/rec/game`，`tag|body|checksum` 格式，3 秒节流 + `on_exit` 全量。`DEV_SKILL_MAX=true` 是调试开关，发布前改 `false`。
- **求合体**：RNG 自实现 Mulberry32（⛔ 不用 `math.random`），**种子与 RNG 状态都入档**（否则续局序列从头，像"又重开一遍"）；满盘存档恢复后仍判"已结束"；12px 汉字对密笔画会糊成黑块 ⇒ 物品名必须 16px。
- **英雄坛说**：发布物是**单文件**（LAPP + 尾部 ZIP_STORED，`--@pkg offset/size` 回填）；运行时用 `app.pkg.self/read` + `app.img.load_mem`（只读该条目那段字节，不整包读入、不落盘）；`pack_single.py --check` 验 `offset+size==文件长度`、全 STORED、脚本区无 NUL。⛔ 固件无 WebSocket 客户端 ⇒ 官方登录/云存档做不了，**不摆假界面**。
- **收藏夹**：NVS `linfav`，密码段单独 AES-256-GCM（密钥走 `applock`），`s_encbuf` 24KB 静态 ⇒ 约 438 组封顶。⛔ **P0 未修**：导入备份后 RAM 里密码被清空，此后任意 `fav_save()` 会把 NVS 密文整份覆盖成空 ⇒ **密码永久丢失**。另有：密码走 URL query、导入写 `.dec.tmp` 明文、`nvs_commit` 在 IDF 6.0 是 no-op ⇒ blob/enc 可错配、`fav_save()` 不查返回值、导出先 remove 再 rename。
- **录音机**：录音异步（`rec.start()` 立即返回，CPU1 任务写盘）；`rec.peak()` 是**全程峰值只增不减**，实时电平用 `rec.spec(bin)`；只播 WAV，**无暂停/seek/变速** ⇒ ⛔ 界面不放假按钮；`fs.read` ≤512KB ⇒ 修不了 `data_len=0` 的坏文件；无 statfs ⇒ 没有剩余容量显示；标准扩展版**无麦克风**（`i2s_din=-1`）。
- **WIN 工作台**：⛔ 退出必须关 USB HID，否则串口被占（"退出后串口没了"）；触控板手势不是滚动，⛔ 不要套 `ui_scroll`；连 PC 时是 USB 复合模式，烧录要进下载模式；HID 只支持 US 布局。
- **矢量地图**：`fs.read` ≤512KB（大文件用 `read_at`）；`http_get` 只支持 HTTP 且 ≤4KB ⇒ 大包必须 `fetch_*`；坐标用整数微度先减后乘。**已知未修**：`files[]` 只处理前 30 条、`scan_pkgs` 只扫前 24 个条目（多了静默漏）；下载中退出**不删半包**。

## 7 Lua 弹窗结果的两个反直觉约定

- `app.dlg.list()` 的 result 是 **0 基下标**，`app.dlg.confirm()` 是 `0=确定 / 1=取消 / -1=返回`。混用就是"点了没反应"（旧版长按菜单点"删除"返回 1 被当成"播放"）。
- 长按弹窗依赖 OS 的"吞掉本次手势松手点击"（`os_dialog.c` 的 `s_swallow_tap`），否则松手那一下会投给新弹窗 ⇒ 弹窗一闪就没或误删。⛔ 应用侧不要自己做"等松手再弹"。
