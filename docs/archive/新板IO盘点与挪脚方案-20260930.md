## 三、怎么"挪出两个"—— 从屏上省，最多能省 4 个

| 方案 | 省 | 代价 | 建议 |

## 7.5 「RST 并到 EN」到底有什么用？（linit 2026-09-30 问）

### 先搞清楚 RST 是干什么的
屏控制器（如 ST7789 / ST7305）和触摸 IC（如 CST816）都有一根 **RESET/RES#** 脚：

1. **它必须接**（不能悬空）—— 芯片靠这根脚在上电时把自己初始化到确定状态；
2. 厂家给的初始化流程固定是：**上电 → RST 保持低一段时间 → 拉高 → 再发初始化命令序列**。

所以"省掉这个 IO"不等于"不接"，而是**把这根脚交给系统上电时序去管**，不再让 MCU 单独控制。

### 并到 EN 之后是什么效果
| 时刻 | 发生了什么 |
|---|---|
| 上电/复位 | EN 因为 RC 有 ~10ms 延时 → 屏/触摸的 RST 也一起保持低 ~10ms → **MCU 和屏同时被复位** ✓ |
| MCU 起来后 | 屏/触摸已经在确定状态，直接发初始化命令即可 ✓ |
| 运行中想复位屏 | ❌ 做不到（只能整机复位） |

**为什么通常没关系**：屏初始化失败时，**重发一遍初始化命令序列**就能救（ST7789 也有软复位命令 `0x01`）；触摸 IC 同理有软复位寄存器。
只有极少数情况需要硬复位（如 ESD 打完后芯片抽风），那种场景本来就该整机复位。

### 更稳的做法（同样省 1 个 IO，我更推荐）
**给 RST 自己一组 RC 自复位**：`RST ── 10kΩ ── 3V3`，`RST ── 100nF ── GND`
- 上电时时间常数 1ms → 屏在上电后约几 ms 释放复位 ✓ 完全够
- **优点**：与模块 EN 解耦（EN 上若有按键/复位芯片、或你以后加长 RC，都不会互相影响）
- **成本**：两个 0402 小件，可忽略
- **不推荐直接悬空**：没有上拉时引脚可能悬空在中间电平 → 芯片状态随机、甚至反复复位

### 什么时候**不要**省这个脚
- 屏/触摸的 datasheet 明确要求 RST 有**特殊时序**（例如必须保持低 >100ms，或必须在某个电源之后）；
- 你需要"运行中热复位屏"（比如做 ESD 恢复、或屏初始化有时序敏感的多路器件）。
⇒ 这两种情况就保留一个 IO 给它，改从"触摸 INT 改轮询"这类地方省。

> **顺带修正**：这块屏**没有背光** → 原稿里"BL 接 3V3 省 1 个"作废（本来就没这个脚）。
> 省脚总数不变：`LCD RST + 触摸 INT + 触摸 RST = 3 个`，加原有空闲 `GPIO4` = **4 个** → 扩展口照拿 **13/14/16/17** ✓
> 无背光还有个好处：**功耗更低** → 之前担心的"500mA 充电够不够"更没问题了。

# 九、`TP INT` 到底干什么、能不能省（代码级取证）

## 9.1 TP INT 的本职
触摸 IC（CST816 / GT911 / FT6236）都有 **INT** 脚：**检测到触摸就输出一个信号**（拉低或脉冲），
通知 MCU"有触摸事件了"。**它的意义是让 MCU 不必轮询** —— MCU 平时可以睡，被 INT 唤醒后再去读 I2C 拿坐标。

## 9.2 但你这套固件**根本没用它当中断**（实证）
| 证据 | 位置 | 说明 |
|---|---|---|
| INT 脚**没配中断** | `touch_panel.c:191/201` | `.intr_type = GPIO_INTR_DISABLE`（INT 和 RST 都是 disable） |
| 触摸数据靠**轮询读 I2C** | `touch_panel.c:536` `touch_panel_read_points()` → gt911/cst816/ft6236 三个分支都是读寄存器 | 没有 ISR、没有队列 |
| 调用方是**输入模块的每帧轮询** | `input.c:363` 调 `touch_panel_read_points()` | 跟随 OS 主循环（日志实测 60 FPS 模式） |
| INT 脚**唯一的实际用途** | `touch_panel.c:137-157` `gt911_reset()` | 只在 **GT911 复位时序**里当输出用，给 GT911 **选 I2C 地址**（INT 低 → 0x14，INT 高 → 0x5D），之后 `gpio_set_direction(..., INPUT)` |

**⇒ 结论：省掉 INT 不影响现有触摸读取逻辑**（本来就是轮询出来的）。

## 9.3 省掉之后要处理的一件小事 + 唯一真代价

| 项 | 说明 |
|---|---|
| **要改的一处** | **GT911 的地址选择**：现在靠复位时拉 INT 电平决定地址。改成 **TP INT 固定接 GND（地址 0x14）或接 3V3（地址 0x5D）**，固件里把 GT911 地址写死或让 `tp_probe_chip` 只探一个地址。<br>（若最终用 **CST816/FT6236** 就完全不用管 —— 它们没有地址选择问题 ✓） |
| ⛔ **不要真悬空** | 触摸 IC 的 INT 脚悬空不稳（易受干扰）。CST816/FT6236 建议给它 **10k 下拉到 GND**；GT911 就按上面固定到 GND/3V3 ✓ |
| ⚠ **唯一真代价** | **失去"深睡 + 触摸唤醒"**（深睡只能靠 GPIO 中断唤醒）。你们现在是**息屏/屏保但主循环仍在跑**（日志证实 60 FPS 常驻），所以**当前不影响** ✓ 只有以后想做"真待机、点屏唤醒"时才需要它 |
| 💡 折中（推荐） | **省掉这个 IO，但在板上留一个焊盘/测试点接到 TP INT**（不连 MCU）→ 以后要做触摸唤醒，飞一根线即可 ✓ 成本 0 |

## 9.4 轮询的开销（让你放心）
I2C @400kHz 读一次触摸（约 8 字节）≈ 180 µs；主循环 60 FPS、每帧读一次 → 约 **1% CPU**
（而且现在的板子就是这么跑的，实测无感）✓ 完全可忽略。

> **一句话**：INT 是"省电/免轮询"用的优雅方案，但**你的代码走的是轮询路线**，
> 所以这一个 IO 可以放心省 —— 只需处理 GT911 的地址（或干脆换 CST816/FT6236），并留个焊盘以后备用。
