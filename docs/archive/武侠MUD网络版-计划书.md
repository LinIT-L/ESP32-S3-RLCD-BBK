# 掌机版《英雄坛说》式武侠 MUD — 制作计划书

> 参考：`https://www.gmud.online/`（网页版《英雄坛说》，用户在此有账号）
> 平台：LinTOS 0.8 / ESP32-S3 / 400×300 1bpp / 6 键
> 目标：**可单机完整玩，架构上为"联机"预留**（用户要求"网络游戏"）

---

## 0. 调研结论（已核实，不是猜的）

`gmud.online` 打开后标题是 **《英雄坛说》**，页面上有这些选项：
`渲染 关闭 / 液晶1 / 液晶2 / 原版菜单 / 窗口大小 160*80 / 352*224 / 224*160`

→ 它是**文曲星（WQX）时代经典武侠 RPG《英雄坛说》的网页复刻**，原版逻辑分辨率就是 **160×80 单色 LCD**。

**原版玩法骨架**（这是要复刻的对象）：
- 建角色（姓名/性别/资质）→ 选**门派**（少林/武当/峨眉/丐帮/唐门…）
- **地图行走**（多张场景图，格子走动，遇 NPC/敌人）
- **回合制战斗**：招式 + 内力，命中/伤害/防御
- **武学修炼**：学新武功、练级提威力；**打坐/休息**回内力体力
- **经济**：钱庄/商店（药品、武器、防具、秘籍）
- **任务与成长**：NPC 委托、比武、等级/属性加点
- **文本为主 + 简单图形**（160×80 里就是几笔线条 + 大量汉字）

### ★ 关键技术分岔（必须先定，否则会白做）
| 路线 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. **跑原版 LAV 游戏** | 用项目已有的 lavax 文曲星引擎加载原版 `.lav` | 100% 原汁原味 | ① 需要原版 ROM/授权 ② 联机改造几乎不可能（黑盒） ③ 分辨率固定 160×80，只能居中缩在 400×300 里 | ❌ 不作为主路；**可作为"原版怀旧"彩蛋**（引擎已在固件里） |
| B. **自己写 Lua 版** | 用现有 Lua 应用框架重写玩法（数据驱动 + 复用刚做的 qqtang 架构） | ① 完全可控、可联机 ② 160×80 逻辑画布按 2 倍放大到 320×160，观感照样"原版" ③ 复用 `NET` 门面/存档/UI 模块 | 工作量大（内容型游戏，靠数据堆） | ✅ **主路** |

## 1. 单机 vs 联机（用户要求"网络游戏"，必须讲清前提）

**结论：联机必须有服务器。** 掌机只是客户端；两台设备要互相看见，必须有一个"共同真相"的地方。

| 方案 | 说明 | 本期 |
|---|---|---|
| **单机(离线)** | 全部逻辑在设备上，存档在 NVS | ✅ 先做（没服务器也能玩） |
| **联机(服务端权威)** | 服务器保存角色/世界/交易；客户端只发**意图**、收**事件** | ⏳ 预留（`NET` 门面 + 确定性世界 + 固定 tick，与 qqtang 同一套） |

**服务端选型（给用户拍板用）**：
| 选项 | 成本 | 说明 |
|---|---|---|
| 项目内置 **cloud-service**（云数据库 + 认证 + 免密钥 LLM） | 免费额度 | 最快：有现成的库/表/鉴权，适合"角色存档 + 排行榜 + 聊天"，**推荐起步** |
| 自建 VPS（Node/Go + WebSocket） | 服务器费 | 实时战斗/大地图同步更自由，但要自己运维 |
| gmud.online 那套 | — | 那是别人的服务，**不能也不应该**直接对接，只能当玩法参考 |

> ⚠ 我不会用你的 gmud 账号做任何事；参考仅限公开可看的玩法与界面。

## 2. 玩法设计（掌机适配后）

### 2.1 屏幕分配（400×300）
```
┌────────────────────────────┐ 0
│ 顶栏: 姓名 门派 等级 HP/内力 │ 24px
├────────────────────────────┤ 24
│                            │
│   游戏画布 320×160 (2×)      │  → 视口 = 160×80 逻辑像素 ×2
│   （地图/战斗/菜单都在这里）   │
│                            │
├────────────────────────────┤ 184
│ 正文: 对话/战斗日志 (16px)    │ 4 行 ≈ 96px
├────────────────────────────┘ 300
```
- **逻辑画布 160×80 ×2 = 320×160**，正是原版分辨率 → 用 `app.fill/px/texts` 画；文字用 8×12/16px。
- 下方留给**文本区**（MUD 的灵魂是文字），左右各留 40px 放"指令条"（`app.mix` 竖排提示）。

### 2.2 交互（6 键映射，与 qqtang 保持同一套肌肉记忆）
| 按键 | 地图 | 战斗 | 菜单/对话 |
|---|---|---|---|
| ↑↓←→ | 走动（按住，格子离散） | 选择指令/目标 | 上下选项 |
| 确认 | 交谈/进门/拾取 | 执行当前指令 | 确定 |
| 长按确认 | 打开**行囊**（同 qqtang） | 打开行囊 | — |
| 返回 | 打开**主菜单**（状态/技能/门派/存档） | 逃跑确认 | 返回一层 |

### 2.3 系统（数据驱动，加内容只加一行 —— 复用 qqtang 的 `ITEM/SKILL/MOB` 模式）
- **属性**：体力/内力/臂力/身法/悟性/资质；升级给点数
- **门派**：少林/武当/峨眉/丐帮/唐门（各自**入门要求 + 独门武功 + 师尊 NPC**）
- **武学**：`{name, 门派, 类型(拳/剑/刀/暗器/内功), 基础伤害, 内力消耗, 命中, 等级上限}`
- **战斗**：回合制；指令 = 攻击/招式/药品/逃跑；命中与伤害按 身法/臂力/内力 计算
- **物品**：药品（回血/回内）、武器/防具（加攻防）、秘籍（学武功）、任务物品
- **地图**：分场景（村镇/山门/野外/洞窟），每张图 = 一张 160×80 的瓦片图 + NPC/入口表
- **存档**：角色 + 背包 + 已学武学 + 进度（紧凑串，同 qqtang 的 `SAVE` 模式）
- **联机预留**：`聊天/排行榜/切磋` 三个动作走 `NET.emit`，单机时是本地直通

## 3. 架构（复用 QQ堂 已验证的骨架，不重造）
```
CFG  RNG  TILE            底层 (不依赖任何模块)
MAP  ENT  BATTLE  ITEM    中层 (地图/实体/回合战斗/数据表)
INV  SKILL  NPC/DLG  UI   上层
SAVE  NET                 存档 / 网络门面
GAME                      总装 (状态机: TITLE/MAP/TALK/BATTLE/BAG/MENU)
```
- **`BATTLE` 是本作新增的核心模块**（qqtang 是实时泡泡，这里是回合制）
- 其余模块**照搬 qqtang 的写法**（脏标记节流、固定 tick + 追帧护栏、内存上限、确定性 RNG）
- 屏幕/文字：160×80 逻辑画布 → 2 倍缩放绘制（一个 `put(x,y)` 辅助函数统一换算）

## 4. 里程碑
| # | 内容 | 验收 |
|---|---|---|
| M1 | 角色创建 + 门派选择 + 地图模块 + 160×80 画布 | 能选门派、能在村镇走动、能跟 NPC 对话 |
| M2 | 回合制 `BATTLE` + 野外遇敌 + 成长 | 能打赢/逃跑、升级加点、属性可见变化 |
| M3 | 物品/商店/武学/秘籍 + 行囊 | 能买卖、学武功、装备生效 |
| M4 | 任务/比武 + 存档 + 主菜单 | 退出重进进度在 |
| M5 | `NET` 门面 + 聊天/排行榜（单机直通的假实现） | 客户端接口跑通 |
| M6 | 接服务端（cloud-service 或 VPS）真正联机 | 两台设备能互相看见 |

## 5. 风险
| 风险 | 对策 |
|---|---|
| **内容量大**（内容型游戏靠数据） | 数据表驱动 + 先做 1 个门派 1 张图跑通，再按表扩 |
| 160×80 里汉字太小看不清 | 逻辑 2× 后 8×12 字变 16×24 → 一屏约 20 字 × 7 行，正好是 MUD 的量 |
| 联机改动面 | `NET` 门面 + 服务端权威 + 存**意图**不存状态（与 qqtang 同构） |
| 与文曲星引擎重复 | 明确分工：lavax 只跑"原版怀旧彩蛋"，主路是自带 Lua 实现 |
| 版权 | 只复刻**玩法**，不抄美术/文本；名称用自拟（避免直接叫"英雄坛说"） |

## v2 修正（v1 漏掉的 6 个关键设计 —— 每一个漏了都会返工）

### 2.6 ★ 160×80 画布的实际映射与相机（v1 只说"2 倍放大"）
- **逻辑单位 = 原版像素**。绘制辅助：`P.put(x, y, c)` → 实际写屏 `app.px(OX + x*2, OY + y*2, c)`（2×2 块），
  `P.rect/fill/text` 同理。汉字 8×12 逻辑 → 实屏 16×24，**一屏约 40 逻辑列 × 6.6 行**。
- 画布区 320×160（=160×80 逻辑×2），原点 `(OX,OY) = (40, 24)`（左右各留 40px 给指令条）。
- **地图比一屏大 → 必须相机**：地图 = 场景瓦片表（每瓦片 8×8 逻辑），视口 20×10 逻辑瓦片，
  相机跟随主角格子；绘制只跑可见瓦片（与 qqtang 的视野循环同构）。

### 2.7 ★ 回合制时序（v1 说"回合制"但没说怎么驱动、会不会卡 UI）
- **事件驱动，不用 tick 累积**：按确认 → 进"结算窗口"，用 `T`（毫秒计时）推进：
  `选出指令 → 300ms 播招式文字 → 结算伤害 → 敌人行动(如有先手权则战前) → 300ms 显示结果 → 回输入`。
- **先手权**：`先手 = 身法 + 随机(0..悟性/4)`；谁高谁先。两边都算完才算一回合。
- **绝不阻塞**：结算窗口期间 `poll()` 仍每帧跑，只是**不接受输入**（`BATTLE.lock`），
  这样按键不丢、UI 还能画数字飘字。回合数/连击用 `BATTLE.round` 记，便于以后联机校验。

### 2.8 ★ 滚动日志（MUD 的灵魂，v1 完全没写）
- 环形缓冲 `LOG.buf[6]`（6 行）+ `LOG.push(s)`；新行进顶部、旧行下移（或底部追加，二选一：
  **定"新行在底部"**，像聊天窗）。
- 行宽上限 `40 逻辑列`（≈320 实屏像素）：超长按 **UTF-8 安全**截断（`--` 补"…"不能用，用 ASCII "..")。
- 战斗/对话/拾取/系统提示**全部只通过 `LOG.push`**（不要各处直接画字），这样联机时能把服务器消息原样塞进同一管道。

### 2.9 ★ 战斗公式（不定死就没法调平衡）
```
命中   = 0.75 + (攻方身法 - 守方身法) * 0.02      钳制 [0.25, 0.97]
伤害   = max(1, 招式基础 + 臂力/3 - 守方防御/2)   × (1 + 内力加成)
内力   = 用招式扣 招式消耗；不足则只能"普通攻击"(伤害 ×0.6, 不耗内力)
升级   = 每级 +1 属性点、+体力上限；打坐回内力(按时间)、睡觉回体力(城镇)
```

### 2.10 ★ 对话/NPC 数据格式（MUD 的内容全在这里）
```lua
NPC.def[id] = { name=, tile=, x=, y=, scene=,
  talk = { { text="少侠何来?", opts={ { "拜师", goto="join" }, { "打听", goto="info" }, { "告辞" } } } },
           join = { text="...", require={ level=3 }, act="join_sect:shaolin" , opts={ {"多谢"} } },
           info = { text="...", opts={ {"知道了"} } } } }
```
→ 加一个 NPC = 加一条数据；**分支用 `goto` 指向同一张表里的 key**（不用写代码）。

### 2.11 ★ 联机权威规则（不先定，以后会把存档写坏）
- **服务器权威**：角色属性/背包/银子/位置**只有服务器能改**。客户端 `NET.emit` 只发**意图**
  （`move/talk/attack/buy/use`），收到 `NET.on` 的**事件**才改本地显示。
- **单机模式**：`NET` 直通 + `SAVE` 落 NVS；**联机模式**：`SAVE` 只做**离线缓存**，
  且**禁止本地写关键数值**（只在"未连接"时允许），避免"本地改档覆盖服务器"。
- 判定方式：`NET.mode = "local" | "online"`，所有写操作前先问它（一处判断，不散落）。
