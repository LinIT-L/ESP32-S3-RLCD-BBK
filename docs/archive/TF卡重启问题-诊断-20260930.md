## 〇、先给结论

**你的三根信号线 + 两个上拉是对的**（1-bit SD 就该这样：CMD 上拉、DAT0 上拉、CLK 不上拉 ✓）。
**问题不在信号线，最可能是"电源"** —— 实证：

> 整条 **`VCC3V3` 网络有 19 个引脚**（WROOM 模组 + TF 卡座 + LCD 排线 3 脚 + 无线模块 4 脚 + 多个上拉 + 8P 排针），
> **却只有 C1、C2 两颗 0603 电容**（工具还把它们报成"疑似重复放置"）。
> TF 卡座 `SD1.4` 就挂在这条轨道上，**卡座近端没有专属储能电容**。

**TF 卡读卡瞬间电流会冲到 50~100mA（突发）** → 3V3 被拉低 → 低于芯片欠压复位阈值 → **BROWNOUT 复位**。
**"不插卡就正常、插卡一读就重启"正是这个的典型表现。**

## 四、两个代码级隐患（值得一并处理）

### 4.1 `allocation_unit_size`：**更正** —— 它其实不是元凶（已改，但属"顺带减负"）

> ⚠ **先更正我前面的话**：我按经验说"16KB 会撑爆 DMA 缓冲"，随后**去翻了 IDF 源码**核实，
> 结论是**这个说法不成立**：
> - `ff.c:1679` 显示 `allocation_unit_size` 只用于**格式化时**算簇缓冲（还有 fallback 逐次减半）
> - FatFs 的读窗口缓冲固定是 `SS(fs)` = **512 B**（`ff.c:3446`），不是 16 KB
> - `ff_memalloc` = 普通 `malloc()`（`fatfs/src/ffsystem.c:22`），512B 小分配按 IDF 默认会落在内部 RAM
>
> 所以它**不是**崩溃原因。仍改成 `0`（= 按扇区）的理由只有一个：万一走到 format 分支不必一次要 16KB 连续内存。
```c
esp_vfs_fat_sdmmc_mount_config_t mount_cfg = {
    .format_if_mount_failed = false,
    .max_files = 5,
    .allocation_unit_size = 16 * 1024,   // ← 16KB
};
```
FATFS 会按这个簇大小做读写缓冲，而 **ESP32-S3 的 SDMMC 走 DMA，缓冲必须在内部 RAM 且连续**。
你们内部 RAM 本来就紧（还挂着蓝牙/音频/无线服务）→ **16KB 连续 DMA 块很容易分不出来**：
失败时若代码没判空就去读 → **PANIC 重启** ✓
**建议**：先改成 **`4 * 1024`**（甚至 0 = 按卡自动）。这一步和 §三-3 的日志一起看，5 分钟能确认。

### 4.2 引脚不是 SDMMC 的 IO_MUX 默认脚
ESP32-S3 的 **SDMMC slot 1** IO_MUX 是 `CLK=39 / CMD=38 / D0=40`；
你们用 `CLK=38 / CMD=21 / D0=39` → **三个脚全走 GPIO 矩阵**（官方板也是这接法，能用，**但高速时更挑信号与电源**）。
⇒ 所以 **"先降速验证"是最有效的判定手段**；如果降速后一切正常，就把板子的电源/走线补强，或把 CLK/CMD 换到 IO_MUX 的脚上（CLK=39/CMD=38/D0=40）。

# 六、电容到底加多少（linit 2026-09-30 问）

**设计依据**：SD 卡协会的 SD 卡座设计指南就是「**卡座 VDD 就近 0.1µF + 附近 10µF**」，

## 6.1 建议加的位置与容值

| 优先级 | 位置 | 容值 | 封装 | 说明 |
|---|---|---|---|---|
| **★★★** | **TF 卡座 VDD 引脚旁（≤3mm）** | **0.1µF** | 0402/0603 | SD 规范要求的高频去耦 |
| **★★★** | **TF 卡座 VDD 附近** | **10µF** | 0805 X5R | 吸收读卡突发（50~100mA）|
| **★★★** | **TF 卡座 VDD（飞线也行）** | **100µF** | 钽 A/B 壳 或 聚合物铝电解 | **专治 brownout**，耐压 6.3V 够 |
| **★★** | **3V3 主轨（buck 输出 / L1 之后）** | **22µF × 2** | 0805 X5R | 现在整条 19 脚轨道只有 C1/C2 两颗 0603 → **太小** |
| ★★ | 3V3 主轨 | 0.1µF | 0402 | 全频段补 |
| **★★** | **无线模块 U5 的 VCC（3 个脚）** | **10µF + 0.1µF** | 0805/0402 | 三个 VCC 脚 = 发射突发电流大 |
| ★ | LCD 排线 3V3 | 1µF + 0.1µF | 0603/0402 | 反射屏刷新电流小，够 |
| ★ | 8P 排针 3V3 | 0.1µF（可选） | 0402 | 外接设备时有用 |

**只加能加的几个的话**：① TF 座 `10µF + 0.1µF`（最关键）→ ② TF 座 `100µF 钽`（飞线最快）→ ③ 3V3 主轨 `22µF × 2`

## 6.2 选型与布线要求（这几点比容值还重要）

| 项 | 要求 |
|---|---|
| 介质 | **X5R / X7R**（别用 Y5V —— 容量随温度/偏压掉得厉害） |
| 耐压 | 3.3V 轨用 **6.3V（钽）/ 10V（陶瓷）** 足够 |
| 100µF | 优选 **钽 或 聚合物铝电解**（普通铝电解 ESR 高、瞬态差） |
| **地回流** | 电容的 GND **就近回到卡座/负载的 GND**，不要跨区、不要长线回流 |
| **VDD 走线** | 尽量短、**≥0.5mm (20mil)** 宽 |

## 6.3 怎么验证加够了
用示波器（或万用表峰值/最小档）看**插卡/读卡瞬间 3V3 的跌落**：
- **< 100 mV** → 合格 ✓
- 100~300 mV → 勉强，建议再加
- **> 300 mV** → 还会复位，继续加 or 查走线/GND

# 七、为什么别人说"接四根线、CS 接地"？

因为**他们说的是 SPI 模式，你用的是 SD 模式 —— 两种不同协议**：

| | **SPI 模式**（别人说的） | **SD 1-bit 模式**（你的板子） |
|---|---|---|
| 线数 | **4 根**：`CS` + `CLK` + `MOSI(DI)` + `MISO(DO)` | **3 根**：`CLK` + `CMD` + `DAT0` |
| CS/片选 | **需要**（CS 选中卡片） | **不需要**（由 CMD 线上的协议承担） |
| 速度 | 慢、CPU 占用高 | 快（硬件控制器 + DMA）|
| 固件 | `sdspi` 驱动 | `sdmmc` 驱动（**你用的这个** ✓）|

**"CS 接地"是 SPI 模式下的省事接法**：总线上只有一张卡时，把 CS 直接接地（永远选中）也能跑。
对 microSD 来说，**上电时若 CS/DAT3 保持低，卡会进入 SPI 模式** —— 所以"脚 2 接 GND"确实能让卡按 SPI 工作。

## ⛔ 但你的板子**千万别**这么做

microSD 脚位：3=CMD · 4=VDD · 5=CLK · 6=VSS · 7=DAT0 · **2=CS(SD 模式则是 DAT3)**
你的固件走 **SDMMC 硬件控制器** → 必须是 **3 线 + 脚 2 保持不接地**（悬空或上拉）。
**把脚 2 接 GND = 强行把卡推进 SPI 模式 → 你的 SDMMC 永远挂不上** ✗

> 💡 **顺便一个很值得量的检查**：用万用表量**卡座脚 2 对 GND 的阻值**，应该是**高阻/断路**。
> 有些便宜卡座的脚 2 内部被接到外壳/GND（或与屏蔽脚短接）→ 卡被钉在 SPI 模式 → 表现就是"卡永远无响应"。
> 这个检查 10 秒，能排掉一整类"挂不上"的怪问题。
