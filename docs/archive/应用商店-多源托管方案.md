# 应用商店 · 多源托管与中转方案（2026-10-04 · 明确不用腾讯）

> lininit 需求原文：「我需要**中转**，不然后期更新很麻烦；需要单纯访问一个链接获取应用列表和相关信息，
> 然后点击下载，**下载失败就切换另外一个**；我有一个域名但想要几个下载源，需要稳定。
> 你先搞一个方案，**首先我不要腾讯了**。」

## 0. 一句话结论

**一个稳定入口（你要的"中转"）= `https://bbk.linit.cn/bbk/`**，
它背后挂 **N 个下载源**；**后端换源设备完全无感**；设备侧再自带一份"直连备源清单"兜底。

分两层切换，覆盖两种故障：

| 层 | 谁在切 | 故障场景 | 设备感知 |
|---|---|---|---|
| **① 中转层（服务器 nginx）** | 服务器自动切后端 | 某个对象存储/Gitee 挂了、慢了 | **完全无感**（设备永远只访问一个域名） |
| **② 设备层（`mirrors[]`）** | 设备依次尝试 | **整个域名都不可用**（服务器宕机/DNS 挂了） | 自动切到直连备源，用户只看到"重试中" |

> 为什么两层都要：只用 ①，服务器挂了就全灭；只用 ②，你就得维护多个源地址、每次换源都要改固件。
> **① 解决"换源麻烦"，② 解决"入口单点"。**

        │  git push（你已有的习惯，唯一发布动作）

## 3. `index.json` 设计（**换源不用改固件**）

关键两点：**① 只存相对路径；② 内嵌 mirrors 列表。**

```json
{
  "ver": 4,
  "mirrors": [
    "https://bbk.linit.cn/bbk",
    "https://<bucket>.<region>.aliyuncs.com/bbk",
    "https://gitee.com/<账号>/ESP32-S3-RLCD-BBK/raw/master/store"
  ],
  "pkgs": [
    { "name": "qqtang", "label": "QQ堂冒险", "cat": "app", "ver": 6,
      "size": 45056, "crc32": "1a2b3c4d",
      "path": "pkgs/qqtang.lua" },
    { "name": "wuxia", "label": "英雄坛说", "cat": "app", "ver": 3,
      "size": 64512, "crc32": "9f3e0a71",
      "path": "pkgs/wuxia.lua" }
  ]
}
```

设备侧拼 URL：`mirrors[i] + "/" + pkg.path`。
⇒ **加源/换源 = 改这个 json 里的 `mirrors[]`，固件一行都不用动。**

`index.json` 本身也要多源：设备按 `mirrors[i] + "/index.json"` 依次试。

## 4. 中转层：nginx 配置（核心是"后端挂了自动换"）

```nginx
# /etc/nginx/conf.d/bbk.conf   —— bbk.linit.cn
upstream bbk_backend {
    server 127.0.0.1:8080;                                  # A. 本机静态(最优先, 0 成本)
    server <bucket>.<region>.aliyuncs.com:443 backup;       # B. 阿里云 OSS
    server gitee.com:443 backup;                            # C. Gitee raw
    keepalive 8;
}

server {
    listen 443 ssl http2;
    server_name bbk.linit.cn;
    # ssl_certificate ...;  ⚠ 必须开自动续期, 证书过期=设备下载直接失败

    location /bbk/ {
        proxy_pass         https://bbk_backend/bbk/;
        proxy_http_version 1.1;
        proxy_set_header   Host $proxy_host;
        proxy_set_header   Connection "";

        # ★ 关键: 后端超时/5xx 自动换下一个, 设备完全无感
        proxy_next_upstream        error timeout http_502 http_503 http_504 invalid_header;
        proxy_next_upstream_tries  3;
        proxy_next_upstream_timeout 10s;
        proxy_connect_timeout      3s;
        proxy_read_timeout         30s;

        proxy_buffering on;                     # 让 nginx 缓冲, 设备侧慢也不拖后端
        add_header Cache-Control "no-store";    # 商店索引要即时
    }

    # 可选: 走本机静态目录直出(比反代快, 适合主后端就是本机的情况)
    # location /bbk-local/ { alias /srv/bbk/; }
}
```

> **这就是你要的"中转"**：设备永远只认 `bbk.linit.cn`，后端在服务器上换，**设备不用改、不用重新配**。

## 5. 自动化：你只 `git push`

`.github/workflows/store-sync.yml`（示例骨架）

```yaml
name: store-sync
on:
  push:
    paths: ["store/**"]
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: 计算每个包的 size/crc32 → 生成 index.json
        run: python tools/store_index.py --src store --out store/index.json
      - name: 上传到本机(linit.cn)
        run: rsync -az --delete store/ ${{ secrets.LINIT_SSH }}:/srv/bbk/
      - name: 上传到阿里云 OSS
        run: ossutil cp -rf store/ oss://<bucket>/bbk/ -e <endpoint> -i ${{ secrets.OSS_AK }} -k ${{ secrets.OSS_SK }}
      # Gitee 走它自己的「GitHub 导入 + 定时同步」, 不用在这里做
```

**这样"后期更新"就只有一步：改包 → `git push` → 所有源自动同步。**

## 6. 设备侧要补的（这是工程，不是改地址）

| 缺口 | 做法 | 优先级 |
|---|---|---|
| **下载→落盘** 链路 | 现在 `app.net.http_get` 只把内容放 PSRAM 不落地。新增"下载到文件"：**优先落 TF** `/sdcard/store_pkg/`（商店已有的第二源，扫描逻辑零改动） | ★★★ |
| **多源依次尝试** | 按 `mirrors[]` 顺序：`index.json` 失败换下一个；某个包的 URL 失败换下一个 mirror 拼同一 `path` | ★★★ |
| **校验** | 下完对 `size` + `crc32`；不符就删掉重试下一个源（**必须**，半包会让应用一打开就崩） | ★★★ |
| **进度与重试** | "下载中 x% / 第 2 个源重试" —— 否则用户以为死机 | ★★ |
| **HTTPS 的 RAM** | TLS 握手+缓冲 ~30–50KB 内部 RAM；把 httpd 缓冲调小、**同一时刻只跑一个 TLS**；验收 `remcon audit` 的 `largest ≥ 8KB` | ★★ |
| **写 SPIFFS 的坑** | `/store/apps/` 写入会**禁 Flash cache** → 必须跑**专用内部 RAM 栈任务**，否则崩；所以**优先 TF** | ★★ |
| **大素材** | `wuxia` 素材 1.8MB 是大头。**先让素材随固件烧录，只有 `.lua` 走网络**（最省事） | ★ |

**单包很小**：`qqtang 44KB + wuxia 63KB + biossim 212KB + planeradar 29KB ≈ 350KB`，1M 带宽够用。

## 7. 落地顺序（我建议）

| 步 | 做什么 | 谁 |
|---|---|---|
| 1 | 在 `bbk.linit.cn` 上开 `/srv/bbk/`，nginx 加一个 `location /bbk/`（先只指向本机静态） | 你（5 分钟） |
| 2 | 传一份 `index.json` + 4 个 `.lua` 上去，**手机浏览器点一下确认能下** | 你 |
| 3 | 我把固件侧"下载→落盘→多源切换→crc32 校验→进度"做出来 | 我 |
| 4 | 接第 2 个后端（阿里云 OSS）并打开 `proxy_next_upstream` | 我（用 WorkBuddy 的连接器） |
| 5 | 加 GitHub Action 自动扇出，之后你只 `git push` | 我 |
| 6 | （可选）Gitee 镜像 + `mirrors[]` 里补直连备源 | 你/我 |

> ⚠ **第 1 步里最容易忘的一条**：**HTTPS 证书的自动续期必须开着**。
> 证书过期 = 设备下载**直接失败**，而且现象和"网络不好"一模一样，极难排查。
