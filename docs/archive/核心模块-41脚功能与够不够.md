### 28/29 脚详解：`LGS4056_CHRG` / `LGS4056_DONE`

**LGS4056 是什么**：力格(Legend-Si)的 **1A 单节锂电线性充电 IC**（4056 家族，与常见的 TP4056 同类）。
4 段充电（短路→涓流→恒流→恒压 4.2V 截止），充电电流由 PROG 电阻设定（最大 1A，**电阻在模块内部**），
输入 4~6V（正好吃 USB 5V），静态 40µA、电池漏电 <1µA，带 OVP/UVLO/过温降流。

这两个焊盘是它的**两个开漏状态输出**（低有效）：

| 焊盘 | 状态 | 电平 | 含义 |
|---|---|---|---|
| **29** | `LGS4056_CHRG` | **充电中：拉低**；其余高阻 | USB 插着且正在充 |
| **28** | `LGS4056_DONE` | **充满：拉低**；其余高阻 | 充到 4.2V 且电流降到 1/10 后 |
| — | 两个都高阻 | — | 没插充电器（或电池未接/异常） |

**原厂板的用法（从网表反推）**：`CHRG` → `R8` → `LED3` → `VBUS`（**充电时点亮那颗指示灯**），
同时引到 `IO41` 让 MCU 可读；`DONE` 只引到 `IO14` 给 MCU 读（没配灯）。

**你三种用法（可组合）**：

| 用法 | 占 GPIO | 说明 |
|---|---|---|
| **a. 纯 LED** | **0 个** ⭐ | `3V3 → LED → 限流电阻 → CHRG/DONE`。充电中亮一个、充满亮另一个。**不占 GPIO**，对"现在差 5 个脚"的预算最友好 |
| **b. 接 GPIO 读** | 2 个 | 各接一个 GPIO（用 `IO14`/`IO41` 或自选），**该 GPIO 必须开内部/外部上拉**（开漏输出，不拉低时高阻）→ 固件可判"充电中/已充满/未充电"，状态栏画充电图标 |
| **c. LED + GPIO 并联** | 2 个 | 开漏互不影响，同时做 |

**注意**：
1. ⚠ **必须上拉**才能读到电平（接 GPIO 的那路上拉到 **3.3V**，**绝不能上拉到 5V**）。
2. 它们是**充电 IC 的输出**，不是 GPIO —— **别用 MCU 去反向驱动**（会打架）。
3. 4056 是**线性充电**：1A 时 IC 自身要耗 ~1W → 模块/PCB 得铺铜散热；实际充电电流要问厂商。
4. "两个都高阻"也可能表示**电池未接**（4056 对空载状态会异常翻转）→ 可当"电池异常"判据用。

**对项目的价值**：`docs/硬件与IO.md` 写的是"TP4056 类 … **CHRG/STDBY 未接 MCU**，想启用要飞线 + 固件加
`board_battery_charge_state()`"。换成这个模块**这一步白得** —— 只要把线接上（甚至只用 LED），
固件侧加个"读 2 个 GPIO → 状态栏充电图标"就完事。

### ⚠ 充电电流：**在模块这一层改不了**

**实测依据（都查过了）**：
- 模块符号 41 脚里 **`PROG` / `CE` / `TEMP` 都没有引出** —— 只有 `BAT`(23)、`5V`(26)、`3V3`(2) + 状态脚 28/29
- 原厂底板网表上**也没有任何 PROG 电阻**（接 GND 的电阻只有：`R1/R2`=CC 5.1k、`R6`=LED、`R9`=4G 开关、
  `R13`=升压 FB、`R23/R25`=4G 控制）
⇒ **设定充电电流的 `R_PROG` 焊在模块内部**，外面碰不到，也**没法用软件直接改**（CE 没引出，连开关充电都做不到）。

**4056 家族的充电电流公式**（要改值的话得换这颗电阻）：

| `R_PROG`（PROG→GND） | 充电电流（用 1200 常数） | （用 1280 常数） |
|---|---|---|
| 10 kΩ | 120 mA | 128 mA |
| 5 kΩ | 240 mA | 256 mA |
| 4 kΩ | 300 mA | 320 mA |
| 3 kΩ | 400 mA | 427 mA |
| **2.4 kΩ** | **500 mA** | 533 mA |
| 2 kΩ | 600 mA | 640 mA |
| 1.5 kΩ | 800 mA | 853 mA |
| **1.2 kΩ** | **1000 mA** | 1067 mA |

> `I_BAT ≈ 1200~1280 / R_PROG`（PROG 脚恒流阶段被钳在 1V）—— 具体常数看厂商 datasheet，
> 4056 家族在 1200~1280 之间浮动（±7%）。

**能做的替代路径**：

| 办法 | 可行性 | 代价 |
|---|---|---|
| **问厂商"默认充电电流多少"**（推荐先做这个） | ✅ 必做 | 决定你配多大电池：默认 1A → 电池≥1000mAh；默认 500mA → 约 1000mAh 最合适（0.5C） |
| 接受默认值 | ✅ 最省事 | 只能靠"配对应容量的电池"来匹配，不能选值 |
| 拆模块换内部 `R_PROG` | ⚠ 物理可行（模块若是普通 PCB 未灌封） | 破坏性；需先量出原值；不推荐量产用 |
| 输入侧限流（弱一点的 USB 源/串限流） | ⚠ 间接 | 输入会被拉低 → 芯片反复进 UVLO/降流，电流不精确、充电时间不可控 |
| 靠过温自动降流 | ⚠ 被动 | 结温 >145℃ 才降，不可选值，且等于"靠发热限流" |
| **不给模块 `5V`，用外部可编程充电 IC 接到 `BAT` 脚** | ✅ 电气上可行（`BAT` 已引出；4056 无输入时电池漏电 <1µA，不会打架） | 等于自己重做充电（含过充保护）——那不如直接用 AXP2101 类 PMIC |

**再提醒两点（4056 的固有短板，与电流无关）**：
1. **线性充电、无电源路径（no power-path / NVDC）** → 插着 USB 时**系统仍从电池取电**。
   "边充边用"时实际进电池的电流 = 充电电流 − 系统消耗，**系统耗电大时电池甚至不掉反降**。
2. 1A 时 IC 自身耗 ~1W（5V 进 / 4.2V 出，效率≈84%）→ **发热明显**，要铺铜；想快充又低热得上开关充电（AXP2101 那类）。

### 「默认充电电流到底多大」—— 工程里查不到，但有两条确定路径

**查不到的依据**：`R_PROG` 在模块内部（PROG 脚未引出）；工程库里 `LGS4056HDA` 器件**没有供应商参数**（厂商自画符号）；
`ESP32-S3-AI-2` 的 `Datasheet` 字段为空；公开检索也没有该模块的充电电流数据。

**① 实测（最靠谱，5 分钟）**
- **最准**：万用表 mA/A 档**串在电池正极与模块 `BAT`(23) 脚之间** → 恒流阶段读数就是充电电流
  （⚠ 用 **1A 档以上**，表内阻会让读数略偏小，但判断 500mA 还是 1A 足够）
- **更省事**：USB 电流表插在充电头与 Type-C 之间 → 输入电流 ≈ 充电电流 + 系统消耗
  （把屏关掉/断外设把系统消耗压到最低再读）
- 读的时候注意：**电池在 3.7~4.0V 区间**才是恒流阶段（>4.1V 进恒压，电流会自然下降，不能误判）

**② 问厂商一句**：`格子派 ESP32-S3-AI-2 的默认充电电流是多少 mA？`（商品页/客服）
或**拆模块量 `R_PROG`**：LGS4056 的 PROG 脚到 GND 的电阻值 → 1.2kΩ≈1A，2.4kΩ≈500mA，5kΩ≈240mA

### 「适合我吗」——判据表（需要你的电池容量才能定论）

锂电最佳充电电流 = **0.5C**（保守）~1C（激进）：

| 电池容量 | 若默认 **500mA** | 若默认 **1A** |
|---|---|---|
| 500 mAh | 1C（可以，但偏热） | **2C ✗ 过流**，发热/折寿，不建议 |
| 1000 mAh | **0.5C ✅ 最理想** | 1C ✅ 可以 |
| 2000 mAh | 0.25C（偏慢但最护电池） | **0.5C ✅ 最理想** |
| 3000 mAh | 0.17C（很慢，充满要 6~7h） | 0.33C（慢，可接受） |

**除了电流，还有两个"适不适合"的硬指标**（比电流更影响体验）：
| 指标 | 你这边的关注点 |
|---|---|
| **无电源路径** | 如果设备经常**插着 USB 用**（桌面模式），充电电流会被系统消耗吃掉甚至倒扣电 —— 这是 4056 的硬伤 |
| **线性充电发热** | 小壳内 + 模块紧贴 WiFi 天线/电池 → 500mA 比 1A 更稳；1A 要确认模块散热够 |
| **充电速度** | 2000mAh 电池想 1 小时充满 → 需 ≥1A；若模块默认 500mA 就**不够**，得快充就得上 AXP2101 那条路 |

## 三、怎么补足（按代价排序）

| 方案 | 省几个脚 | 代价 |
|---|---|---|
| **A. 音频改用模块自带的**（VOP/VON 接喇叭、MIC1/2 接麦） | **省 6**（I2S 5 + MIC 1） | 音频驱动要重写（模块内置 codec，**需要厂商给型号/控制接口**）；但喇叭/麦本来就得接，等于白拿 |
| **B. 充电只点灯（不接 GPIO）+ 去掉自建电池 ADC** | 省 1（空出 GPIO4） | 只能看灯，读不到电量百分比。**若想进 UI 显示，则要花 1~2 个 GPIO 去读 CHRG/DONE** → 那就不是省了（读 1 个=净 0，读 2 个=净 +1） |
| **C. 震动改单脚**（PWM 与 EN 合并 / 用内部上拉） | 省 1 | 省电控制变弱 |
| **D. GPS 不接 EXTINT**（只收 NMEA） | 省 1 | 失去"外部中断唤醒定位"的能力 |
| **E. 触摸只接 I2C 两线**（不接 INT/RST） | 省 2 | 触摸响应改轮询；RST 不接则只能软复位 |

**推荐：A + B**（省 7）→ 需求从 28 降到 **21**，模块给 24 → **余 3 个**，正好把 `IO6/IO13/IO14` 留作以后扩展。

**若坚持用外部 I2S + 外部麦**：只做 C+D+B（省 3）→ 需求 25、可用 24 → **还是差 1**，必须再砍一项（例如触摸 INT 不接）。
