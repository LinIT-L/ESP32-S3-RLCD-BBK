# 频谱仪应用 (page_sdr) — 2.4G 原始 I/Q 本机 FFT 上屏

> 一句话：**官方 ESP-SDR 的瓶颈是"把 2.56 Gbit/s 原始流搬出去"，而频谱/瀑布图只要片段做 FFT
> —— 所以本机算完只画一张图，数据一步不出芯片，占空比不再是问题。**

来源：ESPARGOS/esp-sdr（MIT/开源）的 ESP32-S3 采集实现，去掉 UART/命令行/打包，只留采集。

---

## 1. 文件与分层

| 文件 | 层 | 职责 |
|---|---|---|
| `components/drivers/espsdr/include/espsdr.h` | L1 驱动 | 对外 API（enter/exit/tune/gain/capture/iq） |
| `components/drivers/espsdr/espsdr.c` | L1 驱动 | 64KB SRAM 保留 + PHY 准备 + 突发采集寄存器序列 |
| `components/drivers/espsdr/sram_guard.ld` | — | 链接期断言：静态段不得侵入 0x3fcd0000 |
| `components/apps/pages/page_sdr.c` | L4 应用 | UI：频谱曲线 + 瀑布 + 触摸/按键（esp-dsp 做 FFT）|
| `components/system/os/include/os_app_api.h` | 门面 | 导出 `espsdr.h` + `os_hw.h`（与 st7305/sd_scan 同惯例）|

依赖登记：`os` 组件 REQUIRES 里加了 `espsdr`（跟 st7305/sd_scan/board_battery 一样）；
`apps` REQUIRES 里加了 `espressif__esp-dsp`（FFT，托管组件）。`check_deps.py` 现在 0 隐藏依赖 ✓

## 2. 数据链

```
espsdr_capture(2048, 80MSa/s)          ← 64KB 突发缓冲里的前 2048 个样本
   ↓ 取 I/Q (bit19-10=I, bit9-0=Q, 有符号10bit, /512 归一化)
   ↓ 去 DC (减均值) + Hann 窗
dsps_fft2r_fc32 + dsps_bit_rev_fc32     ← esp-dsp, 走 S3 向量指令
   ↓ dB = 10log10(|X|²)   (fftshift: bin k ↔ f = (k-N/2)·80M/N)
   ↓ 2048 bin → 400 列 (每列取区间**最大值**, 窄带信号不会被抽掉)
   ↓ 中心 ±1 列做 DC 修补
   ↓ 指数平均 (AVG 1/4/16)
上半屏: 每列从底部填到该列 dB     下半屏: 130 行瀑布位图整块 blit (1bpp)
```

**性能预算**（S3 @240MHz）：采集 2048 点 ≈ 26 µs · FFT 2048 点 ≈ 1~2 ms · 绘制 ≈ 1~2 ms
→ 刷新节拍设 **100 ms（10 Hz）**，CPU 占用个位数百分比。

## 4. 关键实现点（都是踩过的坑）

1. **64KB SRAM 必须是保留区**：`SOC_RESERVE_MEMORY_REGION(0x3fcd0000,0x3fce0000,s3_rf_dump)`
   （宏在 IDF 的 **`heap_memory_layout.h`** 里 —— 官方那行 include 很容易漏，漏了编译就报
   "expected declaration specifiers before numeric constant") + `sram_guard.ld` 三条 ASSERT。
2. **采集序列顺序不能改**：填哨兵 → 配 pack 寄存器(0x60033d90) → 把 0x600c101c 的
   MAC_DUMP_USAGE 置 4（**这块 SRAM 交给 modem**）→ 写控制字(0x60033d5c) → 再写 `ctrl|(1<<19)` 触发
   → 轮询 bit18 完成（超时 20 ms）→ 关控制字 → **把 SRAM 还给 CPU**（异常路径也要还，否则下次抓不到）。
3. **增益符号在 IDF 版本间改过名**：官方用 `librftest.a` 的 `force_rx_gain(manual,code,0)`，
   但 IDF **默认不把 librftest.a 挂进链接** → 链不过；`libphy.a` 里有等价的
   **`phy_force_rx_gain(manual, code)`**（官方 S31 路径用的就是它）→ 本项目用后者。
4. **射频独占**：进入时 `wifi_manager_disable()` → `os_hw_request(OS_HW_WIFI)` → espsdr_enter()
   （起 WiFi NULL 模式 + 混杂模式 + PHY 上电序列）；退出反向归还，并按进入前的状态
   `wifi_manager_enable()` 恢复用户联网。**期间 WiFi/BT 不能用**。
5. **采集窗口内不要写 flash**（NVS/日志落盘会禁 cache）→ 本页热路径刻意不打日志。
6. **零中频的固有毛病**：正中一根 DC 尖刺 + 镜像 → 去均值 + 中心 ±1 列修补；
   增益跳变会毁幅度 → 想稳定就切**手动固定增益**。

## 5. 上机必验清单（未上机，先列出来照单核对）

| # | 看什么 | 期望 |
|---|---|---|
| 1 | 启动日志有无 `ESPSDR: PHY 就绪` | 有 → PHY 接管成功 |
| 2 | 屏幕状态行是否出现频率/增益 | 有 → 渲染链通 |
| 3 | 是否显示"采集超时" | 若显示 → PHY 序列/寄存器与实际不符（重点查 ①③） |
| 4 | 频谱上能否看到 2.4G 的 WiFi/BLE 能量包 | 能 → 采集+FFT 正确 |
| 5 | 退出后 WiFi 是否恢复（设置页看状态） | 恢复 → 归还链正确 |
| 6 | 拿手机开热点/遥控器在附近发信号，看瀑布是否出现竖线 | 有 → 全链路可用 |

区分"没触发"（寄存器不对）与"触发但没写"（SRAM owner 没交出去）。

## 6. 已知限制（别指望它做不到的事）

- **量化 10 bit** → 动态范围有限，强邻道 + 弱信号会吃力
- **模拟带宽 ~13–54 MHz**，两端有滚降 → 显示跨度默认 ±16 MHz（避开边缘）
- **单芯片单天线 → 做不了测向**（那要 ESPARGOS 那种多天线相位相干）；配定向天线可手动扫方向
- **与 WiFi/BT 互斥**（射频独占）
- **幅度是相对的**：没做绝对 dBm 校准，用于"比较大小/找干扰"足够
- 寄存器属**未文档化**功能，Espressif 未承诺 → 换 IDF/芯片版本要重验

### 0. 一句话

Espressif 的 ESP32 里**藏了一条没写进文档的通路**：固件可以**绕开** WiFi/蓝牙的固定硬件调制解调器，
把**射频原始 I/Q 采样**直接抓进内存。于是**几块钱的 ESP32 就成了一台软件无线电（SDR）接收机**，
**不用加任何硬件**。

---

### 1. 它抓的到底是什么：**原始 I/Q 基带样本**

#### 1.1 射频链在哪一步被"截"
```
天线 → LNA/混频 → 低通滤波 → 【ADC 采样】 → ⛔硬件调制解调器(WiFi/BT) → 协议栈
                                    │
                                    └─★ ESP-SDR 从这里的"调试出口"把数据旁路进 SRAM
```

#### 1.2 I/Q 是什么，为什么"原始"这么关键
- ADC 采出来的是 **I（同相）+ Q（正交）两路**数字基带 → 合起来是一个**复数**
- 复数同时带 **幅度和相位** —— **相位**才是能做"相干处理/测向/雷达"的东西
- 正常路径下，ADC 数据**直接喂给硬件调制解调器**（去解 OFDM / 蓝牙跳频），软件只能看**解出来的结果**
- ESP-SDR 让软件拿到**调制解调器之前**的数据 → 空口上的**一切**都在里面（信号、干扰、噪声、脉冲）

#### 1.3 每个样本 32 bit 的构成（他们的实测格式）
| 位 | 含义 |
|---|---|
| bit 19–10 | **I**（有符号 10 bit，−512…+511）|
| bit 9–0 | **Q**（有符号 10 bit）|
| bit 27–20 | 当前接收增益（增益表索引）|
| bit 31–28 | 大概是 AGC 状态机内部状态 |

#### 1.4 怎么搬进内存（ESP32-C61 为例）
SRAM 分 bank → 固件占**两块 bank 做成环形缓冲**：一块归调制解调器写、一块归 CPU 拷贝搬走，
固件盯硬件写指针，写满一块就换角色 → 连续采集不丢。

### 2. 硬指标（他们页面给的）

| 项 | 数值 |
|---|---|
| 调谐范围 | **2.2–2.7 GHz**；ESP32-C5 另有 **4.8–6.0 GHz** |
| 采样率 | **最高 80 MSa/s** |
| 模拟接收带宽 | **~13–54 MHz**（随芯片/滤波器设置）|
| 增益 | 内置 **AGC** 或手动固定增益 |
| 数据率 | 80 MSa/s × 32 bit = **2.56 Gbit/s** 写进 SRAM |
| 支持芯片 | **原始 ESP32 / C3 / C5 / C6 / C61 / S2 / S3 / S31** |
| 出口 | 大多数型号走 **UART**（低占空比）；**S31 走千兆以太网** |
| 持续能力 | S31 上 **8 / 16 MSa/s 持续**；社区玩家 h0m3us3r 用 **FPGA 搬运**，在 **S3 上做到 80 MSa/s 持续** |
| 超规格 | C61 的 PLL 实际能到 **2.7 GHz**，覆盖 **LTE band 7 / 5G NR n7（约 2.6 GHz）** |

### 3. 拿到这些数据，能干什么（重点）

#### 3.1 当**频谱分析仪**用（最直接、马上能用）
浏览器（Web Serial）里出**实时频谱 + 瀑布图**：
- 看 2.4G 上**谁在说话**、占多宽、多强 → 判断哪个 WiFi 信道最挤
- 找**干扰源**：微波炉、劣质电源、无线摄像头、坏掉的 AP
- 看 BLE 信标/邻居 AP 的密度（做"无线环境体检"）
- **对你做硬件的意义**：看自己板子发 BLE/WiFi 时的**功率、频偏、占空比、有没有跑飞/杂散**；
  配一个定向天线还能粗测"信号从哪个方向来"（找干扰）

#### 3.2 抓**任意 2.4G 协议**（这是 CSI 做不到的）
原始 IQ 里包含空口一切：**BLE 广播/连接包、Zigbee、802.11b/g/n（含多空间流）、
私有 2.4G（无线鼠标键盘、遥控、航模、无线麦、部分胎压/门磁）**。
有了 IQ，你可以在电脑上**自己写解调器**（GNU Radio / Python / Universal Radio Hacker / inspectrum），
甚至**逆向一个私有协议的编码**（比如自家的无线遥控、遥控车）。

#### 3.3 **相位相干** → 测向 / 定位（他们最核心的放大器）
- 单台接收机只能测"有没有、多强"；**多台相位同步**才有**相位差** → 才能算**到达角（AoA）** → 才能**定位**
- 以前 CSI 方案只能定位"**能发 WiFi 的**"设备；现在能定位**任意 2.4G 信号源**
  （BLE 标签、遥控器、无人机图传、甚至**干扰源**）
- 硬件：**ESPARGOS One** = 8 颗相位同步 ESP32 + **8 个双极化贴片天线** + λ/2 间距（60 mm）+ PoE 以太网；
  还能多阵列拼成 **6×4 = 24 天线** / **8×4 = 32 天线** 的大口径 → 角分辨率更高
- 用途：室内定位、资产追踪、遥控/无人机测向、**频谱监测执法找干扰源**、手势感知

#### 3.4 **无线感知**（ESPARGOS 的本行）
从无线信道的微小扰动反推**环境与人体**：动作识别、**呼吸/心跳检测**、人数统计、跌倒检测、穿墙感知。
原来用 WiFi CSI（20/40 MHz）已能做；加上 IQ 后可以用**非 WiFi 专用波形**做感知（例如脉冲波形对微动更敏感）。

#### 3.5 **（脉冲压缩）雷达**
自己发一个**已知波形** + **相干接收** → 做匹配滤波 → **测距/测速**（这就是雷达）。
ESPARGOS 支持**相干发射**；IQ 相干处理能出距离像/多普勒像。
用途：手势雷达、距离/液位测量、微动检测。

#### 3.6 **安全研究 / 频谱监测**
- 看**谁在发、发了多少、什么节奏**（不涉及破解加密 WiFi 内容，是"看得到空口行为"）
- 检测**攻击**：deauth 洪水、假 AP/邪恶双子、BLE 欺骗、干扰器
- 设备指纹/存在检测（靠信号特征识别机型）
- 反过来也是**安全提醒**：2.4G 上如果传明文，附近一颗 ESP32 就能抓 → 问题在"不该明文传"
  （他们 FAQ 专门解释了"这不是后门，是未文档化功能"）

#### 3.7 **超规格监听蜂窝频段**
C61 可到 2.7 GHz → 覆盖 **LTE band 7 / 5G NR n7（≈2.6 GHz）** → 看蜂窝信号强度与干扰、做被动信号分析。

#### 3.8 **教学 / 科研 / 算法验证**
- 最便宜的 SDR 教学硬件：几十元 vs 动辄上千的多通道 USRP 方案
- 能拿**真数据**验证：解调、同步、滤波、MIMO、波束成形、定位算法
- 他们的 `pyespargos`（Python 库）可以直接把 **CSI 实时流**拉进你的应用做实验

#### 3.9 **接进成熟生态**
- **SoapyESPSDR**（S31 + 千兆网）→ 直接进 **GNU Radio / gqrx / CubicSDR / SDR#**
  → 录 IQ 文件、接力现成的解调/解码模块 → 说明它**能当正经仪器链路的一环**，不只是玩具演示

### 4. 和"以前的 CSI 方案"的本质区别

| | **CSI**（他们以前的做法）| **Raw IQ**（这次新开的）|
|---|---|---|
| 数据是什么 | 每个 OFDM 子载波的**幅度/相位**（已经信道估计过）| **时域复数样本流** |
| 只对什么有效 | **WiFi 的特定前导符号**（L-LTF / HT-LTF）| **任何信号**（ADC 原始输出）|
| 能看哪些协议 | 仅 802.11g/n/ax（**802.11b 和多空间流不支持**）| **BLE / Zigbee / 私有 2.4G / 干扰** 全都能看 |
| 带宽 | 20 MHz（信道绑定 40 MHz）| **~13–54 MHz** 模拟带宽 |
| 在哪加工 | 芯片里已经加工完了 | **你在电脑上想怎么算就怎么算** |
| 能力上限 | 只能定位"能发 WiFi 的" | 定位 / 解调 **任意信号源** |

### 5. 怎么上手（4 步）

1. **拿一块支持的板子**（你的 **ESP32-S3 就在列表里**）→ 用他们的**浏览器 flasher** 刷 ESP-SDR 固件
   ⚠ **别刷到正在跑 LinTOS 的那块板**（会覆盖固件）；找块空闲板，玩完再刷回
2. 拔掉、等 5 秒、插回 → 打开 **ESP-WebSDR** 网页 → 选设备 → 看**实时频谱/瀑布图**
3. 想认真玩 → **S31 + 千兆以太网 + SoapyESPSDR** → GNU Radio / gqrx 里当接收机用、**录 IQ 文件**，
   再用 Python（numpy/scipy）、inspectrum、Universal Radio Hacker 离线解协议
4. 想做定位/感知 → **ESPARGOS One**（Core Kit 单阵列 8 天线；Aperture Kit 拼 24/32 天线）+ `pyespargos`

### 6. 局限（必须知道，别被"牛逼"冲昏）

1. **瓶颈在搬运**：2.56 Gbit/s 写进 SRAM，但出口慢得多 → 浏览器演示是**极低占空比**
   （抓一小段、歇很久）→ **会漏包**，**不能当连续接收机/连续解码**
2. 只有 **S31 + 千兆网** 能 8/16 MSa/s 持续；其他型号（含 S3）走 UART → 够看频谱，不够连续听
3. 量化只有 **10 bit**（不是 12/16 bit）→ 动态范围有限，强邻道+弱信号场景吃力
4. 频段固定在 **2.4G / 5G**；要别的频段得**外接混频器**
5. **只放接收实现**（发射能力确实有，但怕被滥用为干扰，故意不提供）
6. 每颗芯片的寄存器/触发方式都不同 → 支持列表靠**一颗颗逆向**，文档还没补齐
   （他们是从 Espressif `librftest` 的 `adctrig` 函数反推的，还用了 LLM 帮忙）
7. 这是**未文档化功能**，不是官方特性 → 将来新型号可能没有，也可能被固件/量产配置关掉
