# 频谱仪改版计划 — 对齐"网络安全扫描"的交互范式

> 2026-10-02 · linit 要求：像"扫描网络安全的界面"那样 **一步一步、可点选**，不要只有一个图。
> 本计划先给方案与步骤，确认后再动手。

---

## 一、参考的两个现成范式（都是自己的代码，直接抄结构）

| 参考 | 它怎么做的 | 在频谱仪里对应什么 |
|---|---|---|
| `page_netdect.c`（网络检测） | 顶部 **40px 步骤进度条**（"电脑诊断"同款）；`s_step` 当前步骤 + `s_view` 回看某步；每步"进行中 → 结果"；底部 `上一步/下一步/取消`；跑完生成**检测报告** | **一键扫描**：起射频 → 采集 → 找峰 → 判类型 → 出报告，一步一步走 |
| `page_wifiprobe.c`（无线探测） | 左右切 **多视图**（雷达/热力图/探针）；`s_sel` 选中行 + `s_scroll` 滚动；确认进 `s_detail` 详情层，返回退出 | **实时频谱 / 信道占用 / 信号列表 / 瀑布** 四个视图互切，列表可选中看详情 |

## 二、建议架构：**两态 + 一报告**

```
┌─ 列表态（可点选, 像应用管家）────────────┐
│ 频谱仪                                   │
│  ▸ 一键扫描    ← 分步执行(步骤条)        │
│  ▸ 实时频谱    ← 现在这个画面            │
│  ▸ 信道占用    ← 13 条柱状 + 推荐        │
│  ▸ 信号列表    ← 峰列表, 可选中看详情    │
│  ▸ 存到 TF     ← 导出 CSV/截图           │
└──────────────────────────────────────────┘
        ↑ BACK                    ↓ 确认
┌─ 实时态（连续观察, 现在的画面）──────────┐
│  确认 = 打开 5 槽菜单 (分析/保持/跨度…)  │
│  返回 = 回列表态                          │
└──────────────────────────────────────────┘
```
**为什么要两态**：实时图和"一步步选"是两种用法 —— 盯着看变化用实时态，要结论/要操作走列表态。
两者共用同一份采集与判读结果（`sdr_analyze()` 已经在算），不重复实现。

## 四、键位表（4 个键, 每态语义明确, 不再有隐式绑定）

| 键 | 列表态 | 一键扫描 | 报告页 | 实时态 | 实时态-菜单 |
|---|---|---|---|---|---|
| 上 | 选中上一行 | — | 上一页 | 增益 +2 | 上一个槽 |
| 下 | 选中下一行 | — | 下一页 | 增益 −2 | 下一个槽 |
| 左 | — | 上一步 | 上一页 | 中心 −5M | 选左边的槽 |

## 五、分步实施计划

| 步 | 做什么 | 验收标准 | 依赖 |
|---|---|---|---|
| **A1** | 抽"列表态"骨架：`sdr_page_t` 状态机（列表/实时/扫描/报告），先只放「实时频谱」一项 | 进应用先看到列表，确认进实时图，返回回列表 | — |
| **A2** | 抄 netdect 的 **40px 步骤条** 组件到 `sdr_view`，做「一键扫描」流程（起射频→采 20 帧→找峰→判类型→报告） | 扫描时能看到步骤条 + 进度，能取消 | A1 |
| **A3** | 报告**分 3 页**（概览/信道/信号），左右翻页 | 三页都能翻到，内容正确 | A2 |
| **A4** | **信号列表**页（wifiprobe 式列表 + 选中滚动），确认进详情（显示该峰频率/强度/常发间歇/类型） | 能选中任意峰看详情 | A3 |
| **A5** | 列表项「信道占用」「存到 TF」接上（TF 导出 CSV + 截图） | 卡里能看到文件 | A4 |
| **A6** | 实时态保留 5 槽菜单；两态共用 `sdr_analyze()` 结果 | 实时态与报告页数据一致 | A1 |
| **A7** | 进页提速（先出列表画面、蓝牙 suspend、FFT 表预建） | 进页 < 500ms | 全部 |

**顺序：A1 → A2 → A3 → A4 → A6 → A5 → A7**

## 六、不做的 / 风险

| 项 | 说明 |
|---|---|
| ❌ 不改采集与判读内核 | `espsdr_*` / `sdr_analyze()` 已经工作，改版只动"界面与流程" |
| ❌ 不做多点触摸手势 | 本机（微雪）没有触摸芯片，全按键；代码里的触摸分支保留不删 |
| ⚠ 改动面 | 这是把单页改成多态，`page_sdr.c` 会重构；`sdr_view.c` 的绘图函数基本原样复用 |
| ⚠ 回归风险 | 每步都要真机抓屏验收（remcon `page sdr` + `key` + `fbdump`），避免"改完看不出对错" |
