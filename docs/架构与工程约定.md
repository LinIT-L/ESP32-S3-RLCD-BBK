# LinTOS 架构与工程约定

> 处理对象：系统架构分层、模块契约、事件调度、内存策略、编码规范、编译/烧录/提交。
> 新功能怎么做 → 见《开发指南》；UI 细节 → 见《UI规范》。

## 1. 架构分层（微内核，参考 Flipper/LK/ESP-IDF）

```
L4 应用/页面   os/pages/* 、引擎运行循环
L3 内核/服务   os/kernel/* + services/*(页面栈/弹窗/主题/管家/状态栏)
L2 领域服务   favorites/引擎管理器/壁纸/扫描/音频/网络/蓝牙
L1 驱动/兼容   st7305/触摸/input/board_shim/HAL
```

## 2. 依赖规则

- R1 依赖单向向下，禁止反向/同级互调。
- R2 请求逐层传递，不跳层调底层。
- R3 每层职责单一。
- R4 能力经接口契约暴露（`os_module_t`/服务 API/Host API），面向抽象编程。
- R5 新增=注册表加一行+实现模块，不改已有模块（开闭原则）。
- R6 依赖用 `REQUIRES`(对外)/`PRIV_REQUIRES`(仅内部)显式声明。
- R7 一个模块一个职责（SRP）。
- R8 高内聚低耦合：`.c/.h` 结伴自包含，私有 static state 留本文件。

## 3. 组件规范

- 一目录一职责=静态库；`include/` 公共头；命名小写下划线、类型 `_t`。
- 尽量自包含（字体/图标随模块私有）；驱动组件不混业务资源。
- 跨模块相同代码抽共享组件单源。

## 4. 模块契约

- 页面实现 `os_module_t`(on_enter/on_exit/render/action/touch/poll)。
- 懒加载 `os_hw_request/store`；退出必须释放自己申请的资源（任务/堆/外设），不遗留后台线程。
- 全局服务 `os_register_service`（tick/render/touch 热区），不占页面栈。

## 5. 事件调度

单主循环（Reactor）：统一轮询输入 → 分发 action/touch → 服务 tick+模块 poll → 统一渲染。
长时间阻塞操作（TLS/HTTP/扫描）放独立高栈 task 并保证退出回收。

## 6. 内存（ESP32-S3 双区）

- 内部 SRAM：热路径/性能关键。
- PSRAM（`EXT_RAM_BSS_ATTR`/SPIRAM）：大缓冲/表/帧缓冲。
- 目标内部余量 ≈161KB+。

## 7. 编码规范

函数 `xxx_yyy`、常量 `#define XXX_Y`、类型 `typedef ..._t`；
头文件顶部说明用途/依赖、`#pragma once`；
校验输入/指针/边界、状态机带超时、ISR 尽量短；中文资源为 UTF-8。

## 8. 编译 / 烧录 / 提交

### 8.1 环境
- IDF v5.5（`~/esp/esp-idf-v55`）+ py3.13 venv（`idf5.5_py3.13_env`）+ 工具链 `esp-14.2.0_20260121`。VB 烧录一律从 `build.sh` 导出的 PATH 取工具，勿硬编绝对路径。
- 编译（推荐一键）：`bash build.sh`（内部 `idf.py build` + 按需 `merge_flash.sh`）。增量小改也可直接 `idf.py build`。

### 8.2 烧录成功模板（以此为准，全量 16MB 保守安全）
```
# 全量合成 16MB 镜像（bootloader+分区+app+appdata/字库，一文件，保守安全）
bash merge_flash.sh
# 烧到 0x0；460800 波特率；进度=esptool 实时 %；--after hard_reset 写完自动重启
ESPT ≈/.espressif/python_env/idf5.5_py3.13_env/bin/esptool.py
"$ESPT" --port /dev/cu.usbmodem* --baud 460800 --after hard_reset \
        write_flash 0x0 dist/merged_16mb.bin
```

### 8.3 关键经验（深挖历史记录结论）
- **烧全量 16MB @0x0**（保守安全，一文件覆盖 bootloader/分区/app/字库，避免版本漂移）。
- **波特率必须 460800**：921600 在 ESP32-S3 原生 USB-Serial/JTAG 长写入必在中途掉线（实测 63% 断）。所有历史成功均为 460800。
- **能看到进度 + 写完自动重启** = esptool 自带（实时 `%` + `--after hard_reset` 复位）。
- **中途掉线（`Device not configured`/`Lost connection`）**：USB 链路长写入偶发物理掉线，属正常，**自动重试**（端口再现即重烧整个 16MB，直到 `Hash of data verified`）。
- 设备在 app 运行态直接连会 `No serial data received`（未进下载模式）——需进下载模式（按住 BOOT+复位）或趁新枚举的窗口。

### 8.4 提交
- 功能/修复完成 + 烧录验证后单独 commit（`功能:`/`修复:`/`架构:`）。
- 协议：需求改完或未完成需确认方案后，才「编译+烧录」；不逐小改反复烧。诊断优先串口实时日志（remcon），不轻易为排查反复烧录。
