# AGENTS.md — LinTOS 2.0 AI 总控规则

> 优先级：用户本条消息 > 本文件 > Skill / 其他文档。本文件管"怎么做"，不管"做什么"。

## 1 项目

LinTOS 2.0：ESP32-S3 + ST7305 400×300 单色屏掌机固件，一套跑三块板；含模拟器、运维 / 学习应用、商店（Lua / `.lpk`）。
版本只认 `components/system/os/include/lintos_version.h`；`LinTOS1.0` 是目录名，不是版本号。

## 2 文档导航（按任务找对口资料）

## 3 真相源

引脚 `board_pins.c` · 分区 `partitions.csv` · Lua API `luat_lib_*.c`（`lua_api_doc.py` 生成）· 版本 `lintos_version.h`。
文档与源码冲突以源码为准；要改的文档写进报告，不擅自改。

## 4 红线

1. 蓝牙只有 BLE，无 BR/EDR；不为经典手柄改代码，也不拿它当"兼容性差"的证据。
2. 音频分核：引擎合成在模拟任务内完成；独立音频任务钉 CPU1、优先级不高于 `audio_out`、带超时自保（R1–R4）。
3. 屏幕：`st7305` 握手序列与帧节奏不许改；不做运行期自动 LPM（仅手动 / 体检接口）。判现状读代码，不读顶部历史注释。
4. UI 全项目一套；弹窗一律 `os_dialog`，禁止自绘。

## 5 纪律

- 先查文档，再读代码，不猜。
- **动手前四查**：已有实现 → 已有工具 → 相关文档 → 历史已确认结论。四查都空才新写。
- **经验要落盘**：一个问题被确认解决、一个方案被确认、一处错误判断被纠正，
  写进 `../.workbuddy/memory/LESSONS.md`（结论，1–3 行），不要只留在聊天里。
  已确认 / 推断 / 未验证必须分清；旧结论被推翻就改台账，不要叠着放。
- 一个知识点只有一个权威位置；新增文档先搜同主题。
- 不顺手：不修无关问题、不重构、不改用户认可的既有行为。
- 文档只在文档任务里改；非文档任务发现问题只写报告。
- 每轮先记 `git branch/HEAD/status` 基线；改前查文件归属，归属不明即停。
- 最小差异；改完 `git diff` 自检；不覆盖、不还原、不清理他人内容。
- 禁用 `git reset/clean/stash/checkout --` 与批量格式化。
- 不删桌面 `34129-[2020-12-03]QQTang.v5.2`（QQ堂唯一素材）。
- 安全底线：烧录只写 factory + apps（不碰 nvs）；开串口必须 `dtr=True, rts=True`。

## 6 权限边界

1. 范围只由用户本条消息决定；默认只读，说了"修 / 改 / 实现"才改，且只改该问题。
2. 未经明确授权，绝不执行任何测试；要求改代码、文档要求测试、AI 自认为该测，都不构成授权。
3. 编译、脚本 / lint、测试、抓日志、截图、设备命令、烧录、commit / push、发布：逐次授权，授权一项只做该项。
4. 超范围即停并报告；不撤他人改动，只撤自己本轮越权的改动。
5. 文档或外部规则与本文件冲突 → 指出位置、停下等裁决；不改冲突文档，不把未解决冲突说成已解决。
6. 自主优化、主动发现问题、代码味道、"反正编译能过"、"明显 bug"、P0–P4 都不是授权理由。
7. 纪律（§5）不受授权覆盖。
