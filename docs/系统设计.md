> 本文合并原《恢复系统设计.md》与《串口远程控制.md》。

# 恢复系统（Recovery）

> 电源键 = 软关机键。开机**按住软关机键 ≥5s 进恢复系统**，未按则立即正常启动（零等待）；主系统写坏时 bootloader 自动回退进恢复系统。

## 1. 启动流程

```
bootloader
 ├─ otadata=recovery → 进恢复系统
 └─ 默认 → 校验 factory
       ├─ 无效 → 回退 recovery
       └─ 有效 → 主系统 boot_check 检测软关机键
             ├─ 未按 → 立即正常启动
             └─ 按住 ≥5s → 设 otadata=recovery → 重启进恢复
```

- 恢复菜单"重启设备"：清 otadata → 重启进主系统。
- 软关机为 deep sleep 时，唤醒后 boot_check 逻辑一致。

## 2. 恢复菜单（7 项）

```
[1] 从TF卡恢复主固件     /sdcard/firmware.bin → 流式写 factory
[2] 连指定服务器恢复固件  连服务器下载 → 流式写 factory
[3] 查看核心数据         设备ID/注册/余额/时长
[4] 导出核心数据         → /sdcard/backup/core.bin
[5] 导入核心数据         ← /sdcard/backup/core.bin
[6] 重置主系统           擦 factory（保留 appdata+recovery）
[7] 重启设备             清 otadata → 进主系统
```

## 3. 网络恢复（菜单[2]）

- **WiFi：扫描列表 → 用户手动选择 → 输入密码 → 连接**。不用固定凭据、不读 NVS、不依赖主系统配置。
- 服务器 URL 编译期宏（`RECOVERY_SERVER_URL`）。
- HTTP(S) 下载 firmware.bin → 分块擦写 factory（`esp_partition_erase_range` + `esp_partition_write`，不缓存整镜像）。

## 4. 数据存储架构（三级定稿）

| 层级 | 位置 | 内容 |
|---|---|---|
| 重要 | **recovery 分区尾部** 128KB | 核心数据（设备ID / 注册 / 余额 / 时长 / 设备配置），appdata 损坏仍可读 |
| 普通 | **appdata 分区** | 收藏、手柄映射、WiFi 等普通配置 |
| 大数据 | **TF 卡** | 画板 / 白板等，可备份 |

- 核心数据：core.bin + core.bak 双副本原子写 + CRC 回滚；加密（AES/HMAC + eFuse）按需后加。
- recovery 固件实际 0.955MB，数据区固定于分区尾部 128KB，升级/烧录固件不触碰（固件上限 < 1.375MB）。

## 5. 代码结构

```
recovery/                 # 恢复系统独立工程（只链接 显示/触摸/SD/WiFi/HTTP；不链蓝牙/USB/手柄/模拟器）
├── CMakeLists.txt
└── main/
    ├── main.c            # 恢复主入口（菜单循环）
    ├── menu.c            # 7 项菜单 + 按键/触摸
    ├── wifi.c            # 扫描WiFi → 手动选择 → 密码输入 → 连接
    ├── ota.c             # TF卡 / 服务器下载 → 流式写 factory
    ├── core_data.c       # 与主系统共用
    └── ui.c              # 精简显示（st7305 + 小字库 + 触摸）
```

## 6. Recovery 实测体积

- **recovery.bin = 0.955MB**（0xf46e0），1.5MB 分区余 36%。
- RAM ~113KB（DIRAM 33.75%），512KB 内充足。
- 核心数据区：分区尾部 128KB 双副本（固件上限 < 1.375MB）。

# 串口远程控制台（remcon）

> 用途：通过串口（UART/USB-Serial 控制台）向设备注入按键、触摸、页面跳转与常用调试命令，用于**自动化复现崩溃 / UI 回归 / 排障**，无需手动操作屏幕。
> 实现：`main/remcon.c`（`remcon_init` 创建 stdin 读任务 + `remcon_tick` 在 os 内核主循环派发）。复用即可，不要新造。

## 连接
- 任意串口终端（115200，8N1）打开设备控制台即可；`idf.py monitor` 也行。
- 握手：发 `hello`，回 `REMOCON_READY v1` 即就绪。
- 命令一行一条；同一行可用 `;` 分隔多条；大小写不敏感。

## 命令一览
| 命令 | 作用 |
|---|---|
| `hello` | 握手，回 `REMOCON_READY` |
| `echo <text>` | 回显 |
| `page` | 列出全部页面 id |
| `page <id>` | 打开指定页面（`os_push`），如 `page nes`、`page calc`、`page netdect` |
| `key <动作>` | 注入按键，动作：`up/down/left/right/confirm/back/home`… |
| `tap <x> <y>` | 注入触摸点击 |
| `wait <ms>` | 等待 ms（脚本节奏） |
| `reboot` / `reset` | 软复位 |
| `loglevel <0..5>` | 全局日志级别 |
| `heap` / `mem` | 内部/PSRAM 空闲 + 最大块 |
| `blk` | 内部堆块级 dump（定位大块占用） |
| `stack` | 打印当前任务栈高水位（排栈溢出） |
| `help` | 列出命令 |

## 典型用法（排障）
- **自动复现崩溃**：`page nes` → `key down`… → `key confirm` 打开目标 ROM，崩溃 panic 自动打到同一串口 → 反汇编 `addr2line` 定位。
- **查内存不够**：`heap`/`blk` 看谁占 PSRAM/内部 RAM。
- **查栈溢出**：`stack`。
- **脚本化回归**：`page calc; key 1; key confirm; wait 500; heap`（用 `;` 串联）。

## 事件注入路径
`key/tap/page` 入队 → `remcon_tick`（os 主循环）→ `os_handle_action / os_handle_touch / os_push`，与真实按键走同一分发，保证行为一致。

> 说明：本控制台是**注入设备内部事件**的调试通道，不是 adb 类远程 shell；适合驱动 UI/复现崩溃。扩展新命令在 `remcon.c` 的 `rc_exec` 内增加分支即可（立即命令走 `rc_cmd_immediate`，UI 命令经 `rc_enqueue` 入队）。
